# LabOS 并行调度：源码核查清单与实施前置条件

- 日期：2026-11-18
- 性质：**核查清单**，不是设计方案
- 用途：任何并行调度方案在动笔前，先用这张表确认"哪些已有、哪些部分有、哪些没有"
- 核查方式：直接读 `main` 分支源码（commit `bd6fa6f`），逐文件逐方法确认
- 判定口径：**已有** = 能定位到方法且行为符合预期；**部分有** = 有实现但缺关键一环；**没有** = 全仓未找到

**B-04 的注释原文**（第 682–687 行）值得原文引用，因为它明确了设计意图：

> 锁住实验行（异步分批"取下一批"的串行化点）。
> 为什么锁实验行而不是批次行：判定"同实验是否已有批次 run 在队列/执行"是**实验级不变量**，只锁某一批挡不住两个请求同时给不同批建单。

**结论**：批次并行的唯一硬阻塞就是 B-04/B-05。改法是把"同实验是否已有活跃批次"改为"**同批次**是否已有活跃尝试"。

## 7. 事实性纠错（前一版方案写错的地方）

这一节是给后续写方案的人看的，避免再犯同样的错。

| ID | 我之前的表述 | 实际 | 影响 |
|---|---|---|---|
| X-01 | `run.priority`（1 最高 9 最低） | `insertRun` 第 610 行**硬编码 `5`**，从不参与调度；调度读 `experiment.priority`，`priority DESC`（数值大者优先） | 优先级设计全错 |
| X-02 | 并行度受 `RUN_POOL` 4 线程限制 | `RUN_POOL` 是 `WorkflowService` 的单流程池；`ExperimentScheduler` 有自己的 pool（`MAX_CONCURRENT=4`） | 线程池判断张冠李戴 |
| X-03 | 岛锁仍在使用 | 2026-11-10 起资源级已取代岛级互斥 | 表述过时 |
| X-04 | 需要新增开关控制流程互斥 | 已有 `LABOS_WORKFLOW_CONCURRENT_RUN=allow` | 重复造开关 |
| X-05 | 新增 `paused_waiting_resource` 状态 | `run_status` 是 PG 枚举，无此值；且系统原则是"用列不用枚举" | 方案不可实施 |
| X-06 | 4 批 4 设备 ≈ 1 批耗时 | 单臂实测 Transfer 均值 9.33s ⇒ 6.4 次/分；单 run 需 3.5~4 次/分 ⇒ **2 run 已到容量边缘** | 收益表过于乐观 |
