## 6. 已知边界（测试时不要误判为 bug）

1. **`/api/positions` 有两套 id**：`resourceId`（resource_node.id，老口径）与 `pointId`
   （device_point.id，新口径，物料配置/节点绑定用）。`/api/positions/{pointId}/methods`
   的 `pointId` 是 **device_point.id**，不是 resourceId——这是设计约定（避 PF-11 坑）。
2. **「只读」角色矩阵未做**：P0 的导航裁剪只做了「可见/隐藏」（admin-only 项），
   operator/designer 的「只读 vs 可写」是逐页权限，留 P1 后续，尚未实现。
3. **三条件闸门 C2 是简化版**：目前 C2 =「无未分配位置物料」，不是完整的流程预检
   （PreflightChecker 仍独立存在）。真实流程级预检在 start 时叠加。
4. **start 不实际派发**：P1 的 `/start` 只做 readiness 校验并返回 started，**实际派发仍走
   既有调度链路**（未改派发核心）——这是设计边界。
5. **机械臂调试台「示教读取」依赖 debug 开关**（`LABOS_*` 调试通路默认关），关闭时 403 属预期。
6. **manifest_placement 两处 DDL 口径修正**：`position_id` 改可空（unassigned=无位置）、
   `ck` 加 `unassigned` 初态——已同步进迁移文件，重跑幂等。
