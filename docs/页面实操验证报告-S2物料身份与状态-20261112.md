### R13-22 · Q18 命中运行时新数据（本轮测试发现）

**现象**：内核重载后自动跑出 run `1001333`（创建于 15:42:53），Q18
`SELECT ... WHERE status='completed' AND execution_resolution_status='unresolved'`
命中 3 行：`1001333|S1|0`、`1001333|T2|0`、`1001333|S2|0`。

**根因（已核实）**：
- `T2` 在 `workflow_node.params` 里是 `{"builtin": true, ...}` ⇒ BUILTIN 节点走
  `GraphRunner.executeBuiltin`，**不经过** `RunStateMachine.executeNode`，完成处理器不触发；
- `S1` / `S2` 是 `level=1` 步骤行，同样不经过完成处理器；
- 设计 §3.7:419 明确「结构节点（START/END/网关/BUILTIN）**跳过**——它们没有执行确认语义」，
  但 §5.3 的 Q18 **没有排除** BUILTIN 与 level=1 步骤行，只按 `status='completed'` 全表扫。

**判定**：这是**巡检 SQL 与设计口径不一致**，不是本轮 P0/P1 代码回归（T1/T3 两个真实 TASK 节点
在重载后正确写成 `execution_resolution_status='completed'`，证明完成处理器主链路生效）。
处置需走 §13.2 CR：要么让 BUILTIN/步骤行也落一个明确的 `completed` 确认，
要么把 Q18 收窄为「只查 `level=0` 的 TASK 节点」。**本轮未擅自改 Q18 或设计稿**。
