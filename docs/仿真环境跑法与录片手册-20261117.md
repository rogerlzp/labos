# 仿真环境 · 跑法与录片手册（2026-11-17）

> 面向"自己跑一遍"和"录一段给客户/评审看"两件事。
> 配套：`docs/模拟布局与现场数据替换-20261115.md`（模拟布局怎么造、现场数据怎么替换）。

## 0. 一句话

```bash
./scripts/start-sim-station.sh --restart        # ① 起环境（内核 + 13 台模拟器 + sidecar）
python3 scripts/gen-sim-layout.py               # ② 造模拟布局（分区/标定/板/变量）
python3 scripts/reset-sim-station.py --apply    # ③ 复位工位（释放上轮残留的板位归属）
python3 scripts/run-extraction-line.py          # ④ 跑一次提取线并取证
python3 scripts/make-run-film.py --run <runId>  # ⑤ 把这次运行渲染成演示片
```

## 1. 前置条件

| 项 | 要求 | 检查 |
|---|---|---|
| 内核 | 18080 端口、`LABOS_DB_*` 连到 PostgreSQL | `curl -s http://127.0.0.1:18080/api/auth/login -X POST -d '{"username":"admin","password":"admin123"}'` |
| 模拟器 | 13 台（P_AUTO-1..4 / DISP1..6 / ARM1 / STACK1 / D9608-1），端口 196xx | `python3 scripts/sim-all.py --status` |
| sidecar | 每台一个（写 Redis `labos:link:*`，**在线状态的唯一依据**） | 同上，`心跳在线` 列应为 13/13 |
| 事件入站 | 内核必须开 `LABOS_DEVICE_EVENT_ALLOW_ANONYMOUS=1`（仿真态） | `curl -X POST .../api/device-events -d '{"device":"X","eventType":"probe"}'` 返回 **200**（503 = 没开） |
| 模拟布局 | L3 分区集 + 机械臂标定 + 模拟板 + 流程变量 | `python3 scripts/verify-p2-interlock-config.py`（L3/L4 应为 ✓） |

> ⚠ **最容易踩的坑**：内核重启时漏掉 `LABOS_DEVICE_EVENT_ALLOW_ANONYMOUS=1`
> ⇒ 设备事件入站返回 503 ⇒ 侧车事件全被拒 ⇒ 流程永远卡在「等交互」。
> **一律走 `scripts/start-sim-station.sh`，别手动重启内核。**

## 2. 五步跑法

### ① 起环境（一条命令）

```bash
./scripts/start-sim-station.sh --restart     # 内核 + 13 台模拟器 + sidecar 一起
./scripts/start-sim-station.sh --status      # 只看现状
```

它做的事：重启内核（带 DB/Redis/事件入站/自动确认四个开关）→ 重建模拟器 → 拉起 sidecar。

### ② 造/刷新模拟布局（模拟物理布局 + 标定 + 模拟板）

```bash
python3 scripts/gen-sim-layout.py            # 幂等，可反复跑
python3 scripts/gen-sim-layout.py --dry-run  # 只看要生成什么
```

产出（全部带 `SIM-` 标记，可一键撤销）：

| 产物 | 数量 | 作用 |
|---|---|---|
| `rail_zone` + `transfer_rail_zone` | 7 + 1680 | L3 轨道分区互斥（按 x 坐标分带推导） |
| `robot_point` | 78 | 机械臂 ARM1 的点位标定（x/y/z + fill_status=ok） |
| `stirrer_dispenser_pair` | 6 | L4 搅拌—分液配对 |
| `plate` + `workflow_variable` | 4 + 5 | 4 块模拟磁套板（SIM-PLATE-MAG-1..4）+ `mainPlate`/`magPlate1..4` |

撤销：`python3 scripts/clean-sim-layout.py --apply`

### ③ 复位工位（每次跑之前都要）

```bash
python3 scripts/reset-sim-station.py --apply
```

**为什么必须**：上一轮卡住的 run 会一直占着 `position_state.occupied_by_run`
⇒ 新一轮的起点引导按 fail-closed 拒绝接管 ⇒ 每次都撞 `EC-POSITION-OCCUPIED`。
复位会释放归属 + 把板从点位取下（板回库存）+ 把卡住的 run 收尾（只限本流程与模拟板）。

### ④ 跑一次提取线

```bash
python3 scripts/run-extraction-line.py                    # 默认流程 1000929
python3 scripts/run-extraction-line.py --timeout 300
```

输出：runId、终态、节点状态分布、失败节点的错误码。
实测：**94 节点全完成 / 8 次搬运全 CONFIRMED**（约 26 分钟，其中大部分是模拟器跑真实工艺时长）。

### ⑤ 录一段演示片

```bash
python3 scripts/make-run-film.py --run 1001706 --speed 3 --fps 24 \
        --out "docs/media/提取线仿真回放-run1001706.mp4"
```

- **不用重跑**：影片直接用那次运行的**真实执行记录**回放
  （`run_node` 时间线 / `transfer_transaction` 搬运 / `position_scan_evidence` 扫码证据 / `device_event` 设备事件）
- **长空档自动折叠**：洗脱那种 400 秒的纯等待会被压成 6 秒 ⇒ 26 分钟真实时长 → 约 2 分钟影片，每个动作都看得清
- `--speed` 越大越快；`--fps` 建议 24

## 2.5 两条演示链路怎么衔接（剧本 × 画面）

仓库里有**两件互补的东西**，别当成重复：

| 产出 | 脚本 | 回答的问题 |
|---|---|---|
| **演示剧本**（Markdown + 机读 JSON） | `scripts/replay-run.py`（另一条线做的） | "**这一步在做什么、为什么、缺什么**" —— 按客户 §3 的 8 阶段分组，给讲解词 + 缺口清单 |
| **演示影片**（mp4） | `scripts/make-run-film.py`（本手册配套） | "**板在哪、设备在动、什么时候扫码/取锁**" —— 工位示意 + 板移动 + 事件流 |

串起来用：

```bash
# ① 讲解词（给人看）
python3 scripts/replay-run.py <runId> --out docs/media/剧本.md

# ② 画面（给机器看），可选吃剧本 JSON：阶段边界用剧本的、缺口清单显示在右下角
python3 scripts/make-run-film.py --run <runId> --script docs/media/剧本.json \
        --out docs/media/回放.mp4
```

> ⚠ **当前有个 interop 缺口**（2026-11-17 实测）：`replay-run.py` 的**机读 JSON**
> 自检会失败 —— 它的阶段归类按**节点名**匹配（客户 8 阶段的叫法），
> 而提取线流程的节点名（`机械臂 放磁套板到 P_AUTO-1 交互位` 等）**落不进任何阶段**
> ⇒ 「有节点没落进任何阶段 ⇒ 拒绝出 JSON」。
> Markdown 剧本**不受影响**（它照常产出，阶段划分也正确）。
> ⇒ 要出机读 JSON，得给 `stage_of()` 补上提取线的节点名映射；这属于那条线的改动。

## 3. 想录"真实界面"（不是动画）怎么办

动画片适合讲**工艺与互锁**；要证明"这是真的系统在跑"，可以再录一段真实界面：

```bash
# ① 浏览器录屏（Playwright 自带 video 录制，产物是 webm）
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b = p.chromium.launch()
    ctx = b.new_context(record_video_dir="/tmp/vid", viewport={"width":1920,"height":1080})
    pg = ctx.new_page()
    pg.goto("http://127.0.0.1:5173/login")
    pg.fill("input[placeholder*='用户名'], input#username", "admin")
    pg.fill("input[type=password]", "admin123")
    pg.click("button:has-text('登录')")
    pg.goto("http://127.0.0.1:5173/live")     # 运行看板
    pg.wait_for_timeout(120000)                 # 录 2 分钟
    ctx.close()
PY
# ② 转成 mp4
ffmpeg -i /tmp/vid/*.webm -pix_fmt yuv420p -crf 20 docs/media/运行看板录屏.mp4
```

界面入口：
- `/live` —— **运行看板**（在跑/待人工/未闭环告警/离线设备 + 运行列表 + 人工窗口）
- `/designer/1000929` —— **流程设计器**（看图与节点绑定）
- `/positions` / `/devices` —— 点位与设备

> 工具齐全：`ffmpeg` ✓、`playwright` ✓（python + Chromium）、`screencapture`（macOS 整屏录制）✓

## 4. 3D 要不要做？（结论与理由）

**结论：想要"更像真的"，优先级应该是 ① 数据真实 ② 画面能表达设备在动 ③ 3D —— 3D 排最后。**

理由（都基于本项目实测）：

1. **3D 治不了这次的病**。之前七层阻塞全部是**接线/配置**问题（点位码当设备码、缺板号、
   扫码证据没落位、id 空间撞号），3D 模型一个都帮不上。
2. **仿真动画已经有信息量**：板在设备间移动 + 扫码证据 + 分区取锁 + 阶段推进，
   这些**才是客户要看的"安全与互锁怎么落地"**。
3. **3D 资产可得性有限**：平台记录的三家参考机型里，只有埃斯顿 ER3-400-SR 有官方
   2D/3D 数模（官网免费下载）；**PAuto 磁珠提取仪、D9608、板栈都是客户定制/小众型号，没有公开 3D**。
4. **成本**：拿到的多半是 CAD（STEP/SLDASM），要转成可动模型还得做绑定与动画，
   远超"让人看懂这条线在跑"的收益。

**如果确实要做 3D，推荐的路径（不是找模型，而是做轻量数字孪生）**：

| 做法 | 成本 | 收益 |
|---|---|---|
| 复用现有 2D 设备图（`webapp/public/devices/*.svg`：PAUTO / D9608 / GANTRY_ROBOT_GENERIC / PLATE_STACK_GENERIC）＋ 用 `position_state` 驱动板移动 | 低（半天） | 画面与真实台账一致，设备外形由客户确认 |
| Three.js 搭 3D 工位，用 `robot_point` 的 x/y/z 摆设备、板按 `transfer_transaction` 飞 | 中（2~3 天） | 运动包络可视化（正好呼应 P2 的"完整运动包络"） |
| 导入厂商 3D 数模（ER3-400-SR 等）做高保真 | 高（数模清洗 + 绑定动画） | 观感好，但对"证明系统是对的"贡献最小 |

> 已有资产：`webapp/public/devices/` 下 20 张 2D 设备线稿（含 PAUTO.svg / D9608.svg /
> GANTRY_ROBOT_GENERIC.svg / PLATE_STACK_GENERIC.svg），且 `robot_point` 里已有 78 个
> 点位的 x/y/z ⇒ 做 3D 时**不用另找坐标来源**，直接用库里的标定。

## 5. 出问题先看这里

| 症状 | 多半是 | 处理 |
|---|---|---|
| 流程卡在「等交互」 | 事件入站 503（内核没带匿名开关） | `start-sim-station.sh --restart` |
| 新一轮就 `EC-POSITION-OCCUPIED` | 上轮 run 还占着板位归属 | `reset-sim-station.py --apply` |
| `EC-06-0006`（并发守卫拒） | 模拟器还有命令在飞 | `sim-all.py --restart`（等 45 秒心跳落定再跑） |
| `EC-05-1007`（命令超时） | 超时上限查错设备（id 空间 bug，已修） | 确认内核是最新构建 |
| `EC-INTERLOCK-RAIL`（全拦） | L3 分区集没配 | `gen-sim-layout.py` + `verify-p2-interlock-config.py` |
| `EC-SCAN-EVIDENCE-MISSING` | 扫码节点没声明被扫位置 | 流程里 `method_params.sourcePosition` 要写点位码 |
