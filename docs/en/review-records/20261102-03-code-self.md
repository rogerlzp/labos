## 2. Conclusion summary

**Fail.** Problems found: **16 P0 blocking, 31 P1 severe, 60+ P2 normal, 60+ P3 suggestion.**

Three **systemic** defects (more serious than single-point bugs):

1. **The "dual-path" split**: `driver/` and `workflow/` each have their own execution / lock / pause implementation, and the production path only takes one of them → the "dual lock / return-leg position
   / three-state plate position" in the other one is **never reachable in production** (`WorkflowService.java:588` `db=null`).
2. **"Declared to exist, the entity does not exist"**: the code refers in large numbers to **DB columns / tables that do not exist** (`device_state.online/last_heartbeat/current_method`,
   `run.attendance`, `run_command.device_id`, `plate.plate_id/current_pos/current_run`, `error_code.attr`, `sys_user`), and in many places the exception is swallowed by `catch(SQLException ignore)` → **the
   core chain fails silently**.
3. **"The safety net is a mere formality"**: the authentication interception is in the wrong place (most write routes bypass it), the weak default password is echoed in clear text, the `\unrestrict`
   token is left over in the schema, and the script hard-codes the password.

- **[P0-1] api/ApiServer.java:682 — the authentication interception is in the wrong place; all the routes registered on lines 188–680 bypass authentication entirely.** Evidence: `route()` is a giant

### 12.1 About the three items that are not fixed / not touched

**P1-29, P1-30 (the scripts) — not accepted**

- `set -e` makes the script exit at the first failed assertion, which **precisely breaks the design of "run all the scenarios and then summarise"**. The exit code is already correct
  (`[ $FAIL -eq 0 ] && exit 0 || exit 1`), so the CI can judge success or failure.
- `/tmp/verify-*.txt` is a **diagnostic artefact for humans**; deleting it makes a failure impossible to investigate. Repeated runs overwrite the file of the same name, so it does not grow without
  bound.

**P1-33 (the test really connects to the database) — not touched**

Turning it into a hermetic test requires extracting an interface for `DbConfig` + introducing an in-memory database or a mock, which means refactoring all 8 test classes. **The benefit is "the tests
do not depend on the environment"; the cost is changing the test infrastructure**. 26 P1 items have been fixed in this round; this one is left for a separate round.

**P1-18/19 (a read timeout is misjudged as a dropped connection) — not touched**

Distinguishing a "read timeout" from a "connection drop" requires changing the socket timeout semantics + the error-code mapping, and the current `setSoTimeout(0)` (a resident reading thread) means
that **a read timeout can never occur at all** — whether the defect really exists needs the reviewing party to confirm the scenario.
