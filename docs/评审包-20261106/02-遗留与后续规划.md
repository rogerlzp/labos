# 02 · 遗留与后续规划（2026-11-06）

## 1. 等用户输入的三件事（阻塞项）

| # | 事项 | 为什么要你定 | 定了之后我做什么 |
|---|---|---|---|
| 1 | **现场可中断方法清单** —— 哪些方法能停、哪些不能 | 机械臂搬运类（`Transfer`/`Grip`/`Release`/`Load`/`Unload`）中断就是**板掉地上**，不可逆；长工艺类（离心/孵育/PCR/读板）停掉通常安全 | 我把对应 `device_method.interruptible` 置 `true`（**只改数据，不改代码**），并在演示岛上实测一轮 |
| 2 | **界面对「等人工继续」与「已中断·将自动重试」的区分** | 这两者的现场动作不同：前者等人点继续，后者恢复时**自动重跑这一步** | 我补前端文案与状态着色（数据侧已经能区分：`aborted` vs `manual`） |
| 3 | **日常门禁的仿真机耗时区间** | 机械臂现在配的是 30–300 秒随机（你指定的），代价是**全量门禁从 ~17 分钟涨到 ~32 分钟**（2.7 段就占 14 分钟） | 你选：① 保持 30–300 秒（演示最真实，门禁最慢）② 日常用窄区间/固定种子（如 `30000:45000:42`），演示时再切回 ③ 其他折中 |

> 另有一个**纯技术决策**也可以交给你：`device_method` 的**能力默认超时值**（本轮给了 16 个能力一组保底）
> 是否合理 —— 特别是「扩增/PCR 60 分钟」和「扫码 10 分钟」这两个是否偏保守。

## 2. 挂起项（本轮登记，**未做**）

| 项 | 状态 | 说明 | 建议 |
|---|---|---|---|
| **删 run 不释放设备锁** | ⚠ 根因未治 | 本轮是在**启动兜底**清锁（幽灵锁 + 孤儿锁）。但「删除 run」这个动作本身仍不释放锁 ⇒ 设备要等到**下一次 API 重启**才恢复可用 | 在删除 run 的入口（API / 后台清理 / 手工 SQL 脚本）统一释放；或给 `device_state` 加「租约过期」机制（按 `updated_at` 判定失效） |
| **多设备并行执行中暂停** | ❌ 未覆盖 | 暂停是 **run 级**的，并行分支同时在跑时「停哪个」没有定义 | 需要设计：是否停全部？停可中断的那些？ |
| **`subProcess` 静默跳过** | ❌ 沿用上轮裁定 | `subProcess` 不在解析器白名单 ⇒ 连进链路会静默跳过后继（整单仍报 `completed`） | 三条候选：预检拦截 / palette 移除 / 解析器透明化。**等评审意见** |
| **界面区分中断态** | ❌ 未做 | 见 §1-2 | 与现场清单一起做 |
| **真机验证** | ❌ 未做 | 本轮全是仿真机 | 需要一台真机 + 现场清单 |
| **真机长任务（离心 5 分钟 / 孵育 30 分钟）** | ⚠ 机制齐了，未实测 | 超时按方法取已实现（孵育 1800s / 离心 900s），但没有真机跑过 | 需要真机 + 现场确认 |
| **`EC-99-0005` 未登记进错误码表** | ⚠ 已知 | 中断用的错误码在 `error_code` 表里**没有** ⇒ 恢复策略查不到 ⇒ 兜底「转人工」 | 建议登记该码并给出明确作用域（`command` 级、不可重试或「重跑本步」） |

## 4. 需要的输入（列清楚，方便一次给全）

1. **可中断方法清单**：格式建议 `能力/方法 → 可中断(true/false)`。
   机械臂搬运类默认 false；长工艺默认 true。
2. **真机可访问环境**（若要做真机验证）：至少一台设备 + 现场可执行的方法。
3. **仿真机区间偏好**（见 §1-3）。
4. **本轮能力默认超时值是否认可**（尤其扩增 3600s / 扫码 600s 这两个极值）。

## 5. 复跑提醒（给下一个接手的人）

- 全量门禁：`export LABOS_TRANSFER_PLAN=1 LABOS_EXEC_GRAPH=1 LABOS_DRIVER_MODE=persistent LABOS_AUTH=1` 后跑 `./scripts/ci-gate.sh --all`。
- **机械臂仿真机若配 30–300 秒随机，门禁要 ~32 分钟**；先用窄区间跑一遍更省时间。
- `verify-s3-2-residuals.py` 会**真 kill 内核进程再重启**，只在测试环境跑。
- DB 口令环境变量名是 `LABOS_DB_PASS`。
- 门禁「阈值只许涨」：`scripts/ci-gate.sh` 顶部的 `MIN_*` 只许升不许降，
  降了会被第 0 段扫 git 历史直接判红。
