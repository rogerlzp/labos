## 0. 这份文档解决什么

现在的界面是**按数据表分的**（执行 / 工艺 / 状态 / 告警 / 策略）——
一个值班员想看"为什么停了"，要跳 3 个页面拼信息。

本文档把导航改成**按角色任务分**。

---

## 1. 导航怎么分

按人正在做的事分，不按数据表分。同一个人换任务时，信息应该还在同一组页面里，而不是散落到执行、告警、策略几个入口。

### 1.1 五个一级导航

| 导航 | 主要角色 | 一句话职责 |
|---|---|---|
| **编排** | 工艺工程师 | 把方法画出来、编译、预检 |
| **运行** | 值班员 | 盯住现在跑什么、卡在哪 |
| **分析** | 工艺/设备工程师 | 跑得快不快、哪里慢 |
| **运维** | 运维 / 主管 | 告警怎么处理、策略怎么改 |
| **系统** | 管理员 | 用户、权限、审计 |

> **和现状的差别**：现在没有「分析」入口（甘特没地方放），
> 「告警」和「策略」被拆成两个 Tab（其实是同一件事的两面）。

## 2. 信息架构

```
LabOS 2.0
├── 编排            （工艺工程师）
│   ├── 流程库      库内工艺的列表 / 搜索 / 筛选
│   ├── 流程设计器  bpmn-js 画布 + 编译预览 + 预检结果
│   └── 实验编排    React Flow 块级画布（拖 workflow 组装实验）
├── 运行            （值班员）
│   ├── 实时看板    正在跑的 run + 当前节点 + 设备 + 是否卡住
│   └── 执行详情    节点树（含子步骤）+ 事件流 + 值守切换
├── 分析            （工艺/设备工程师）
│   ├── 甘特        预测 vs 实际，可展开到命令级
│   ├── 时长分布    按方法/设备统计 p50/p90
│   └── 利用率      设备占用、停摆
├── 运维            （运维 / 主管）
│   ├── 告警        待处理 / 已认领 / 已关闭 + 认领关闭操作
│   ├── 策略        错误码 → 动作，可编辑 + 生效校验
│   └── 设备        在线状态、能力、隔离记录
└── 系统            （管理员）
    ├── 用户与角色
    └── 审计日志
```

**配色与状态语义统一**（贯穿所有页面）：

| 状态 | 颜色 | 用途 |
|---|---|---|
| `completed` | 绿 `#22c55e` | 成功 |
| `skipped` | 灰 `#8b93a7` | 按策略跳过（留痕不告警） |
| `running` | 蓝 `#3b82f6` | 正在执行 |
| `manual` | 橙 `#f59e0b` | 需要人（无人值守下升为红） |
| `failed` | 红 `#ef4444` | 失败 |
| 走不到的节点 | 红虚线框 | 预检 PF-03 |

## 3. 页面清单

每个页面写 6 项：**谁用 / 要解决什么 / 看到什么 / 能做什么 / 空态 / 异常态**。

### 3.1 实时看板（运行 · 首页）

| 项 | 内容 |
|---|---|
| **谁用** | 值班员 |
| **要解决** | "现在有没有在跑？卡在哪？" |
| **看到什么** | 每行一个 run：进度条（`12/65`）、当前节点名、设备号、值守模式、最近事件、运行时长 |
| **能做什么** | 切值守模式、打开执行详情、中止 |
| **空态** | "当前没有正在执行的流程" + 「去编排」入口 |
| **异常态** | 后端不可达 → 顶部红条 + 自动重试倒计时 |

> **设计要点**：数据来自内存态（`/api/process-status`），因为 `run_node` 执行完才落库。
> 页面要标注"实时内存态"还是"数据库"，让值班员知道数据新鲜度。

### 3.2 执行详情

| 项 | 内容 |
|---|---|
| **谁用** | 值班员 / 工艺工程师 |
| **要解决** | "为什么停了？第几步？哪台设备？" |
| **看到什么** | ① 头部：单号、状态、值守、进度<br>② 节点树：父节点 + 子步骤（`└1 OpenDoor completed 200200`），失败的步骤标红<br>③ 事件流：`#2 STEP_FAILED 第 3 步 CloseDoor device=200` |
| **能做什么** | 切值守、重跑、查看设备原文 |
| **空态** | — |
| **异常态** | 事件流为空 → 提示"该 run 未记录事件（可能是历史数据）" |

**关键**：子步骤必须显示**设备号**和**尝试次数**（`第2次`），否则看不出"换了设备还是失败"。

### 3.3 流程库

| 项 | 内容 |
|---|---|
| **谁用** | 工艺工程师 |
| **要解决** | "哪个流程？能不能跑？" |
| **看到什么** | 列表：名称、编号、节点数、分类；支持按名称/编号搜索 |
| **能做什么** | 打开设计器、一键执行、看预检结果 |
| **空态** | 无流程 → "先建一个" |
| **异常态** | 预检有 ERROR → 列表项左侧红点 + 悬浮提示 |

### 3.4 流程设计器

| 项 | 内容 |
|---|---|
| **谁用** | 工艺工程师 |
| **要解决** | "画流程、看会展开成几步、保存前知道能不能跑" |
| **看到什么** | ① 画布（bpmn-js）<br>② 右侧：节点属性（能力下拉 + 方法下拉）+ 编译预览（"将执行 7 步"）+ 预检问题<br>③ 底部：节点数 / 连线数 / 总步骤 / 预检状态 |
| **能做什么** | 拖节点、连线、折叠子流程、改能力、保存 |
| **空态** | 未选中节点 → "选中一个节点查看它的编译结果" |
| **异常态** | 预检 ERROR → 底部红字 + 节点标红虚线；保存时二次确认 |

**关键交互**：多步节点显示成**可折叠 subProcess**（已实现），点开能看到内部 7 步。

**按岛找设备（2026-11-05）**：新建流程时可先选「所属岛屿」（存进 `workflow.attr.island_id`，留空 = 全部岛，兼容旧流程）；设计器顶部有岛屿筛选器，右侧「节点设置」的设备下拉按该岛过滤，选项带 `@岛code` 避免跨岛误选。后端 `GET /api/devices/pool?islandId=` 是可选过滤，不传仍是全量池（岛屿视图与既有用例不回归）。新拖出、尚未保存的节点原本只显示「不在编译结果里」，设备/方法下拉完全不出现；现在给出「保存并继续设置」按钮，保存后刷新编译结果即可绑定。

### 3.5 告警

| 项 | 内容 |
|---|---|
| **谁用** | 运维 / 值班员 |
| **要解决** | "有什么要处理的？谁在处理？" |
| **看到什么** | 按 `错误码|设备` 聚合：命中数、级别、最近消息、**处置状态**（待处理/已认领/已关闭）、处理人 |
| **能做什么** | 认领（填处理人 + 备注）、关闭、静音、重开 |
| **空态** | "没有未处理的告警" |
| **异常态** | 处置失败 → toast 提示，不改本地状态 |

> **设计要点**：默认只显示「待处理」，已认领/已关闭折叠在下面——
> 值班员打开就应该看到"还需要我做什么"。

### 3.6 策略

| 项 | 内容 |
|---|---|
| **谁用** | 运维 / 主管 |
| **要解决** | "这个错误码应该怎么处理？我改了会不会影响别的？" |
| **看到什么** | 列表：错误码、层级、动作、次数、退避、优先级、启用状态、来源（手工/推导） |
| **能做什么** | 编辑、启用/停用、**生效校验**（用历史错误回放，告诉你"这条匹配不到任何历史错误"） |
| **空态** | — |
| **异常态** | 校验失败 → 显示"永远不生效"的红色提示，仍允许保存（但需确认） |

**关键**：策略编辑是**危险操作**，必须二次确认 + 显示影响范围（这条策略会作用到已有的历史错误）。

### 3.7 甘特（分析）

| 项 | 内容 |
|---|---|
| **谁用** | 工艺 / 设备工程师 |
| **要解决** | "这段要多久？哪台设备是瓶颈？" |
| **看到什么** | 泳道=设备，块=节点/命令；两种视图：**预测**（仿真时长）/ **实际**（`run_node` 时间） |
| **能做什么** | 展开到命令级、切换设备分配、缩放时间轴 |
| **空态** | "先跑一次或做一次仿真" |
| **异常态** | 缺时长模型 → 该命令用虚线块 + "无历史时长"标记 |

### 3.8 设备（运维）

| 项 | 内容 |
|---|---|
| **谁用** | 设备工程师 |
| **要解决** | "哪台离线？哪台被隔离了？它能干什么？" |
| **看到什么** | 设备卡片：编号、名称、能力标签、在线状态、已隔离次数、最近错误 |
| **能做什么** | 解除隔离、查看历史错误 |
| **空态** | — |
| **异常态** | 设备状态未知 → 灰色 + "状态未知" |

## 4. 设计规范

### 4.1 布局

```
┌──────────────────────────────────────────────────┐
│ 顶栏：品牌 | 环境标识 | 全局搜索 | 用户           │
├────────┬─────────────────────────────────────────┤
│ 侧导航 │ 内容区                                   │
│ 编排   │  ┌─ 页头（标题 + 主操作）              │
│ 运行   │  ├─ 筛选/工具栏                        │
│ 分析   │  ├─ 主体（列表 | 表格 | 画布）          │
│ 运维   │  └─ 分页 / 状态栏                      │
│ 系统   │                                         │
└────────┴─────────────────────────────────────────┘
```

- 侧导航可收起，默认展开（一级 5 项，二级最多 4 项）
- 内容区最小宽度 1024，低于此值侧导航自动收起

### 4.2 表格（最高频组件）

| 规则 | 说明 |
|---|---|
| 行高 | 紧凑 36px / 标准 44px；执行详情用紧凑 |
| 首列 | 标识（编号/名称），等宽字体 |
| 状态列 | 徽章，颜色按 2 章的状态色 |
| 数值列 | 右对齐，等宽字体 |
| 空态 | 居中文案 + 主操作按钮，不显示空表头 |
| 长文本 | 单行截断 + 悬浮显示全文 |

### 4.3 危险操作

三类必须**二次确认 + 说明后果**：

| 操作 | 确认文案示例 |
|---|---|
| 保存流程（有 ERROR 时） | "预检发现 2 个阻塞问题，保存后流程可能跑不起来。仍要保存？" |
| 修改策略 | "该策略会作用到已有的历史错误，改完立即生效。确认修改？" |
| 中止运行 | "中止后已执行的设备动作不会撤销。确认中止 #204888？" |

### 4.4 长任务反馈

| 场景 | 反馈方式 |
|---|---|
| 执行工艺（同步，<5s） | 按钮 loading + 禁用 |
| 执行工艺（异步） | 立即返回 runId + 跳转详情 + 轮询进度 |
| 全量预检（约 90s） | 进度条 + 已检查条数 + 可取消 |
| 保存流程 | 按钮 loading + 成功后 toast |

### 4.5 时间显示

- 相对时间优先（"3 分钟前"），悬浮显示绝对时间
- 跨天显示日期（`10-30 23:16`）
- 时区统一 +08:00，不显示时区后缀

| 告警 | 7.2 告警认领/关闭 | ✅ 后端有 |
| 策略 | 9.1 策略管理 + 生效校验 | 🟡 **只读**，编辑与校验未做 |

### 5.2 六条门槛 → 界面落点

| 门槛 | 界面落点 | 现状 |
|---|---|---|
| 1 按图执行 | 设计器（折叠 subProcess）+ 执行详情（分支都执行） | ✅ 后端已修，界面待接 |
| 2 值守切换 | 实时看板 + 执行详情（切换按钮） | 🟡 后端有接口，页面未接 |
| 3 运营闭环 | 预检（设计器）+ 告警（认领关单）+ 策略（可改）+ 状态看板 | 🟡 策略可改、预检时点待调整 |
| 4 时长预测 + 间隔 | 甘特 + 时长分布 | ⬜ 后端无 |
| 5 影子模式 | 系统 → 驱动联调页 | ⬜ 无 |
| 6 离线改派 | 执行详情（显示换机过程）+ 设备页（隔离记录） | ✅ 后端有 |

### 5.3 对照发现的 5 个缺口

| # | 缺口 | 说明 |
|---|---|---|
| 1 | **实验编排无后端** | 界面设计了入口，但 D1 决议 2.0 只做顺序，得先定是否放开 |
| 2 | **策略只读** | 界面设计了编辑 + 生效校验，后端只有 GET |
| 3 | **甘特无时长模型** | 界面设计了预测/实际双视图，后端 `duration_model` 表有数据但没接 |
| 4 | **预检时点错位** | 界面设计成"保存前"，实现是"保存后" |
| 5 | **无鉴权** | 界面要显示"当前用户"，但后端全站无鉴权（审核必修项） |

## 6. 与现状的差异清单

| 现状 | 改为 | 理由 |
|---|---|---|
| 5 个 Tab：执行/工艺/状态/告警/策略 | 5 个一级导航：编排/运行/分析/运维/系统 | 按角色任务分，不按数据分 |
| 无「分析」入口 | 新增（甘特/时长/利用率） | 门槛 4 需要落点 |
| 状态页独立 | 并入「运行」首页 | 值班员只关心"现在" |
| 告警与策略分开 | 同在「运维」下 | 是同一件事的两面 |
| 单文件 HTML | React + AntD 项目 | 见 `webapp/` |
