# 并行能力验证（2026-11-03）

> 回答两个问题：
> ① **甘特要不要做"多实验并行"的图？** —— 不做，理由见 §5。
> ② **"多个实验、多个流程并行跑"现在支持到什么程度、测过哪些？** —— 见 §1–§4。

## 1. 一句话结论

| 能力 | 现状 | 证据 |
|---|---|---|
| **流程内并行分支**（fork/join） | ✅ 支持，已实测 | `verify-parallel-flow.py` 4/0 |
| **同一台设备被两条分支同时要** | ✅ 自动串行（设备锁） | 命令时间段重叠 = 0 |
| **同岛多个实验** | ✅ 排队串行（岛级互斥） | `verify-parallel-experiments.py` 3/0，峰值并行 = 1 |
| **跨岛多个实验** | ⚠️ 代码支持，**本环境未实测** | 仅读码，见 §4 |
| **甘特里的并行排程** | ❌ 不做（有意） | 见 §5 |

## 2. 流程内并行分支（已实测）

图：`开始 → 分叉 → (封膜 / 读状态) → 汇合 → 结束`，两条分支都绑同一台 S100。

```
设备：T1=504830（Seal） T2=504830（GetStatus）  [同一台]
节点：
T1 completed
T2 completed
命令：
Seal      | 15:00:54.833 → 15:00:54.833 | completed
GetStatus | 15:00:55.034 → 15:00:55.034 | completed
  ✓ 整单 completed（汇合后正常结束）
  ✓ 两条分支都有节点记录
  ✓ 两条分支都 completed
  ✓ 同一台设备：命令时间段不重叠（DeviceLock 串行）
通过 4 / 失败 0
```

两条分支的到达间隔 201ms、**时间段不重叠**：不是"没并行"，是 `DeviceLock`
把"两条分支抢同一台设备"排了队 —— 这才是物理约束（一台设备一次只能收一条指令）。

> 这也解释了为什么"并行"在单机场景看不出加速：**设备是瓶颈，不是线程**。

## 3. 同岛多个实验（已实测，串行）

4 个实验（同一个岛 `Device_Test`，各 1 条流程）**同时异步提交**：

```
4 次提交耗时 0.07s
采样: 0R/4Q 0R/4Q 0R/4Q 0R/4Q 1R/3Q 0R/3Q 1R/2Q 0R/2Q 1R/1Q 0R/1Q 1R/0Q 0R/0Q
  ✓ 同岛并发出现排队（峰值排队 4）
  ✓ 峰值同时 running = 1（同岛互斥应为 1）
  ✓ 4/4 个实验执行完成
通过 3 / 失败 0
```

5 轮采样都是 `1R/NQ` —— 一个在跑、其余排队，**没有出现两个 running**。
4 个实验全部完成，没有丢失。

## 4. 跨岛多个实验（未实测，只是读码）

代码上确实允许：

- `ExperimentScheduler.islandLocks` 是 **岛 → 锁** 的映射，不同岛不互斥
- 线程池 `newFixedThreadPool(MAX_CONCURRENT = 4)`
- 启动日志：`[调度] 已启动（岛级互斥，最多 4 个实验并行）`

**但本环境验证不了**：只有 `Device_Test` 一个岛接了可达的模拟器
（S100 / ASPIN_2K），其它岛（Pre-NGS、CC、SIQC…）的设备没有可连的 sidecar，
提交上去只会失败，测不出"并行"。

补测需要：两个岛各接一台可达设备，同时提交两个实验，
观察 `experiment_run` 是否同时出现两条 `running`。

> 顺带记一个环境坑：脚本默认取"第一台设备"时抓到过一台没接模拟器的（Seal 连失败 4 次转人工）。
> 现在默认取**最近 2 小时真的跑成功过命令**的那台设备。

## 5. 甘特：不做并行建模（明确取舍）

排程甘特按 **"同一时间只跑一个实验"** 串行累加画时间轴。这是有意的，不是没做完：

1. 实际调度是"岛级互斥 + 最多 4 并行"，**能不能并行取决于实验落在哪个岛**；
2. 要画并行，得先有"实验去哪个岛、岛里哪台设备什么时候空"的完整模型；
3. 而跨岛并行的收益在本环境**无法验证**（§4）。

所以：**甘特只做串行下界，并行交错不做**。页面与文档都已写明，避免被当成"已经算好了"。

## 6. 复现

```bash
export LABOS_DB_HOST=... LABOS_DB_NAME=... LABOS_DB_USER=... LABOS_DB_PASS=...

# 流程内并行（同一台设备 → 应串行）
python3 scripts/verify-parallel-flow.py

# 不同设备（可选；本环境 ASPIN 侧不完整，可能拿不到有效结论）
python3 scripts/verify-parallel-flow.py --device 504830 --device2 504831 --method2 CurrSpeed

# 同岛多实验（峰值并行应为 1）
python3 scripts/verify-parallel-experiments.py --count 4 --island 100030 --workflow 1254
```

两个脚本会删掉自己建的实验/流程；`run` 记录保留（真实执行历史）。
