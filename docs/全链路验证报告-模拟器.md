## 三、过程中修的真问题

跑验证脚本本身也暴露了问题，都修了：

### 1. 3 台设备没有声明能力（数据缺失）

```
ID1731-2        XRobot A10LR-PreNGS (2)   能力数 0
Incubator_2C-1  Incubator_2C #1           能力数 0
Incubator_2C-2  Incubator_2C #2           能力数 0
```

**后果**：驱动注册被跳过（`DriverDescriptor` 要求至少一项能力），
这 3 台设备**完全不可用**——探针直接失败。

**修**：补 `resource_capability`

```sql
INSERT INTO resource_capability (resource_id, capability_id)
SELECT r.id, c.id FROM resource_node r, capability c
WHERE (r.code = 'ID1731-2' AND c.code = 'TRANSFER')
   OR (r.code LIKE 'Incubator_2C-%' AND c.code = 'INCUBATE')
ON CONFLICT DO NOTHING;
```

**这类问题在界面上看不出来**——设备卡片照常显示，只是永远不干活。

### 2. `resource_capability` 没有 `tenant_id`

写 INSERT 时按习惯加了 `tenant_id`，报错：

```
column "tenant_id" of relation "resource_capability" does not exist
```

这张表是**设备与能力的多对多**，靠 `resource_id` 已经隐含租户。

### 3. `workflow` 表用的是 `graph` 不是 `graph_xml`

脚本按记忆写的列名，实际是 `graph`。

### 4. `shadow-run` 只接受 POST

脚本用 GET 调，返回 `{"error":"method not allowed: GET"}`。

### 5. 脚本里 `$VAR：` 全角冒号被当成变量名

```bash
echo "当前 running 设备数：$RUNNING："   # bash 把 "RUNNING：" 当成变量名
# → line 229: RUNNING：: unbound variable
```

**修**：全部改成 `${VAR}`。

**这个坑在这个项目里出现第 3 次了**（写 shell 脚本时，中文标点紧跟变量名）。

### 6. 用 `>>` 追加日志导致误判

为了看驱动注册日志，用 `tail /tmp/hb.log`——**结果看到的是上一次启动的日志**，
误以为"补了能力还是被跳过"。

**教训**：调试启动问题时，**换新日志文件名重启**，不要 `tail` 一个追加的文件。

## 四、模拟器能验证什么 / 不能验证什么

### 能验证（本次全部覆盖）

| 项 | 手段 |
|---|---|
| 路由（命令发给对的设备） | 7 个独立端点，发错就连不上 |
| 协议契约 | 探针的 `contract` 四项 |
| 设备分配（按能力） | 流程执行的 `device_id` |
| 长任务不误判 | `--long`（先回运行中再回完成） |
| 超时设置 | `--delay 5000` |
| 重试逻辑 | `--fail 3` |
| 设备离线处理 | `--offline` / kill |
| 三态上报 | 执行期间查 `device_state.status` |
| 离线告警 | 杀掉一台，40 秒后只报那一台 |
| 心跳 | `/api/heartbeat` |
| 稳定性 | 重复 20 次 |

### 不能验证

| 项 | 为什么 |
|---|---|
| **真实耗时** | 模拟器的 `--delay` 是固定值，真设备有波动 |
| **物理约束** | 会不会撞、夹具能不能夹住 |
| **厂商 DLL 边界** | 驱动内部的状态机、异常路径 |
| **并发干扰** | 多台设备同时动作时的电磁/机械干扰 |
| **长时稳定性** | 模拟器跑 20 次没问题，真机跑 20 天是另一回事 |

## 五、上现场时这份报告怎么用

**本报告证明的是"逻辑对"**，不是"能上生产"。

上现场照 `docs/现场部署手册.md` 走，**顺序不能变**：

```
① 改端点配置
② 起 Sidecar
③ 探针 Home（归位，不碰板）
④ 契约四项全 true 才继续
⑤ 关键方法逐个试，记录真实耗时
⑥ 整流程影子
⑦ 单流程实跑
⑧ 重复 20 次
```

**和本报告的差别**：

| 步骤 | 模拟器 | 真设备 |
|---|---|---|
| ③ 探针 | 152-166ms | 可能几百毫秒到几秒 |
| ⑤ 方法 | 全部返回固定值 | 可能某个方法参数名不对 |
| ⑦ 实跑 | 20 次全过 | **可能第一次就挂**，要修 |

**第 ⑦ 步的"修"是最花时间的**——估 3-5 天，取决于问题多少。

```bash
cd labos-kernel

export LABOS_DB_USER=<用户> LABOS_DB_PASS=<密码>
./scripts/sim-up.sh LAB-DEMO-02 150

# 2. 起中控
nohup java -cp "out:lib/postgresql-42.7.3.jar" \
     com.labos.kernel.api.ApiServer 18080 >> /tmp/api.log 2>&1 &

# 3. 跑验证
cd ..
./scripts/verify-all.sh LAB-DEMO-02
```

**报告同时写到 `/tmp/verify-report.txt`**，可以存档。
