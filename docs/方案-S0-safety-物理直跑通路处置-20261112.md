
# S0-safety 物理直跑通路处置方案（第一版 · 2026-11-12）

> **状态**：**方案（未实施）**，只做设计与触达点盘点，不改代码、不改 schema。
> **对应**：[v4 第一版收敛稿](物料身份与状态-设计-v4.md) §8.4「S0-safety」、第 7 轮 openai 评审 P2-05、以及第 7 轮 08-deepseek 复审指出的「执行通路缺口」。
> **目的**：在进入 S1 前，把所有能真实驱动设备、但不产生物料执行事实的通路收口，避免物料状态与物理现实脱节。

---

## 1. 背景

v4 已把物料效果处理统一到 RunStateMachine 的完成处理器上；但只要以下通路仍可被调用，就可能出现：

- 设备动作真实发生，但 run/run_node/run_command 与物料效果没有任何记录；
- 物料状态看起来没变，实际板已经被搬走/封膜/处理；
- 后续对账与审计无法回答「这次动作是谁、哪次执行、什么时间做的」。

因此 S0-safety 的目标不是「把功能做完」，而是先把物理动作的可审计性关住。

## 2. 现状清单（已逐条对源码核对）

| # | 通路 | 代码位置 | 行为 | 前端是否在用 | 认证/开关 | 风险 |
|---|---|---|---|---|---|---|
| P1 | POST /api/experiments/flow-run | ExperimentActionController:88-135 → ExperimentFlowRunner:61-146 → ShadowProbe.probe → driver.execute（ShadowProbe:54-90） | 真实驱动物理设备，并自己写 run/run_node/run_command（RunMapper.xml:906-948）；绕过 RunStateMachine | 否（grep webapp/src 无 flow-run 调用） | 仅登录（无写权限细分、无功能开关） | 高 |
| P2 | POST /api/workflows/{id}/shadow-run | WorkflowController:419-427 → WorkflowWebService:404-405 → ShadowRunner.run（ShadowRunner:71-129） | 真实下发每一步设备动作，但不落 run/run_node/run_command | 是（webapp/src/pages/Workflows.tsx:292） | 仅登录 | 高 |
| P3 | POST /api/shadow/probe | WorkflowController:429-495 → ShadowProbe.probe | 单条命令真实下发 | 是（webapp/src/pages/Island.tsx:441、:569） | 仅登录 | 高 |
| P4 | POST /api/islands/{id}/robot-points/{code}/capture | DeviceController:约 461-500 → ShadowProbe.probe | 读取机械臂当前点位（真实设备读取动作） | 未见前端调用（调试/脚本可能用） | 仅登录 | 中（读动作，但仍真实下发） |
| P5 | CLI / demo（RealWorkflowRunner 等） | labos-kernel/src/main/java/.../RealWorkflowRunner.java 等 | 验证/演示入口，可真实下发 | — | 非 HTTP 入口 | 低（需文档声明仅测试用） |

补充事实：

- 全局鉴权由 ApiAuthInterceptor 承担，开关是 ApiServer.AUTH_ENABLED = !"0".equals(env LABOS_AUTH)（默认开启）；没有 per-endpoint 功能开关或调试权限角色（RbacRules 只有 admin/operator/viewer + canWrite/canManageUsers）。
- ExperimentFlowRunner 目前只被 ExperimentActionController 引用（grep new ExperimentFlowRunner 仅 1 处）⇒ 下线端点不需要删除该类的其他调用方。
- 一次现场动作即使不落 run，也可能改变 position_state/plate 等既有投影（取决于动作），所以「不落执行事实」不等于「没有副作用」。

## 3. S0-safety 完成判定（进入 S1 的硬条件）

1. flow-run 端点不可用：返回 404/410，且 webapp/scripts 无调用；
2. shadow-run / shadow/probe 在生产配置下默认拒绝：未显式开启时返回 403/410，不得静默执行；
3. 调试通路若被允许：必须 admin + 显式环境开关 + 审计日志 三件套；
4. 所有上述通路在开启时必须在 UI/日志明确标注「调试通路：不产生执行事实」；
5. 自动化负向测试覆盖「默认拒绝」；核心场景回归（scripts/ci-gate.sh 等）不因处置而失败；
6. 操作手册明确：调试通路不得用于生产加工。

## 4. 推荐方案（A：下线 + 默认拒绝 + 审计）

### 4.1 flow-run：直接下线（推荐）

- 移除 ExperimentActionController 中 @PostMapping("/experiments/flow-run")（或保留方法但去掉路由映射，返回 410）；
- ExperimentFlowRunner 类保留不删：未来若要接入统一执行器，需要它的逐步执行能力，但第一版不提供 HTTP 入口；
- 前端无调用，无需兼容；脚本若引用需同步更新；
- 验收：curl -X POST /api/experiments/flow-run 返回 404/410；grep 无路由注册。

### 4.2 shadow-run / shadow/probe：默认拒绝 + 显式开关 + admin

- 新增配置项（建议 labos.safety.shadow-run-enabled、labos.safety.device-probe-enabled，默认 false）；
- 未开启：返回 403，响应体说明「调试通路已关闭（S0-safety）」；
- 开启条件：LABOS_ALLOW_SHADOW_RUN=1（或对应 env）+ 会话角色 = admin（新增 RbacRules.canDebug(role) 或直接 admin）+ audit.record；
- 生产部署检查清单强制这两个开关为 false；
- 前端：开关关闭时隐藏/禁用调试按钮，或显示「调试模式」标识 + 二次确认。

### 4.3 robot-points capture：并入 probe 开关

- 归入 labos.safety.device-probe-enabled（或单独 labos.safety.read-probe-enabled）；
- admin + audit；未开启返回 403；
- 说明：这是读动作，风险低于整流程下发，但仍属于真实设备通路，第一版按统一口径收口。

### 4.4 CLI/demo

- 不加开关（非 HTTP 入口），但在操作手册与 README 注明「仅测试/演示，不产生执行事实」。

## 8. 明确不做

- 不删除 ShadowRunner / ShadowProbe / ExperimentFlowRunner 代码（保留能力，第一版只关入口）；
- 不新建物料处理逻辑、不改执行引擎；
- 不因关闭调试通路而修改现场已有的只读监控/点位读取需求（按 §4.3 单独开关）。
