# 核酸提取工作站 · P2 互锁与板级安全方案（第二版 · 评审修订稿）

> 目标：把五条互锁、抓板身份核验和放板到位证据做成**覆盖所有物理命令路径的执行期硬约束**，不能只写在 BPMN 条件里。
>
> 第二版修订重点：统一派发入口、关闭检查至下发的竞争窗口、区分暂态等待与人工处置、建立位置绑定的扫码证据、取消该工作站的 `DEVICE_REPORT` 自动确认，并补充数据库唯一约束与验收矩阵。
>
> 上游依据：评审 P2 清单、`runtime-consistency/01-05`、第一版评审意见，以及现有 `RuntimeHold` / `DeviceLock` / `PositionLock` / `ScanPolicy` / `TransferTransaction` / `CommandLedger` 的真实语义。

---

## 0. 目标与边界

### 0.1 安全不变量

1. **只有明确的最新安全事实才能放行。**状态缺失、过期、通讯异常、会话不符、配置缺失均不得下发物理命令。
2. **所有物理命令走同一派发门禁。**任何 `driver.execute` 旁路都视为设计未完成。
3. **检查与动作之间必须持有必要资源锁，并在下发前复核状态版本。**只检查一次不构成互锁闭环。
4. **运动报告不等于位置确认。**目标位置占用和板状态 `KNOWN` 必须另有位置证据。
5. **一板一有效位置、一个位置最多一块板。**该约束最终由数据库唯一性和事务保证，不能只靠应用先查后写。
6. **物理结果未知时不得自动重发。**必须保留候选位置、封锁相关资源并转人工核对。
7. **fail-closed 不等于一律立即转人工。**明确的暂态忙可以有界等待；状态不可信或物理结果未知才阻断并转人工。

### 0.2 边界

- 本方案是中控软件互锁与物料一致性设计，不替代设备自身的急停、防撞和其他硬件安全机制。
- 不改机械臂运动规划；轨道分区只做保守互斥，不做路径优化。
- 不做真机标定；点位、分区、状态时效和传感器能力需在真机 FAT 前配置并验证。
- 不新增业务功能，不用互锁错误码改变既有正常工艺流程。

## 1. 统一物理命令派发门禁

### 1.1 当前必须消除的旁路

当前 `DriverStepExecutor` 存在两类路径：

- 普通命令经 `executeCommand` 进入 `CommandLedger.begin` 后下发；
- 受保护 Transfer 的主机械臂动作直接调用 `driver.execute`，没有经过 `executeCommand`。

因此，第二版不允许仅在现有 `executeCommand` 前增加几个 `if`。必须先收敛为统一的 `PhysicalCommandDispatcher`（名称可随实现调整），覆盖：

| 命令路径 | 第二版要求 |
|---|---|
| 普通设备方法 | 统一走派发门禁 |
| TransferPlan 开门/关门等子命令 | 统一走派发门禁，并继承本次搬运的互锁上下文 |
| 受保护 Transfer 主机械臂动作 | 拆除直接 `driver.execute` 旁路，统一走派发门禁 |
| 后续新增物理命令 | 默认只能经派发门禁；新增旁路必须被测试发现 |

验收时使用静态搜索和运行期探针双重确认：任何物理命令都有互锁决策记录和命令账本记录。

### 1.2 标准派发顺序

1. **解析动作与资源集**：设备、源位、目标位、交互位、搅拌—分液配对、完整轨道分区集。
2. **获取资源锁**：按固定顺序、全有或全无地获取；失败不得带着部分锁继续等待或下发。
3. **读取互锁事实快照**：得到状态值、来源、会话/步骤、观测时间、状态版本。
4. **形成互锁决策**：记录允许、等待或拒绝，以及事实版本和理由。
5. **登记命令账本**：同一逻辑命令使用稳定幂等键。
6. **在锁内做最终复核**：状态版本变化、锁失效或事实过期则不得下发。
7. **标记已发送并调用驱动**：只有完成最终复核后才能进入本步。
8. **监视执行期事件**：收到新的不安全事实时，按设备物理中止能力处理。
9. **回写命令与搬运事务终态**：设备物理动作到达终态后才释放相关运动资源锁。

若已执行 `CommandLedger.begin`，但最终复核失败且命令尚未发送，账本必须落为明确的 `REJECTED_NOT_SENT`（或等价终态），不得遗留为 `DISPATCH_STARTED`，也不得伪装成设备执行失败。

### 1.3 检查至下发的竞争窗口

设备上报状态无法与本地账本简单放进同一个数据库事务，因此本方案采用：

- 本地资源互斥锁；
- 设备会话与状态版本；
- 下发前最终复核；
- 执行期事件监视；
- 对不支持物理中止的设备，运行到已验证的安全边界并阻断后续命令。

不得通过“两条语句在同一个 Java 方法里”声称已经消除竞争。

## 2. 互锁事实与决策合同

### 2.1 事实快照

每次判定至少保存：

```text
tenant_id
run_id / node_id / command_id
resource_id
fact_type / fact_value
device_session_id / workflow_step_id / interaction_id（适用时）
observed_at / received_at
state_version 或 device_event_seq
decision / reason / error_code
```

只有 `fact_value` 没有时间和会话上下文，不足以作为放行证据。

### 2.2 状态分类与动作

| 分类 | 示例 | 默认动作 |
|---|---|---|
| 明确安全 | 转盘明确停止且状态新鲜；当前步骤有有效等待交互 | 放行 |
| 暂态忙 | 转盘正在运动；轨道分区被正常占用；等待事件尚未到达 | 有界等待或排队，超时后转人工 |
| 明确不安全 | 搅拌单元故障；扫码不匹配；分区配置冲突 | 拒绝下发，按故障/安全流程处置 |
| 状态过期 | 超过该事实允许时效；连接断开后未重新取得快照 | 拒绝下发，刷新失败则转人工 |
| 状态未知 | 无状态、无法解析、会话不符、数据库读取失败 | 拒绝下发并转人工 |
| 物理结果未知 | 已抓板后失联；放置后无证据；命令在途时崩溃 | 禁止自动重试，封锁候选位置并转人工 |

状态时效按事实类型配置，不使用一个全局固定值。设备重连后必须重新获取当前快照，不能沿用断线前事件直接放行。

## 3. 五条互锁

### 3.1 L1：转盘运动时禁机械臂操作该提取仪交互位

- **事实源**：提取仪上报的转盘状态，不使用中控根据上一命令推断的状态。
- **放行条件**：当前设备会话中明确上报“转盘停止”，状态未过期，且目标确为该提取仪 `deck_out` 交互位。
- **暂态处理**：明确“运动中”时等待停止并重新取证；等待超时才转人工。
- **拒绝条件**：状态缺失、过期、通讯异常或设备身份不符。
- **持锁范围**：从最终复核起持有提取仪交互位及相关运动资源锁，直到机械臂退出交互区。
- **执行中变化**：若转盘在运动中途变为运动中，支持物理中止时按既有中止契约处理；不支持时不得谎称已停止，应阻断后续命令并转人工确认。
- **错误码**：暂态占用用等待/忙语义；真正互锁拒绝用 `EC-INTERLOCK-TURNTABLE`；过期和未知分别使用 §6 的通用码。

### 3.2 L2：同一板同一时间只有一个有效位置

数据库至少需要两层约束：

```sql
-- position_state 主键保证一个位置只有一行，不能单独保证一板一位置。
CREATE UNIQUE INDEX uk_pos_plate
ON position_state (tenant_id, plate_id)
WHERE plate_id IS NOT NULL;
```

实施要求：

1. 上线唯一索引前先查询并处置既有重复板号，不能直接在生产库盲目建索引。
2. 目标位置预留仍使用 `PositionLock` 原子完成；证据确认后，源位释放、目标位占用、板状态和搬运事务在同一业务事务中闭环。
3. `plate.position_status` 不得继续作为可独立漂移的旁路副本；若保留，必须明确其与 `position_state` 的同事务更新和异常对账规则。
4. 取板前发现账本重复但尚未发生物理动作时，拒绝操作并隔离冲突记录，**不得仅凭数据冲突把物理板位标成 UNKNOWN**。
5. 已发生物理动作且无法确定位置时，才进入 UNKNOWN 与候选位置封锁流程。

错误码：`EC-PLATE-DUPLICATE-POS`。

### 3.3 L3：机械臂轨道分区互锁

- `DeviceLock` 在这里按**每分区一个互斥资源**使用，不把它误称为可多次进入的计数信号量。
- 分区集必须覆盖机械臂及所抓板件的完整运动包络，包括接近、源位、途经、目标位和退出区域。
- 不做路径规划时，使用经真机验证的保守静态分区映射；无法确定完整分区集时禁止动作。
- 多分区按 `tenant_id + resource_id` 固定排序获取，全有或全无，防止循环等待。
- 分区锁从动作前最终复核持有到机械臂完全退出相关分区，不能在收到第一个 ACK 时提前释放。
- 正常被占时排队，超时返回忙；锁归属或运动结果未知时不得按普通超时直接清锁放行。

错误码：正常占用复用 `EC-RESOURCE-BUSY`；分区配置缺失、互锁状态不可信或安全拒绝使用 `EC-INTERLOCK-RAIL` / `EC-STATE-UNKNOWN`。

### 3.4 L4：搅拌单元故障禁对应分液器并暂停报警

- 必须显式配置 `stirrer_resource_id ↔ dispenser_resource_id` 配对；配对关系缺失、一对多无法解析时按未知处理。
- 只有配对搅拌单元上报新鲜、明确可用状态时才允许分液。
- `error`、失效、状态过期或通讯异常均不得下发分液命令。
- 默认触发当前 run 的 `paused_fault`。若同一搅拌单元服务多个并发 run，必须暂停所有受影响的配对命令，不能只暂停先发现故障的一条 run。
- 执行中发生故障时，按分液设备的物理中止能力处理；不能中止时运行到安全边界并禁止下一条相关命令。
- 恢复必须同时满足：设备故障已清除、重新取得新鲜状态、受影响物料位置仍可信。涉及物理故障时还需人工确认恢复，不得仅凭状态从 `error` 变回 `idle` 自动续跑。

错误码：`EC-INTERLOCK-STIRRER`；过期、未知和通讯异常使用相应通用码。

### 3.5 L5：无有效等待交互时禁机械臂操作交换位

不能只在 `device_event` 日志中找一条历史 `waiting_interaction`。必须维护“当前有效等待交互”投影，至少绑定：

```text
tenant + device + device_session + workflow_step + interaction_id
```

有效等待交互必须属于当前会话、当前步骤和本次预期动作；已完成、已取消、超时或被后续事件取代的等待均无效。事件乱序按设备序号/版本处理，重连后重新查询当前状态。

- 当前会话仍活跃、事件可能只是尚未到达：有界等待。
- 等待交互属于旧会话/旧步骤、已被消费或无法确认：拒绝并转人工。
- 从最终复核到机械臂退出交换位期间，保持对应交互与位置资源锁，防止另一分支消费同一等待。

错误码：`EC-INTERLOCK-NO-WAIT`；状态过期、未知分别使用通用码。

## 4. 板级安全

### 4.1 每次抓板前的强制扫码闸门

该闸门是工作站级安全要求，不受流程节点 `barcode_policy=none/read/update` 影响。任何夹爪闭合、抬升或使板离开原位的动作之前，都必须通过闸门。

每次扫码证据至少绑定：

```text
run_id + node_id + source_position_id
expected_barcode + scanned_barcode
observed_at + scan_id + transfer_id / command_id
```

以下情况一律不得抓板：

- 未扫码、扫码失败、扫码结果过期；
- 期望板号缺失；
- 扫码结果与期望板号不一致；
- 扫码无法绑定到当前源位置；
- 同一次扫码证据已被另一块板、另一次搬运或另一条命令消费。

复用边界：

- 可复用 `ScanPolicy` 的条码解析和一致性判断工具，但**不能复用其无策略或无期望值时放行的语义**。
- `confirmScanAtDevice` 目前要求整台设备只有一块板，不能直接承担多槽位设备的抓板前位置绑定；需要新增位置级证据，不得把设备级唯一板假设带入本方案。

错误码：`EC-SCAN-MISMATCH`；无有效扫码证据使用 `EC-SCAN-EVIDENCE-MISSING`；状态过期使用 `EC-STATE-STALE`。

### 4.2 搬运与位置确认状态机

建议显式区分以下事实，不再用一次设备成功回包横跨全部状态：

```text
STARTED
  → PICK_REPORTED          设备报告已取板；板进入 IN_TRANSFER，目标仍只是预留
  → PLACE_REPORTED         设备报告完成放置；仍不得写目标 KNOWN
  → CONFIRMED              获得有效位置证据后，原子写位置与板状态
```

任何阶段无法确认物理结果均可进入 `UNKNOWN`，但不得自动重发原动作。

- `IN_TRANSFER` 只表示板处于搬运链中，不代表已经到达目标。
- 目标位置在确认前保持预留/封锁，不得被其他 run 选用。
- 只有确认步骤才能把目标位置写成该板占用，并把板状态写为 `KNOWN`。

### 4.3 到位证据类型

| 证据 | 能证明什么 | 使用条件 |
|---|---|---|
| 目标位置扫码 | 目标位置、板身份、到位事实 | 扫码必须绑定目标位置和本次 transfer，不能复用旧扫码 |
| 传感器 + 搬运身份链 | 有物到位；结合已验证身份链确认本次板件 | 传感器必须绑定目标位置和 transfer；全程身份链无歧义 |
| 人工盘点 | 人工确认的位置与身份 | 记录操作员、时间、位置和证据说明 |
| `DEVICE_REPORT` | 仅证明设备报告了运动结果 | **该工作站不得据此自动确认位置** |

现有 `confirmByDeviceReport` / `LABOS_TRANSFER_AUTO_CONFIRM` 路径不得用于核酸提取工作站。若其他旧流程暂保留该兼容能力，必须按工作站/流程显式隔离，不能共享默认放行配置。

### 4.4 失败处置

| 场景 | 状态与资源处置 | 是否允许自动继续 |
|---|---|---|
| 抓板前扫错板 | 不发生抓取；源位保持原事实；记录冲突并转人工 | 否 |
| 抓板前无码/证据过期/期望板号缺失 | 不发生抓取；保持源位和搬运资源封锁直至处置 | 否 |
| 抓板后、放板前失联或扫码失败 | 板标 `IN_TRANSFER`；保持源位、夹爪、目标位候选封锁；不自动放板 | 否 |
| 放置后无有效到位证据 | 板标 `UNKNOWN`；候选集合至少包括夹爪与目标位，必要时包括源位 | 否 |
| 物理放置已发生但证据/数据库写入失败 | 按 UNKNOWN 处理，不得因账本失败自动重发放置 | 否 |
| 位置确认成功但审计旁路失败 | 保留主事实并报警，通过对账补审计；不得反过来改写物理位置 | 不自动重放动作 |

人工恢复必须显式确认“板在哪里、目标位是否占用、哪些锁可以释放”，不能只点击继续后复用原命令重试。

## 5. 暂停、恢复与锁释放

1. 互锁拒绝发生在命令下发前时，不生成“设备已执行”的假记录；账本若已建立，必须落 `REJECTED_NOT_SENT`。
2. 已下发命令的暂停与中止继续遵守既有契约：只有设备确认 `PHYSICALLY_STOPPED` 才能按已停止处理。
3. 普通锁超时只适用于物理状态仍可信的暂态等待；动作在途、设备失联或位置未知时，不得由清理任务自动释放安全封锁。
4. 恢复前重新获取互锁事实，不复用暂停前快照。
5. 位置 UNKNOWN、搬运 REPORTED/UNKNOWN、命令 UNKNOWN 的既有恢复门禁继续保持，不被任何自动确认开关短路。
6. 每次拒绝、等待超时、暂停、恢复和人工处置均保存决策快照，能够回答“当时凭什么放行/拒绝”。

## 6. 错误码与恢复语义

| 类别 | 错误码 | 默认恢复语义 |
|---|---|---|
| 暂态资源忙 | 既有 `EC-RESOURCE-BUSY` | 有界等待/排队，超时转人工 |
| 转盘互锁 | `EC-INTERLOCK-TURNTABLE` | 拒绝当前下发；按明确状态决定等待或人工 |
| 一板多位置 | `EC-PLATE-DUPLICATE-POS` | 阻断并核对位置账本/物理位置 |
| 轨道互锁 | `EC-INTERLOCK-RAIL` | 配置或安全状态异常时转人工 |
| 搅拌互锁 | `EC-INTERLOCK-STIRRER` | `paused_fault`，满足恢复条件后人工恢复 |
| 无有效等待 | `EC-INTERLOCK-NO-WAIT` | 短等待或转人工，不使用旧事件放行 |
| 状态过期 | `EC-STATE-STALE` | 拒绝下发并刷新；无法刷新则转人工 |
| 状态未知 | `EC-STATE-UNKNOWN` | 拒绝下发并转人工 |
| 通讯异常 | 优先复用既有 `EC-05-*` | 未下发可重连重查；在途动作不得自动重发 |
| 扫码不匹配 | `EC-SCAN-MISMATCH` | 不抓板，转人工核对 |
| 扫码证据缺失 | `EC-SCAN-EVIDENCE-MISSING` | 不抓板/不确认，补充有效证据 |
| 放置未确认 | `EC-PLACE-UNCONFIRMED` | UNKNOWN，封锁候选位置并转人工 |

新增错误码必须登记恢复作用域，不能依赖未知错误码默认落入 NODE。错误码只表达失败类别，是否等待、暂停或转人工还需结合“命令是否已下发、物理位置是否可信”判断。

## 7. 现有组件复用边界

| 组件 | 可以复用 | 不得直接沿用 |
|---|---|---|
| `RuntimeHold` | 暂停/扣留覆盖与恢复门禁 | 不能替代设备状态和互锁事实 |
| `DeviceLock` | 设备、轨道分区的互斥与等待 | 不能把它当成路径规划；未知在途动作不能按普通超时清锁 |
| `PositionLock` | 源/目标位置原子预留、归属校验 | 预留不等于到位；数据库读回自己写入的板号不等于物理证据 |
| `ScanPolicy` | 条码解析、策略工具方法 | 无策略、无期望值时放行；设备级单板假设 |
| `TransferTransaction` | REPORTED/UNKNOWN/CONFIRMED 状态机与恢复门禁 | 该工作站禁用 `DEVICE_REPORT` 自动确认 |
| `CommandLedger` | 派发前登记、幂等、崩溃对账 | 不能只覆盖普通命令而遗漏 Transfer 主动作 |

## 8. 落地顺序

### 阶段 A：先收口，不新增设备语义

1. 统一所有物理命令派发路径，消除 Transfer 直接 `driver.execute` 旁路。
2. 建立互锁决策快照、状态时效、最终复核和错误码恢复映射。
3. 用既有命令做回归，验证未启用新互锁时行为不变。

### 阶段 B：先建立板级事实，再做自动搬运确认

1. 新增位置级扫码证据与强制抓板闸门。
2. 调整搬运状态机，位置证据确认后再写 KNOWN/占用。
3. 清理重复数据并上线 `uk_pos_plate` 唯一索引。
4. 对该工作站关闭 `DEVICE_REPORT` 自动确认，接通 UNKNOWN 候选位置封锁和人工恢复。

### 阶段 C：接设备状态与事件

1. L1/L5：先完成设备会话、状态版本、有效等待投影和重连重查，再接守卫。
2. L4：完成搅拌—分液配对、`paused_fault` 影响范围和人工恢复后，做端到端垂直切片。

### 阶段 D：轨道分区

在精确点位和完整运动包络配置完成后上线 L3；未完成分区映射的设备/路径保持禁止自动运行，不做“先空集合放行、后补配置”。

## 9. 验收测试矩阵

| 编号 | 场景 | 必须通过的结果 |
|---|---|---|
| D-01 | 枚举并触发所有物理命令路径 | 每条命令均有互锁决策与账本，无直接 `driver.execute` 旁路 |
| D-02 | 初次检查通过后、最终复核前改变设备状态 | 命令不下发，账本落未发送终态，锁正确保留或释放 |
| D-03 | 账本已建立但最终复核失败 | 不留 `DISPATCH_STARTED`，重启不错误判为已发送 |
| L1-01 | 转盘运动中、停止、状态过期、重连 | 分别等待、重新取证放行、拒绝、重查；不使用旧状态 |
| L1-02 | 机械臂动作中转盘开始运动 | 按物理中止能力进入安全边界，无后续命令下发 |
| L2-01 | 两个并发事务把同一板写向不同位置 | 数据库只允许一个成功，另一个无物理副作用地失败 |
| L2-02 | 已有重复数据 | 上线预检能发现并阻止直接建唯一索引 |
| L3-01 | 两条搬运路径共享中间分区 | 不能同时进入；等待者不持有可能造成死锁的半成品锁集 |
| L3-02 | 同 run 两个并行分支穿过分区 | 仍互斥，不能因同 run 重入而同时动作 |
| L3-03 | 分区映射缺失、动作在途时进程崩溃 | 前者禁止动作；后者不自动清锁放行 |
| L4-01 | 搅拌 error、状态过期、配对缺失 | 分液均不下发，暂停影响范围正确 |
| L4-02 | 故障清除后恢复 | 重新取证并完成必要人工确认，不自动重发已在途命令 |
| L5-01 | 旧会话/旧步骤等待事件、重复事件、乱序事件 | 均不能授权当前机械臂动作 |
| S-01 | 无策略、无期望板号、无码、错码、旧扫码 | 抓板动作均不发生 |
| S-02 | 多槽位设备有两块以上板 | 扫码必须绑定具体源位置，不能按设备唯一板关联 |
| T-01 | 抓板后、放板前崩溃或失联 | 板 IN_TRANSFER/UNKNOWN 语义正确，候选位封锁，不自动重发 |
| T-02 | 放置后、证据确认前崩溃 | 目标不写 KNOWN，恢复时进入人工对账 |
| T-03 | 只有运动成功回包 | 事务保持 REPORTED，不自动写 CONFIRMED |
| T-04 | 传感器有信号但身份链有歧义 | 不得确认板身份和目标占用 |
| R-01 | 人工盘点后恢复 | 重新取证，只释放经人工确认的资源，不重复物理动作 |

测试不仅检查错误码，还必须断言：**设备是否收到命令、位置是否被写入、锁是否仍持有、重启后是否会重发**。

## 10. 真机与配置前置清单

- 提取仪能明确上报转盘停止/运动状态，并提供可判断新鲜度的时间或序号。
- `waiting_interaction` 能绑定设备会话、流程步骤和交互实例。
- 每个抓取源位可取得位置级条码证据；不能满足时该源位不得进入全自动模式。
- 每个目标位明确采用扫码、传感器加身份链或人工确认中的哪种证据。
- 搅拌—分液配对、故障影响范围和恢复权限已配置。
- 每条机械臂搬运路径的完整分区集已验证。
- 新错误码、恢复作用域、暂停范围和通知策略已登记。

任一安全配置缺失时，对应动作按未知处理，不以空配置默认放行。
