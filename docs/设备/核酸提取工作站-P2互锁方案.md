# 核酸提取工作站 · P2 互锁与板级安全方案（第一版 · 供评审）

> 目标：把五条互锁 + 扫码到位做成**命令下发前的执行期硬约束**，不能只写在 BPMN 条件里。
> 上游依据：评审 P2 清单、`runtime-consistency/01-05`（事实/投影 + 命令生命周期 + 位置一致性）、
> 现有组件 `RuntimeHold` / `DeviceLock` / `PositionLock` / `ScanPolicy` / `CommandLedger`。

---

## 0. 总原则（fail-closed）

- 互锁是**安全事件**，不是业务判断：状态缺失、过期、通讯异常一律按「不安全」处理（拒绝下发 + 转人工）。
- 互锁判定放在**命令下发前**（`DriverStepExecutor.executeCommand` 之前），与 `CommandLedger.begin` 同层。
- 四类失败用**不同错误码**（见 §3），操作员能区分「忙 / 互锁拒绝 / 状态过期 / 设备故障」。

---

## 1. 五条互锁（事实源 → 守卫点 → 失败动作 → 错误码）

| # | 互锁 | 事实源 | 守卫点 | 失败动作 | 错误码 |
|---|---|---|---|---|---|
| L1 | 转盘转动时禁机械臂操作该提取仪交互位 | 提取仪上报的「转盘运动中」状态（`device_state` 或设备事件） | Transfer 下发前 + 提取仪交互位（deck_out）的 `PositionLock` 预约前 | 拒绝 + 转人工（等转盘停） | `EC-INTERLOCK-TURNTABLE` |
| L2 | 同一板同一时间只有一个有效位置 | `position_state` 主键 `(tenant, resource_id)` + `plate.position_status` + `ix_pos_plate` | 放板/取板前的位置登记（`noteTransferMove`） | 拒绝 + 板标 UNKNOWN | `EC-PLATE-DUPLICATE-POS` |
| L3 | 机械臂轨道分区互锁（防碰撞） | 机械臂的轨道分区资源锁（每分区一个 resource_id） | Transfer 下发前按分区抢锁（复用 `DeviceLock` 信号量） | 分区被占 → 排队/拒绝 | `EC-INTERLOCK-RAIL` |
| L4 | 搅拌单元故障/失效 → 禁对应分液器 + 暂停报警 | 搅拌单元 `device_state.status='error'` | 分液命令下发前查配对搅拌单元状态 | 拒绝 + `paused_fault` 暂停报警 | `EC-INTERLOCK-STIRRER` |
| L5 | 无有效「等待交互」→ 禁机械臂操作交换位 | `device_event`（waiting_interaction 事件）的当前会话/步骤命中 | 机械臂操作该提取仪交换位前，查当前设备会话+步骤是否有有效等待交互 | 拒绝 + 转人工 | `EC-INTERLOCK-NO-WAIT` |

**关键**：L1/L4 的事实来自**设备上报状态**（不是中控推断）；设备不报状态时按「未知=不安全」fail-closed。

## 2. 板级安全：扫码闸门 + 到位证据

### 2.1 抓板扫码闸门（每次抓板动态核对身份）

- 机械臂**每次抓板前**执行扫码（`ReadBarcode`/`BarcodeScan`），动态核对：
  - 扫到的真 barcode == 声明板号（`plate` 参数 / 位置上的板）。
  - 不匹配 ⇒ 拒绝抓板，板留在原位（不抓）。
- 复用现有 `ScanPolicy`（P2-7）：`validate_in`/`validate_both` 进设备方向校验；不匹配 ⇒ 转人工（`manual_window`）。
- **关键差异**：评审要求「每次抓板都扫码」，不是只在扫码节点扫——闸门挂在机械臂抓板动作前。

### 2.2 放板到位证据（不能只更新数据库账本）

- 放板后必须有**扫码或传感器到位证据**，才把 `position_state` 写成占用：
  - 有传感器 → 传感器到位信号；
  - 无传感器 → 放板后立即扫码确认（板在目标位）。
- 复用现有 `TransferTransaction` 的「运动报告 vs 位置确认」两段：运动报告到位 ≠ 确认到位；
  只有「确认」（扫码/传感器）才写 `KNOWN` + `position_state.occupied`。

### 2.3 三态失败处置（扫错板 / 扫码失败 / 放置不到位）

| 场景 | 板的位置 | 动作 |
|---|---|---|
| 扫错板（抓板前） | 仍在原位（没抓） | 拒绝抓板，转人工核对板身份 |
| 扫码失败（抓板后、放板前） | 在夹爪 | 板标 `IN_TRANSFER`（在途未确认），转人工，**不自动放板** |
| 放置不到位（无到位证据） | 在夹爪或未知 | 板标 `UNKNOWN` + 封锁可能位置，转人工盘点 |

## 3. 错误码词表（新增）

| 错误码 | 含义 | 处置 |
|---|---|---|
| `EC-INTERLOCK-TURNTABLE` | 转盘运动中 | 转人工（等转盘停） |
| `EC-PLATE-DUPLICATE-POS` | 一板多位置 | 转人工盘点 |
| `EC-INTERLOCK-RAIL` | 机械臂轨道分区冲突 | 排队 / 转人工 |
| `EC-INTERLOCK-STIRRER` | 搅拌单元故障 | 暂停报警（paused_fault） |
| `EC-INTERLOCK-NO-WAIT` | 无有效等待交互 | 转人工 |
| `EC-SCAN-MISMATCH` | 扫码不匹配 | 转人工 |
| `EC-PLACE-UNCONFIRMED` | 放置不到位 | 板标 UNKNOWN 转人工 |

与既有 `EC-RESOURCE-BUSY`（忙）区分：忙=暂时，互锁=安全，过期=状态不可信，故障=设备坏了。

## 4. 与现有组件的关系（不重复造轮子）

| 需求 | 复用 |
|---|---|
| L1/L4/L5 执行期守卫 | `RuntimeHold`（扣留闸门）+ `DeviceLock`（设备锁）扩展 |
| L2 一板一位置 | `position_state` 主键 + `ix_pos_plate`（已有） |
| L3 轨道分区 | `DeviceLock` 信号量（每分区一个 resource_id，同 P2-6 多臂手法） |
| 扫码闸门 | `ScanPolicy`（P2-7）+ `confirmScanAtDevice`（P3） |
| 到位证据 | `TransferTransaction` 的 report/confirm 两段（已有） |

---

## 5. 落地顺序

1. **L4（搅拌→分液）**：最简单，纯设备状态查询 + 守卫，先做。
2. **L1/L5（转盘/等待交互）**：依赖提取仪上报状态 + 设备事件，做在事件链之后。
3. **L3（轨道分区）**：复用 DeviceLock 信号量，做在精确点位之后。
4. **L2（一板一位置）**：约束已有，补校验。
5. **扫码闸门 + 到位证据**：挂在机械臂抓/放板动作前后，做在互锁之后。

---

## 6. 本方案不做什么

- 不改机械臂运动规划（轨道分区只做互斥，不做路径规划）。
- 不做真机标定（那是真机 FAT 阶段）。
- 不新增业务功能。
