# 9608 加液（分液）设备 · 串口指令整理与中控映射

> 来源：`private/实际流程/新款9608 串口指令说明V241023.docx`（198 行文本，含 3 张表）。
> 整理日期 2026-11-15。原文件未标注厂商名；同批资料（`private/实际流程/`）为天隆科技，型号 9608。

---

## 1. 这台机器是什么

**96/384 孔板的自动加液（分液）设备**，带试剂管路：可设加液量、板高、喷头高度、泵速，支持 A/B 两个板位、单管/双管、横向/纵向、96/384 孔整板、梯度稀释、复杂移液，以及管路填充/试剂回收/管路清洗。

与"移液工作站"的区别：它**只能加液，不能吸液转移**（没有 Aspirate/Transfer 语义），所以中控能力用 `ALIQUOT`（移液分装），不是 `TRANSFER`。

## 3. 帧格式

### 3.1 下行（上位机 → 设备）

固定 **12 字节**十六进制：

| 字节 | 含义 |
|---|---|
| 1 | 报头，固定 `0xAA` |
| 2 | 指令码（`0x00`…`0x41`，见 §4） |
| 3–11 | 参数区（**携带数据的指令，数据从第 5 字节开始**；多字节字段**小端**，例 `0x1234` → 第 5 字节 `0x34`、第 6 字节 `0x12`） |
| 12 | 报尾，固定 `0xFF` |

### 3.2 上行（设备 → 上位机）

| 项 | 值 |
|---|---|
| 报头 | `0xAC` |
| 第 11 字节 | **校验和** = 第 2 字节到第 10 字节之和（取低 8 位） |
| 报尾 | `0xFF` |

例：`ac 04 00 00 00 00 00 00 00 00 04 ff` —— 04 + 00×8 = `0x04` ✓
例：`AC 04 01 00 00 00 00 00 00 00 05 FF` —— 04 + 01 = `0x05` ✓

### 3.3 故障帧（设备主动上报）

`ee 00 00 00 xx ** ** ** 00 00 00 ff`

- 第 1 字节 `0xEE` = 故障帧标识
- **第 5 字节 `xx` = 错误识别码**（用户判断错误类型的唯一依据）
- `**` 为辅助判断码，需记录但**不作为判断依据**

## 4. 指令表

| 指令 | 报文模板 | 含义 | 应答 |
|---|---|---|---|
| `0x00` | `aa 00 ** 00 yy xx 00 00 00 00 00 ff` | 设置序号 `**` 的参数为 `0xxxyy`（小端） | 无 |
| `0x01` | `aa 01 ** 00 00 00 00 00 00 00 00 ff` | 查询序号 `**` 的参数 | `ac 01 ** 00 yy xx …` |
| `0x02` | `aa 02 00 … 00 ff` | **保存参数**（不保存则断电丢失） | 无 |
| `0x03` | `aa 03 00 … 00 ff` | 以字符串形式输出所有参数 | 所有参数字符 |
| `0x04` | 见 §4.1 | **开始加液**（多种模式） | `ac 04 00 … 04 ff` |
| `0x04 01` | `aa 04 01 00 … 00 ff` | **暂停**加液 | `AC 04 01 … 05 FF` |
| `0x04 02` | `aa 04 02 00 … 00 ff` | **放弃**本次加液实验 | `AC 04 02 … 06 FF` |
| `0x05` | `aa 05 00 … 00 ff` | **复位** | `ac 05 00 … 05 ff` |
| `0x06` | `aa 06 00 … 00 ff` | **清除错误状态** | `ac 06 00 … 06 ff` |
| `0x30 00` | `aa 30 00 00 … 00 ff` | 开始填充管路 | **立刻**回 `AC 30 00 … 30 FF`，何时结束由上位机控制 |
| `0x30 01` | `aa 30 01 00 … 00 ff` | 结束填充管路 | `AC 30 01 … 31 FF` |
| `0x31 00` | `aa 31 00 00 … 00 ff` | 开始回收试剂 | **立刻**回 `AC 31 00 … 31 FF` |
| `0x31 01` | `aa 31 01 00 … 00 ff` | 结束试剂回收 | `ac 31 01 … 32 ff` |
| `0x32` | `aa 32 xx 00 SS 00 00 00 00 00 00 ff` | 管路清洗：`xx` = 清洗次数，`SS` = 每次冲洗时间 | `ac 32 00 … 00 ff` |
| `0x36` | `aa 36 00 xx 00 … 00 ff` | 选择机内保存的第 `xx` 套程序，从零开始调用 | — |
| `0x40` | `aa 40` + 96×2 字节 | **96 孔** EXCEL 表加液：每孔 2 字节 | — |
| `0x41` | `aa 41` + 384×2 字节 | **384 孔** EXCEL 表加液：每孔 2 字节 | — |

> ⚠ `0x40/0x41` 的报文长度远超 12 字节（96 孔 = 2 + 192 = 194 字节；384 孔 = 770 字节），与"每帧 12 字节"的总述**矛盾**。整理时按原样记录，接真机前必须确认：是变长帧，还是分多帧续传。

### 4.1 加液的各模式（`0x04` 的第 4 字节）

| 第 4 字节 | 模式 |
|---|---|
| `0x00` | 只加 A 板位 |
| `0x01` | 只加 B 板位 |
| `0x02` | A + B 板位 |
| `0x03` | 单管横向 |
| `0x04` | 单管纵向 |
| `0x05` | 双管横向 |
| `0x06` | 双管纵向 |
| 其它（配合后段位） | 96 孔位 / 384 孔位 / 标准加液 / 不同体积加液 / 梯度稀释 / 复杂移液 |
| 后段标志 | 震荡 / 不震荡、靠壁 / 不靠壁 |

> 文档用 `**` 通配位表达"模式 + 附加标志"的组合（如 `aa 04 00 ** **** 01 ** ** 00 00 ff` = 靠壁），**各位的精确偏移未逐条给出**。实现时按"模式字节 + 4 个参数位"建模，具体字节含义现场对表。

## 5. 参数表（序号 + 内容）

表头为字节 2…10。文档给的三张参数行：

| 参数序号 | 字段 |
|---|---|
| `0x1F` | 加液量 / µL；孔位选择（每 bit 一列，1 = 该列需要加液） |
| `0x20` | 预喷；管路类型（0 大管 / 1 小管 / 2 大管 / 3 小管）；板高 / mm；喷头加液高度 / mm；泵速（0 低速 / 1 中速 / 2 高速） |
| `0x21` | 喷头加液后复位高度 / mm；预喷高度 / mm；X 轴修正 / 0.1 mm；Y 轴修正 / 0.1 mm |
| `0x22` | 加液量 1–4 / µL |
| `0x23` | 加液量 5–8 / µL |
| `0x24` | 加液量 9–12 / µL |

> 注意"管路类型"里 **0 与 2 都写大管、1 与 3 都写小管** —— 原文如此，大概率是笔误（应为 0/1 大管小管、2/3 另一档）。接真机前必须确认，否则可能装错管径。

## 6. 故障码（`0xEE` 帧第 5 字节）

| 码 | 含义 | 建议处置 |
|---|---|---|
| `0x02` | 错误消息类型 | 协议版本不符 → 中止，不要重试 |
| `0x03` | 参数范围有误 | 改参数后重跑（检查加液量/板高/高度） |
| `0x04` | CAN 通信错误 | 重试 2 次；持续出现查串口线/驱动板 |
| `0x05` | 电机堵转 | 转人工（机械卡住，重试会加剧） |
| `0x06` | 电机走步误差偏大 | 转人工（需重新校准） |
| `0x08` | 收到错误指令 | 指令码/模式不支持 → 中止 |
| `0x09` | 指令参数数值错误 | 改参数后重跑 |
| `0x0A` | 存储参数出错 | 转人工（重新保存参数/复位） |
| `0x0B` | 传感器失效 | 转人工 |
| `0x0E` | 卡扣脱落 | 转人工（机械故障） |
| `0x10` | 等待超时 | 重试（瞬时） |
| `0x12` | 放弃本次实验 | 用户主动放弃，不重试 |

## 7. 文档没写的东西（必须现场确认）

| # | 缺什么 | 影响 |
|---|---|---|
| 1 | `0x40/0x41` 是变长帧还是多帧续传 | 96/384 孔逐孔加液是核心能力，实现错等于用不了 |
| 2 | 「管路类型」0/2、1/3 重复 | 可能装错管径（见 §5） |
| 3 | 单次加液耗时 | 只知"开始/暂停/放弃"，没给整板耗时；模拟器按 96 孔 ≈ 8 s 估（与其他分液器同量级），**不是实测** |
| 4 | `0x03` 输出参数的字符串格式 | 无法解析 ⇒ 只能逐条 `0x01` 查询 |
| 5 | 加液量的合法上下限 | 参数表只给字段，没给范围；中控按 0.5–2500 µL（同类设备公开规格）做**软校验**，不是厂商值 |
| 6 | 板位 A/B 的物理编号与中控点位如何对应 | 需要现场标定（对应 `device_point` 的 `deck_in`/`deck_out`） |

### 8.1 方法（真实指令 → 流程别名）

| 真实指令 | 中控方法 | 参数 |
|---|---|---|
| `0x00` 设置参数 | `SetParam` | index, value |
| `0x01` 查询参数 | `ReadParam` | index |
| `0x02` 保存参数 | `SaveParam` | — |
| `0x03` 打印参数 | `PrintParams` | — |
| `0x04` 加液 | `Dispense` | mode（a/b/ab/单管/双管/96/384/标准/梯度/复杂）, volumeUl, plateHeightMm, nozzleHeightMm, pumpSpeed, plateType(96\|384) |
| `0x04 01` 暂停 | `PauseDispense` | — |
| `0x04 02` 放弃 | `AbortDispense` | — |
| `0x05` 复位 | `Reset`（别名 `Home`） | — |
| `0x06` 清错 | `ClearFault` | — |
| `0x30 00/01` 填充管路 | `PrimePipe` / `StopPrime` | — |
| `0x31 00/01` 回收试剂 | `RecoverReagent` / `StopRecover` | — |
| `0x32` 管路清洗 | `CleanPipe` | times, secondsPerRinse |
| `0x36` 选程序 | `SelectProgram` | programIndex |
| `0x40` 96 孔 | `Dispense96` | wells（96 个 2 字节值） |
| `0x41` 384 孔 | `Dispense384` | wells（384 个 2 字节值） |
| （框架）状态 | `GetStatus` | **文档没有**，`documented=false` |

### 8.2 模拟器要验的物理约束

1. **参数未设置就加液** ⇒ 拒绝（真机用的是"上次保存/默认"的参数，模拟器按"必须先 `SetParam` 至少 0x1F 加液量"处理，避免流程漏发参数还跑通）。
2. **加液量越界**（0.5–2500 µL 软校验）⇒ `0x09` 指令参数数值错误。
3. **`0x32` 清洗次数/时间缺省** ⇒ `0x03` 参数范围有误。
4. **管路填充/回收必须成对**：`PrimePipe` 后再 `PrimePipe` ⇒ 拒绝（真实设备会重复灌液）；同理 `RecoverReagent`。
5. **不加液时暂停/放弃** ⇒ `0x08` 收到错误指令。
6. **未知指令码** ⇒ `0x08`。
7. **未保存的参数在"断电"后丢失** —— 模拟器用 `SaveParam` 标记区分，`Reset` 不清参数但重启会（行为类按"保存态"与"暂存态"两份表处理）。
