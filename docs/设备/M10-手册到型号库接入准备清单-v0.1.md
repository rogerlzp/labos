## 1. 现状盘点（2026-11-03）

### 1.1 型号库的四层结构

| 层 | 代码/位置 | 回答什么 | 接新设备要改吗 |
|---|---|---|---|
| 设备类型 | `labos-kernel/src/main/java/com/labos/kernel/sim/DeviceProfile.java` | 参数边界（转速/量程/温度…） | 只有新品类才改 |
| 具体型号 | `labos-kernel/src/main/java/com/labos/kernel/device/DeviceModels.java` | 真实指令名/参数/超时/错误码 | **改这里（一条定义一个型号）** |

| 恢复策略 | `pg_rebuild/schema/95_seed_data.sql` | 出错后中控怎么反应 | **由型号库生成，不手写** |

`docs/模拟器设备库.md`（14 类设备的参数边界与典型方法）、
`docs/设备/现场确认清单.md`（手册没写、必须现场实测的项）。

## 2. 资料清单（向用户/厂商要什么）

> 原则：要**通信接口说明/协议手册**（含指令帧、返回帧、错误码），不是"操作手册"。
> 手册里最值钱的是**错误码表**和**参数单位**；没有错误码表，接上去也只是"能发命令"。

### 2.1 每台设备通用（P0 阻塞项）

| # | 资料 | 说明 | 用到哪张表 |
|---|---|---|---|
| 1 | 通信接口说明（PDF/Word） | 帧格式、报头/报尾、校验、超时、重发规则 | §3-B |
| 2 | 指令集清单（指令名 + 参数 + 返回） | **原始指令名**必须与手册一致；别名才是中控流程用的 | §3-B |
| 3 | 错误码表（厂商码 → 含义 → 建议处置） | 含子码/状态位说明；没有就显式记录"厂商无码表" | §3-C |
| 4 | 参数单位/范围/默认值 | rpm、秒、毫米、温度…；单位错了仿真全绿、现场必炸 | §3-A/B/D |
| 5 | 状态查询/忙闲查询指令 | 长任务（离心/封膜）必须要；没有则说明"只能等固定时长" | §3-B/F |
| 6 | 上电/复位/回原点流程 | 断电恢复后停在哪、是否需要复位 | §3-E/F |
| 7 | 安全互锁说明 | 运行中能否开门/开盖；**未确认前不上真机** | §3-E |
| 8 | 板位/托盘/耗材规格 | 板型、托盘位置有效范围、膜卷规格 | §3-D |
| 9 | 固件版本 + 厂商支持联系方式 | 协议可能分版本；现场问题找人 | 归档 |
| 10 | 现场连接拓扑（IP/端口或串口参数、网关） | driver 端点配置依据 | §3-G |

### 2.2 360R（Hettich Rotanta 460R，离心机）额外要

| # | 资料 | 为什么 |
|---|---|---|
| 11 | 离心程序参数（转速/时间/加速度/减速度）的**单位与范围** | 手册示例 byCentriRamp=150 未写单位；猜错会把细胞甩碎 |
| 12 | 运行中能否开盖（安全互锁）的明确条款 | 手册没写 = 现场实测 + 书面确认 |
| 13 | 报错码/故障码表 | 没有码表 → 只能识别"通讯失败"，无法区分"门没关/不平衡/超温" |
| 14 | 转子/适配器型号与最大转速关系 | 同型号不同转子限速不同，参数边界不能拍脑袋 |

### 2.3 PlateLoc（Agilent PlateLoc，封膜机）额外要

| # | 资料 | 为什么 |
|---|---|---|
| 15 | 封膜温度/时间/压力参数范围与**参数索引表** | S100 靠 0x00 索引预设；PlateLoc 是另一套协议，不能套用 |
| 16 | 托盘/载板机构原点与位置范围 | 半自动热封，上料方式可能与 S100 不同 |
| 17 | 膜类型/耗材规格与温度对应关系 | 膜换了温度不对 → 封不上且**设备不报错**（最难查） |
| 18 | 封膜一次的实际时长（实测） | 超时 = 重复封膜（废板）；必须实测取最大值 ×1.5 |

## 3. 参数提取模板（拿到手册后照此填）

> 一张表对应 DeviceModels.java 里的一条 DeviceModel；填完整再动代码。

### 3.1 表 A · 型号主档（对应 new DeviceModel(...)）

| 字段 | 填什么 | 例子（aspin-2k） |
|---|---|---|
| id | 小写短横线，全局唯一 | aspin-2k |
| type | 设备类型（对齐 sim/DeviceProfile） | centrifuge |
| vendor / model | 厂商 / 型号 | 上海爱翱 / ASpin 2K |
| protocol | binary-serial / xml-dll / tcp-json … | xml-dll |
| transport | 串口参数或网络地址类型 | CAN 卡 / 串口（经 Cluster.dll） |
| manual | 手册路径（证据） | docs/设备/AC离心机…pdf |
| evidence | MANUAL / PLANNED | MANUAL |
| doors | 门数（0=无门） | 2 |
| actionTimeoutMs | 最长动作超时（来自手册或实测） | 120000 |
| notes | 接真机前必须确认的点（逐条写） | 见源码 |
| errorCodeBlock | 错误码块（0x40/0x41/…，见 §5） | 0x41 |

### 3.2 表 B · 方法映射（一条指令一行）

| 手册指令名 cmd | 中控别名 alias | 参数/参数 XML | 超时 ms | 手册有吗 documented | 页码/章节 |
|---|---|---|---|---|---|
| … | … | … | … | ✅/❌ | … |

规则：
- cmd **必须逐字照手册**（大小写/空格都算）；别名才是流程里用的；
- 手册没写的指令（如 GetStatus）显式标 documented=false —— 接真机时可能根本不存在；
- 一个指令多种用法（如 S100 0x04 封膜/改板型/查板型）登记多条别名，参数里写清索引。

### 3.3 表 C · 错误码

| 厂商码 | 含义 | 建议处置（MANUAL/RETRY/ABORT/IGNORE） | 建议动作（一句话，给人看） | 页码 |
|---|---|---|---|---|
| … | … | … | … | … |

规则：
- 中控码由"型号错误码块 + 低字节"自动生成，**不手填**；
- 厂商无码表时写"仅有适配层码"，并用 adapterError 登记通讯类错误（参考 aspin-2k）；
- 每条码必须有处置和动作，否则现场只能干瞪眼。

## 4. 接入流程（拿到手册后 10 步 DoD）

| # | 步骤 | 产出 | 验收 |
|---|---|---|---|
| 1 | 资料完整性核对（§2 清单逐项勾） | 资料清单缺口表 | P0 项无缺口 |
| 2 | 填表 A–G（§3） | 一台设备一份参数表 | 评审通过（参数/单位/错误码有出处页码） |
| 3 | 改 DeviceModels.java 加一条型号 | 代码 + 自测 | --list-models 可见；纯逻辑测试通过 |
| 4 | 重生成 SQL 种子（错误码/策略） | 95_seed_data.sql diff | 码块编号无冲突、策略条数对得上 |
| 5 | 写/对齐型号行为（如需） | sim/XxxBehavior | 时序约束用例通过 |
| 6 | 模拟器行为对齐（同参数校验/同错误码） | 模拟器用例 | 模拟器能复现手册错误路径 |
| 7 | 绑定设备 + 驱动端点 | 库变更 + 配置 | 心跳在线、设备可见 |
| 8 | 单机 smoke（真机，安全前提下） | 测试记录（截图/日志） | 指令往返、错误码识别、超时不误判 |
| 9 | 混线验收（M10 门槛） | 实录 | ≥3 设备、≥5 节点工艺跑通 + 失败→恢复→继续实录 |
| 10 | 长任务策略验证 | 报告 | 区分"设备忙"与"设备死"（M10 范围项 2）；长任务不误超时 |

### 4.1 长任务超时策略（M10 范围项 2，随手册一起定）

| 设备 | 长任务 | 需要手册/实测回答 |
|---|---|---|
| 360R | 离心（分钟级） | 是否有"查询运行状态"指令？手册建议超时怎么定？最大离心时长？ |
| PlateLoc | 封膜（十秒级） | 是否有完成信号？封膜时长的最大值？ |

判定口径（初稿，待评审）：
1. **有忙闲/状态查询指令** → 超时后先查询：还在跑 = 设备忙（继续等，不重发）；查不到 = 设备死（abort + 报警）；
2. **没有查询指令** → 只能按"实测最大值 × 1.5"设动作超时，**超时后不自动重发**（防重复动作）；
3. 任何"动作类指令超时后自动重发"都必须有幂等保证，否则禁止。

### 4.2 错误码回流（M10 范围项 4）

现场遇到未登记码时：
1. 记录**原始码 + 完整帧 + 设备/固件版本 + 上下文**（哪个方法、哪一步）；
2. 在 DeviceModels 对应型号补 .error(...)（手册有）或 .adapterError(...)（通讯/适配层）；
3. 跑 make seed 重生成 error_code + 策略；
4. 回归：模拟器注入该码能走到预期处置（人工/重试/终止）；
5. 记入本文附录（码 → 处置 → 复发情况）。

## 7. 风险 / 不做什么 / 待确认问题

**风险**
- 没有手册就编协议 = 到现场全废（本项目已有教训：PLANNED 里 6 条都故意不绑型号）；
- PlateLoc 是半自动热封，**不能套用 S100 的二进制帧协议**；360R 不能套用 aspin-2k 的错误码含义；
- 安全互锁（运行中开门/开盖）未书面确认前**不上真机**；
- 长任务超时取小 → 重复动作（重复封膜废板）；取大 → 白等、节拍慢。

**不做什么（本轮）**
- 不写驱动代码、不改 DeviceModels 逻辑（等手册）；
- 不把 360R/PlateLoc 强行绑定到已有型号；
- 不做型号库配置化（G1，M10 之后再评估）。

**待确认问题（给用户/厂商）**
1. 360R / PlateLoc 的**通信接口说明**（电子版）能否提供？版本/日期？
2. 两台设备当前**固件版本**；协议是否分版本？
3. 产线上 360R（1 台）/ PlateLoc（2 台）的**连接方式**（串口/网口/中间件）与地址？
4. 厂商是否提供**错误码表**与 SDK/示例代码？
5. PlateLoc 的封膜参数（温度/时间/压力）范围与**参数索引表**；
6. 360R 的离心加速度单位/范围、转子限速、运行中开盖互锁条款；
7. 是否允许现场做**破坏性测试**（拔电/断网/错误注入），以及安全责任人；
8. 长任务场景（离心 30 分钟）现场期望的**告警阈值与处置流程**。
