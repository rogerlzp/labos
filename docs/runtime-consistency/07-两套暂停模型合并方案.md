# 07 · 两套暂停模型合并方案（R8 · 第一版 · 供评审）

> 本方案是阶段二唯一剩余的「大工程」，**先评审、后动手**。
> 上游依据：`LABOS_STATE_MACHINE_MULTILAYER_20261107.md`（两套模型并存的分析）、
> `runtime-consistency/01`（事实 vs 投影）、`ADR-PAUSE-008`（control_state）。

---

## 1. 现状：两套模型并存

| 层 | 表 | 谁写 | 关键字段 |
|---|---|---|---|
| workflow run | `run` | `PauseManager` | `status`、`pause_kind`、`pause_reason`、`paused_at`、`pause_node_key` |
| experiment run | `experiment_run` | `RunControl` / `ExperimentExecutor` | `status`、`pause_kind`、`pause_reason`、`paused_at`、`control_state`、`pause_requested_at` |
| 阻断闸门 | `runtime_hold` | `RuntimeHold` | 真正的「暂停生效」事实 |

**问题**：两张表各自直写 `status='paused'`，靠约定衔接——
`RuntimeHold.Kind.of()` 兼容两套 code、`RunControl.resume()` 作废旧 paused run、`PauseManager.pausedRuns` 查孤儿。
**没有统一协调器，没有「事实→投影」的单一方向**。

---

## 2. 合并目标（事实 vs 投影）

- **事实**：`runtime_hold`（有没有扣留）+ `control_state`（暂停请求的状态机，见 01 §2）。
- **投影**：`run.status` 与 `experiment_run.status` 都是「设备确认已停」这一事实的投影。
- **单一写入口**：暂停/恢复只改 `runtime_hold` + `control_state`；两张 status 表由**投影器**统一回写。

即：不再让 `PauseManager` 直写 `run.status`、`RunControl` 直写 `experiment_run.status`，
而是两者都调用同一个 `PauseProjector`（事实 → 投影）。

---

## 3. 合并策略（增量，不搞大爆炸）

**不合并两张表**（`run` 与 `experiment_run` 的 id 空间不同、生命周期不同，合并是更大的坑）。
**只收口「暂停/恢复的写入口」**：

1. 建 `PauseProjector`（或复用 `ExperimentStateProjector` 扩展）：唯一的「暂停事实→两张 status」投影器。
2. `PauseManager.pause` / `RunControl.pause` 改为：写 `runtime_hold` + `control_state`，**不再直写 status**；
   由投影器在「设备确认已停」（R3 的 reconciliation 判定）后统一写 `paused`。
3. 两套 `pause_kind` 词表统一成一个（`RuntimeHold.Kind` 为唯一真源，`PauseManager.Kind` 删除或别名）。

---

## 4. 迁移步骤（每步独立可回滚）

| 步 | 内容 | 风险 |
|---|---|---|
| 1 | 抽 `PauseProjector.projectedStatus(facts)` 纯函数（事实→投影），先与现状双写比对 | 低 |
| 2 | `RunControl` 暂停路径切到投影器（experiment_run 侧） | 中 |
| 3 | `PauseManager` 暂停路径切到投影器（run 侧） | 中 |
| 4 | 删直写点 + 统一 pause_kind 词表 | 中 |
| 5 | 回归：三层状态（run/experiment_run/experiment）一致性 | — |

每步都有 `PauseCoordinatorDbSelfTest` / `RunControlDbSelfTest` 兜底。

---

## 5. 风险与验收

| 风险 | 缓解 |
|---|---|
| 投影器与直写不一致（过渡期） | 步骤 1 双写比对，diff 归零再切 |
| 两套 pause_kind 词表冲突 | 步骤 4 统一真源 + 兼容别名 |
| 恢复（resume）对称性 | 与 01 §2 的 resume 状态机对齐（ResumeRequested/ResumeUnknown） |
| 批次/非批次路径差异 | 投影器按 `syncExperimentStatus` 分路径（同现状） |

**验收标准**：
1. 暂停→恢复全链路：`runtime_hold` + `control_state` + 两张 status 三者最终一致。
2. `grep` 全仓无 `PauseManager`/`RunControl` 直写 `status='paused'`（除投影器）。
3. 既有 `RunControlDbSelfTest` / `PauseCoordinatorDbSelfTest` / `BatchDbSelfTest` 全绿。

---

## 6. 本方案不做什么

- 不合并 `run` 与 `experiment_run` 两张表。
- 不动命令生命周期（已在 `command_ledger`，R4）。
- 不新增功能。
