## 3. 冻结 §12 验收矩阵闭环映射

### 3.1 Compiler / GraphPlan（§12.1）
- `C1`–`C8` 主体由生产方 `G5WaitGraphPlanCompilerAndCodecTest`、`GraphWaitSchedulingTest` 覆盖；
- 独立验收 `A5`、`A5b`、`B3` 交叉验证 `Kind.WAIT`、`WaitSpec`、`RouteKind.TIMEOUT`、`v1/v2` round-trip 及非法降级/篡改 fail-closed。

### 3.2 Repository / PG17（§12.2）
- `R1`–`R10` 主体由 `G5WaitRepositoryIntegrationTest` 覆盖；
- **独立 QA 闭环补洞**：
  - `R6` 两阶段事务边界由 `B2` 补齐 `FaultInjectingTransactionManager` 真实提交前/后注入与重放幂等；
  - `R11` 唯一索引反向语义由 `A7` 补齐同 Run 不同 `correlation_key` 共存及同 key `23505` 校验；
  - `B3` 独立复验纯图 Wait `0 attempt`、v2 `continuation` 持久化、`SATISFIED` / due `EXPIRED` 双路径收敛。

### 3.3 Inbox / Dispatch / Recovery（§12.3）
- `D1`–`D8` 由 `G5WaitRepositoryIntegrationTest`（队头公平性）与 `G5WaitRuntimeIntegrationTest`（DispatchLoop WAIT-only 无热循环、TASK+WAIT 不饿死、PAUSE→Signal→Resume 重放、Gate 关闭、重启恢复）覆盖；
- `B5` 补齐 `004` 索引（`inbox_wait_signal_pending_idx`）在数据库 catalog 中的存在性与 partial predicate 校验。

### 3.4 Drain / 并发（§12.4）
- `DR1`–`DR3`、`DR5`–`DR6` 由 `G5WaitRepositoryIntegrationTest` 与 `G5WaitRuntimeIntegrationTest` 覆盖；
- **独立 QA 闭环补洞**：`DR4`（`PAUSE` / `STOP` / `FAILURE` Drain 与 `registerGraphWait` 并发竞争）由 `B1` 在 PostgreSQL 17 上通过外层 Run 锁 + `pg_stat_activity` 锁等待观测与 `CountDownLatch` 竞态验证完成。
