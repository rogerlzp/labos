# 03 设计口径与边界（评审必读）

## 1. 三层状态的单一口径

| 层 | 表/字段 | 本批处理 |
|---|---|---|
| Workflow 级执行 | `run.status/pause_kind/pause_reason` | PauseManager；E-1~E-3 写集单事务 |
| 实验级执行 | `experiment_run.status/control_state/pause_kind` | RunControl/ExperimentExecutor；E-4~E-6 单事务 |
| 现场闸门 | `runtime_hold(scope,scope_id,kind)` | 三态（CLEAR/HELD/UNKNOWN）+ 多 Hold（kind 维度） |
| 幂等/事件 | `pause_request`、`pause_event` | 请求幂等 + 事件 Outbox |
| 设备命令 | `command_ledger`、`command_outbox` | 命令账本 + 外部事件 Outbox |
| 物理位置 | `plate`、`position_state`、`position_evidence`、`transfer_transaction` | 物理证据/搬运事务分离 |

原则：`status` 是生命周期；`control_state` 是控制过程（NONE/PAUSE_REQUESTED/PAUSING/RESUMING）；`runtime_hold` 是现场闸门；`pause_event`/`command_outbox` 是可重放事件。

## 2. P-06 V2：事务边界

- **E-4 实验级 Pause**（`PauseCoordinator.pauseExperimentRun`）：同一事务内 `claimTx`（pause_request）→ `RuntimeHold.raiseTx` → `RunControl.markControlRequestedTx`（control_state=PAUSE_REQUESTED）→ `settleTx`（结果）→ `insertPauseEvent`；异常整体回滚。
- **E-5 实验级 Stop**：同一事务内 `claimTx` → `RunControl.stopTx`（running 只写 stop_requested；非 running 写 aborted + 同步实验状态）→ `settleTx` → `STOP_REQUESTED`；批次聚合在 commit 后补。
- **E-6 实验级 Resume**：同一事务内 `claimTx` → `coveringForExperimentCheckedTx` → `clearKindTx`（只解命中的 kind）→ `RunControl.resumeTx`（queued/同步实验/作废旧 paused workflow run/事务内复查）→ `settleTx` → `RESUME_REQUESTED`；批次聚合与 `scheduler.resumeRun` 在 commit 后执行。
- **E-1 Workflow Pause**：`claimTx` → `PauseManager.pauseTx`（run paused + 释放位置/预约/通道/设备锁同事务）→ `settleTx` → `PAUSE_REQUESTED`。
- **E-2 Workflow Resume**：`claimTx` → `PauseManager.resumeTx`（校验/板位校正 `locatePlateTx`/审计/run 状态同事务）→ `settleTx` → 成功时 `RESUME_REQUESTED`；异步续跑 commit 后。
- **E-3 忽略**：单条/批量 `dismissTx/dismissBatchTx` + 事务内幂等结果/事件。
- `pause_event`：与暂停受理同事务写入；`PauseEventOutbox` 每 tick `FOR UPDATE SKIP LOCKED` 标记 DELIVERED（真实外部消费者未接）。
- PAUSING：调度器每秒 tick，`RunControl.markPausing(db,tenant,5)` 把「受理超过 5 秒、仍 running」的 run 标 PAUSING；执行器 settle 时回 NONE，绝不提前写 paused。

## 3. P-07：命令账本/Outbox

- `command_ledger` 状态：`DISPATCH_STARTED` → `ACKED/FAILED`；启动对账把陈旧 `DISPATCH_STARTED` 标 `UNKNOWN`；`POST /api/commands/{id}/resolve` 人工处置。
- 稳定 idempotency key：`run|node|attempt|step|device|method|opSeq`（opSeq 为执行器内存自增，覆盖 Transfer 多指令）。
- `CommandLedger.begin`：账本 DISPATCH_STARTED + `command_outbox` PENDING 同事务；`finish` 单独连接写 ACKED/FAILED。
- `command_outbox`：调度器标 DELIVERED；`POST /api/command-outbox/{id}/replay` 只重投外部事件，不重发物理命令；物理重发仍受 `command_ledger` fail-closed 守卫。
- 四个崩溃点已用 DB 单测覆盖：派发前/派发中/回包后落库前/重复下发；真 kill -9 未做。

## 4. N-10 / P-03：故障闭包与派发

- `experiment_workcell` 显式绑定：存在时优先；为空才回退「workflow_node 资源 → resource_node 祖先链 island 根 + experiment.island_id」。
- `RuntimeHold.coveringForExperiment`：优先级 experiment > 所属 island > site；任一所属 Workcell 的 island Hold ⇒ 整实验 HELD；范围外 island Hold 不误伤。
- `ExperimentScheduler.dispatch`：逐候选 `coveringForExperiment`；HELD 跳过该候选、UNKNOWN 整轮阻断；`autoContinueHeldBatches` 同样逐候选。
- 多 Hold：`uk_runtime_hold_active` 改为 `(tenant,scope,scope_id,kind)`；`clearKind` 精确解除，`clear` 仍清全部。
- Handoff：`experiment_handoff` 配置 → `POST /api/experiments/{id}/handoffs/confirm` 同时写 L-01 介入记录 + 已决策 manual_window，回填两个 id；HandoffGate 要求 `confirmed + intervention_record_id + manual_window_id`，缺一阻断执行。

## 5. P-08：隔离/证据/搬运事务

- 启动顺序：命令账本对账 → `quarantineUncertainRuns` → 普通 `settle` 已排除「账本 UNKNOWN/DISPATCH_STARTED」的 run（不会被当 failed 清设备锁）。
- `quarantined`：run 标隔离 + input.quarantine=true + 实验级 Hold；`POST /api/runs/{id}/quarantine/release` 人工确认 → failed(EC-QUARANTINE-CONFIRMED) + 解 Hold + L-01。
- `position_evidence`：人工盘点自动落 MANUAL；SCAN/SENSOR 仅 API 入口。
- `transfer_transaction`：Transfer 执行前建；设备成功回包 → REPORTED（仅运动报告）；失败/异常 → UNKNOWN；人工/扫码 confirm → CONFIRMED + position_evidence。
- 恢复强门禁：`resume/resumeTx` 发现该 run 有 REPORTED/UNKNOWN transfer_transaction ⇒ 拒绝 continue/retry，ABORT 允许。

## 6. L-01 / N-08

- `intervention_record`：operator（登录用户名）、action、板/样本、源/目标交接点、result、note。
- `/manual-windows` 页：待决窗口 + 决策弹窗 + 介入记录表；waiting_human 暂停自动建窗，恢复自动关窗。
- `/handoffs`、`/quarantined` 页：配置确认/隔离解除。

## 7. 已知边界（不要在评审中当成隐藏缺陷，但也请判断是否可接受）

1. 真实外部事件总线消费者未接；Outbox 只做到内部 DELIVERED 标记 + 重放 API。
2. 扫码/传感器自动证据未接；只有 API 入口与人工落证。
3. TransferTransaction 只在 `LABOS_TRANSFER_PLAN` 且 protect 分支创建；非 protect 路径没有事务记录。
4. 恢复门禁只覆盖「恢复」；**派发前**对未确认位置的强制门禁尚未实现。
5. `resolveQuarantine` 解 Hold 使用 `clearTx(EXPERIMENT, expId)`（清该实验所有 kind），多 Hold 场景可能连带清掉人工 Hold——请重点评审。
6. Handoff 的 manual_window 是 run_id=0 的「确认窗口」记录，不是真实执行窗口。
7. PAUSING 是 5s 最小 worker，不是完整异步收敛状态机。
8. E-2 commit 后异步续跑若失败只记日志；启动 rehydrate 只覆盖 queued experiment_run，不覆盖 workflow run。
9. 多实例/并发场景未验证；调度器岛锁仍是 JVM 内存锁 + DB 约束。
10. 前端新页面只有 Playwright 冒烟，没有独立 e2e 断言集。
