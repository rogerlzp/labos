## 1. 问题：一个真实的事故场景

```
实验 A：把板子 PL-001 放进 Incubator_2C-1 的第 3 层
实验 B：同时想把板子 PL-002 放进 Incubator_2C-1 的第 3 层
        ↓
     机械臂把 PL-002 推进去
        ↓
    两个板子挤在同一层 → 卡死 / 压碎 / 污染
```

**这不是逻辑错误，是物理事故**。板子碎了、样本毁了、设备卡死要人工拆。

### 1.1 岛级互斥为什么不够

之前的方案是"一个岛同时只跑一个实验"：

```
岛 = Incubator_2C-1 + XRobot + Thermo ATC
岛级互斥 → 同岛的两个实验不会同时跑 ✅
```

**但漏了两种情况**：

| 情况 | 岛级互斥能不能防 |
|---|---|
| 两个实验在**不同岛**，但要往**同一个共享位置**放板 | ❌ 防不了 |
| 上一个实验的板**还留在**位置里，下一个实验不知道 | ❌ 防不了 |

第 2 种更常见：实验 A 跑完把板留在孵箱里（正常的，孵育要几小时），实验 B 以为位置是空的。

### 1.2 根本原因

**岛级互斥管的是"谁在用机械臂"，不是"哪个位置有板"。**

这是两个不同维度的资源：

| 资源 | 忙闲特征 | 互斥粒度 |
|---|---|---|
| **机械臂**（执行器） | 瞬时（搬一次几秒） | 动作级 |
| **位置**（存储） | **持久**（板放进去占几小时） | 占用级 |
| **设备**（单台机器） | 中等（一个方法几十秒） | 动作级 |

**岛级互斥把三者混在一起，用了最粗的粒度** —— 安全，但并行度低。

## 2. 四级资源模型

```
岛（island）              容量 1  → 建议 2.0 放开
 └ 设备（device）          容量 1  → 动作级互斥
     └ 位置（nest）        容量 1  → **占用级互斥（本文重点）**
         └ 板（plate）     → 一个板只能在一个位置
```

### 2.1 位置的类型

库里 `resource_node.kind` 已有：

| kind | 数量 | 用途 |
|---|---|---|
| `incubator` | 1,021 | 培养箱层位 |
| `storage` | 1,122 | 存储塔槽位 |
| `transfer_point` | 420 | 转运点（中转，临时放） |
| **合计** | **2,563** | 每个都是"只能放一块板"的位置 |

### 2.2 位置的状态

```sql
CREATE TABLE position_state (
  tenant_id      bigint      NOT NULL,
  resource_id    bigint      NOT NULL,   -- resource_node.id（位置）
  plate_id       varchar(64),            -- 当前放的板（null=空）
  occupied_since timestamptz,
  occupied_by_run bigint,                -- 哪个 run 放的
  reserved_until timestamptz,            -- 预约到何时（搬运中）
  reserved_by_run bigint,                -- 谁预约的
  updated_at     timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, resource_id)
);
```

**两个状态**：

| 状态 | 含义 | 谁能清 |
|---|---|---|
| `plate_id` 非空 | 板**实际在**里面 | 取板动作 |
| `reserved_until` 未过期 | 有人**预约**了，搬运中 | 到期自动 / 搬运完成 |

### 2.3 为什么区分"实际占用"和"预约"

```
t=0s   实验 A 决定把板放到位置 X
       → 立刻预约 X（reserved_until = now+60s）
       → 此时 X 还不能被别人用

t=5s   机械臂搬运中
       → X 仍是预约状态

t=8s   板放进去了
       → plate_id = 'PL-001'，清掉预约

t=8s+  板一直占着 X，直到被取走
```

**如果不做预约**，两个实验可能同时看到"X 是空的"，然后都去放板。

**预约 = 分布式锁在数据库里的实现**。

## 3. 搬运的原子性（关键）

### 3.1 一次搬运涉及两个位置

```
取板：位置 A（源）→ 板到机械臂上
放板：位置 B（目标）← 板从机械臂下来
```

**中间状态**：板在机械臂上，A 空出来了，B 还没占。

### 3.2 必须一次性锁定两个位置

```java
/**
 * 搬运前一次性预约源和目标，全有或全无。
 *
 * 为什么不能"先占源，再占目标"：
 *   实验 A 占了源的 X，等目标的 Y（被 B 占）
 *   实验 B 占了源的 Y，等目标的 X（被 A 占）
 *   → 死锁
 */
boolean reserveTransfer(long sourceId, long targetId, long runId, Duration ttl) {
    // 按 resource_id 升序申请（全局顺序，消除循环等待）
    long first  = Math.min(sourceId, targetId);
    long second = Math.max(sourceId, targetId);

    return tx(() -> {
        if (!tryReserve(first,  runId, ttl)) return false;
        if (!tryReserve(second, runId, ttl)) {
            releaseReserve(first, runId);   // 第二个失败，立刻放掉第一个
            return false;
        }
        return true;
    });
}
```

**两条规则**：

1. **全有或全无**：拿不到目标就放掉源
2. **按 id 升序**：消除循环等待

这两条正好对应死锁四条件里的"持有并等待"和"循环等待"。

### 3.3 预约超时

```java
// ttl 默认 120 秒（搬运正常几秒，留足余量）
// 超时未完成 → 预约自动失效，位置可被重新申请
```

**为什么需要**：机械臂故障、进程崩溃时，预约不会永久卡住。

**代价**：超时后可能两个实验都认为位置可用 → 但这是"极少数异常下的降级"，**比永久卡死好**。

## 4. 调度器如何使用位置占用

### 4.1 静态预检（试算排程时）

```
实验 EXP0812 的步骤：
  1. 入板流程 → 目标位置：Incubator_2C-1/L3
  2. 孵育流程 → 位置不变
  3. 出板流程 → 从 Incubator_2C-1/L3 取出
```

**预检结果**：

```
┌─ 排程试算 · EXP0812 ────────────────────────────┐
│ 需要占用的位置：                                  │
│   Incubator_2C-1/L3   当前：空 ✅                 │
│                       预计占用 00:00-06:00       │
│                                                  │
│   XRobot 夹爪          当前：空闲 ✅              │
│   Thermo ATC/S1        当前：被 EXP0810 占 ⚠️     │
│                        预计 04:00 释放           │
│                                                  │
│ 建议开始时间：04:00（等 Thermo ATC/S1 释放）      │
│ [调整] [仍然执行（会等）]                         │
└──────────────────────────────────────────────────┘
```

### 4.2 运行时检查（执行前）

```java
// 每步执行前检查（不是只看预检）
void beforeStep(StepContext ctx) {
    for (long posId : ctx.targetPositions()) {
        if (!positionLock.tryReserve(posId, ctx.runId(), TTL)) {
            throw new NodeFailure("EC-12-0001",
                "目标位置已被占用：" + posName(posId));
        }
    }
}
```

**为什么运行时还要查**：

预检到执行之间可能隔几小时，期间位置可能被别人占了。

**预检是为了排程，运行时检查是为了安全**——两件事。

### 4.3 位置占用不阻塞调度，只阻塞一步

```
目标位置被占 → 抛 EC-12-0001
  ↓
走恢复策略（已有）：
  - 换一个位置（如果流程允许）
  - 等待（配置了 wait）
  - 转人工
```

**不是让整个实验失败**——一步失败可以重试或换位置。

## 5. 板级跟踪（板在哪）

### 5.1 最小实现

```sql
CREATE TABLE plate (
  tenant_id    bigint      NOT NULL,
  plate_id     varchar(64) NOT NULL,     -- 条码
  plate_type   varchar(32),              -- 96孔/384孔
  current_pos  bigint,                   -- 在哪个位置（null=机械臂上/已出)
  current_run  bigint,
  status       varchar(16),              -- in_storage / in_transfer / consumed
  updated_at   timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, plate_id)
);
```

**`plate.current_pos` 和 `position_state.plate_id` 互为反查**，两边都要维护（或用视图）。

### 5.2 一致性问题

两个表可能不一致（一个说 X 有板，另一个说板在 Y）。

**解决**：以 `position_state` 为准（它是物理事实），`plate` 表是查询用的冗余。

```sql
-- 每日对账
SELECT count(*) FROM position_state ps
LEFT JOIN plate p ON p.plate_id = ps.plate_id
WHERE ps.plate_id IS NOT NULL AND p.plate_id IS NULL;
-- 应该 = 0
```

## 6. 与岛级互斥的关系（重要）

### 6.1 两个方案对比

| 方案 | 并行度 | 安全 | 复杂度 |
|---|---|---|---|
| **A. 岛级互斥**（之前的方案） | 岛数（26） | ✅ 绝不打架 | 低 |
| **B. 位置级 + 机械臂级**（本文方案） | 高得多 | ✅ 位置安全 | 高 |
| **C. 两者都做**（1.0 建议） | 26 | ✅ 双重保险 | 中 |

### 6.2 为什么 1.0 建议 C

**只用 A**：跨岛的共享位置冲突防不住。

**只用 B**：
- 需要秒级准确的时长（现在只有 10 秒级）
- 需要完整的板位初始化（现在 2,563 个位置，不知道哪些有板）
- 需要机械臂时间片调度（没做过）

**A + B**：
- A 兜住"同岛不同时跑"（保守但绝对安全）
- B 兜住"位置不重复占"（防跨岛冲突 + 防历史遗留板）

> **A 是安全网，B 是正确性。** 先有正确性，再逐步放开安全网。

### 6.3 2.0 放开岛级互斥的前提

| 前提 | 现在 |
|---|---|
| 秒级准确的时长模型 | ❌ 10 秒级 |
| 位置初始状态已知 | ❌ 2,563 个位置，未初始化 |
| 机械臂时间片调度 | ❌ 未做 |
| 位置锁稳定运行 3 个月 | ❌ 刚做 |

**四条都满足才放开**。

## 7. 初始化：位置状态从哪来

### 7.1 冷启动（首次上线）

```
所有位置 → 空
```

**风险**：实际设备里可能有板（此前跑的）。

**处理**：
1. 上线前人工清空所有板
2. 或者：上线时做一次盘点（人工扫码）
3. 或者：跑一个"库存扫描"流程（如果设备支持）

### 7.2 过渡期

**绝对禁止两边同时操作设备**。

**过渡方案**：
```
原有系统停 → 人工清空 → 新系统上线 → 盘点 → 开始跑
```

不能"原有系统跑 A 岛，新系统跑 B 岛"——位置锁不知道原有系统放了板。

## 10. 错误码

| 码 | 含义 | 处理 |
|---|---|---|
| `EC-12-0001` | 目标位置已被占用 | 换位置 / 等待 / 转人工 |
| `EC-12-0002` | 源位置没有板 | 数据不一致，转人工 |
| `EC-12-0003` | 预约超时未完成 | 检查机械臂状态 |
| `EC-12-0004` | 位置不存在 | 配置错误 |

## 11. 验收标准

| 问题 | 怎么验 |
|---|---|
| 两个实验往同一位置放板 | 第一个占住，第二个抛 `EC-12-0001` |
| 板放进去后位置被占 | `position_state.plate_id` 非空，其他实验预约失败 |
| 取板后位置释放 | `plate_id = null`，其他实验能预约 |
| 搬运中途崩溃 | 预约 TTL 到期自动释放，不会永久卡住 |
| 互相等对方的目标位置 | 按 id 升序申请，不会死锁 |
| 板到底在哪 | `GET /api/plates/{id}` 返回当前位置 |
