**V7-01【P1·设计风险】「每轮绑定先于派发并冻结进 target_snapshot」没有派发前的持久载体。**
- **来源**：G1 / S02（多源印证）。
- **位置**：§5.3 L398-402、§6.2a L690-715、§5.5 L473-477、§7⑤ L886-925、§5.8 L608。
- **问题与证据**：快照 L401 要求「子过程每轮执行前把 iterationBindings 原始表达式与解析后值冻结到 target_snapshot」；但 target_snapshot 唯一载体是 plate_material_effect.target_snapshot（§7⑤ L897），而效果行按 §5.3 L391 是**回包后、节点标 completed 前**才创建 ⇒ 派发前不存在该行。相邻载体均不具备：command_ledger 无 payload/params（99f:9-27）；run_command.payload 是回包后才写（WorkflowService.java:2212-2305）；run_node.input.material_effect_snapshot 是 run 启动静态声明（§5.3 L398），不含每轮 bindings。⇒ §5.8 L608「T1 前崩溃先按命令账本和回包对账、证据满足快照才补建」**无法重建当轮解析值**。
- **影响**：§16.3 前置 3 的「每轮绑定通过评审」不满足；T1 前崩溃窗口的绑定证据不可恢复。
- **建议**：指定派发前载体（推荐 command_ledger 增 request_payload jsonb，或新增 run_node_binding 表，键 (tenant, run, callPath, loop_index)）；§5.3/§5.8 写清从该载体补建；§6.1/§6.2a 明确 iterationBindings 存储列。

**V7-02【P1·完整性缺口】run 作用域身份上下文 materialIdentities[scanKey] 无 DDL/接口/生命周期/轮次维度，且跨续跑丢失。**

**V7-05【P1·完整性缺口】「完成处理器只有一个注入点」只覆盖成功路径；reconciliation_required/failed_confirmed 的写入点缺失。**
- **来源**：S03。
- **位置**：§5.7 L568（注入点=executeNode 设备成功之后）、§5.7 L564、§5.2c L378。
- **问题与证据**：RunStateMachine.executeNode 成功返回在 RunStateMachine.java:110-112；失败/未知结论产生在另一分支 catch (StepFailure) → decider.decide → 返回 SKIPPED/ABORTED/MANUAL（:114-171，返回点 :141/:155/:161/:166）；超时/通讯失败（EC-05-1007/EC-05-1006）走这条链。设计未给该分支任何 handler 调用点 ⇒ §5.2c 要求的 reconciliation_required/failed_confirmed 在运行期**无处落库**。
