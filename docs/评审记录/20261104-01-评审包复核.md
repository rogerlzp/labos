## 三、阻断级

### B1. e2e「24 / 0」不可复现 —— 实测 **23 / 1**，`ci-gate.sh --e2e` 当前必然红灯

**现象**：`python3 scripts/e2e-smoke.py` 连跑两次，均为 **通过 23 / 失败 1**，失败断言为
[e2e-smoke.py:190](file:///path/to/labos/scripts/e2e-smoke.py#L190) `✗ 执行历史没有可展开行`。

**根因链（已闭环验证）**：

| 步 | 事实 | 证据 |
|---|---|---|
| 1 | 实验列表按 `ORDER BY e.id DESC` 取首行 | [QueryService.java:721](file:///path/to/labos/labos-kernel/src/main/java/com/labos/kernel/api/QueryService.java#L721) |
| 2 | 当前 id 最大者为 **962**，`experiment_no=EXP-20261104001045-2428`，`name=rbac-operator-允许建实验-22244` | `psql … ORDER BY id DESC LIMIT 3` = 962 / 844 / 843 |
| 3 | 962 的 `experiment_run` 数 = **0** | `psql … count(*) WHERE experiment_id=962` = 0 |
| 4 | 执行历史表**未设 `rowExpandable`** ⇒ "有 run 才可展开"；0 条 run ⇒ 无展开图标 | [Experiments.tsx:848-854](file:///path/to/labos/webapp/src/pages/Experiments.tsx#L848-L854) |
| 5 | 断言要求"存在可展开行" ⇒ 失败 | [e2e-smoke.py:180-190](file:///path/to/labos/scripts/e2e-smoke.py#L180-L190) |

**反证**：次行实验 **844** 有 1 条 run（run_id 37，completed）⇒ 清理 962 后首行变为 844，e2e 应回到 24 / 0。

**性质**：**功能无回归**，是"e2e 断言对列表首行的数据分布强依赖"的**门禁脆弱性**；
叠加 §四 的**测试残留**才触发。二者需一起修。

**修复建议（由执行方完成）**：
1. 清掉残留（§四）；
2. e2e 选实验不取首行，改为**筛选"有 run 的实验"**（消除数据分布依赖）。

**修复建议**：清理实验补一条 `name LIKE 'rbac-%'` 兜底（与 `username LIKE 'rbac_%'` 对称），
