## 5. 关键设计决策与理由（供挑战）

| # | 决策 | 理由 | 反例/风险 |
|---|---|---|---|
| D1 | **不改恢复门禁**，只补一条合法的 `CONFIRMED` 路径 | 门禁判据 `count(status IN ('REPORTED','UNKNOWN'))>0` 是对的；短路等于丢掉 fail-closed | 若 `DEVICE_REPORT` 不足以算「独立位置证据」，则 M 方案本质上是放宽了 P-08 |
| D2 | 位置登记放在 `DriverStepExecutor.executeWithPlan` 成功分支，**不改 `writeStep`/`notePlateMove` 签名** | 该处已持有 `db/tenantId/runId/srcRes/dstRes/plate/transferTxn`，与 `TransferTransaction.report()` 同时机；`writeStep` 每个门控 step 都会调，改它易写中间态 | 只在 `LABOS_TRANSFER_PLAN` protect 分支生效（该分支由环境变量控制） |
| D3 | 板号单一真源 `resolvePlateBarcode`，拒绝数值 / `${}` / `AUTO-` | 数值 `plateId` 是 `plate.id`（bigint），`String.valueOf` 会造出假条码；`AUTO-{runId}` 受唯一约束会让多板串账 | 真实条码若恰好以 `AUTO-` 开头会被误拒 |
| D4 | 开关**按 workflow 生效**（`LABOS_TRANSFER_AUTO_CONFIRM=1000830`），默认关 | 全库 23 个 wf 含 Transfer 节点，只有 1 个配了板号；全局开关会让启动预检把另外 22 个流程阻断 | `System.getenv` 是进程级，多 run 共享；`autoConfirmWfCache` 需确认不会串 run |
| D5 | 九项条件全满足才自动确认；不满足保持 `REPORTED` 转人工 | `DEVICE_REPORT` 不能无条件等价物理确认 | 条件分散在 `noteTransferMove` 与 `autoConfirmTransfer` 两处，缺集中校验 |
| D6 | 新增 `selectFirstOccupiedPositionAny` 区分「源位空」与「源位有别人的板」 | 归属过滤查询两者都返回 null；误判成「首次引导」会凭空在目标位复制一块板 | 只取「第一个」有板层位，多点位设备可能判断不全 |
| D7 | 临时板号 `TMP-{runId}-{pointId}-{seq}` + `plate_barcode_alias`，**扫码后不改写任何历史字符串** | audit/evidence 是 append-only 证据，改写等于伪造历史 | `MaterialMapper.xml` 用 `p.barcode = ps.plate_id` JOIN；若未来只改一侧会断链 |
| D8 | 选位 SQL 用 `LEFT JOIN device_point` + `dp.id IS NULL` 兜底 | 老系统 2563 个点位没有配置行，INNER JOIN 会把它们全排除 | 兜底意味着**未配置点位绕过角色/可达约束**，可能形成安全缺口 |
| D9 | 启动快照是「说明不是闸门」，写失败只告警 | 清单不能因为写不进去就挡住实验 | 每 run 2576 行 append-only，增长与性能未评估 |
| D10 | 源通道方向改 `"out"`，靠 `hasPorts` 兜底 | 20 节点 13 台设备 `device_port` 全为 0 ⇒ 跳过通道锁，零回归 | 也意味着**这条改动在当前环境从未被真正执行到**（零验证） |
| D11 | 不编造机械臂 x/y/z，13 行全标 `pending` | 编坐标会导致撞机 | `robot_point` 暂时不可用于动态规划 |
| D12 | 设计口径**追加而非改写**历史文档 | 保留可追溯性 | 审核时需读追加章节，前几节是旧口径 |

## 8. 请审核 AI 逐条给结论的问题

1. **D1 是否成立**：`DEVICE_REPORT` 加上九项条件，能否算 P-08 要求的「独立位置证据」？
   若不成立，M 方案是否实质上削弱了 fail-closed？恢复门禁保持不动是否只是形式？
2. **原子性**：`noteTransferMove`（位置写入）与 `confirmByDeviceReport`（状态+证据）
   **不在同一个数据库事务**，部分成功会留下什么不一致？是否需要强原子改造？
3. **D8 的安全缺口**：`dp.id IS NULL` 兜底让未配置点位绕过角色/可达过滤，
   在 2563 个老点位存在的情况下，是否会产生「选到机械臂不可达点位」的调度错误？
4. **D7 的 JOIN**：`MaterialMapper.xml` 的 `p.barcode = ps.plate_id` 在引入 alias 后
   是否仍然自洽？扫码后若某处只更新 `position_state.plate_id` 会怎样？
5. **`insertPlateIfAbsent`**：现在把任何未知板落成 `PROVISIONAL` 并写 `TEMP` alias，
   会不会污染 `plate` 表 / 撞 `uk_plate_barcode`？`ON CONFLICT DO NOTHING` 无目标是否掩盖了
   `uk_plate_alias_canonical` 冲突？
