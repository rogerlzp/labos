## 二、意见清单

### R1（P1）决策记录编号体系已坏：D10 重复、D9 乱序

**现象**（`grep -oE "^## D[0-9]+" docs/并发调度决策记录.md`）：

```
## D1 … ## D8
## D10. 三层资源模型 + 等待图死锁检测
## D11 … ## D20. 异步结果查询
## D9.  已知的未做项          ← D9 跑到文档末尾
## D10. 怎么用这份文档         ← 第二个 D10
```

**根因**：插入 D10-D20 时代码用 `replace('## D9. 已知的未做项', new + D9)` 反复在 D9 前
插入，D9 被越推越后；而原"怎么用这份文档"一节恰好也叫 D10，被新 D10 撞号。

**为什么是 P1**：文档内部和评审包、其他文档大量用 `D5` / `D10` 交叉引用。
**两个 D10 意味着"引用 D10"有歧义**；D9 乱序意味着按编号阅读会断。

**处置**：见"被评审方回应"。

### R2（P1）R1（银行家误述）修正不彻底，原文错误表述残留
