## 三、未修复 / 误判 / 修复不彻底（阻塞项）

### 3.1 [P0-11] 角色种子 `code` 不匹配 —— **仍存在**，且被误判为"不存在"

**事实层（确凿）**：

- 种子定义角色：`app_role` 写入 `code = 'admin' / 'operator' / 'viewer'`
  （`pg_rebuild/schema/95_seed_data.sql:20-24`）。
- 装配用户角色：JOIN 条件要求 `code = 'ROLE1' / 'ROLE2' / 'ROLE4'`
  （`pg_rebuild/schema/95_seed_data.sql:71-82`）。
- 全仓 `grep ROLE1|ROLE2|ROLE4` **仅命中 95_seed_data.sql:78-80 与评审文档**（无第三处写入）。
- 本轮 `95_seed_data.sql` 的**唯一改动**是给 `app_user` 插入补 `ON CONFLICT DO NOTHING`
  （`git diff af8d5f3 HEAD -- pg_rebuild/schema/95_seed_data.sql` 已证），**JOIN 一行未动**。

→ **`ROLE1/ROLE2/ROLE4` 在 `app_role` 中永不匹配，`user_role` 装配恒为 0 行。缺陷实体仍在。**

**为何被判"不存在"**：修复方在
`docs/评审记录/20261102-03-code-self.md:472-474`
以 `grep -rn "ROLE1\|ROLE2\|ROLE4" --include=*.java` **零命中**为据，结论"复核后该问题不存在"。
**但 `--include=*.java` 范围错误**——问题在 `.sql`（JOIN 在种子脚本里），Java 侧本就不会出现该字面量。
这是一个**自证陷阱**：用受限范围的 grep 反证"不存在"。

**分层归因（影响层，需被评审方确认）**：
运行时认证走 `sys_user.role` 单列（`labos-kernel/src/main/java/com/labos/kernel/api/AuthService.java:130`），
`app_role/user_role` 这套 RBAC 表**在本仓找不到读取方**。
故原意见"RBAC 完全失效"的**表述应被修正**为更准确的两种表述：
（a）种子装配失效（`user_role` 恒空）；
（b）**两套角色模型并存分裂**（`sys_user.role` vs `app_role/user_role`），与项目"双套路径"病根同源。
无论取哪种表述，**"不存在"的结论都不成立**。

### 3.2 [A1 · 新增] `P0-3` 只建表、未接种子 —— 认证域再现"双套路径"

- 认证读表：`sys_user`（`labos-kernel/src/main/java/com/labos/kernel/api/AuthService.java:73-130`）。

### 3.3 [A2] `P1-4` 修复不彻底 —— 同一判定两处实现，只改了一处
