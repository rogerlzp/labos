## 意见清单

### R1（P1 阻塞级）概念错误：银行家算法的前提不是"可抢占"

**位置**：`设计审核包.md` 风险 3；`并发调度决策记录.md` D12 末节；`暂停恢复与故障处理-设计.md` §七。

**问题**：三处文档都说"银行家算法的前提是资源可抢占，物理世界不允许，所以不能用/失去意义"。**这是对经典算法的误述**。银行家算法恰恰相反——它就是为**不可抢占**资源设计的死锁避免算法：通过拒绝进入不安全状态来避免死锁，全程不发生任何抢占。死锁四条件里"不可抢占"正是死锁存在的条件之一，银行家是在承认不可抢占的前提下做避免。

银行家真正的前提只有两条：
1. **预知每个进程的最大资源需求**；
2. 进程拿到全部所需后会在有限时间内释放全部资源。

**对本项目的影响**：结论（不用银行家）依然成立，但**正确的理由是第 1 条**——流程有分支、无法预知最大需求；而且本项目的资源不是同质可数的（位置有身份、机械臂有空间约束），不符合银行家的"资源实例计数"模型。

**处置要求**：修正三处文档的论证。理由错了，即使结论对，后续实现者会基于错误前提做推断（例如以为"加了抢占就能上银行家"）。

### R2（P1 阻塞级）硬矛盾：D5 回程预留 × D12 暂停释放

**位置**：`并发调度决策记录.md` D5 vs D12；`暂停恢复与故障处理-设计.md` §五"释放资源是必须的"。

**问题**：
- D5：取板时**预留回程位置**，任务全程占用，根治形态 1（回程死锁）。
- D12/暂停恢复 §五：故障暂停时**释放"已占但未用的位置"**，否则拖死全岛。

**回程预留位恰恰是"已占但未用"的位置。** 流程故障暂停 → 按 D12 释放回程位 → 别的流程占用 → 人工恢复后继续运行 → 回程位置没了 → **形态 1 死锁原样复现**，D5 的防护在故障路径下完全失效。

**处置要求**：写代码前必须定义豁免规则。建议：回程预留位（`returnTo` 声明的）在暂停释放规则中**显式豁免**，只允许释放"前瞻预留但未声明 returnTo 的位置"；并在 D5、D12 两处互相引用这条豁免。

### R3（P1 阻塞级）Transfer 的多资源获取顺序没有 invariant，"拒绝"语义在物理世界不成立

**位置**：`资源模型与死锁避免-设计.md` §二、§三。

**问题**：一次 Transfer 实际要同时持有 **L3 机械臂 + 源 L2 + 目标 L2 + 目标 L1（+ D5 的回程 L1）**。现有 `tryReserveTransfer` 只对两个位置按 id 升序，**跨资源类型的获取顺序没有任何规定**。

更严重的是时序：如果实现成"机械臂先抓板（已持有 L3、板已离源位）→ 再申请目标 L1/L2 → 被等待图拒绝"，此时**板已经在臂上**，"拒绝这次申请，返回失败重试"在物理上无法执行——板不能悬停。

**处置要求**：设计必须补一条硬 invariant：**所有资源申请完成前，板不离开源位置（先申请、后抓取）**；并定义五类资源的固定获取顺序（建议 L3 → 源 L2 → 目标 L2 → 目标 L1 → 回程 L1，全程按同一拓扑序）。等待图是兜底，不是获取顺序的替代品。

### R4（P1 严重）等待图粒度与并行网关矛盾；`auto` 开关引入竞态

**位置**：`资源模型与死锁避免-设计.md` §五；`并发调度决策记录.md` D10"优化"节。

**问题**：
1. 等待图的节点是 run，但 D6 允许单 run 内并行网关的多个分支**并发抢资源**。run 级等待图无法表达 run 内分支互等——要么误判自环，要么漏检。
2. `LABOS_DEADLOCK_GUARD=auto` 用 `running > 1` 判断，恰好把"单 run 内并行"排除在检测之外。审核包把 `hasParallelNode` 列为"可选更精确"——**它不是可选，是必须**。
3. COUNT 判断有真实竞态：两个 run 同时启动，各自都看到 `running = 1`，都关掉检测。

**处置要求**：建议**删掉 auto，检测常开**。作者自己算过开销是微秒级——开关省下的是微秒，引入的是竞态 + 漏检 + 一个需要运维理解的配置项。等待图节点应改为"执行分支（execution branch）"而非 run。

### R5（P1 严重）被拒后的活锁/饿死没有答案

**位置**：`资源模型与死锁避免-设计.md` §六 第二批"被拒后等 200ms 重试，最多 N 次"。

**问题**：被拒者重试时环大概率还在（环上的持有者还没走完），会**反复被拒**。设计未给出：
- 退避策略（固定 200ms 会同步震荡）；
- 老化机制（等得久的优先放行，否则某个流程可能永远是被拒的那个——等待图天然偏袒先到者）；
- N 次耗尽后的处置（失败？升级告警？转 `waiting_human`？）。

**处置要求**：补拒绝后的完整策略。最低限度：指数退避 + 按等待时长老化 + 耗尽后转 `waiting_human` 并告警（与 D14 状态机衔接）。

### R6（P2 一般）L2 出入口"穿过"的终点事件未定义

### R7（P2 一般）板 UNKNOWN 后的资源传播规则缺失

**位置**：`暂停恢复与故障处理-设计.md` §四；`并发调度决策记录.md` D13。

**问题**：板标 UNKNOWN 后，设计只说"暂停所有涉及这块板的流程"，但**没说它可能占据的物理空间怎么办**——源位、目标位、机械臂工作空间。其他流程可能往"可能压着一块板"的位置放新板，造成物理碰撞。

## 对"是否过度设计"的独立判断

作者的自我质疑是真诚的，也是对的：**"一天并行几个实验"是本案第一问题**，应先于一切技术讨论。补充一个作者没提的视角：

**即使答案真是 1-2 个并行，D5（returnTo）也不能砍。** 2 个并行就足够触发形态 1（回程死锁）——文档自己的推演就是 2 个实验。所以砍的候选是 D10（等待图）、D11-D14 的一部分，**D5 是 2 并行场景的最低配置**，它在"砍"名单里的位置要拿出来。

建议的决策树：
- 并行 ≤ 1：D1-D4 已够，D10-D14 全部搁置；
- 并行 2-3：**D5 必做**，D10 等待图可降级为"超时 + 告警"（形态 2 在 2 并行下不构成环，3 并行才需要环检测）；
- 并行 ≥ 4：全套有必要。
