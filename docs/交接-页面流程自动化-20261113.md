真实触发 React `onDragStart` → `onDropMethod`（不是注入建模）：

```python
# 1) 展开设备（palette 显示的是设备 code，不是 resource_id）
pg.click('[data-testid="palette-device"]:has-text("ID-X231")', force=True)
pg.wait_for_function(
  "() => !!document.querySelector('[data-testid=\"palette-method\"]"
  "[data-method=\"Transfer\"][data-resource-id=\"200231\"]')", timeout=8000)
# 2) 触发真实拖放：dragstart 设 dataTransfer → drop 到画布
pg.evaluate("""() => {
  const dt = new DataTransfer();
  const src = document.querySelector('[data-testid="palette-method"][data-method="Transfer"][data-resource-id="200231"]');
  src.dispatchEvent(new DragEvent('dragstart', {dataTransfer: dt, bubbles: true, cancelable: true}));
  const cv = document.querySelector('.djs-container');
  const r = cv.getBoundingClientRect();
  cv.dispatchEvent(new DragEvent('drop', {dataTransfer: dt, bubbles: true, cancelable: true,
    clientX: r.left + 500, clientY: r.top + 260}));
}""")
```

要点：
- `dataTransfer` 在 `dragstart` 里由 React 的 `onDragStart` 写入 `application/x-labos-method`
  （payload = `{resourceId, code, method, capability, icon, islandId, islandCode}`），
  `drop` 事件会冒泡到 React `onDropMethod`。
- 这样节点会走真实 `onDropMethod`：写 `$attrs.protocolName/resource/methodParams/icon`、
  自动插机械臂 Transfer、自动连线、草稿落库。

## 四、卡住的问题（这是要接续的点）

### 问题 A：拖入的方法没有插进 S→E 线，成了孤立节点（用户指出的关键 bug）
- **现象**：页面新建流程默认只有 `S → E` 一条线（backend 初始化了 start+end+直连）。
  拖入一个设备方法后，`onDropMethod` 里 `lastDroppedRef` 为 null（第一次拖），
  **不会自动连线** → 方法节点浮在画布外，`S → E` 直连还在 → 不合法流程。
  当前 1000798/1000799/1000800 都是这个坏状态（3 节点 1 边：S→E + 孤立 Transfer）。
- **已做的修正**（在 `scripts/s2-page-transfer.py`）：拖入后手动删 S→E、连 S→T→E：
  ```python
  pg.evaluate("""() => {
    const m=window.__bpmnModeler, reg=m.get('elementRegistry'), modeling=m.get('modeling');
    const S=reg.getAll().find(e=>e.type==='bpmn:StartEvent');
    const E=reg.getAll().find(e=>e.type==='bpmn:EndEvent');
    const T=reg.getAll().find(e=>e.type==='bpmn:Task' && e.businessObject.name==='Transfer');
    for (const f of reg.getAll().filter(e=>e.type==='bpmn:SequenceFlow')) {
      const bo=f.businessObject;
      if (bo.sourceRef.id===S.id && bo.targetRef.id===E.id) modeling.removeElements([f]);
    }
    modeling.connect(S,T); modeling.connect(T,E);
  }""")
  ```
- **这是页面行为本身的设计缺口**：产品上应考虑「拖入第一个方法时自动插入 S→E 之间」
  （类似 `onDropMethod` 已做的设备间自动插机械臂 Transfer）。可做为后续产品改进，
  但当前自动化里先用上面的手动连线绕过。

### 问题 B：参数面板的 source/target 选择（antd Select）没调通
- **流程**：新拖的节点还没进库 → 右栏显示「不在编译结果里」+「保存并继续设置」按钮；
  点该按钮 → 保存 + 刷新 compile → 参数卡片才出现 source/target 两个 Select。
- **实测 Select 下标（在已保存流程 1000798 上，选中 Transfer 后 dump 得到）**：
  `.ant-select` 共 8 个：`0=语言(中文) 1=岛 2/3=(流程选项) 4=方法(Transfer·Transfer)
  5=seal_state(none) 6=source(占位 Location) 7=target(占位 Location)`。
  **所以 source/target 是 index 6、7**，不是 2、3。选项用
  `.ant-select-item-option:has-text("ID-ASPIN_2K-1")` 匹配。
- **卡点 1**：「保存并继续设置」按钮是**瞬态**的：`!plan` 分支才渲染，但
  `onDropMethod` 拖入后立即 `persistAfterDrop` 草稿落库 + 刷新 compile，节点很快进 `plan`，
  按钮就换成完整 NodeSettings 了 → `get_by_role` 常超时。
  **绕法**：别点「保存并继续设置」，直接点主「保存」按钮（`button.ant-btn-primary:has-text('保')`）
  → compile 刷新 → 参数面板出现 → 再选 index 6/7。
- **卡点 2**：source/target 是 `control_type=select`，但 `param_schema` 里 `default="Location"`，
  `missingRequired` 会被 default 回填骗过（source=target="Location" 也算已填）。
  所以保存不会被必填拦下，但会带 `Location` 假值落库。**选真实值时用 index 6/7**。
- **卡点 3**：`modeling.connect` 后要重新 `m.get('selection').select(T)`，否则 React `selected`
  被清掉、右栏不显示该节点。
- **卡点 4**：`pick(6, ...)` 偶发「element is not visible」——index 6 的 Select 在已保存流程上
  是可见的，但若前面任何一步导致面板重渲染（如保存/compile 刷新），下标会变。
  **建议改用更稳的选择器**：按参数名定位，例如先找含 `source` 文本的 `.ant-form` 块，
  再取块内 `.ant-select`（而不是全局 nth）。

## 六、已发现的关键 bug（页面拖 vs 脚本生成对比，用户点名要研究的）

1. **脚本直存 XML（无 DI）→ 设计器「no diagram to display」**：`GET /api/workflows/{id}/graph`
   原样返回存的 XML；没有 `<bpmndi:BPMNDiagram>` 段时 bpmn-js 画布为空
   （root 变 `__implicitroot_0`）。脚本生成必须带 DI，或用页面拖。
2. **页面 auto-connect 在分支场景产生多余边**：连续拖两个设备方法，`onDropMethod`
   会 `modeling.connect(prev, cur)`，即便它们是 XOR 分支也会多一条 R1→R2。
3. **XOR 分叉无条件/默认边时引擎跑所有分支**（语义等同并行）：1000790 的 XOR split
   两条出边都执行了。要给 XOR split 设 default 或条件。
4. **新流程默认 S→E + 拖方法不自动插线**（见问题 A）。
5. **保存按钮文案是「保 存」**（antd 两汉字自动加空格），选择器不能用 `保存`。
6. **新拖节点参数面板不直接出现**，要先「保存并继续设置」（见问题 B）。
