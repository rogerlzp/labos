# 03 · 设备命令生命周期验收（第一版 · 字段级清单）

> 接 02 §2.3。本文把命令生命周期细化到表/字段级证据 + 测试方法。
> 设计要求：`runtime-consistency/02`（五态 + UNKNOWN + 幂等 + 超时查询）。

## 3.1 现状证据（字段级）

| 字段/表 | 现状 | 设计要求 | 判定 |
|---|---|---|---|
| `run_command.status` | 只有 INSERT，无 UPDATE（步结束才落一行） | 五态可观测推进 | **GAP** |
| `run_command.sent_at` | 有（下发时刻） | 保留 | PASS |
| `run_command.finished_at` | 有（回包时刻） | 保留 | PASS |
| `execution_resolution_status` | 有 completed/failed/unknown | 保留 + UNKNOWN 一等 | PARTIAL |
| `device_method.interruptible` | 有 | Abort 契约 | PASS |
| `device_state.current_run_id` | 有（设备锁） | 命令与设备占用一致 | PARTIAL |
| 幂等键 | `(run_id, node_key, attempt, loop)` | 加 `command_id` | PARTIAL |

## 3.2 测试方法（实现期补）

| 场景 | 测试方法 | 当前是否有 |
|---|---|---|
| 命令中间态推进 | 模拟器回 ACK→执行→完成，断言 `run_command.status` 逐步变 | ❌ 无 |
| 超时→查询→UNKNOWN | 模拟器不回包，断言先查询再落 unknown | ❌ 无 |
| 重复命令幂等 | 同 command_id 重发，断言设备只执行一次 | ❌ 无（有 `DeviceDriverAbortContractSelfTest` 覆盖 abort，非命令幂等） |
| 设备报告 vs 中控冲突 | 注入矛盾回包，断言转人工不自动覆盖 | ❌ 无 |

## 3.3 结论

- 命令生命周期是**实现期第一批**，依赖模拟器能回 ACK/执行/完成三态。
- 现有 `run_command` 的「只 INSERT」结构要在实现期补状态列（或新表），这是 02 §2.3 GAP 的根。
