## 4. 下阶段工作（四步，串行）

> 遵循评审「先修测试 → 再定状态一致性 → 再物料/搬运 → 最后系统可靠性」的顺序，不并行开工。

### 步骤 1：测试体系最后修正（收尾）

- 复核 8 个 verify 脚本全部连跑两次 + 终态 `plan=0/booking=0/stale=0`（门槛已可执行）。
- 补 `stale-auto-dismiss` 的负向用例：`autoDismissDays=0` 时不误清 `paused_fault` / `paused_unknown`。
- 交付：`docs/系统可靠性验收/06-测试矩阵与验收标准.md`（把「已通过/已实现未验证/未覆盖/不适用」四态固化）。

### 步骤 2：实验与设备状态一致性（最高优先级）

- 以 `runtime-consistency/01-03` 为设计要求，逐条落「当前实现 + 证据 + 测试方法 + 判定」。
- 核心三题：① 暂停命令发出 ≠ 设备已暂停；② 命令 sent/received/executing/done 中间态；③ 状态冲突以设备为准。
- 交付：`docs/系统可靠性验收/02-实验与流程状态一致性.md` + `03-设备命令生命周期验收.md`。

### 步骤 3：物料、位置与搬运一致性

- 以 `runtime-consistency/04` 为设计要求，重点「一个物料不能占两个位、搬运成功≠到位、中途失败可识别真实位置」。
- 交付：`docs/系统可靠性验收/04-物料与位置一致性验收.md`。

### 步骤 4：系统运行可靠性

- 事务并发、服务重启恢复、设备离线、审计、迁移兼容、真实设备端到端。
- 交付：`docs/系统可靠性验收/05-异常恢复与并发验收.md` + `07-遗留风险清单.md`。
