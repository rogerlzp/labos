# 04 · 物料与位置一致性验收（第一版 · 问题清单）

> 设计要求：`runtime-consistency/04`（四态 + 谁写 + 封锁）。
> 判定口径同 02。

## 4.1 位置状态模型

| 问题 | 设计要求 | 当前实现 | 证据 | 判定 |
|---|---|---|---|---|
| 位置四态 | `KNOWN / IN_TRANSIT_UNCONFIRMED / UNKNOWN / ABSENT` | 有 `KNOWN` / `UNKNOWN`，无 `IN_TRANSIT_UNCONFIRMED` 一等态 | `plate.position_status` | PARTIAL |
| 命令成功 ≠ 到位 | `position_state` 只能由「确认」写 | `TransferTransaction` 已分 report / confirm | `TransferTransaction.confirmByDeviceReport` | PASS |
| 一个物料不占两个位 | 位置唯一 | `position_state` 主键 `(tenant, resource_id)` + `ix_pos_plate` | 表结构 | PASS |
| 一个位置不混放 | 板型/高度校验 | `checkPlateFits`（内部搬运） | `PositionLock` + `verify-internal-transfer` | PASS |

## 4.2 搬运一致性

| 问题 | 设计要求 | 当前实现 | 证据 | 判定 |
|---|---|---|---|---|
| 搬运中间态 | 发命令 → `IN_TRANSIT_UNCONFIRMED` | 无此中间态；自动确认或保持 REPORTED | `TransferTransaction.report` | **GAP** |
| 搬运失败可识别 | 板标 UNKNOWN + 封锁可能位置 | `markPlateUnknown` 已封锁源/目标/臂 | `PauseManager.markPlateUnknown` | PASS |
| 失败不提前改终位 | 中途失败不改 final 位置 | `noteTransferMove` 只在确认后写 | `PositionLock` | PASS |
| 生命周期卸载也走确认 | 卸载 = 确认后清位置 | §4.5.2 卸载已按 process/inventory 判别 | `verify-material-lifecycle` | PASS |

## 4.3 结论

- 核心 GAP：**缺少 `IN_TRANSIT_UNCONFIRMED` 中间态**——「已发命令、未确认到位」这段时间板的状态与「还在原位」无法区分。
- 这是实现期第二批（物料/搬运一致性）的第一项改动：加中间态枚举 + 调度/暂停在涉板时先确认。
