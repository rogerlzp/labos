# 04 · 物料与位置一致性验收（第一版 · 问题清单）

> 设计要求：`runtime-consistency/04`（四态 + 谁写 + 封锁）。
> 判定口径同 02。

## 4.1 位置状态模型

| 问题 | 设计要求 | 当前实现 | 证据 | 判定 |
|---|---|---|---|---|
| 位置四态 | `KNOWN / IN_TRANSIT_UNCONFIRMED / UNKNOWN / ABSENT` | 实测有 `IN_TRANSFER`(4) / `KNOWN`(9)：**在途态已存在**，但无「未确认到位」语义且未接入调度/暂停，不是从零新增枚举 | `plate.position_status`（DB 取值） | PARTIAL |
| 命令成功 ≠ 到位 | `position_state` 只能由「确认」写 | `TransferTransaction` 已分 report / confirm | `TransferTransaction.confirmByDeviceReport` | PASS |
| 一个物料不占两个位 | 位置唯一 | `position_state` 主键 `(tenant, resource_id)` + `ix_pos_plate` | 表结构 | PASS |
| 一个位置不混放 | 板型/高度校验 | `checkPlateFits`（内部搬运） | `PositionLock` + `verify-internal-transfer` | PASS |

## 4.2 搬运一致性

| 问题 | 设计要求 | 当前实现 | 证据 | 判定 |
|---|---|---|---|---|
| 搬运中间态 | **发出搬运命令时**置「在途未确认」（设计 04 §1/§2 已统一） | 有 `IN_TRANSFER` 但语义是「在途」而非「未确认到位」，且未接入调度/暂停；发命令到 DONE 之间状态不可判定 | `plate.position_status` 取值 → `TransferTransaction.report` | **GAP** |
| 搬运失败可识别 | 板标 UNKNOWN + 封锁可能位置 | `markPlateUnknown` 已封锁源/目标/臂 | `PauseManager.markPlateUnknown` | PASS |
| 失败不提前改终位 | 中途失败不改 final 位置 | `noteTransferMove` 只在确认后写 | `PositionLock` | PASS |
| 生命周期卸载也走确认 | 卸载 = 确认后清位置（`runtime-consistency/04 §4`） | **评审改判**：`unloadProcessMaterials` 直接 `clearProcessPositionStates` + `markProcessPlacementsUnloaded`，无设备确认环节；`verify-material-lifecycle` 只验 process/inventory 判别性，**不覆盖确认链** | `ExperimentTemplateController.unloadProcessMaterials` | **GAP** |

## 4.3 结论

- 核心 GAP 一：`IN_TRANSFER` 已有，但**缺「未确认到位」语义与调度/暂停接入**——「已发命令、未确认到位」这段时间板仍被当成可用。实现期在现有枚举上收口语义，不另开并行值。
- 核心 GAP 二：**生命周期卸载没有确认链**——`process` 物料卸载直接清 `position_state`，与设计要求「卸载也要确认」不符。`verify-material-lifecycle 5/0` 是判别性通过，不能当作本项 PASS 的证据。
- 两处 GAP 一并登记进 `07-遗留风险清单.md`，作为实现期第二/三批的输入。
