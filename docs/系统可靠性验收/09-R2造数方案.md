# 09 · R2 造数方案：批次实验「整单聚合终态才卸载」端到端验收

> 目的：给**另一个 AI / 执行者**一份可直接照做的造数方案，补齐 R2（08 §5 的阻塞项）。
> 背景：`MaterialUnloadPathsDbSelfTest` 已用**合成负数 id** 覆盖两条卸载路径（15/0），
> 但那是"直接调 `settle` / `syncExperimentStatusFromBatches` + 手工改状态"，
> **没有验证真实批次流程**（`batch-split → runBatch ×2 → 自动聚合 → 卸载`）。
> 本方案补的就是这一段：真实流程下，"只完成 1 批不得卸载"这个反例必须成立。

---

## 0. 一句话目标

造一个 **2 批**的实验，第 1 批正常跑完时**不得**卸载（实验仍未终态）；
第 2 批也跑完后，`process` 物料才进入 `unloading`，确认后清位置；`inventory` 全程原位不动。

---

## 1. 验收判据（按顺序断言）

| # | 时机 | 断言 | 判定方式 |
|---|---|---|---|
| 1 | 第 1 批 run 终态、实验仍 running | `experiment.status` ≠ `finished` | API `/api/experiments/{id}` 或 SQL |
| 2 | 同上 | `manifest_placement.status` 仍为 **`loaded`**（**不得** `unloading`） | SQL |
| 3 | 第 2 批 run 终态 | `experiment.status` = `finished`（或 `failed`，取决于流程结果） | 同上 |
| 4 | 同上 | `process` 物料 placement → **`unloading`**，且 `position_state` **仍占用** | SQL |
| 5 | 调 `confirm-unload` 后 | placement → **`unloaded`**，`position_state` **清空** | SQL |
| 6 | 全程 | `inventory` 物料 placement 仍 `loaded`、位置仍占用 | SQL |

> 判据 2 是**判别性核心**：只完成 1 批就卸载 = "见一个终态就卸"的 bug，合成自测抓不到，
> 真实流程也不一定抓得到（取决于是否真的等聚合）。必须显式断言。

## 3. 数据模型（造数要碰的表）

```
experiment            (id, experiment_no, name, batch_split, status, run_id)
  └ experiment_batch  (id, experiment_id, batch_no, sample_count, samples, status)
      └ experiment_batch_run (id, batch_id, experiment_run_id, attempt_no, status)
          └ experiment_run   (id, experiment_id, status, control_state)
              └ manifest_placement (id, run_id, manifest_item_id, position_id, status)  ← loaded/unloading/unloaded
                  └ manifest_item   (id, template_id, material_kind, material_ref)
                      ├ plate      (id, barcode, lifecycle, position_status)  ← process / inventory
                      └ position_state (resource_id, plate_id, content_id, occupied_by_run)
```

关键口径：
- **卸载触发点是 `experiment` 的聚合终态**，不是单个 `experiment_run` 终态（批次路径）。
- 聚合口径：`experiment_batch` 全部终态（`completed/failed/aborted`）才聚合；
  任一 `running/paused/queued/pending` ⇒ 不卸载。
- `experiment_batch.status` 与 `experiment_batch_run.status` 是两层，**两层都要终态**。

## 4. 两条造数路径

### 方案 A：合成数据（10 秒，稳定，覆盖 "聚合终态才卸载" 逻辑）

直接复刻 `MaterialUnloadPathsDbSelfTest.batchPathWaitsForAggregateTerminal`（第 152 行起）：

1. INSERT 负数 id：`experiment(-994012)`、`experiment_batch(-994025/-994026)`、
   `experiment_batch_run`、`experiment_run(-994014/-994015)`、
   `manifest_item`、`manifest_placement`（`loaded`）、`position_state`、`plate`
2. 把批次 1 置终态（run/batch/batch_run 三层都 `completed`），批次 2 保持 `running`
3. 调 `BatchOrchestrator.syncExperimentStatusFromBatches(experimentId)`
4. 断言：placement **仍 `loaded`**（不得 unloading）
5. 把批次 2 置终态，再调一次
6. 断言：placement → `unloading`，位置仍占用
7. 调 `confirmUnload` → `unloaded` + 位置清空

**优点**：不依赖模拟器/设备，可进 CI；**缺点**：不验证"真实跑完一批时是否真的不会提前卸载"。

## 5. 造数 SQL 模板（按需替换 `<...>`）

```sql
-- 点位（取两个空闲的）
SELECT dp.id AS point_id, dp.point_resource_id
  FROM device_point dp
  LEFT JOIN position_state ps
    ON ps.resource_id = dp.point_resource_id AND ps.tenant_id = 1
 WHERE ps.resource_id IS NULL
    OR (ps.plate_id IS NULL AND ps.content_kind IS NULL AND ps.occupied_by_run IS NULL)
 ORDER BY dp.id LIMIT 2;

-- 板（process / inventory 各一）
INSERT INTO plate (tenant_id, barcode, lifecycle, position_status)
VALUES (1, 'R2-PROC', 'process',   'KNOWN'),
       (1, 'R2-INV',  'inventory', 'KNOWN')
RETURNING id;

-- manifest_item（模板 id 用真实模板）
INSERT INTO manifest_item (tenant_id, template_id, role_code, material_kind, material_ref)
VALUES (1, <TPL_ID>, 'PLATE-P', 'plate', <PLATE_PROC_ID>),
       (1, <TPL_ID>, 'PLATE-I', 'plate', <PLATE_INV_ID>)
RETURNING id;

-- placement：两批都要挂（run_id 分别是两批的 experiment_run.id）
INSERT INTO manifest_placement (tenant_id, run_id, manifest_item_id, position_id, status)
VALUES (1, <RUN_BATCH1>, <MI_PROC>, <POINT1>, 'loaded'),
       (1, <RUN_BATCH1>, <MI_INV>,  <POINT2>, 'loaded');
-- 第 2 批同理（若要"两批共用同一块板"，则只挂一批，按业务口径定）

-- 位置占用
INSERT INTO position_state (tenant_id, resource_id, plate_id, content_kind, content_id, occupied_by_run)
VALUES (1, <RES1>, 'R2-PROC', 'plate', <PLATE_PROC_ID>, <RUN_BATCH1>),
       (1, <RES2>, 'R2-INV',  'plate', <PLATE_INV_ID>,  <RUN_BATCH1>)
ON CONFLICT (tenant_id, resource_id) DO UPDATE
  SET plate_id = EXCLUDED.plate_id, content_kind = EXCLUDED.content_kind,
      content_id = EXCLUDED.content_id, occupied_by_run = EXCLUDED.occupied_by_run;
```

## 6. 断言查询（可直接复制）

```sql
-- 判据 2/4：process 物料当前 placement 状态
SELECT mi.role_code, mp.status
  FROM manifest_placement mp JOIN manifest_item mi ON mi.id = mp.manifest_item_id
 WHERE mp.run_id IN (SELECT id FROM experiment_run WHERE experiment_id = <EXP_ID>)
 ORDER BY mi.role_code;

-- 判据 2/4：process 点位是否仍占用
SELECT ps.resource_id, ps.plate_id, ps.occupied_by_run
  FROM position_state ps
 WHERE ps.plate_id IN ('R2-PROC', 'R2-INV');

-- 判据 1/3：实验聚合状态
SELECT status, batch_split FROM experiment WHERE id = <EXP_ID>;
SELECT batch_no, status FROM experiment_batch WHERE experiment_id = <EXP_ID> ORDER BY batch_no;
```

## 7. 清理（必须执行）

```sql
DELETE FROM manifest_placement
 WHERE run_id IN (SELECT id FROM experiment_run WHERE experiment_id = <EXP_ID>);
DELETE FROM experiment_batch_run
 WHERE batch_id IN (SELECT id FROM experiment_batch WHERE experiment_id = <EXP_ID>);
DELETE FROM experiment_batch  WHERE experiment_id = <EXP_ID>;
DELETE FROM experiment_run    WHERE experiment_id = <EXP_ID>;
DELETE FROM manifest_item     WHERE material_ref IN (SELECT id FROM plate WHERE barcode LIKE 'R2-%');
DELETE FROM position_state    WHERE plate_id LIKE 'R2-%';
DELETE FROM plate             WHERE barcode LIKE 'R2-%';
DELETE FROM experiment        WHERE id = <EXP_ID>;
```

> 顺序：placement → batch_run → batch → run → item → position_state → plate → experiment。
> 用 `R2-` 前缀，避免和 `VERIFY-LC-%` / `VERIFY-R6-%` 等自测数据混淆。

## 8. 已知坑（先看，省时间）

1. **`out/` 资源可能旧**：改过 mapper XML 后必须跑 `scripts/sync-resources.sh`（或 `test-all.sh` / `build-kernel.sh`），
   否则报 `BindingException: Invalid bound statement`（2026-11-15 实测）。
2. **内核在线别跑连库自测**：调度循环会抢 queued run / Outbox 事件。
3. **`unloading` 没有超时兜底**：自动路径只发请求，确认必须手工调 `confirm-unload`；
   若忘记确认，物料会长期停在 `unloading` 且位置占用。
4. **批次聚合是"所有批次终态"**，不是"最后一批终态"：任何一批 `paused` 都会卡住聚合。
5. **两批的 manifest 要不要共用同一块板**：按业务口径定。共用时第 2 批跑完不能重复搬同一块板，
   建议两批各用一块 process 板，或第 2 批只跑 inventory 板。
