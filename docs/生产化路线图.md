# 生产化路线图

> 回答一个问题：**从现在的实现基线，到真正能上生产、达到同类商业产品水平，还差多少？**

---

## 一、现状盘点

### 已经能做的

| 能力 | 成熟度 | 证据 |
|---|---|---|
| **流程编排** | 可用 | BPMN 图解析、并行/异或/回环、设备+变量+循环画布 |
| **流程执行** | 可用（仿真） | 全部流程在虚拟总线上走通，无环无孤立节点 |
| **多实验并行** | 基础可用 | 岛级互斥 + EDD 排序 + 排队 |
| **板位追踪** | 可用 | 位置级原子抢占、搬运双锁、三色可视化 |
| **设备驱动框架** | 框架完整 | 短/长连接、契约校验、探针、Mock |
| **崩溃恢复** | 基础可用 | 幂等键、启动收尾 |
| **告警** | 可用 | 生成/去重/合并 |
| **执行追溯** | 可用 | 命令级存参数、原文、设备、耗时 |

### 还不能做的

| 缺口 | 影响 | 严重度 |
|---|---|---|
| **没接过真设备** | 所有"通过"都是仿真结论 | 🔴 极高 |
| **没有排程甘特/可视化排程** | 只能按优先级排队，不能人工调整 | 🟠 高 |
| **没有审计与合规** | 制药/临床场景无法过审 | 🟠 高 |
| **长任务（孵育 30 分钟）会误判超时** | 真机上直接失败 | 🔴 极高 |
| **没有性能基线** | 不知道 10 个实验并行会不会卡 | 🟡 中 |
| **没有权限细分** | 只有登录，没有"谁能改流程" | 🟡 中 |
| **没有报表/BI** | 利用率、周转时间只能查库 | 🟡 中 |
| **单实例** | 中控挂了全线停 | 🟡 中 |

## 二、差距分析：对标商业产品

按能力维度拆，标注"我们有什么、缺什么"。

### 2.1 流程编排

| 商业产品有 | 我们 | 差距 |
|---|---|---|
| 图形化拖拽编排 | ✅ 双画布（实验 / 岛屿） | — |
| 变量与循环 | ✅ 变量表格 + `${var}` + 循环列 | — |
| 分叉/并行/汇合 | ✅ 四种节点型状区分 | — |
| 流程模板库 | ⚠️ 有流程库，无模板市场 | 中 |
| 版本管理与回滚 | ❌ | **缺** |
| 流程仿真预览 | ✅ 影子模式 | — |

**结论**：编排能力**接近**商业产品，缺**版本管理**。

### 2.2 调度排程

| 商业产品有 | 我们 | 差距 |
|---|---|---|
| 多实验并行 | ✅ 岛级互斥 | — |
| 优先级 + 截止时间 | ✅ EDD | — |
| **甘特图可视化** | ❌ | **缺** |
| **手动拖拽调整排程** | ❌ | **缺** |
| 资源日历（设备维护窗口） | ⚠️ 表存在，未用 | 中 |
| 滚动时域重排 | ❌ 只有贪心 | **缺** |
| 利用率分析 | ⚠️ 只能查库 | 中 |

**结论**：调度是**最大的能力差距**。商业产品的卖点就是"看得见的排程"。

### 2.3 设备接入

| 商业产品有 | 我们 | 差距 |
|---|---|---|
| 驱动框架 | ✅ 能力声明 + 契约 | — |
| 内置驱动库（几百种设备） | ❌ 只有框架 | **缺**（需逐个接） |
| 驱动热插拔 | ❌ | 中 |
| 设备自检/校准 | ❌ | 中 |
| 协议调试工具 | ✅ 探针 + Mock | — |

**结论**：**框架有了，驱动库是体力活**——每接一台设备 1-3 天。

### 2.4 板位与样本

| 商业产品有 | 我们 | 差距 |
|---|---|---|
| 板位级追踪 | ✅ 位置级抢占 | — |
| 板号追踪（条码） | ✅ 三级解析 | — |
| 样本级追踪（孔位） | ⚠️ 表有，未用 | 中 |
| 板位可视化 | ✅ 三色 | — |
| 冷链/时效追踪 | ❌ | 低 |

**结论**：板位这块**不落后**。

### 2.5 运维与合规

| 商业产品有 | 我们 | 差距 |
|---|---|---|
| 执行追溯 | ✅ 命令级 | — |
| **审计日志（谁改了什么）** | ⚠️ 部分 | **缺** |
| **电子签名（21 CFR Part 11）** | ❌ | **缺** |
| 数据完整性校验 | ❌ | 中 |
| 告警与通知 | ✅ | — |
| 报表导出 | ❌ | 中 |
| 多租户隔离 | ⚠️ 有 tenant_id，未验证 | 中 |

**结论**：**合规是进制药行业的硬门槛**，现在过不了。

## 三、分阶段路线

### P0：能跑起来（2-3 周）

**目标**：一台真设备、一条流程、一次真实执行。

| 任务 | 估时 | 状态 |
|---|---|---|
| 修长任务超时（`method_status=1` 继续等） | 2 天 | **✅ 已完成** |
| 每台设备一个模拟器（本机仿真全岛） | 3 天 | **✅ 已完成** |
| 设备心跳 + 三态 + 离线告警 | 2 天 | **✅ 已完成** |
| 写现场部署手册 | 1 天 | **✅ 已完成** |
| 接第一台真设备（选最简单的，如孵箱） | 2 天 | ⬜ 待现场 |
| 全端点探针跑一遍，确认契约 | 1 天 | ⬜ 待现场 |
| 单流程实跑（2-3 个节点） | 2 天 | ⬜ 待现场 |
| 修实跑暴露的问题 | 3-5 天 | ⬜ 未知，取决于问题多少 |

**剩余工作量：约 1.5-2 周**（都需要现场设备和网络）。

**P0 结束标志**：

```
一条真实流程在真设备上跑通，run_command 里有真实原文和耗时
```

## 三之前：现在能跑什么（本机仿真已闭环）

在等现场设备期间，这些**现在就能跑通**：

| 环节 | 怎么跑 | 验证什么 |
|---|---|---|
| **起全岛模拟器** | `./scripts/sim-up.sh LAB-DEMO-02 150` | 7 台设备各占一个端口 |
| **驱动注册** | 启动日志 | `[驱动] DRV-SIM-ID1183 → tcp://127.0.0.1:19501` |
| **心跳探活** | `GET /api/heartbeat` | 在线/离线状态 |
| **流程执行** | `POST /api/workflows/239/run` | 每台设备收到自己的命令 |
| **运行中状态** | 界面设备卡片 | 黄灯 + 方法名 |
| **离线告警** | 杀掉一台模拟器，等 40 秒 | 只报那一台，恢复后自动关 |
| **长任务** | `--long` 参数 | 先回运行中再回完成，不误判 |
| **设备慢** | `--delay 5000` | 超时设置够不够 |
| **间歇故障** | `--fail 3` | 重试逻辑 |
| **设备离线** | `--offline` 或 kill | `EC-05-1006` + 告警 |

**这一层已经能回答"逻辑对不对"**，剩下的只有物理约束和厂商 DLL 的边界情况。

## 五、最关键的三个判断

### 1. 仿真通过 ≠ 能上生产

现在所有"通过"都是虚拟总线上的结论。**真机会暴露一堆问题**：
驱动字段名不对、超时设置不合理、机械臂点位不准、设备响应比预期慢。

**P0 那 2-3 周的估时，一半是"修实跑暴露的问题"**——具体多久取决于运气。

### 2. 排程可视化是"看起来专业"的分水岭

商业产品的演示里，最抓眼球的是**甘特图**。
我们现在只能按优先级排队，用户看不到"为什么这个实验排在后面"。

**P2 的 2-3 周甘特图，是投入产出比最高的一项**。

### 3. 合规是行业门槛，不是加分项

如果要进制药/临床，**P3 绕不过去**。
但如果只做科研实验室/高校，**P3 可以不做**——这取决于目标客户。

## 六、建议的下一步

**按 P0 走，先接一台真设备。**

理由：
1. 现在所有结论都是仿真的，**越早接触真机越早发现真问题**
2. P0 只需要 2-3 周，风险可控
3. 真机跑通后，才知道 P1 的估时靠不靠谱

**具体第一件事**：

```bash
# 1. 改驱动端点配置
vi labos-kernel/sidecar-dotnet/appsettings.json

# 2. 起 Sidecar
cd labos-kernel/sidecar-dotnet && dotnet run -c Release

# 3. 探针验证（最安全的第一步）
curl -X POST "/api/shadow/probe?resourceId=<设备id>&method=Home"

# 4. 契约四项全 true 后，再跑单流程
```

## 七、和同类产品的差距一句话总结

| 维度 | 差距 |
|---|---|
| **流程编排** | 接近（缺版本管理） |
| **板位追踪** | 不落后 |
| **执行追溯** | 不落后（命令级存原文是优势） |
| **调度排程** | **明显落后**（无甘特、无手动调整、无滚动重排） |
| **驱动库** | **明显落后**（有框架无设备） |
| **审计合规** | **明显落后**（进不了制药） |
| **报表分析** | 落后 |

**我们的优势**：内核干净、可仿真、命令级可追溯、单机部署轻。
**我们的短板**：没接真机、没有排程可视化、没有合规能力。

**先把 P0 做完，再谈对标。**
