# 系统重构 · 设计文档（对标 外部厂商A / 外部厂商B）

> 承接 `private/对标-商用调度平台/`（分析稿）。
> 本文是**设计稿**：落到角色、数据模型、页面、接口、分期与验收，供评审后按分期实施。
> 密级：不含客户工艺/物料名。

---

## 1. 目标与非目标

### 目标

1. **三种角色各就各位**：操作员（实验员）、编排员、系统管理员，各看各的页面。
2. **机械臂从流程抽象出来**：流程只表达「把板从 X 搬到 Y」，机器人是系统布局里的执行器。
3. **流程 = 点位 + 方法**：编排员在点位上配方法，不在设备上配方法。
4. **实验 = 模板 → 实例 → config → 一键启动**。

### 非目标（本轮）

- 不推倒数据模型：`集群→岛→设备库→设备实例→设备池→设备方法→点位` 全部保留。
- 不做真机 HIL、不做机械臂运动学。
- Campaign（批次）列为 P5，不在前四期。

## 2. 角色与权限

现有 RBAC：`admin / operator / viewer`（`RbacRules.ROLES`）。现 operator 既管执行又管编排，职责混在一起。
重构为四角色：

| 角色 | 中文 | 能做什么 | 不能做什么 |
|---|---|---|---|
| `admin` | 系统管理员 | 建岛/设备实例/设备池/设备方法/点位、调点位、调机械臂、调设备、管账号 | — |
| `editor` | 编排员 | 流程编排、点位配置、设备方法配置 | 执行实验、改系统布局 |
| `operator` | 操作员 | 实验 config（物料→点位）、创建/启动实验、看甘特/岛进程 | 改流程/点位/方法 |
| `viewer` | 只读 | 看一切 | 任何写 |

### 权限矩阵（关键动作）

| 动作 | admin | editor | operator | viewer |
|---|---|---|---|---|
| 建/改岛、设备实例、设备池、设备方法、点位 | ✅ | ❌ | ❌ | ❌ |
| 调点位 / 调机械臂 / 调设备 | ✅ | ❌ | ❌ | ❌ |
| 流程编排（workflow 建/改） | ✅ | ✅ | ❌ | ❌ |
| 点位方法配置（device_point 方法集） | ✅ | ✅ | ❌ | ❌ |
| 实验模板实例化 + config 物料 | ✅ | ❌ | ✅ | ❌ |
| 启动/暂停/停止实验 | ✅ | ❌ | ✅ | ❌ |
| 看甘特 / 岛进程 / 库存 | ✅ | ✅ | ✅ | ✅ |
| 管账号 | ✅ | ❌ | ❌ | ❌ |

### 落点

- `RbacRules`：`ROLES = [admin, editor, operator, viewer]`；`canWrite` 拆成
  `canOperate`（operator/admin）与 `canEditWorkflow`（editor/admin）。
- 账号表 `role` 白名单扩展；「最后一个 admin」保护沿用。
- 前端 `App.tsx` 按角色过滤导航（见 §3）。

## 3. UI 信息架构（四份目录）

登录后按角色显示对应目录（`viewer` 复用 operator 目录但只读）。

### 3.1 操作员（operator）—— Dashboard 优先

| 菜单 | 页面 | 说明 |
|---|---|---|
| 首页 | **Dashboard（岛进程总览）** | 全岛所有实验的实时进程：哪些在跑/排队/暂停/异常，一条时间线 |
| 实验 | 实验列表 + **新建实验** | 选模板 → 实例化 → config 物料 → 一键启动 |
| 实验 | **Config 页** | 样品/试剂/耗材/板 → 绑到具体点位（本轮 `position_state` 内容模型是底座） |
| 运行 | 甘特图 | 排程 + 实际进度 |
| 库存 | 板 / 耗材 / 试剂 | 只读 + 扫码盘点 |

### 3.2 编排员（editor）

| 菜单 | 页面 | 说明 |
|---|---|---|
| 流程库 | 流程模板列表 | — |
| 设计器 | **点位化流程设计器** | 按点位拖方法（见 §4.2） |
| 点位 | **点位方法配置** | 每个点位允许哪些方法、角色、板型/高度约束 |
| 方法 | 设备方法库 | 方法的参数 schema |

### 3.3 系统管理员（admin）

| 菜单 | 页面 | 说明 |
|---|---|---|
| 系统布局 | **岛 + 设备 + 点位 + cell/handoff**（对标 外部厂商B System Layout） | 机器人是 cell 根、设备是子节点 |

| 调试 | 点位调试 / **机械臂调试（Mover）** / 设备调试 | 对标 MoverConfig/MoverTeach |

> 现有「分析（甘特/时长）」并入操作员运行组；「策略/告警/错误码」归管理员运维组。

## 4. 数据模型变更

### 4.1 机械臂抽象（Move Plate 取代 Transfer 节点）

**现状**：流程里有 `Transfer` 节点（机械臂方法，source/target 是设备码）。

**目标模型**：

```
流程节点（用户可见）          系统布局（管理员配置）          调度编译（系统内部）
┌──────────────┐        ┌──────────────────────┐        ┌──────────────────┐
│ Move Plate   │ ────▶  │ 岛 → cell(机器人根)    │ ────▶  │ 选机器人 →       │
│ 从点位 X 到 Y │        │  └ 设备/点位(子节点)   │        │ 跨cell走handoff →│
└──────────────┘        │  └ handoff nest(cell间)│        │ 开门 → 抓/放     │
                        └──────────────────────┘        └──────────────────┘
```

**新增/改动**：

| 对象 | 变更 |
|---|---|
| `device` | 加 `is_mover`（机器人类设备标记，不再作为流程方法源） |
| 新表 `robot_cell` | 机器人 + 其可达的设备/点位（对标 外部厂商B cell） |
| 新表 `handoff_nest` | cell 间交接位（一对方向一条） |
| 流程节点 | `Move Plate` 逻辑节点：`sourcePoint` / `targetPoint`（点位 code），不再有「机械臂方法」 |
| `TransferPlan`（现有） | 升级为「Move Plate → 机器人动作」编译器：选机器人、跨 cell 走 handoff、门控、双锁 |

**语义**：用户在流程里只表达「板从离心机 P1 搬到封膜机 P1」，系统根据布局决定用哪台机器人、是否 handoff、开哪个门。

### 4.2 点位中心（device_point 加方法集）

**现状**：流程绑「设备 + 方法」；`device_point` 只有角色/可达/板型约束。

**目标**：点位上配方法。

| 变更 | 说明 |
|---|---|
| 新表 `point_method`（或 `device_point.methods jsonb`） | `point_resource_id → 允许的方法 code 列表` |
| 流程设计器 | 左侧 palette 从「设备方法」改为「点位 + 该方法」，拖入即绑定点位 |
| `workflow_node` | `resource_id` 语义从「设备」改为「点位」（或新增 `point_resource_id`） |

**语义**：初始化时把「工作站有 N 个点位，每个点位在哪些流程里干什么、同一点位可有不同方法」配好（正是 `系统修改.txt` 第 3 条）。

### 4.3 实验模型（模板 → 实例 → config → 一键启动）

**现状**：`experiment`（模板）+ `run`（实例），物料 config 分离。

**目标**：

| 概念 | 现有 | 目标 |
|---|---|---|
| 模板（template） | `workflow` + `experiment` | 不变，是编排员产出 |
| 实例（instance） | `run` | 实验员「实例化模板」生成 |
| **config** | 分散 | **新增实验 config 表**：把样品/试剂/耗材/板绑到具体点位/板号 |
| 启动 | 手动 run | config 完成后「一键启动」 |

**新增**：

| 对象 | 说明 |
|---|---|
| `experiment_config` 表 | `experiment_id + 物料类型 + 物料 id/条码 + 目标点位 code`，复用本轮 `position_state.content_kind/content_id` 作为落地 |
| `POST /api/experiments/{id}/instantiate` | 实例化模板 → 生成可 config 的实验实例 |
| `POST /api/experiments/{id}/config` | 写物料→点位绑定 |
| `POST /api/experiments/{id}/launch` | 一键启动 |

## 5. 关键用户旅程

### 5.1 操作员跑一个实验

1. 首页 Dashboard 看到全岛进程。
2. 「新建实验」→ 选模板（如 NGS 流程）→ 实例化。
3. Config 页：把 `样品板 PL-xxx` 绑到「读板机 P1」、`试剂 A` 绑到「液站 P2」……（点位是下拉，不写机械臂）。
4. 点「启动」→ 跳甘特，看板子自动流转（机械臂动作由系统编译，不出现）。

### 5.2 编排员配一个流程

1. 打开流程设计器，palette 是「点位」不是「设备」。
2. 拖「离心机 P1 · RunProgram」→「封膜机 P1 · Seal」→ 之间自动插「Move Plate」。
3. 保存为模板。

### 5.3 管理员布置一个岛

1. 建岛 → 拖设备进岛 → 设机器人 cell（哪些设备归哪台机器人）。
2. 配 handoff nest（两台机器人之间交接位）。
3. 调点位（机械臂示教坐标）、调设备（单命令探针）。

## 6. 分期实施（每期可独立验收）

| 期 | 内容 | 输入/输出 | 验收 | 风险 |
|---|---|---|---|---|
| **P1 · 角色化 UI + RBAC** | 四角色 + 三份目录 + Dashboard 骨架 + 登录按角色过滤 | 纯前端 + RBAC | 三种角色登录看到不同目录；operator 看不到流程编辑 | 低 |
| **P2 · 实验 config + 一键启动** | `experiment_config` 表 + 实例化/config/launch 接口 + 操作员 config 页 | 复用本轮物料/点位模型 | 操作员能「选模板→实例化→config 物料→一键启动→甘特看到流转」 | 中 |
| **P3 · 点位中心编排** | `point_method` + 设计器点位化 + `workflow_node` 点位语义 | 依赖 P2 的点位下拉 | 编排员按点位拖方法；同一点位不同方法可配 | 中 |
| **P4 · 机械臂抽象** | `is_mover` + `robot_cell`/`handoff_nest` + Move Plate 节点 + TransferPlan 升级为编译器 | 依赖 P3 的点位 | 流程里无 Transfer；Move Plate 被编译成机器人动作；跨 cell 走 handoff | **高** |
| **P5 · Campaign** | 批量实例 | 依赖 P2 | 一批同模板不同样品的实例一键跑 | 低 |

> 顺序固定：**P1 → P2 → P3 → P4 → P5**。P1 独立可先行；P4 最重，依赖 P3 的点位语义。

## 7. 迁移与兼容

- **不推倒**：现有 `device/device_instance/device_pool/device_method/device_point/position_state/plate/consumable/reagent` 全保留。
- **P3 前**：`workflow_node.resource_id` 仍指设备（兼容期），P3 引入 `point_resource_id` 并做一次数据回填。
- **P4 前**：现有 `Transfer` 节点保留为「兼容的 Move Plate」（内部已带 source/target），P4 后隐藏为 Move Plate。
- **本轮已建资产**（装载口/内部格、内容统一模型、DeviceInternalTransfer、TransferPlan 门控）在 P2-P4 里逐一升级，不回退。
