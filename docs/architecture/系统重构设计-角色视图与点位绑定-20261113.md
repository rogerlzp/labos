## 0. 一句话

保留「集群→岛屿→设备库→设备实例→设备池→设备方法」骨架，落地三件事：

1. **点位成为流程编排的一等绑定对象**（流程节点绑点位，不直接绑设备）；
2. **界面按角色切三副面孔**（操作员 / 编排人员 / 系统管理员），机械臂原始方法只存在于管理员调试台；
3. **执行层对象化**（Experiment 模板实例化 + 样品/试剂/耗材位置配置 + 三条件启动状态机），为 Campaign（批次化批量执行）留出接口。

## 1. 背景与目标

### 1.1 重构动机（`docs/系统修改.txt` 原文归纳）

- 用户做实验的正确动线是：实例化实验模板 → 配置样品/试剂/耗材位置 → 一键启动；
- 编排人员配置的是**点位**，点位在初始化时定义用途，同一流程不同点位、同点位不同流程可以挂不同方法；
- 机械臂（mover）的任何方法不得出现在用户流程里，机械臂操作收敛到一个管理员调试场所；
- UI 目录按角色裁剪：操作员只见物料配置 / 创建实验 / 运行甘特图 / 全岛进程；编排人员只见流程编排 / 点位配置 / 设备方法配置；管理员持有岛屿、设备实例、设备池、设备方法、点位、机械臂的全部创建与调试权。

### 1.2 对标结论（详见对标分析文档）

| 对标点 | 外部厂商A 7.0 | 外部厂商B 7.5 | 我们采纳 |
|---|---|---|---|
| 对象分层 | Process → Experiment → Campaign → Work Unit/Run | Method → Plate Association → Run | Process → Experiment(+物料配置) → Campaign → Run |
| 设备配置 | 四页签：Settings / Nests / Teach / Profile Settings | System Layout Editor（Device Library + Robot Configuration） | 设备实例 + `device_point`（配置层）+ `robot_point`（机械臂侧）已对齐 |
| 池 | 操作池（同型号）/ 存储池（可异构 + 下一位策略） | 未强调 | 保留现有池，策略后置 |
| 启动条件 | 三条件：在线 + 有工单 + 容器已加载（逐项核验） | 条码/关联校验后入队 | 三条件状态机 + 扫码核验 |
| 界面 | Dashboard（操作员）/ General Interface（全功能），按角色默认 | 按 Role 控功能页 | 三角色三副导航 |
| 机械臂 | 独立 Mover Framework（MoverConfig + MoverTeach），用户不可见 | Robot Configuration 仅在布局编辑器 | 管理员调试台 |

### 1.3 目标

1. 流程节点可绑定**点位**（`resource_node` kind=storage/incubator/transfer_point），编排器不再要求用户直接选设备实例；
2. 机械臂（`device_type='arm'`）的 `device_method` 从编排器方法面板消失，仅保留业务语义「转运 Transfer」节点；
3. 新增三角色 RBAC 与按角色裁剪的导航；
4. 新增实验物料配置模型与页面，启动前执行「在线 / 工单 / 物料」三条件检查；
5. 新增管理员机械臂调试台（单步动作、点位坐标维护）。

### 1.4 非目标（本设计不做）

- 不改 BPMN 存储与网关执行语义（`LabOS功能规格说明书.md` §7.3，设计已成熟）；
- 不改执行引擎的命令展开/调度核心（TransferPlan、PositionLock 语义保持稳定）；
- 不做 Campaign 完整实现（只留对象与接口，见 §5.3.3）；
- 不做池调度策略细化（操作池/存储池的运行时策略沿用现状，后置）；
- 不做老系统 2563 个迁移点位的归属对账（数据治理，独立批次，见 §14 未决问题）；
- 不做盖子独立实体、试剂余量/死体积（沿用既有非目标）。

## 4. 总体架构

```
┌─────────────────────────── 系统管理员（全量目录 + 调试台） ───────────────────────────┐
│ 岛屿 / 设备库 / 设备实例 / 设备池 / 设备方法 / 点位注册与示教 │ 机械臂调试台（G6）      │
├─────────────────────────── 编排人员（编排目录） ────────────────────────────────────┤
│ 流程编排器（节点绑点位 G1）/ 点位配置（只读选择）/ 设备方法配置（绑定，不改定义）       │
├─────────────────────────── 操作员（工作台目录） ────────────────────────────────────┤
│ 物料配置（G4）/ 创建实验 / 运行甘特图 / 全岛进程                                      │
└──────────────────────────────────────────────────────────────────────────────────┘
              执行引擎（不动）：BPMN 语义 → 命令展开 → TransferPlan / PositionLock
```

**关键边界**：三副界面共用同一套后端 API；权限在后端逐接口校验（前端隐藏只是体验层）。执行引擎（Gantt 调度、搬运确认、扫码身份）本轮零改动。

## 5. 领域模型设计

### 5.1 资源层（管理员建，编排人员只读消费）

沿用现有五层，无新表；两处语义收紧：

1. **方法定义 vs 方法绑定分工**（消解 `系统修改.txt` 第 9、10 条的表面矛盾）：
   - **系统管理员**在设备型号上创建/维护方法定义（`device_method`：method 名、参数 schema、时长、超时）；
   - **编排人员**做的是**绑定**：在流程节点上选定点位后，从该点位设备型号的 `device_method` 集合中挑一个、填参数。编排器不提供"新建方法定义"入口。
   - 解析链：`workflow_node.point_resource_id` → `device_point.device_resource_id` → `device_instance.device_id`（型号）→ `device_method`。
2. **点位用途由流程决定**（`系统修改.txt` 第 3 条"同一流程不同点位、同点位不同流程不同方法"）：点位本身只携带物理属性（角色/可达/板型/网格）；「这个点位在这个流程里干什么」是 `workflow_node` 的语义，不进 `device_point`。`device_point.point_role` 的 `entry/exit/internal` 是**搬运调度语义**（机械臂能不能直达、取放方向），不要与流程用途混用。

### 5.2 流程层（编排人员建）

#### 5.2.1 节点-点位绑定（G1）

`workflow_node` 增加一列：

```sql
ALTER TABLE workflow_node
  ADD COLUMN IF NOT EXISTS point_resource_id bigint REFERENCES resource_node(id);
```

绑定规则：

| 规则 | 说明 |
|---|---|
| 优先级 | 执行/编译时 `point_resource_id` 优先，为空回退 `resource_id`（老流程兼容，见 §12 风险 R1） |
| 校验（保存时预检） | 点位必须属于某台 `device_instance`（`device_point.device_resource_id` 非空）；点位 `robot_reachable` 要求按节点类型判定（转运节点取放板要求 true；读写类设备动作节点允许 false，由设备内部机构处理） |
| 方法可用集 | 选定点位后，可选方法 = 点位所属设备型号的 `device_method`；面板不再按"设备"列方法，改为按"点位"列方法 |
| 多点位 | v1 一个业务节点绑一个点位；池语义（"这批板任意一台离心机"）由运行时池调度承担，编排器不表达 |

#### 5.2.2 机械臂方法出流程（G2）

- `device_type='arm'` 的设备方法**从编排器方法面板过滤掉**（API 层过滤，不靠前端）；
- 流程中保留「转运 Transfer」语义节点：它是**调度语义**（把板从点位 A 搬到点位 B），由 `TransferPlan`/`PositionLock` 在运行时翻译成机械臂动作——翻译细节对用户与编排者均不可见；
- 存量流程审计 SQL（迁移前必跑）：

```sql
-- 找出引用了机械臂方法的流程节点（应只在老流程/测试流程出现）
SELECT w.code, n.node_key, n.name, d.device_type, dm.method
FROM workflow_node n
JOIN workflow w ON w.id = n.workflow_id
JOIN device_method dm ON dm.id = n.protocol_id  -- 或按实际 method 引用链调整
JOIN device d ON d.id = dm.device_id
WHERE d.device_type = 'arm' AND w.deleted_at IS NULL;
```

命中的流程列入迁移清单：要么改为 Transfer 语义节点，要么标记为管理员专用（见 §12 R2）。

### 5.3 执行层（操作员用）

#### 5.3.1 Experiment 实例化

`experiment` 表已有 `workflow_id`、`experiment_no`、`status`。补一个**模板来源**字段，让"实验模板"成为显式概念：

```sql
ALTER TABLE experiment
  ADD COLUMN IF NOT EXISTS template_id bigint REFERENCES experiment(id),
  ADD COLUMN IF NOT EXISTS iteration_count int NOT NULL DEFAULT 1;  -- 对标 外部厂商A Experiment.iterations
```

- 实验模板 = `experiment` 中 `template_id IS NULL` 且 `status='template'` 的行（种子状态值）；
- 实例化 = 复制模板行（新 experiment_no、template_id 指向模板）+ 复制 `experiment_variable` 默认值；不复制 run/batch；
- 编排人员在模板上预绑流程（workflow_id），操作员实例化后不可换流程（换流程 = 重新实例化）。

#### 5.3.2 物料配置（G4，新增表）

```sql
CREATE TABLE IF NOT EXISTS experiment_material_config (
  id            bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  tenant_id     bigint NOT NULL REFERENCES tenant(id),
  experiment_id bigint NOT NULL REFERENCES experiment(id) ON DELETE CASCADE,
  material_kind varchar(16) NOT NULL,        -- sample / reagent / consumable
  ref_id        bigint NOT NULL,             -- sample.id / reagent_lot.id / consumable_lot.id
  point_resource_id bigint REFERENCES resource_node(id),  -- 可空：只到设备级
  device_resource_id bigint REFERENCES resource_node(id), -- 可空：与点位二选一/冗余
  quantity      numeric NOT NULL DEFAULT 1,
  barcode       varchar(64),                 -- 期望条码（核验用）
  verified      boolean NOT NULL DEFAULT false,  -- 扫码核验通过
  verified_at   timestamptz,
  attr          jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_emc_kind CHECK (material_kind IN ('sample','reagent','consumable')),
  CONSTRAINT ck_emc_location CHECK (point_resource_id IS NOT NULL OR device_resource_id IS NOT NULL)
);
CREATE INDEX IF NOT EXISTS ix_emc_experiment ON experiment_material_config (tenant_id, experiment_id);
COMMENT ON TABLE experiment_material_config IS
  '实验物料位置配置：操作员在启动前声明样品/试剂/耗材放在哪里；启动条件3逐项核验 verified';
```

- 与既有物料链路的关系：`run_material_effect_declaration`（20261112，流程内的物料声明）是**流程视角**，本表是**实验视角**；启动时以本表为准生成/校验声明，不双写历史；
- 扫码核验复用已落地的 `PlateIdentity`/`confirmScanned`：物料是板（样品）时走 `plate_barcode_alias`；耗材/试剂批次直接比对 `consumable_lot.barcode`/`reagent_lot.barcode`；
- 核验失败不阻断物理放置，只置 `verified=false`，启动条件 3 不通过（对标 外部厂商A「加载对话框逐项 verify」）。

#### 5.3.3 Campaign（G7，接口预留）

本设计只锁定对象边界，不实现：

- `experiment_batch`（单实验内分批）**不动**；
- 跨实验批量 = 新表 `campaign(id, name, status, attr)` + `campaign_item(campaign_id, experiment_id, batch_no, start_option jsonb)`，语义对标 外部厂商A Campaign（多 batch、各自 start option）。DDL 先不建，等 P4 排期；§8 API 预留 `/api/campaigns`。

### 5.4 机械臂语义边界（红线）

| — | — | 用户 `/users` 审计 `/audit` 等 |

- 操作员菜单**不出现**：拓扑、模型库、变量、策略、错误码、S2 用例、手动窗口、隔离区（这些归管理员；操作员遇到 `WaitingForOperator` 由运行页内嵌处理面板承接，不挂全局菜单）；

## 7. 界面设计（按角色的关键交互）

### 7.1 操作员 · 物料配置页 `/materials?experimentId=`

两栏：左「实验信息 + 流程步骤摘要」，右「物料清单表格」。每行：
`物料(名称/条码) | 类型 | 数量 | 目标点位(下拉，按设备分组) | 核验状态(未核验/已扫码/匹配/不匹配)`。

交互：① 按实验生成空配置（从模板/流程声明预填建议点位，可改）；② 扫码枪扫条码 → 调核验 API → 行内状态更新；③ 全部核验通过 → 「启动实验」按钮点亮。空态主操作 = 「添加物料」。

### 7.2 操作员 · 创建实验页 `/experiments`

模板卡片墙 → 实例化向导（三步：选模板 → 填名称/迭代次数/优先级 → 去物料配置）。列表页 = 当前用户的实验（对标 Dashboard 的 Display Only Mine），状态徽章沿用五级词表。

### 7.3 操作员 · 运行甘特图 `/gantt` 与全岛进程 `/runs`

- 甘特图：当前实验的节点时间轴（现有能力重组，实验范围过滤默认"我的最近运行"）；
- 全岛进程：本岛全部 run 的简化看板（行：实验号/流程/状态/进度/当前节点/预计完成；对标 外部厂商B 的 Current/Queued 合并视图）。**删除**操作员可见的调度器内部页（`/scheduler` `/schedule` 归管理员与编排只读）。

### 7.4 编排人员 · 流程编排器改造（Designer）

方法面板从「按设备」改为「按点位」：左树第一级 = 岛上设备（只读分组），第二级 = 该设备的点位（`GET /api/points`），展开点位显示可用方法（`GET /api/points/{id}/methods`）。机械臂设备不出现在树中；Transfer 节点在"逻辑节点"区（现有 LogicNodeRow 旁）。节点属性面板增加「点位」只读徽标 + 换绑按钮。

### 7.5 编排人员 · 点位配置 `/points-config`

只读视图复用 `/positions` 的表格（无编辑权限时隐藏编辑按钮）；用途列展示「被哪些流程节点引用」（查询 `workflow_node.point_resource_id`，反向索引）。

### 7.6 系统管理员 · 机械臂调试台 `/arm-console`

三个区块：
1. **单步动作**：选机械臂 → 选方法（`/api/devices/{id}/methods` 全量，含 arm）→ 参数表单（`param_schema` 驱动）→ 执行 → 回包展示。每次执行写 `run_event` 或独立审计（见 §8）；
2. **点位示教**：选机械臂 → 点位列表（`robot_point` fill_status='pending' 置顶）→ 录入/读取坐标 → `fill_status='synced'`；只录真值，禁止手填猜测值（UI 层校验 + 后端二次校验坐标来源标记）；
3. **运动状态**：当前位置、忙碌/空闲、最近错误（只读轮询）。

**安全**：调试台所有写操作要求 `arm:debug` 且二次确认；机械臂被某 run 占用时（`device_state` busy）禁止单步动作，返回 409。

## 9. 运行状态机：三条件启动（G5）

### 9.1 状态定义

```
ExperimentRun 启动前 readiness（计算值，随查询刷新）：
  C1 system_online   = 流程涉及的全部设备 device_state ∈ {idle, busy可预约} 且机械臂在线
  C2 work_ready      = 流程编译通过 + 预检无 Blocked + 设备资源可预留
  C3 material_verified = experiment_material_config 每行 verified=true
                          （或 experiment 声明无物料，则恒真）
C1 ∧ C2 ∧ C3 → 允许启动（启动后走既有 run 状态机，不动）
任一不满足 → Blocked，原因码：NOT_ONLINE / WORK_NOT_READY / MATERIAL_UNVERIFIED（可带行号）
```

### 9.2 落地

- 新组件 `StartupReadinessChecker`（与 `PreflightChecker` 并列，不合并——预检是流程视角，readiness 是实验视角）；`WorkflowService` 启动处调用，三条件不齐拒绝启动并写 `run_event`（原因码）；
- `GET /api/experiments/{id}/readiness` 返回 `{c1, c2, c3, reasons[], blockingRows[]}`，物料配置页与创建实验页共用；
- C3 的 `verified` 置位路径：① 页面扫码核验 API；② 搬运链路 `confirmScanAtDevice` 已落地，扫到真条码时若命中某 config 行的期望条码则联动置位（联动是 P1 增强，v1 只靠 ①）。

### 9.3 与既有预检的关系

| | PreflightChecker（保留） | StartupReadinessChecker（新增） |
|---|---|---|
| 视角 | 流程/图 | 实验/物料 |
| 时机 | 保存时 + 启动时 | 启动时（+页面轮询） |
| 输出 | 预检报告（可警告） | 启动闸门（硬性三条件） |
