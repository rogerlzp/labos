## 0. 定调

**采纳《重构详细设计》为主干**，一句话主张照搬：

> 流程节点绑「点位 + 方法 + 物料角色」，不绑设备。四件事原本挤在一个 `resource` 属性里。

三条绑定链（方法链 / 物料链 / 搬运链）与「新建 `device_pool`/`position_method`/`node_binding` + `manifest_*` + `transport_segment`」的表结构，**全部认可，不动**。

## 1. 三处必改（评审 P1-A/B/C）

### 修正 A · P0 收缩，不碰执行引擎

评审正确：原 P0 把 `BindingResolver`（P0-4）和 `TransportPlanner`（P0-5）塞进第一批，等于第一步就动最脆弱的执行层。

**改后 P0 = 纯数据层 + 权限层 + 示教补齐**：

| 保留在 P0 | 移出 P0 |
|---|---|
| P0-1 `device_pool` 表+页 | ~~P0-4 BindingResolver~~ → P1 |
| P0-2 `position_method` 表+接口 | ~~P0-5 TransportPlanner~~ → P1 |
| P0-3 `node_binding` 表+面板 | |
| P0-6 角色重划 + 导航裁剪 | |
| P0-7 补 9 个可达点位示教坐标 | |

理由：P0 只建「数据与权限」这两堵墙，`binding_mode='legacy'` 路径全程不变，存量 136 流程 / 85 实验零风险。执行链改造（绑定解析 + 隐式搬运）整批下沉 P1，等 P0 的数据层稳了再动。

### 修正 B · 绑定固化语义（补进 §4.1）

这是本会话**实测踩过**的坑：`workflow_node.resource_id` 绑了 ≠ 用——运行时会 GraphRunner 候选池重解析成别的设备（MoveInLabware 绑 ID-2011 被解析到 ID-X202）。

`§4.1 ② BindingResolver` 必须补一条**硬规则**：

> **BindingResolver 产出的 `ResolvedBinding{positionId, deviceInstanceId, poolId, ...}` 是 pinned 绑定；GraphRunner 命中绑定即直接用，不参与候选池排序/重解析。只有 `node_binding` 为空且 `binding_mode='legacy'` 时才进候选池。**
> （`poolId` 例外：绑定的是池，运行时由池策略在**池内**选设备——但候选集被限定为该池成员，不回退到全岛池。）

### 修正 C · node_binding 真源规则（拍板）

问题：`node_binding` 是 BPMN XML 之外的旁挂表，导出/导入会静默丢绑定。

**裁决**：`node_binding` 与 workflow **同生命周期、一起打包**，但**不塞进 BPMN XML**（bpmn-js 会重写 XML，自定义属性易丢）。

- 存储：`node_binding` 独立表，键 `(workflow_id, node_key, seq)`，随 `workflow` 同删同迁。
- 导出：`GET /api/workflows/{id}/export` 返回 `{graph, bindings}` 两段；导入时两段一起写。
- 真源判定：**存在 node_binding 且 enabled → 以绑定为准；否则回落 XML `resource`（legacy）**。两处只暴露一个编辑入口（`binding_mode` 决定是点位模式还是设备模式），不做混合编辑（原 §10.1 R1 的缓解，升级为硬规则）。

## 3. 七个开放问题裁决

| # | 问题 | 裁决 | 理由 |
|---|---|---|---|
| 1 | `lifecycle` 建在物料实例还是分配上 | **建在 `manifest_placement`**（一次分配一次语义），实例级只作默认值 | 同一块板跨实验复用不会互相污染 |
| 2 | `viewer` 角色去留 | **保留**，给 `/runs` 只读，不占主导航 | 存量 1 个 viewer 账号，删了反而要迁移 |
| 3 | 跨岛搬运 handoff | **不建模**，等第 2 个岛 | 现状 1 个岛，`experiment_handoff` 已有但语义未定 |
| 4 | 一岛多机械臂 | **允许**，`robot_resource_id` 区分 | 单臂是现状不是约束；P2-6 已列多臂 |
| 5 | 集群 vs 岛 | **删集群层**（若确认是历史包袱） | 现状 `island` 只有 1 个，集群层空转 |
| 6 | `node_binding` vs `position_method` 合并 | **不合并** | 前者「节点用这个点位」，后者「点位允许这个方法」，是不同关系 |
| 7 | 工位是否新 kind | **新 kind `workstation`** | `parent_id` 现成，拓扑视图免费 |

## 4. 最终分期（修正版）

| 期 | 内容 | 验收口径 |
|---|---|---|
| **P0 承重墙** | 数据层（pool/position_method/node_binding 三表+页+接口）+ 角色重划+导航裁剪 + 补 9 个示教坐标 | 存量零回归；Operator 登录只见 4 屏；`binding_mode='legacy'` 全绿 |
| **P1 执行链** | BindingResolver（含**绑定固化**硬规则）+ ManifestResolver + 隐式 Transport + 三条件闸门 + 操作员四屏 + 机械臂调试台 | 端到端：绑点位→展开取到→命令带点位；隐式搬运可追溯；三条件拒绝启动且原因码正确 |
| **P2 工业化** | 工位层/空闲分配、双交接位、接力链、排程持久化、resource_booking、多臂、扫码校验节点、物料角色目录 | 批量 10 板自动分 10 工位不冲突；接力链可表达 |

**核心顺序保证**：先数据后执行；执行链改动集中在 P1 一处；P0 全程不碰 `GraphRunner`/`RecipeCompiler`/`TransferPlan`/`PositionLock`。
