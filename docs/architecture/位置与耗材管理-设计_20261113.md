# 位置管理 + 耗材管理 · 设计（2026-11-13）

> 目标：在页面上把「位置」和「耗材」整理成两个可管理、可与设备关联的视图，
> 从而既能**从位置看整个岛**（哪台设备、哪个点位、放着什么），也能**从耗材看整个岛**
> （哪种耗材、多少库存、放在哪台设备/哪个点位），且都能直接修改。
> 参考：`docs/板位级占用与位置互斥-设计.md`（四级资源模型）、
> `docs/UI-界面设计说明书.md`（运维导航 + 表格规范）、
> `docs/architecture/点位初始化与物料身份-设计_20261113.md` §4（点位清单内容类型）。

## 1. 数据模型（复用现有表，不新建平行模型）

### 1.1 位置视角

```
resource_node (device)
  └─ resource_node (position: kind=storage/incubator/transfer_point)
       ├─ device_point        配置：point_role / robot_reachable / is_entry / is_exit / order_in_device
       └─ position_state      运行态：plate_id（板 barcode）/ content_kind / content_id / occupied_by_run / reserved_by_run
```

### 1.2 耗材视角

```
consumable (目录)            code / name / category / unit / max_stack
  └─ consumable_lot (库存)    lot_no / barcode / quantity / remaining
                              / location_id（点位 resource_node.id，可空）
                              / device_id（设备 resource_node.id，可空）
                              / expire_at / status
```

**关联到设备的两条路径**：
1. `consumable_lot.device_id` → 设备（粗粒度：这盒耗材放在哪台设备）。
2. `consumable_lot.location_id` → 点位（细粒度：放在设备的哪个点位）。

v1 优先用 `device_id`（粗粒度，必填性弱）；`location_id` 作为可选的细粒度补充。

## 2. 两个页面

### 2.1 位置管理页 `/positions`（运维）

**谁用**：设备工程师 / 实验前检查。
**看什么**：岛选择器 → 按设备分组的点位表。每行：
`点位 code | kind | 角色(entry/exit/both/internal) | 机械臂可达 | 序 | 占用(板号/内容/空) | 预约 | 所属设备`。
**能改什么**：点位角色、可达、进口/出口、顺序、备注（`device_point` 配置）。

### 2.2 耗材管理页 `/consumables`（运维）

**谁用**：实验员 / 库管。
**看什么**：两段式——
- 上：耗材目录表（code / name / category / unit / max_stack）。
- 下：库存批次表（lot_no / barcode / quantity / remaining / 所在设备 / 所在点位 / 效期 / 状态）。
**能改什么**：增删改耗材目录；增删改库存批次（数量、剩余、搬到哪台设备/点位、效期、状态）。

## 3. API 设计（新增，薄 HTTP 层 + MyBatis）

### 3.1 耗材目录

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/consumables?islandId=&category=` | 目录列表（可按岛筛：关联 lot 的 device 属于该岛） |
| POST | `/api/consumables` | 新增（code 唯一，重复 409） |
| PUT | `/api/consumables/{id}` | 改 name/category/spec/unit/max_stack |
| DELETE | `/api/consumables/{id}` | 软删（`deleted_at`） |

### 3.2 耗材库存（批次）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/consumable-lots?consumableId=&islandId=` | 批次列表，带 `deviceCode`/`positionCode` |
| POST | `/api/consumable-lots` | 新批次（quantity/remaining/location_id/device_id/expire_at） |
| PUT | `/api/consumable-lots/{id}` | 改 remaining/location/device/expire/status（`ck_consumable_qty` 约束 remaining∈[0,quantity]） |
| DELETE | `/api/consumable-lots/{id}` | 软删 |

### 3.3 点位配置

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT | `/api/device-points/{pointResourceId}` | 改 point_role / robot_reachable / is_entry / is_exit / order_in_device / note |

### 3.4 试剂（对称，与耗材同结构）

| 方法 | 路径 |
|---|---|
| GET/POST/PUT/DELETE | `/api/reagents`、`/api/reagents/{id}`、`/api/reagent-lots`、`/api/reagent-lots/{id}` |

> v1 先做耗材 + 位置配置；试剂复用同一套，若时间够一并做（结构完全对称）。

## 7. v2 追加：点位属性 / 物料-板子关系 / 特殊位置类型（2026-11-13）

### 7.1 三句话回答用户的三个问题

1. **耗材/试剂要不要挂到具体板子？** —— **v1 不挂**。耗材（枪头盒、PCR 板、盖子…）和
   试剂容器**物理上占的是点位**，不是板；它们和板子平级，都是「点位内容」
   （`position_state.content_kind ∈ {plate, consumable, reagent}` 三选一）。
   「试剂进板孔」是 `plate_well` 深层模型，本轮不做（见 §7.5 非目标）。
2. **板子的属性？** —— `plate` 已有 `plate_type / rows / cols / process_state / seal_state /
   state_version / identity_status`；板是物理物，**放位置**（`location_id` 指向点位）。
3. **板子放的位置怎么对应？** —— `plate.location_id = 点位 resource_node.id`；
   点位用 `plate_types` 声明「能放哪些板型」，放板时校验板型是否匹配。

### 7.2 点位属性扩展（device_point 加 4 列）

培养箱/堆栈/中转位这些设备是「多排多列、每格高矮/板型不同」，光有 `order_in_device`
表达不了。给 `device_point` 补：

| 列 | 类型 | 含义 |
|---|---|---|
| `grid_row` | smallint | 排（1 起，培养箱的层 / 堆栈的层） |
| `grid_col` | smallint | 列（1 起，同一层第几列） |
| `max_height_mm` | numeric | 该点位最高能放多高的板（mm） |
| `plate_types` | varchar[] | 能放的板类型集合（如 `{pcr96,deep96}`；空 = 不限制） |

- `resource_node.code` 就是点位**标识符**（如 `ID-X229-P1`）。
- 运行态（占用/预约/状态）仍在 `position_state`；`device_point` 是静态配置。

### 7.3 三类特殊位置

| 类型 | 布局 | 关键属性 |
|---|---|---|
| 培养箱（incubator） | 层 × 列（如 2×2） | `grid_row/grid_col` + `max_height_mm` + `plate_types` |
| 耗材堆栈（storage） | 单列多层 | `grid_row` + `max_stack`（同层可叠几盒） |
| 中转位（transfer_point） | 单层 | `robot_reachable=true`，机械臂抓手位 |

位置管理页按 `(设备 → grid_row, grid_col)` 分组排序展示，编辑弹窗改这些属性。

### 7.4 实现清单

- DDL：`pg_rebuild/migration/20261113_device_point_attrs.sql`（幂等加 4 列）。
- 后端：`GET /api/positions` 回 `gridRow/gridCol/maxHeightMm/plateTypes`；
  `PUT /api/device-points/{id}` 接受这 4 个字段（`ConsumableMapper.updateDevicePoint` 扩展）。
- 前端：`Positions.tsx` 按网格展示 + 编辑；`Consumables.tsx` 不变（已是「点位内容」模型）。
- 测试：`scripts/verify-material-mgmt.py`（API 冒烟）+ Playwright 页面用例。

### 7.5 非目标（仍是）

- 试剂进板孔（`plate_well` 与 `reagent` 的关联）、板内容标签。
- 放板时的板型/高度自动校验拦截（只做展示与手工编辑，校验留到下一轮）。

## 8. v3 追加：机械臂无点位 / 装载口模型（2026-11-13 用户澄清）

### 8.1 两点澄清

1. **机械臂（TRANSFER 设备）不要有点位**：机械臂是搬运机构，不存放板；
   ID-X231 / ID-XRobot_A10LR-1 的 `transfer_point` 已删除。它们仍出现在位置管理的设备列表里，
   但点位数 = 0。
2. **培养箱 / 耗材堆栈 = 放的位置（内部格）+ 进口/入口（装载口）**：
   - **放的位置**：内部存储格（`point_role='internal'`、`robot_reachable=false`），
     由设备内部机构搬运，机械臂不直达；`grid_row/grid_col` 表达排/列。
   - **进口/入口**：一个装载口（`{设备}-IN`，`point_role='both'`、`robot_reachable=true`），
     机械臂只在这里放/取板；「进口」和「入口」可合并为同一个点。

### 8.2 现状（修正后，13 台设备）

| 设备 | 内部格 | 装载口 | 说明 |
|---|---|---|---|
| ID-X229 培养箱 | 30（2列×15层） | 1（ID-X229-IN） | incubator |
| ID-Hotel12H-1 堆栈 | 120（10列×12层） | 1 | storage |
| ID-Hotel12H-2 堆栈 | 120（10列×12层） | 1 | storage |
| ID-X231 / ID-XRobot_A10LR-1 机械臂 | 0 | 0 | 已删 transfer_point |
| 其余 8 台 | 见位置管理 | — | 读板/离心/封膜各 2；撕膜/液站/洗板/磁力架/PCR 未配 |

### 8.3 板型/高度自动校验（已实现，OPT-IN）

- `PositionLock.checkPlateFits(position, barcode)`：放板前校验
  `plate.plate_type ∈ position.plate_types` 且 `plate.height_mm ≤ position.max_height_mm`；
  只在点位显式配置了约束时才拦（空约束 = 不限制），校验异常只告警不阻断搬运。
- 集成在 `noteTransferMove` 放板前；不匹配返回 `TransferMove(false, 原因)`，保持 REPORTED 转人工。
- **已知边界**：装载口（机械臂直达点）通常不设板型限制，板型/高度约束应落在内部格；
  而「机械臂放装载口 → 设备内部机构搬到内部格」这一步当前未建模，因此内部格的
  板型/高度校验在现有执行链里不会触发（见 §7.5 非目标，留下一轮）。

## 9. v4 追加：实验范围看板子流转 + 网格外的单独位置/位置标识（2026-11-13）

### 9.1 「板子流转」加实验范围

**需求**：在板子流转上加实验范围；能在一个实验里面看到板子是怎么流转的。

**为什么不改表**：`plate_location_audit` 只存 `run_id`（实测 = workflow `run.id`，
不是 `experiment_run.id`；`experiment_run.id` 是另一套 id 空间）。加 `experiment_id` 列
需要动执行链写入侧，风险高且历史行仍要回填 ⇒ 改为**查询时解析**，零 DDL、零写入改动：

| 优先级 | 关联路径 |
|---|---|
| ① | `experiment_run_step.run_id = audit.run_id` → `experiment_run.experiment_id`（实验编排执行主路径） |
| ② | `experiment.run_id = audit.run_id`（单 run 实验兜底） |
| ③ | 都命中不到 = 独立 workflow 执行 / 人工盘点，实验列标记「独立执行」 |

🔴 **绝不用时间窗猜归属**：多实验并行时 `created_at` 落在同一区间会串台。

**改动链**：`PauseMapper.xml#traceExperimentId`（LATERAL 解析，主查询/范围清单共用）
→ `selectPlateTraces` 增加 `experimentId`/`runId` 过滤并带出 `experimentId/No/Name`
→ 新增 `selectPlateTraceExperiments` / `selectPlateTraceRuns`（只列**有流转记录**的范围）
→ `RunQueryController` / `RunService` → `PlateTraces.tsx`。

**页面**：① 实验范围 + 执行单范围两个下拉（默认全部）；② 表格加「实验」列，可点进实验详情；
③ 新增「实验内 · 板子流转链路」卡片：按板号聚合、时间正序、相邻重复位置合并，串成
`位置A → 位置B → 位置C`；④ 实验详情页加「板子流转」按钮，带 `?experimentId=` 直达。

⚠️ **数据现状（接手必读）**：库里 201 行 audit **只有 4 行**能精确归到实验
（4 个实验各 1 行），其余都是验证脚本直接跑的独立 workflow run，本来就不属于任何实验。
所以选实验看到 1 行、或实验清单只有 4 项，是**数据事实不是 bug**；要看现有这批流转请用
「执行单范围」（25 张）。真实实验编排执行时 `experiment_run_step.run_id` 会写入，audit 就能自动归属。

### 9.2 培养箱/堆栈：网格之外的单独位置 + 位置标识

**需求**：除了「几行几列」的网格点位，还要有一个**单独的位置**标记为出口和进口，以及位置标识。

**此前缺口**：装载口 `{设备}-IN` 的数据早就有了（`both` + `is_entry/is_exit` + 可达），
但它 `grid_row/grid_col` 为 NULL ⇒ 位置管理页按网格渲染时**整个看不见**；
「位置标识」也只能复用 `resource_node.code`（系统唯一编码，现场标签不该改它）。

| 层 | 改动 |
|---|---|
| DDL | `pg_rebuild/migration/20261113_device_point_standalone.sql`（幂等）：`position_label varchar(64)`（可编辑的现场标识，空 = 页面回退显示 code）+ `is_standalone boolean`（网格之外的单独位置）；回填已有 3 个装载口并清掉误写的 grid 坐标 |
| 后端 | `DeviceStateMapper.xml` / `PositionLock.PositionState` / `DeviceController` 输出两字段；`ConsumableMapper.updateDevicePoint` + `StockController` 接受并校验（单独位置不得是 `internal`，且强制清 grid 坐标；备注为空时保持原值不冲掉「装载口」备注） |
| 前端 | `Positions.tsx`：网格维度只算非单独位置；网格下方新增「单独位置 · 进口 / 出口」区块，每张卡片显示**位置标识** + 系统编码 + 进口/出口 Tag + 占用；编辑弹窗可改位置标识、勾选单独位置（勾上后禁用排/列输入） |
| 脚本 | `gen-grid-points.py --load-port [--load-port-label 名称]` 生成时写入 `is_standalone=true` + `position_label`，COALESCE 保留现场改名 |

**验收**：迁移 `UPDATE 3`（ID-X229 / ID-Hotel12H-1 / -2）；`build-kernel.sh` ✓、
`test-all.sh --pure-only` 883/0、`npx tsc --noEmit` 0 错误；
`verify-material-pages.py` 8/0（含新增 P2c 单独位置）；API 冒烟 8/0（scopes、实验/执行单
范围过滤、PUT 位置标识并恢复、网格点未被误标）；流转页 UI 冒烟 9/0（含 `?experimentId=` 直达）。

⚠️ **既有失败（与本轮无关）**：`verify-plate-trace.py` 的「放板→取板」legacy 流程在 v3
模型下已跑不出留痕（内部格 `internal` + 装载口模型、装载口上有历史遗留板、R1C1 被页面
验证脚本设过 `plate_types`），其 ①②③④ 断言失败。本轮只把 ① 的过时断言
（「机器人 2 个中转位」）改成 v3 口径；新增的 ⑤ 实验范围断言不依赖该流程，已由 API 冒烟
与页面冒烟验证通过。**legacy 流程本身的重修需单独一轮，不在本轮范围。**

**回滚**：`DROP COLUMN` 不需要（两列可空/有默认值，旧代码忽略即可）；
