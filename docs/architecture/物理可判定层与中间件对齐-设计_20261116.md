## 0. 一句话结论

**LabOS 已经在"中间件"这个位置上了，不需要引入一个新系统；缺的是把闸门从"资源/身份"扩到"物理量"，把物理状态从"分散字段"变成"有血缘的孪生状态"。**

外部方案 A 的核心命题是：中间件夹在会思考的智能体和会动手的机械臂之间，
全部工作就是回答「**这条指令，此刻能不能真的执行**」，并且强调它
「不保证实验科学上成立，只保证实验物理上没有作弊」。

LabOS 的现状恰好是**已经有闸门链、账本、审计、物料投影，但没有物理量这一层**：

| 维度 | LabOS 今天能判定 | LabOS 今天不能判定 |
|---|---|---|
| 资源与时序 | 谁占用、谁先谁后、锁序、消环 | — |
| 位置与身份 | 板在哪个位、是不是那块板、证据够不够新 | — |
| **物理量** | — | **体积够不够、几何会不会撞、耗材还有没有、液面公差** |

而 LabOS 当前**唯一真正卡住上现场的两个外部依赖**（`docs/功能清单与实施路线-20261115.md` §2.1 A1/A2）
——物理布局配置缺失、机器人未标定——**恰恰就是"物理量"缺失**。

> **所以结合点不是"给 LabOS 加一个 AI"，而是：把"物理量"从"等客户来填的配置"
> 变成"从规则推导 + 可校验的约束"。**

## 1. 外部方案 A：可迁移的四项服务

只提取**可迁移的架构原则**，不摘录其案例细节。

| # | 服务 | 原则（一句话） | 本方案中的落点 |
|---|---|---|---|
| ① | 可查询的内省 | 不从日志猜、也不从像素推，**直接问此刻的物理状态** | §3 G1/G2 |
| ② | 时间压缩的仿真 | 把现场复制一份，在副本上把整段流程跑完，**等待被快进** | §3 G3 |
| ③ | 多模态轨迹留存 | 状态快照 / 影像 / 逐行日志 **对齐同一个时钟**；隐藏的执行力学要变成显式字段 | §3 G2/G5 |
| ④ | 安全执行 | 指令到硬件之前，**再对一次实时状态**；状态是**持久**的（活过多次运行与硬件故障） | §3 G1/G4 |

外部方案最有价值的一句判断是：**"它不是让实验变快，是让实验的误差变得可归因"**。
它把世界模型拆两半——**已知的物理用规则强制，未知的物理才交给数据**——
因此它的第一阶段**不需要学习模型**，只需要把规则写死、把痕迹记下来。

> 这一点决定了本方案的第一阶段**不上任何学习/残差模型**（见 §5 第二道墙）。

### 1.1 外部方案自己划的三道墙（我们必须对齐口径）

| 墙 | 含义 | LabOS 的对应墙 | 本方案的态度 |
|---|---|---|---|
| 动作类型 | 它管"笛卡尔坐标系内精确吸分液体"这一族动作；称量/回流/旋蒸/过柱不在动词表里 | LabOS 管设备动作（Transfer/Incubate/Dispense/Mix/Seal/Read），同样不管化学操作 | **同墙**：双方都不做化学合成 |
| 生物学复杂度 | 它用染料 + 去离子水验证；换成细胞，未建模变量多一个数量级 | LabOS 的 `sim/` 不建模流体与光学 | **同墙**：不承诺自愈，只做规则闸门 + 显式字段 |
| 记账边界 | 能追踪自己移动过的体积，**追踪不了反应本身**——那要靠分析仪器回填 | LabOS 能追踪板去了哪、耗材用了多少，**追踪不了反应** | **同墙**：见 §6 对外话术 |

**三道墙全对齐 ⇒ 这不是巧合，是同一类问题的同一组边界。** 差别在于：外部方案在自动化实验室里做，LabOS 在中控里做——**LabOS 的位置更靠后（更接近现场），所以它的"物理量"必须能被现场审计**。

## 3. 五个缺口（带落点）

### G1 · 物理量闸门缺位（L0）

**缺口**：现有闸门全部在判"资源 / 位置 / 身份 / 时序"，没有一条判"物理上做不做得到"。
外部方案 A 的核心事故场景是**语法完全正确、物理完全不能执行**——
LabOS 的对应场景是：流程参数合法，但源孔体积不足 / 耗材余量不够 / 通道间距超槽长。

**落点**：`driver/DriverStepExecutor.java:341`（`executeWithPlan` 入口）**之前**，
作为 **L0 物理可行性闸门**。

**为什么插在最前**：物理量判定是**纯计算 + 只读**，不占资源、不写库。
放在位置预留之前 ⇒ 物理不可行时**不产生任何资源占用与位置预留**（无泄漏）。

**判什么（第一批，只做能确定判的）**：

| 判据 | 数据来源 | 动作 |
|---|---|---|
| 源孔体积 ≥ 计划取量 + 底部间隙容差 | `plate_well.volume`（需先接通血缘，见 G2） | 拒 `EC-PHYS-VOLUME` |
| 耗材余量 ≥ 计划通道数 | `consumable_lot.remaining` | 拒 `EC-PHYS-CONSUMABLE` |
| 通道间距 ≤ 槽长（几何间隙） | `robot_point` / `device_point` + 耗材规格 | 拒 `EC-PHYS-GEOMETRY` |
| 目标位可达 | `robot_point.robot_reachable` | 拒 `EC-PHYS-UNREACHABLE` |
| 标定数据质量（坐标退化 / `fill_status=pending`） | `robot_point.fill_status` | 拒 `EC-PHYS-UNCALIBRATED` |

**口径（必须与既有链一致）**：
- fail-closed，但**只拦"确定不可能"**：数据缺失 ≠ 不可行 ⇒ 记一条待查，**放行**（见 §7 R4）
- 错误码族新增 `EC-PHYS-*`，在 `InterlockContract.SCOPES` 登记作用域
- 事实时效沿用 `InterlockContract.freshnessTtl`，新事实类型登记 TTL，未登记 → `ZERO`（实时取证）

### G2 · 孪生状态没有血缘（孔级 / 枪头级）

**缺口**：孔级体积**运行期**没有任何写入方。`plate_well` 有 `volume` 字段（`pg_rebuild/schema/30_business.sql:78-90`），
但该字段目前**只有一个设计期写入方**——`QpcrLayoutController.java:121-145`（先 `DELETE FROM plate_well WHERE plate_id = ?`，
再逐孔 INSERT 整板行，写入 `volume` 与 `status='filled'`，API `POST /api/qpcr-layout`），
它写的是**实验设计结果**（qPCR 布局的意图体积），**不是执行后的实际孔内液体**。
运行期的吸液/分液没有任何写入方（T2 物料投影写的是 `plate` 的 `process_state/seal_state/state_version`
与 `plate_material_effect*` 系列，**不写 `plate_well`、不写 volume**）。
耗材侧只有 `consumable_lot.remaining` 批次余量，
**"上一次哪个枪头用过"无法回答**（schema 中无 tip 级运行记录表）。

> **修订（2026-11-16 外部核验后）**：本节原表述为"`plate_well` 全仓库没有任何写入方（本次 grep `plate_well` 命中 0）——字段是死的"。
> 该**证据表述不成立**（设计期写入方确实存在），但**结论成立**（运行期写入方缺失）。
> 仓库自身的 `pg_rebuild/migration/20261116_twin_diff_report.sql:17`（"哪天开始 plate_well 还没有写入方"，指运行期）
> 与 `docs/评审记录/20261112-01-grok.md:105`（"内核 Java 侧没有写入点"）口径正确，应以它们为准。
> **同时新增一个必须先裁决的问题**：设计态与运行态要写同一张表的同一个 `volume` 列，
> 构成两个写入方、两种语义，直接违反下文"唯一写入方原则"——见 §8 Q10。

这正是外部方案 A 强调的"**持久**"：它要记住"上一次哪个枪头用过了、哪个孔被读板器搬走过、哪一步中途报过错"，
并指出**没有这份记忆，"从故障点续跑"根本无从谈起**。

**落点**：
- 孔级体积：物料投影 T2（`material/MaterialEffectService.java:346/:510` 的 `updatePlateState`）
  —— **唯一写入方**，业务代码不得直接写 `plate_well`
- 枪头级台账：新增 `tip_usage`（run_id / node_id / channel / tip_id / 动作 / 体积 / z 高度），
  由同一次物料投影落库
- 查询面：新增 `GET /api/twin/state`（聚合 `device_state` / `position_state` /
  `plate_well` / `robot_point` / `consumable_lot` / `tip_usage` → "此刻现场"一次返回）

> **唯一写入方原则**是这套东西能不能用的分水岭：多写入方必然出现状态漂移，
> 而状态漂移会让"可查询内省"直接退化成"从日志猜"——那就白做了。

### G3 · 仿真没有时间轴、没有持久化

**缺口**（§2.2 ②）：无 time-scale；`sim/` 状态全在内存。

**落点**：
- `sim/DeviceCore.java` 行为对象（内存态）→ 增加**孪生快照落库**（快照即"此刻现场"，
  复用 G2 的 `plate_well` / `position_state` 表达，不另起一套）
- 模拟器增加 `--time-scale`（30 分钟孵育 → 30 秒）
- 续跑：外部方案的"把板移出读板器、空腔校准、把读数补完（不重新移液）"，
  在 LabOS 的对应物是 **`run` 续跑 + 账本 UNKNOWN 对账 + 物料/位置 reconcile**。
  **LabOS 已经有一半**（`run_quarantine`、`command_ledger` 的 UNKNOWN 对账、`position_evidence`、
  `plate_location_audit`）——缺的是"孪生状态能告诉续跑**从哪一步接着做**"

**诚实的边界**：不做"从任意历史状态重放并还原物理现场"。这一条只做
"**同一次运行内**，设备报错后能否基于孪生状态续跑"。

### G4 · 权威下发前闸门层级未定

**缺口**（F1）：run 路径上的下发前检查分散在
`AdmissionController`（启动准入，**由前端调用**）、
`IslandBindingGate` / `HandoffGate`（派发期）、
`DriverStepExecutor` 闸门链（下发瞬间）。
**哪一层是"权威下发前闸门"没有定义**。

**为什么必须在加 L0 之前裁决**：2026-11-15 已经踩过一次同型坑——
L4 搅拌复核最初对**每条**设备命令生效，而配对表 0 行 ⇒
每条命令都 `EC-STATE-UNKNOWN` ⇒ **全平台发不出命令**。
L0 若重演，即是第二次停摆。

**建议裁决**：**下发瞬间的 `DriverStepExecutor` 闸门链 = 唯一的权威安全闸门**；
设计期预检与启动准入降级为**体验层**（给提示，不给安全保证）。

### G5 · 结果侧空白（**最被低估的一条**）

**缺口**：LabOS 管到"命令发出去了、位置确认了、物料投影了"，**不管"结果对不对"**。

外部方案 A 明确区分三类故障，前两类会报错，**第三类不报错**——
"代码跑通了，数据也出来了，但没被建模的流体效应把结果悄悄改了，**它会给你一个漂亮的、错的数**"。
它举的例子是：梯度稀释目标 log2 斜率 −1.00，实测只有 1.4–1.8 倍，
靠**重复实验**修不好（重复只会把同一个偏差复制得更精确），
只能靠"**让缺陷自己搬家**"的因子诊断定位到具体物理机制。

LabOS 的对应空白：**没有任何机制能发现"结果偏了"**。
`capability_recipe.criteria`（`pg_rebuild/schema/30_business.sql`）字段已存在，
但**全仓无任何读取方**（本次 grep `criteria` 命中 0）——这是为"每步的验收判据"预留的坑，
**现在正好可以填**。

**落点**（**中期，本方案不承诺**）：
读板结果回填 → 与声明值比对 → 偏差登记 → 归因到"未建模物理清单"。
配套需要一张**未建模物理登记表**（`unmodeled_effect`）：现象 / 首次观测 / 当前假设 / 验证状态。

> **诚实口径**：这一条是论文级的，LabOS 的仿真不建模流体与光学，
> **本方案不承诺自动归因**，只承诺"把偏差变成可查询的显式记录"。见 §5 第二道墙。

### P-D · agent 入口（**是否立项取决于 §8 Q1 裁决**）

| # | 交付 | 说明 |
|---|---|---|
| D1 | 只读工具集（状态查询 / 诊断） | **只读先行**；工具分级 READ / CONTROL / HAZARD；**数据来源必须标注**（仿真数据必须标"仿真"） |
| D2 | 控制类工具**必须**走同一条闸门链 | **不得旁路**——这是与外部方案的安全分工：它保证"物理上没有作弊"，不保证"科学上成立" |
| D3 | `trace_id` 透出到 agent 层 | 仓库已有 `audit_log.trace_id`，MCP 层要透出 |

> **差异化护城河**（来自 `private/` 竞品调研，**不外发**）：现有开源 agent-仪器接口
> 覆盖的是**台式仪器**（读数、设温度、启动程序），**没有板 / 没有孔位语义**。

> ⇒ 结论：**P-D 的价值必须落在"板级物理语义 + 审计"，不能落在"工具数量"**。

### P-E · 结果自检与偏差归因（**远期，论文级，本方案不承诺**）

读板结果回填 → 与 `capability_recipe.criteria` 比对 → 偏差登记 → 归因。
**当前只做"把偏差记下来"**（A3 的登记表），不做自动归因。

## 5. 三道墙（必须写进对外材料与评审结论）

1. **动作类型墙**：LabOS 的动词表覆盖设备动作，**不覆盖化学操作**（称量/回流/旋蒸/过柱）。
   与外部方案 A 同墙。⇒ 对外不说"全流程自动化实验室"。
2. **生物学复杂度墙**：`sim/` 不建模流体与光学 ⇒ **不承诺自愈、不上学习模型**。
   第一阶段只做"规则闸门 + 显式字段 + 未建模物理登记"。
3. **记账边界墙**：LabOS 追踪板去了哪、耗材用了多少，**追踪不了反应本身**——
   那要靠分析仪器回填。

> **对外定位话术（建议采用）**：
> **「LabOS 保证过程物理上没有作弊，不保证科学上成立。」**
> 这句话比"全自动实验室"诚实，且与实际能力一致。
