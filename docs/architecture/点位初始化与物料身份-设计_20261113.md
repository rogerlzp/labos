## 2. 设计目标与非目标

**目标**

1. 岛建好后，按**设备型号**一次性生成该设备全部点位（名称、物理位置、顺序确定）；
2. 中控持有一层显式配置：点位归哪台设备、机械臂是否直达、是进口/出口/两者皆是/内部位；
3. 实验开始前能看到**所有**点位及其占用、板上内容（板/耗材/样品/试剂/空），并留一份快照；
4. 未扫码的板用临时板号把链路串起来，扫到真 barcode 后**关联**而非改写历史；
5. 调度/搬运按点位角色选位，不再写死方向。

**非目标**（本轮不做）

- 不做盖子独立实体、试剂余量/死体积、板内容标签（见映射文档 §四.B）；
- 不改老系统 2563 个点位的 `legacy_id` 语义；
- 不改 `plate_material_*` 的事件/版本链语义。

## 3. 点位初始化配置层

### 3.1 分层（不新建平行模型，把预留表用起来）

```
device_point_template   型号级模板：某型号有几个点位、每个点位的角色/可达/门/通道/顺序
        │  初始化时展开
        ▼
resource_node (点位实例)  parent_id = 设备；location = 物理坐标；code = 稳定命名
        │
        ├── device_point (★新增配置层)  点位级语义：归属设备 / 角色 / 可达 / 通道 / 门 / 顺序
        ├── robot_point                机械臂侧：坐标 + access_id/port_id/approach_axis/fill_status
        └── position_state            运行态：一行/点位，初始化即写空行
```

**为什么不直接给 `resource_node` 加列**：那张表混了岛/站/设备/机械臂/人员 9 类，
加只服务点位的列会让主表语义发散；独立配置层可带 CHECK、可版本化、可只影响点位。

### 3.2 新增 `device_point`（配置层主表）

```sql
CREATE TABLE IF NOT EXISTS device_point (
  id                 bigserial PRIMARY KEY,
  tenant_id          bigint NOT NULL,
  device_resource_id bigint NOT NULL REFERENCES resource_node(id),   -- 归哪台设备
  point_resource_id  bigint NOT NULL REFERENCES resource_node(id),   -- 哪个点位
  point_role         varchar(8)  NOT NULL DEFAULT 'both',
  robot_reachable    boolean     NOT NULL DEFAULT true,
  is_entry           boolean     NOT NULL DEFAULT false,
  is_exit            boolean     NOT NULL DEFAULT false,
  approach_axis      varchar(16) NOT NULL DEFAULT 'front',
  access_id          bigint,                    -- 到访前必须开的门
  port_id            bigint,                    -- 通过哪个通道可达
  order_in_device    int         NOT NULL DEFAULT 0,
  max_stack          smallint    NOT NULL DEFAULT 1,
  requires_door      boolean     NOT NULL DEFAULT false,
  note               text,
  created_at         timestamptz NOT NULL DEFAULT now(),
  updated_at         timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uk_device_point UNIQUE (tenant_id, point_resource_id),
  CONSTRAINT ck_device_point_role CHECK (point_role IN ('entry','exit','both','internal')),
  CONSTRAINT ck_device_point_flags CHECK (
      (point_role <> 'internal' AND (is_entry OR is_exit))
      OR (point_role = 'internal' AND NOT is_entry AND NOT is_exit))
);
COMMENT ON TABLE device_point IS
  '设备点位配置层：中控持有「哪个位置归哪台设备、机械臂能否直达、进口/出口」；机械臂只提供坐标与点位 code';
```

**一个设备既是进口也是出口**：`point_role='both'`（或 `is_entry=true AND is_exit=true`）。
**培养箱/液体站多进多出**：同一 `device_resource_id` 下多条 `entry`/`exit`/`both` 点位 +
`order_in_device` 排序 + `internal` 表示设备内部位（机械臂不可达）。
`robot_reachable=false` 的点位不参与搬运选位。

### 3.3 `device_point_template` 补齐型号数据

现表 0 行。按设备型号（`device_model`）为每个点位定义一行模板，字段沿用现有列，
并补 `point_role` / `robot_reachable` / `is_entry` / `is_exit` / `order_in_device`：

```sql
ALTER TABLE device_point_template
  ADD COLUMN IF NOT EXISTS point_role varchar(8) NOT NULL DEFAULT 'both',
  ADD COLUMN IF NOT EXISTS robot_reachable boolean NOT NULL DEFAULT true,
  ADD COLUMN IF NOT EXISTS is_entry boolean NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS is_exit boolean NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS order_in_device int NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS point_code_suffix varchar(32);
```

### 3.4 初始化流程（幂等，可反复跑）

1. 选岛 → 列出岛上 `kind='device'` 节点；
2. 按 `device_instance` 的型号查 `device_point_template`；
3. 对每个模板点位：`INSERT INTO resource_node ... ON CONFLICT (tenant_id, code) DO UPDATE`
   （`parent_id=设备`、`kind=incubator|storage|transfer_point`、`location` 写物理坐标、
   `code = 设备code + '-' + point_code_suffix`）；
4. `INSERT INTO device_point ... ON CONFLICT (tenant_id, point_resource_id) DO UPDATE`；
5. `INSERT INTO position_state (tenant_id, resource_id, updated_at) VALUES (...)
    ON CONFLICT (tenant_id, resource_id) DO NOTHING` —— **这一步解决「实验前看不到全部点位」**；
6. 与机械臂同步：`robot_point` 写坐标 + `access_id/port_id/approach_axis/fill_status`
   （现有 `syncRobotPoints` 只写 `name/device_resource_id/action/synced_at`，需补齐）；
7. 自检：每台设备的点位数 ≥ 1、`position_state` 行数 = 点位数、角色至少有一个可达的
   entry/exit。

> 与现有 `scripts/baseline-build.sql:79-101` 的关系：那份 CROSS JOIN 写死 6 个点位，
> 属于一次性基线；新流程以模板为准，基线脚本保留为回归对照。

### 3.5 与调度侧衔接

- 选位 SQL（`DeviceStateMapper.xml:310-341`）改为 `JOIN device_point dp ON
  dp.point_resource_id = r.id`，按调用意图过滤：
  - 取板（source）→ `dp.is_exit = true AND dp.robot_reachable = true`
  - 放板（target）→ `dp.is_entry = true AND dp.robot_reachable = true`
  - 按 `dp.order_in_device` 排序，不再依赖 `r.id` 的偶然顺序
- `TransferPlan.java:134,140` 两处硬编码 `"in"` → 按源点位 `is_exit` / 目标点位 `is_entry`
  取 `device_port.direction`；`DeviceAccessManager.accessOf` 改为按 `dp.access_id`。
- `GET /api/positions` 改为从 `resource_node` **全量左连接** `position_state` + `device_point`。

## 5. 临时板号 → 真 barcode 的身份层（🔴 关键红线）

### 5.1 红线：不要改写历史字符串

`plate_location_audit` / `position_evidence` / `transfer_transaction` 是**证据/审计**表，
`plate_material_event` 有版本链。扫码后去 `UPDATE` 这 5 张表的历史 barcode 等于伪造历史，
且会破坏 `changed_fields` / 版本链的自洽。全仓现无 `UPDATE plate SET barcode`，这个约束要保住。

### 5.2 方案：不可变 `plate_uid` + 别名表

```sql
CREATE TABLE IF NOT EXISTS plate_barcode_alias (
  id           bigserial PRIMARY KEY,
  tenant_id    bigint NOT NULL,
  plate_uid    bigint NOT NULL,              -- 指向 plate.id，物理板身份，永不改变
  alias        varchar(64) NOT NULL,         -- TMP-... / 真 barcode / 老条码
  alias_kind   varchar(12) NOT NULL,        -- TEMP / SCANNED / LEGACY
  is_canonical boolean NOT NULL DEFAULT false,
  first_seen_at timestamptz NOT NULL DEFAULT now(),
  seen_run_id  bigint,
  note         text,
  CONSTRAINT uk_plate_alias UNIQUE (tenant_id, alias),
  CONSTRAINT ck_plate_alias_kind CHECK (alias_kind IN ('TEMP','SCANNED','LEGACY'))
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_plate_alias_canonical
  ON plate_barcode_alias (tenant_id, plate_uid) WHERE is_canonical;

ALTER TABLE plate
  ADD COLUMN IF NOT EXISTS identity_status varchar(16) NOT NULL DEFAULT 'CONFIRMED';
-- PROVISIONAL = 未扫码的临时身份；CONFIRMED = 已读到真 barcode
```

**临时号按点位生成，不按 run 生成**：

```
TMP-{runId}-{pointResourceId}-{seq}
```

解决现状 `AUTO-{runId}` 在同一 run 只能有一块占位板的问题（多板/并行分支必须区分）。

**扫码后只做三件事**（不 UPDATE 历史字符串）：

1. `INSERT plate_barcode_alias(plate_uid, alias=真barcode, alias_kind='SCANNED', is_canonical=true)`；
2. `UPDATE plate SET identity_status='CONFIRMED'`（只改这一列，不改 barcode）；
3. 保留所有历史 `TMP-` 字符串原样。

**统一解析入口** `PlateIdentity.resolveUid(barcode)`：先查 `plate.barcode`，
未命中查 `plate_barcode_alias` → `plate_uid`。所有按板查历史的 API 走它，
于是 `TMP-...` 与真 barcode 自然指向同一块板，链路串起来而历史不被改写。

### 5.3 与现有代码的接口

| 现有位置 | 改动 |
|---|---|
| `PositionLock.resolvePlateId` 的 `AUTO-{runId}` 兜底 | 改为 `TMP-{runId}-{pointId}-{seq}`，且**不落 `plate` 表**为永久真板 |
| `DeviceStateMapper.xml:360-368` `insertPlateIfAbsent` | 建 `identity_status='PROVISIONAL'` 的板行 + 一条 `TEMP` alias |
| `resolvePlateBarcode`（本轮已加） | 仍拒绝 `AUTO-`/`${}`/数值；新增对 `TMP-` 的放行（它是合法临时身份，不是脏占位） |
| `MaterialMapper.xml:115` `p.barcode = ps.plate_id` JOIN | 保留；需要跨临时号关联时改走 `PlateIdentity.resolveUid` |
| 模拟器 `DeviceCore.java:925-955` 通用回包 | 为 `ReadBarcode/BarcodeScan` 加专门回包 `{"barcode":"<真条码>"}`，并支持注入指定值以便验收 |

**语义澄清**：拒绝 `AUTO-` 拒绝的是「把同一 run 的未知板都塞进一个假身份」，
不是「拒绝记录未知板」。`TMP-` 是按点位的、可关联的合法临时身份。
