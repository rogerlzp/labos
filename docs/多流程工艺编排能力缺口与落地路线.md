## 〇、结论摘要（一句话版）

> **三条新增流程共用同一个执行骨架，LabOS 已经具备这个骨架；
> 真正缺的是八块公共底座，而八块里最贵的不是设备驱动，是「工位层」和「胶水层」。**
>
> ① **编排层直接可用**：循环 / 并行 / 条件分支 / 人工介入 / 幂等 / 超时 / 留痕 ——
>    四条流程线的骨架全部落在这个范围内。
> ② **缺八块底座**：外部系统调用与文件通道、工位层、转运接力链、物料身份与状态、
>    设备驱动、事件与触发器、扫码校验、耗材与试剂目录。
> ③ **一次投入，多线复用**：三条流程反复出现同一组模式 ⇒ 这不是三个定制项目，
>    是**一个平台能力缺口**。
> ④ **交叉验证**：本文独立印证了物料视角线的结论 —— "LabOS 编排的是动作，
>    真实工艺编排的是物料 + 位置 + 事件"，而且给出了更硬的证据
>    （台面工位号、多臂接力链）。

## 一、四条流程线概览（横向对照）

| | 物料视角线（分子生物） | 细胞培养岛 | 化合物管理岛 | 文库制备岛 |
|---|---|---|---|---|
| **做什么** | 扩增 → 纯化 → 酶切 → 体外转录 → 检测 → 显色 | 细胞计数 → 种板 → 换液 → 收获 → 转板 | 化合物库：溶解、稀释、分装、梯度稀释、挑选 | 样本前处理 + 文库构建 + 上机前质控 |
| **岛** | 单岛 | 细胞岛 + 高通量岛 | 化合物管理岛 | 前置岛 + 后置岛 |
| **子流程** | 14 个 | 3 个主流程 + 2 组测试 | 8 个主流程 + 试管校验 + 梯度稀释 | 前置 9 段 + 后置 10 段 |
| **液体工作站方法** | 少（以设备动作为主） | 10 个 | 8 个 | 约 25 个 |
| **设备** | 多工位平台为主 | 约 25 类（双机械臂、双导轨、多个处理单元） | 10 类 + 岛外物流 | 约 15 类（含磁珠提取仪、恒温位、氮吹仪、实时荧光定量仪） |
| **耗材目录** | 未成表 | 23 种（含盖子、试剂槽、试管架） | 试管理架 / 板 / 槽 | 约 23 种（吸头盒、试剂槽、提取板、培养板） |
| **体积 / 浓度计算** | 浓度调整 | 细胞数 → 体积映射 | **孔位死体积 + 当前体积** | 稀释梯度定量 |
| **外部系统** | 无 | **实验室信息系统下单 + 成像计数** | **化合物管理系统自身 6 个接口** | 质控数据 → 生成工作站文件 |

> **共同点**：三条新流程都把**液体工作站**放在中心位置，且都把"工作站方法 + 输入输出文件"
> 当作一等公民。
> **差异**：细胞培养岛难在**转运拓扑与数据驱动**；化合物管理岛难在**外部系统与库存**；
> 文库制备岛难在**工位与批量**。

## 二、八种跨流程复现的模式（这才是真正的需求）

> 下面 8 条在**三条新增流程里都出现**。⇒ 它们是产品需求，不是某个客户的定制。

### P1 · 液体工作站方法 = 方法名 + 输入文件 + 输出文件

| 流程 | 证据 |
|---|---|
| 细胞培养岛 | 方法对照表：`PrepareForCellCounting` ← 板码输入表 / 样本计数表 → 输出表；文件来源列写着"中控" / "中控/成像" |
| 化合物管理岛 | 脚本节点调化合物管理系统 → 生成输入表 → 上传对象存储 → 赋给文件变量 → `RunMethod` 消费 → 输出表回传 |
| 文库制备岛 | 约 25 个方法名；"**中控通过收到的质控数据，生成工作站需要的文件**" |

⇒ **三条流程共用同一个抽象**。LabOS 今天的设备命令模型是「方法 + 载荷，跑一个动作」，
**对"带文件参数的外部方法"零支持**。

### P2 · 台面工位（P 系列 / T 系列）

| 流程 | 证据 |
|---|---|
| 文库制备岛 | 试剂槽放 P 系列、浅孔板放 P 系列、吸头盒放 T 系列；**液面上还有 T8 / T10** |
| 细胞培养岛 | 「台面位置对照表」17 行：序号 / 耗材标识 / 条码 / 备注（哪块板放哪个槽） |
| 化合物管理岛 | 台面命名：试剂槽 / 化合物试管架 / 耗材板 / 挑选板，各带编号 |

⇒ **工位层是三条流程的公共词汇表**，且 LabOS 的 `resource_node.kind` 里**没有这一层**。

### P3 · 批量展开 + 工位分配

| 流程 | 证据 |
|---|---|
| 文库制备岛 | "重复上述操作，直到 **10 块** 培养板全部放到台面上" —— **落位不连续，被占用的工位被跳过**；"直到 4 块样本板全部放入" |
| 细胞培养岛 | "重复拍照流程，直到完成 4 块板子"；"该批次剩余的培养板重复执行以上动作" |
| 化合物管理岛 | "1~4 块 96 板"、"以 3 块板是一个批次，8 块板就分成 3、3、2" |

⚠ **文库制备岛文档自己暴露了一个冲突**："把板子从氮吹仪转移到液体工作站（**P8 位置？？目前冲突！**）"
⇒ 需要的不是"人工指定位置"，而是"**从空闲工位里分配一个**"。

### P4 · 数据驱动的分支与数量决策

| 流程 | 证据 |
|---|---|
| 细胞培养岛 | `case1` 细胞数高于阈值 → 取 4 块培养板并补加培养基；`case2` → 3 块；`case3` → 2 块；`case4` 低于阈值 → **"提示：样本质控失败"**。换液流程触发收获流程有**三种方式**：(1) 质控结果 (2) **中控指定条码换液（或实验室信息系统下单给中控）** (3) 换液循环结束 |
| 化合物管理岛 | 校验通过继续 / 失败终止；"需要体积 <= 系统体积 − 孔位死体积" |
| 文库制备岛 | "中控校验板码"（多处）、"中控通过收到的质控数据，生成工作站需要的文件" |

⚠ **细胞培养岛明确要"定时"**："（1）种板结束后，**启动记时，到时换液**" ⇒ 这不是"睡 N 秒再往下走"，
是**到点触发另一件事**。

### P5 · 盖子 / 耗材是独立实体

| 流程 | 证据 |
|---|---|
| 文库制备岛 | "盖子**扔进垃圾桶**"、"工作站把**盖子**放到工作站台面"、"耗材堆栈出板盖" |
| 细胞培养岛 | "给样本板开盖，**把盖子放到暂存架**"、"**盖子对应的记录**"、"盖子位置？"（全文出现十余次） |
| 化合物管理岛 | 开关盖机"盖子保持在开盖机"、暂存位专门"放置溶剂的盖子" |

⇒ 三条流程都要求**盖子有自己的位置、库存和记录** —— 这正是物料视角线 G2 的"盖子那半边"。

### P6 · 废料与消耗

文库制备岛：垃圾箱（吸头盒、试剂槽、板子、盖子）｜细胞培养岛：固体废弃物处置 + 冲洗单元清洗管路 ｜
化合物管理岛：废液桶液位报警（客户自己记为已知问题）

### P7 · 外部系统

化合物管理岛（6 个接口）｜细胞培养岛（**实验室信息系统下单给中控** + 成像计数）｜
文库制备岛（质控数据 → 生成文件）

### P8 · 转运是"接力链"，不是"一对 from/to"

细胞培养岛的典型链（一步搬运跨 **4 个搬运主体**）：

```
机械臂 B ──► 中转位 1 ──► 机械臂 A ──► 板架位 ──► 导轨 B ──► 液体工作站台面
```

⇒ LabOS 的 `resource_node` 是"设备"、`position_state` 是"位置"，
但 **"中转位是什么"和"一次搬运是一段接力"** 两件事都没有表达。

## 五、新增发现（旧报告没有的六条）

| # | 发现 | 证据 | 判断 |
|---|---|---|---|
| **X1** | **转运是接力链**，一步搬运跨 4 个主体 | 细胞培养岛全文 | 需要新的"搬运段"模型，不只是 from/to |
| **X2** | **一个动作有"参数化模板 + 变体"** | 细胞培养岛的十九步固定模板 + 四个 case 只改数量与体积 | 与物料视角线结论一致：**要"工位动作模板"，不要"每个流程手写十几个节点"** |
| **X3** | **工位要自动分配，且客户已经撞上冲突** | 文库制备岛"（P8 位置？？目前冲突！）" | 人工指定位置不可持续，必须有"分配空闲工位" |

| **X5** | **方法需要版本 + 结构化参数契约** | 细胞培养岛"（忽略孔位序号，是 96 头序号）"、"（体积）"；文库制备岛同一方法跑两遍 | 平铺 CSV 不够，方法要有 schema |
| **X6** | **"并行段"是资源让渡，不是流程分支** | 文库制备岛"这 10 分钟，工作站将三块样本板转出" | 与物料视角线"用不到网关"结论一致：**并行是资源占用问题** |

## 六、统一扩展路线

> **排序依据**：
> ① 先补**不依赖真机、可影子验收**的公共底座 → ② 再做依赖手册的设备层 → ③ 最后做范式级的物料/事件。
> **不按流程排期，按底座排期** —— 因为三条流程共用。

### 阶段 0 · 胶水层（第一刀，不依赖真机）

| 动作 | 覆盖 |
|---|---|
| **0.1 执行期参数再解析** —— 设备命令参数在**执行期**解析 `${x}`（运行时变量表），不只在加载期 | B1 |
| **0.2 `__http` 白名单节点** —— 方法/URL/头/体（表单或扁平 JSON）/超时/重试/**响应体存变量**；域名白名单 + 审计 | B1 |
| **0.3 文件通道** —— 对象存储客户端 + 上传下载端点 + `run_artifact` 挂接（`file_blob` 表已有，零实现） | B1 |
| **0.4 `__csv` 节点** —— 读 CSV → 变量表（表头映射）/ 写 CSV → 文件 | B1、X5 |
| **0.5 命令返回值结构化回填** —— 让 `DriverResult.outputs` 真被填；替掉现在的正则抠值 | B1 |

⚠ **0.1 是 0.2 的前置**：化合物管理岛的"文件变量"模式（脚本节点写路径 → 下个节点消费）
今天必然断链，因为设备参数只在**图加载期**解析一次（`WorkflowService.java:919,1500-1548`），
而 `__setVar` 只改内存不回写库（`GraphRunner.java:121`）。

⚠ **不要直接上"通用脚本节点"**：[自定义脚本节点-设计](自定义脚本节点-设计.md) 已选方案 C（独立进程 + 受限 API），
方向对但工程量大、该文档自标"全系统风险最高"。三条流程的实际需求只是
"调几个固定 HTTP 接口 + 传文件 + 解析 CSV" ⇒ **白名单 `__http` 够用且安全得多**。

**验收（可影子跑，不碰真机）**：mock HTTP + mock 对象存储 ⇒
`__http` 取回表文件路径 → `__csv` 解析 → `__http` 上传 → 变量传给下一个设备命令 ⇒
**化合物管理岛的第一条主流程影子跑通**。

### 阶段 1 · 工位与接力（B2 + B3 + X3 + X4）

| 动作 | 覆盖 |
|---|---|
| 1.1 `resource_node` 下增加**工位**层（`parent_id` 现成） | B2 / G4 |
| 1.2 `position_state.port_id` 改成真正的工位引用 | B2 |
| 1.3 **空闲工位分配**（"给我这台设备下一个空位"），替代人工指定具体位置 | X3 |
| 1.4 **中转位**建模 + **搬运段**（一次搬运 = 一串接力） | B3 / X1 |
| 1.5 液体工作站"台面内 / 台面外"双交接位 | X4 |

**验收**：文库制备岛的一段 —— 耗材堆栈出 10 块培养板 →
机械臂扫码 → 自动分配 10 个空闲台面位 → 放好 —— **不需要真机，仿真总线即可**。

### 阶段 2 · 物料身份与状态（B4）

沿用物料视角线 G1/G2/G11：板级工艺阶段（`process_state`）、**盖子作为独立实体**、
废料状态、耗材类型分类。**三条流程共同需要**，且旧报告已出设计稿。

> ⚠ 口径提醒：**化合物成分账不进 LabOS**（委托化合物管理系统，自建会形成双份真相）；

### 阶段 3 · 设备驱动（B7）
