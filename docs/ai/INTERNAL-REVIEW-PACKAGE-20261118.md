## 1. 背景：为什么现在做这件事

LabOS 现在是设备中控：流程执行、设备通信、板位与物料跟踪、暂停恢复。它已经能跑通真实实验流程，但也积累了 G0 核查发现的执行安全问题。

AI 化的诱惑是"让模型直接指挥设备"。本方案的立场相反：

> **AI 负责推理与建议，LabOS Core 负责授权、校验、执行、状态和事实。**
> 自然语言永远不能直接变成设备命令。

这条边界决定了整个设计：AI 只能产出"草案"，必须经过结构化 DSL → 编译 → 校验 → 资源规划 → 仿真 → 人工批准 → 冻结快照，才能进入执行。本次材料就是这套边界的完整落地设计。

## 4. 核心设计主张（供讨论，不是结论）

1. **AI 不直接控制设备**，只调用受控业务工具。
2. **命令完成 ≠ 物理完成**：命令事实、物理事实、流程事实、实验事实四流分离，由 Reconciler 对账，无法判定时进 `UNKNOWN / NEEDS_RECONCILIATION`。
3. **对象级授权**：`Allow = TenantMatch ∧ ProjectMembership ∧ SubjectPermission ∧ CapabilityPolicy ∧ ResourceStatePolicy`；Agent 权限取交集，不取并集，且每次工具调用重新授权。
4. **数据默认不出域**：D0–D3 四级，D2 默认不出域、D3 禁止外发；供应商条款不明时状态为 `UNKNOWN`，禁止出域。
5. **成熟度逐对象评级**：L0–L4、证据 E0–E5，禁止跳级，`UNKNOWN` 不得默认通过。
6. **准入按数据流分档**（09 §6 的 7 档）：合成数据开发 → 内部演示 → 真实只读 → 真实 readiness → 真实草稿 → 确认实例化 → 设备执行（本期**不允许**）。

第 6 条是本次最重要的落地创新：**不再用一把总闸，而是按"这条能力实际碰不碰真实数据、有没有副作用"分别设门**。

## 5. 三个争点（会议必须裁决）

### 争点 A：第一阶段到底交付什么

**需要确认**：以 09 的裁决为准，还是 07 的"未裁决"为准？两者结论相反。

### 争点 B：对象级 ACL 的门槛放在哪

- 原 30 天方案：本期只做"角色 + 租户"，项目级 ACL 延后
- 09 §9 #2 **部分接受**：**不采纳**"降级到租户+角色"，而是要求真实数据前必须完成 Project ACL

**这是成本项**：ADDENDUM 已把估工修正为 **35–44 人日**，并明确"不含安全治理、ACL、审计补强的额外工作"。如果按 09 执行，真实数据阶段的实际人日可能显著高于 44。

**需要确认**：是先只做合成数据（ACL 可以延后），还是同步投入 ACL？两种都合理，但必须选一个，否则任务卡会自相矛盾。

### 争点 C：时间线口径

04 已改为"最早开工 / 最早完成"双列，重叠只表示可并行准备。但 12 个月总周期、G1 与 30 天方案的归属仍未有单一权威表述。

**需要确认**：是否接受"30 天试点归 G1 准备阶段、不占独立 G 编号"（09 §9 #3 的裁决）。

## 6. 两个可立即开工的热修

这两个与 AI 路线**解耦**，不占 AI 工期，可独立分支、独立 PR、独立验收。

| | G0-01 | G0-07 |
|---|---|---|
| 问题 | 门禁 fail-open + 准入非原子 | 能力映射丢参 |
| 范围 | 新建 + **resume 再激活** + 异步 worker 失败收尾 | 两处透传 + 全仓调用点清查 |
| 验收 | **29 组 / 33 个可独立判断单元** | **14 项** + 判别性夹具 |
| 关键要求 | 数据库级原子准入（同事务同连接）、终态 `active ≤ 1`、`COMMIT-UNKNOWN` 与 `DENY_UNKNOWN` 区分 | 完整 `NodePlan` 三方一致、旧实现必须失败 |
| 风险 | 改错会让流程"再也起不来"，必须有回滚方案 | 低 |

**开工顺序**（不可颠倒）：先写能打穿旧实现的失败测试 → 确认旧代码确实失败 → 最小修复 → 跨连接/跨进程并发验证 → 独立 QA 验收。
