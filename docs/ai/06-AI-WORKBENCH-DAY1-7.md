> **日期**：2026-11-18

> **上游契约**：[AI Workbench 第 0–30 天实施拆解](05-AI-WORKBENCH-0-30D.md)。
> **本稿交付**：数据库迁移、异步 worker、权限与审计三张可直接开发的任务卡，以及联调顺序和批次出口标准。

## 0. 一周交付目标与依赖

### 0.1 周末应形成的能力

- 新库和既有库都能幂等建立 `ai_task/ai_artifact`，结构漂移会明确报错。
- 通用 AI 任务可以创建、查询、领取、重试和取消，长任务不占用 HTTP 请求线程。
- worker 崩溃或取消后，旧执行体不能覆盖新 attempt 的状态或产物。
- viewer/未知角色只读；草稿确认实例化预留 operate 权限，不允许 designer 越权。
- AI 未配置时返回稳定降级结果；非 AI 功能不受影响。
- 成功、失败、重试、取消和越权均有可追溯审计，密钥与原始供应商响应不落日志。
- 三张卡合起来仍**不连接真实模型业务处理器、不生成实验、不执行设备**；真实草稿生成属于第 8–15 天。

### 0.2 依赖与估工

| 任务卡 | 名称 | 估工 | 依赖 | 可并行关系 |
|---|---|---:|---|---|
| T1 | AI 数据对象与幂等迁移 | 2–2.5 人日 | 上游字段契约已评审 | 开始最早；T2/T3 依赖其表契约 |
| T2 | 异步任务服务与 worker | 2.5–3 人日 | T1 表结构、现有 Tx/Mapper 约定 | 表契约冻结后可与 T3 并行 |
| T3 | RBAC、AI 降级与审计 | 2–2.5 人日 | T1 实体 ID；T2 端点骨架 | 与 T2 并行，最后联调 |
| 联调 | 三张卡集成与全量回归 | 0.5–1 人日 | T1–T3 完成 | 第 6–7 天 |

总计约 **7–9 人日**。另有一项非编码工作并行进行：按上游 §9 采集现有流程基线，建议 1 人日，由产品/领域用户负责，不占用三张开发卡。

### 0.3 三张卡共同冻结的契约

- `taskId/artifactId` 均为 `bigint`，可直接写入现有 `audit_log.entity_id`。
- 任务状态仅：`QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED`。
- 任务类型仅：`EXPERIMENT_DRAFT/READINESS_EXPLAIN/RUN_REVIEW`。
- 创建任务返回 202；查询返回 200；未配置返回 503/`AI_NOT_CONFIGURED`。
- 重试使用同一 taskId，`attempt + 1`；SUCCEEDED 不允许重试。
- artifact 消费记录使用 `consumed_experiment_id + consumed_run_id + consumed_at`，不能只保存其中一个业务 ID。
- 所有 SQL 都带租户条件；当前固定租户部署不等于完成动态多租户改造。
- AI worker 不依赖、不调用任何实验启动、运行控制、设备命令、物料核验或驱动服务。

## T1-3 数据定义要求

### A. `ai_task`

| 列 | 定义要求 |
|---|---|
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `tenant_id` | bigint NOT NULL，引用 tenant |
| `task_type` | text NOT NULL，三类型 CHECK |
| `subject_type` | text NOT NULL，仅 `PROJECT/EXPERIMENT_RUN/RUN` |
| `subject_id` | bigint NOT NULL；多态主体由服务层校验，不假装一个 FK 能约束三张表 |
| `status` | text NOT NULL DEFAULT `QUEUED`，五状态 CHECK |
| `idempotency_key` | text NOT NULL；`UNIQUE(tenant_id, requested_by, idempotency_key)` |
| `input_json` | jsonb NOT NULL DEFAULT `{}` |
| `context_snapshot_json` | jsonb NOT NULL DEFAULT `{}` |
| `context_hash` | varchar(71)，可空；格式 `sha256:` + 64 位小写 hex |
| `requested_by` | bigint NOT NULL |
| `model_name/prompt_version/artifact_schema_version` | text，可空；执行后由具体 handler 填写 |
| `stage` | text NOT NULL DEFAULT `WAITING` |
| `progress` | smallint NOT NULL DEFAULT 0，CHECK 0–100 |
| `attempt` | int NOT NULL DEFAULT 1，CHECK ≥1 |
| `error_code/error_detail_safe` | text，可空；禁止写原始密钥/完整供应商响应 |
| `lease_owner/lease_until` | text/timestamptz，可空 |
| `created_at/updated_at` | timestamptz NOT NULL DEFAULT now() |
| `started_at/finished_at` | timestamptz，可空 |

索引至少包括：

- 队列：`status, id`， QUEUED 可使用部分索引。
- 主体历史：`tenant_id, subject_type, subject_id, id DESC`。
- 租约恢复：`status, lease_until`，仅 RUNNING。
- 唯一幂等键：上述三列组合。

### B. `ai_artifact`

| 列 | 定义要求 |
|---|---|
| `id` | bigint identity 主键 |
| `tenant_id/task_id` | bigint NOT NULL；task 引用 `ai_task(id)`，删除策略按归档要求评审，默认不级联业务对象 |
| `kind` | text NOT NULL，与三类任务同词表 |
| `schema_version` | text NOT NULL |
| `content_json` | jsonb NOT NULL |
| `content_hash` | varchar(71) NOT NULL，SHA-256 格式 CHECK |
| `evidence_refs_json` | jsonb NOT NULL DEFAULT `[]`，必须为数组 |
| `review_status` | text NOT NULL DEFAULT `UNREVIEWED`，仅 `UNREVIEWED/CONFIRMED/REJECTED` |
| `confirmed_by/confirmed_at` | bigint/timestamptz，可空 |
| `consumed_experiment_id/consumed_run_id` | bigint，可空，必须同时为空或同时非空 |
| `consumed_at` | timestamptz，可空；与 consumption ID 同空/同非空 |
| `created_at` | timestamptz NOT NULL DEFAULT now() |

约束至少包括：

- `UNIQUE(task_id, kind)`：一个成功任务每类只保留一个当前产物。
- `kind` 与 `ai_task.task_type` 的一致性由服务层事务校验，不用跨表 CHECK 假装数据库已保证。
- consumption 字段必须成组填写，避免重复确认只能找回 run、找不回 experiment。
- 不添加 `approved_for_execution`、`auto_start`、`device_command` 等字段。

### C. 时间更新

复用现有 `set_updated_at()` 触发器机制，或在 Mapper 每次更新时显式 `updated_at=now()`；只能选一种清晰口径。建议触发器与现有业务表保持一致。

## T2-4 核心实现步骤

### A. 创建与幂等

1. 校验登录、角色、任务类型、主体类型、输入大小和主体存在性。
2. 由服务端按当前租户重新读取主体；不信任客户端提交的状态或证据。
3. 在事务内插入任务；捕获幂等唯一冲突后读取并返回首次任务。
4. 返回 202/QUEUED；不在 Controller 内调用模型。
5. 创建任务只写 `ai_task`，不得创建 experiment、experiment_run、run 或 placement。

### B. 领取任务

在一个 `Tx.inTransaction` 中完成：

```text
SELECT candidate
FROM ai_task
WHERE tenant_id=? AND status='QUEUED'
ORDER BY id
LIMIT 1
FOR UPDATE SKIP LOCKED
  → UPDATE ... SET status='RUNNING', lease_owner=?, lease_until=?, started_at=COALESCE(...)
  → 提交后才允许执行 handler
```

要求：锁行与状态更新必须同事务；UPDATE 仍带 `status='QUEUED'` 护栏；每批默认只领取 1 条，避免单实例占满队列。

### C. 租约与长任务

- 建议配置：`LABOS_AI_WORKER_ENABLED=false`（默认关闭，B2 再开启）、`LABOS_AI_WORKER_POLL_MS=1000`、`LABOS_AI_TASK_LEASE_SEC=120`。
- 长模型调用期间必须续租；续租条件带 `taskId + tenantId + leaseOwner + attempt + status=RUNNING`。
- 若使用 scheduled pool，至少为“执行”和“心跳”保留独立线程，不能让一个长调用堵住自己的续租。
- 租约过期由恢复器标为 `FAILED/LEASE_EXPIRED`，默认等待人工重试；不在旧执行体仍可能运行时直接让另一个 worker 写同一 attempt。
- 完成/失败提交必须再次锁任务并核对 `leaseOwner + attempt + RUNNING`；不匹配即丢弃本次写入。

### D. 成功、失败与产物原子性

- 成功：同一事务内锁任务、核对租约/attempt、写 artifact、更新 SUCCEEDED/progress=100/finished_at。
- 失败：只写安全错误码和脱敏摘要，更新 FAILED/finished_at；不写半份 artifact。
- 模型 JSON/schema 不合法统一 `AI_OUTPUT_INVALID`；超时统一 `MODEL_TIMEOUT`；是否可重试由明确白名单决定。
- 旧 attempt 或已取消任务返回成功时，不能插入 artifact，也不能把状态改回 SUCCEEDED。

### E. 重试与取消

- retry：只允许 FAILED/CANCELLED；锁行后 `status=QUEUED、attempt=attempt+1`、清租约/安全错误/finished_at。
- cancel：QUEUED 直接 CANCELLED；RUNNING 标记 CANCELLED 并协作中断，最终以后台状态为准。
- SUCCEEDED 再 retry 返回 409；重复 cancel 返回当前 CANCELLED，不新增任务。
- handler 应按 taskType 注册；未注册类型失败为 `AI_HANDLER_NOT_REGISTERED`，不进入无限重试。

### F. 生命周期与依赖边界

- worker 使用可关闭的 Spring 生命周期 Bean；进程停止时停止领取新任务并中断等待。
- 测试可调用单 tick/直接 handler，不依赖真实等待。
- `AiTaskWorker` 只依赖任务存储、handler registry、时钟/ID 生成器和审计接口；构造器与 import 均不得出现执行/设备服务。

## T2-5 测试与完成定义

`AiTaskStateSelfTest`（纯逻辑）：

- 合法/非法状态转移全矩阵。
- FAILED/CANCELLED 可重试，QUEUED/RUNNING/SUCCEEDED 不可重试。
- 重试 attempt 单调递增；SUCCEEDED 为终态。
- 未配置错误、handler 缺失、模型超时和 JSON 非法的错误码映射。
- 取消后完成、旧租约后完成、旧 attempt 后重试均被状态校验拒绝。

`AiTaskWorkerDbSelfTest`（连库、假 handler、不动设备）：

1. 创建接口语义返回 QUEUED，HTTP 不等待 handler。
2. 同 idempotencyKey 并发创建只有一条任务。
3. 两个 worker 并发领取同一队列，同一 task 只有一个领取成功。
4. 假 handler 成功后 artifact 与 SUCCEEDED 原子落库。
5. handler 抛错只落 FAILED，无 artifact。
6. RUNNING 取消后，旧 handler 成功也不能写产物/覆盖状态。
7. attempt 1 超时，人工 retry 后 attempt 2 成功，旧 attempt 1 迟到结果不能覆盖。
8. worker 崩溃且租约到期后变为 `FAILED/LEASE_EXPIRED`，可人工重试。
9. 全过程中 experiment/run/placement/设备命令测试表计数不变。
10. 跨租户 task/artifact 查询和更新均为 0 行或 404。

**Done 条件**：自测登记并实际通过；可用假 handler 完整演示 202→QUEUED→RUNNING→SUCCEEDED/FAILED；默认 worker 关闭；代码中无执行服务依赖。未使用真实模型不构成本卡失败，因为真实 handler 属下一批。

6. 当前没有项目成员级授权模型，本周验收只声明“角色 + 租户”隔离，不写“项目级 ACL 已完成”。
7. 既有 `/workflows/{id}/ai/plan` 仍走 design 权限，operator 不因新 AI 工作台获得工艺修改权。

权限断言至少覆盖：

| 动作 | admin | operator | designer | viewer/未知角色 |
|---|---|---|---|---|
| GET 授权任务/产物 | 允许 | 允许 | 允许 | 允许 |
| POST 三类任务 | 允许 | 允许 | 允许 | 403 |
| retry/cancel | 允许 | 允许 | 允许 | 403 |
| confirm-instantiate | 允许 | 允许 | 403 | 403 |
| 既有 workflow ai/plan | 允许 | 403 | 允许 | 403 |

## T3-4 AI 降级与输出安全

- `GET /api/ai/capabilities` 在缺少 key 时返回 200：`enabled=false, reasonCode=AI_NOT_CONFIGURED`。
- `POST /api/ai/tasks` 在缺少 key 时返回 503，同一代码；不得创建任务后再假装可运行。
- capabilities 不返回 key、key 文件路径、base URL、供应商响应或内部异常堆栈。
- AI 不可用不影响模板列表、项目只读列表、物料配置、readiness 和运行详情原接口。
- 用户需求、设备回包、事件 payload 和模型文本全部按不可信数据处理；不得拼成 SQL、Shell 或可执行 HTML。
- 本周服务端只保存结构化 JSON/纯文本；浏览器 XSS 实机用例在第 8–15 天页面出现后必须补跑，本周不能宣称 UI XSS 已验收。

## T3-5 审计实施步骤

1. 保留 `AuditRecorder.record(...)` 原签名并默认 result=`ok`，新增带 result 的 overload 或明确的新方法，避免逐处改坏旧调用。
2. 用户动作记录：create/retry/cancel/confirm、task/artifact ID、操作者、IP、结果。
3. worker 动作记录：succeed/fail/lease-expired、taskId、attempt、模型、提示词/schema 版本、上下文/内容哈希。
4. worker 无登录 Session 时不得伪造 Session；可用任务创建者 username 快照记审计，user_id 为空时保持为空。
5. 越权与校验失败写 result=`fail`；成功写 `ok`，与现有 AuthService 实际口径一致。
6. 审计 detail 只放白名单字段；API key、Authorization、密钥文件内容、完整 LLM 原文和敏感上下文不得写入。
7. 为现有 `/workflows/{id}/ai/plan` 增加失败审计；成功路径保留，不把该端点改造成异步任务。
8. 审计写失败仍按现有策略打安全日志、不泄露秘密；安全关键动作是否允许“审计失败仍继续”需保持现网口径，不在本卡擅自改变。

## T3-6 测试与完成定义

`AiSecuritySelfTest`：

- 上表权限矩阵逐格断言，含直接 URL 和未知角色。
- viewer 可读但不能写；designer 可生成草稿但不能确认实例化。
- 未配置 503 与 capabilities 降级响应稳定，响应体不含敏感配置。
- 提示词注入文本不改变 taskType、subject、role 或目标动作。
- 错误响应与审计 detail 不含假 key、Authorization 或供应商原始 body。

`AiAuditDbSelfTest`：

1. 创建成功、创建失败各产生正确结果的审计。
2. retry/cancel 记录同 taskId 和最新 attempt。
3. worker 成功/失败均有模型、版本、attempt、哈希；失败无秘密。
4. 越权访问写 fail 审计且不泄露目标内容。
5. 租户 A 的 task/artifact 不被租户 B 查询或更新。
6. 既有 `/ai/plan` 失败可写 fail 审计，成功路径不回归。
7. 原非 AI 权限自测保持通过。

**Done 条件**：权限矩阵、降级和审计自测实际通过；`RbacRouteGuardSelfTest`、`RbacRulesSelfTest` 无回归；明确记录“项目级 ACL 与浏览器 XSS 实测不在本周完成范围”。

## 4. 联调顺序与第 7 天出口

### 4.1 建议日程

| 时间 | 工作 |
|---|---|
| 第 1 天 | T1 迁移与字段 drift；并行开始基线采集 |
| 第 2 天 | T1 连库测试完成；冻结 Mapper 契约；T2/T3 并行启动 |
| 第 3–4 天 | T2 状态机、并发领取、租约与假 handler；T3 权限/降级/审计 |
| 第 5 天 | 三卡联调，补并发、取消、迟到写入和失败审计 |
| 第 6 天 | 全新库/既有库升级各跑一遍；纯逻辑与连库自测；安全复核 |
| 第 7 天 | 全量回归、代码评审、验收记录；决定是否进入第 8–15 天页面与真实草稿 handler |

### 4.2 联调必过场景

1. AI 未配置：capabilities 正常降级，创建 503，原功能可用。
2. 已配置但未注册真实 handler：只展示实际能力；测试 handler 不进入生产注册表。
3. 同请求重复提交：同 taskId，不多排队。
4. 两 worker 抢同任务：仅一个 RUNNING 领取成功。
5. 取消后模型迟到：状态保持 CANCELLED，无 artifact。
6. 租约过期后重试：旧 attempt 不得覆盖新 attempt。
7. viewer/未知角色：所有 POST 403。
8. designer：可以创建草稿任务，但确认实例化 403。
9. 跨租户 ID 猜测：无数据、无更新、无敏感错误。
10. 全链路计数：无 experiment/run/placement 新增，无设备命令，无启动调用。

### 4.3 批次出口标准

只有以下证据齐全才进入下一批：

- 迁移幂等与 drift 报告。
- 纯逻辑、连库自测结果及新增登记位置。
- 并发、取消、租约、迟到写入测试记录。
- 权限矩阵和 AI 降级测试记录。
- 成功/失败审计样例的脱敏截图或查询结果。
- 静态依赖检查证明 worker 无执行服务依赖。
- 基线原始记录已开始采集，且计时口径与上游 §9 一致。

**任一安全项失败，停止进入真实用户页面；不得用“先演示、后补权限/审计”替代本批次出口。**
