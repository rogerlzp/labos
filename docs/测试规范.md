# LabOS 测试规范

> 面向问题：**改了一个功能，凭什么说它没坏、也没把别的弄坏？**
> 答案：先写用例再写实现；脚本测试与页面测试两条轨道都要有；
> 用例通过才算改完，通过之后才允许 `git commit`。

配套上位文档：[测试与上线策略](测试与上线策略.md)（L1–L5 五层验证模型）、
[完整流程测试矩阵-设计](完整流程测试矩阵-设计.md)（45 条流程矩阵）、
[测试用例总表](测试用例总表.md)（功能 × 用例 × 层次 × 是否进 CI 的全量台账）。

## 一、三条硬规则

这三条不满足，改动视为**未完成**，不允许提交。

| # | 规则 | 怎么落地 |
|---|---|---|
| 1 | **测试先行**：新功能先写用例，再写实现 | 用例可以先红（失败），提交时必须绿 |
| 2 | **双轨覆盖**：脚本测试 + 页面测试都要有 | 后端/编排改动看脚本轨；界面改动看页面轨；同时改两边就两边都补 |
| 3 | **通过才提交**：用例全绿才能 `git commit` | 提交前跑 `./scripts/ci-gate.sh --all`，非 0 不提交 |

**为什么测试先行**：先写用例会逼着人把"这个功能到底该输出什么"想清楚；
写完实现再补用例，多半补出来的是"实现现在的样子"，挡不住回归。

## 二、两条轨道

| 轨道 | 跑什么 | 放在哪 | 需要什么在跑 | 判定单位 |
|---|---|---|---|---|
| **脚本轨** | 纯逻辑单测、连库单测、链路脚本、流程矩阵 | `labos-kernel/src/test/`、`scripts/verify-*.py`、`scripts/verify-*.sh` | 视脚本而定（纯逻辑不需要任何环境） | 断言条数 |
| **页面轨** | 浏览器真点：登录、建流程、建实验、执行、暂停恢复、告警、策略 | `scripts/e2e-*.py`（Python Playwright） | 前端 + API（+ 仿真机，视页面而定） | 断言条数 |

**为什么页面轨必须单独有**：库里 `run.status=completed` 不代表页面显示对了。
历史上 5 个真 bug（图显示未执行、按钮不刷新、保存无提示）都是真点页面抓到的，
脚本轨一个都看不见。

### 2.1 该补哪条轨

| 改动类型 | 脚本轨 | 页面轨 |
|---|---|---|
| 后端逻辑（状态机、求值器、恢复策略、调度） | 必须 | 不必 |
| 数据库读写（建批、扣留、暂停落库） | 必须（连库单测） | 不必 |
| 接口契约（字段增删改名） | 必须；同步改 `webapp/src/api/client.ts` | 涉及展示的必须 |
| 界面交互（按钮、弹窗、空态、只读禁用） | 不必 | 必须 |
| 端到端链路（页面 → API → 驱动 → 设备） | 必须（链路脚本） | 必须（e2e） |

## 三、改功能 = 改用例

| 场景 | 必须做 |
|---|---|
| 新增功能 | 新增用例；在 `scripts/ci-gate.sh` 顶部加 `MIN_*` 阈值并接入对应小节 |
| 修改功能行为 | 修改对应用例的期望值；**不允许只改实现不改用例** |
| 删除功能 | 删除对应用例，并同步下调 `MIN_*` 阈值（下调要在提交信息里写明原因） |
| 改接口字段 | 用例里的字段名、`client.ts` 的类型、页面展示三处一起改 |
| 纯重构（不改行为） | 用例不动；跑一遍确认条数与结果都不变 |

**阈值只许涨不许跌**：`ci-gate.sh` 顶部的 `MIN_*` 常量是"用例数量下限"。
少了就红灯，逼着人回答"少的那几条去哪了"。真要删用例，得显式改常量并在提交信息说明。

## 四、用例怎么写

### 4.1 脚本轨约定

| 约定 | 说明 |
|---|---|
| 放哪 | 纯逻辑/连库单测放 `labos-kernel/src/test/java/`；带环境的链路上 `scripts/` |
| 输出 | 末尾必须打印 `通过 N / 失败 M`（门禁用正则抠这两个数） |
| 跳过 | 环境不满足时在**首行**打印 `SKIP`，门禁据此判"跳过"而不是"失败" |
| 数据库 | 严禁回落到 `127.0.0.1`；必须显式设 `LABOS_DB_HOST` 等环境变量 |
| 收尾 | 自己造的数据自己清（流程、实验、扣留），不留残留影响下次断言 |

### 4.2 页面轨约定

| 约定 | 说明 |
|---|---|
| 放哪 | `scripts/e2e-*.py`，Python Playwright（本机已装，不加 npm 依赖） |
| 入参 | 至少支持 `--base`（默认 `http://localhost:5173`）、`--user`、`--pass`、`--headed` |
| 计数 | 统一 `ok()` / `bad()` 累计 `PASS` / `FAIL`，末尾打印 `通过 N / 失败 M` |
| 文案 | antd 中文按钮带空格（`登 录`、`保 存`），locator 用正则 `re.compile(r"保\s*存")` |
| 只读 | viewer 只读态用 `useReadOnly()`；用例要断言"可写按钮被禁用" |
| 收尾 | 用例自己建的流程/实验/告警要清理，避免污染下一次运行 |

### 4.3 页面轨的四个必测面

新增一个页面或改一个页面的交互，至少要覆盖：

| # | 面 | 例子 |
|---|---|---|
| 1 | 列表/空态渲染 | 表格有行、空态文案出现 |
| 2 | 主操作可达 | 点进详情、弹窗能开、保存有提示 |
| 3 | 库/接口真的变了 | 点完暂停，`run.status` 真的是 `paused` |
| 4 | 只读边界 | viewer 下按钮 disabled 且给出原因 |

## 五、环境与 SKIP 规则

| 变量 | 用途 | 缺失时 |
|---|---|---|
| `LABOS_DB_HOST` / `_PORT` / `_NAME` / `_USER` / `_PASS` | 连库测试与链路的库 | 连库小节 SKIP（不是失败） |
| `LABOS_API` | API 地址（默认 `http://127.0.0.1:18080`） | API 类脚本 SKIP |
| `LABOS_WEB` | 前端地址（默认 `http://localhost:5173`；nginx 8080 亦可） | 页面轨 SKIP |
| 仿真机 19500–19506 | 仿真机联调（`e2e-sim-flow.py`） | 该小节 SKIP |

**SKIP 不是失败，也不等于通过**：门禁把 SKIP 单独打印，评审时要能看出"这条没跑"
而不是被算成绿。**禁止把 SKIP 静默算通过**。

造仿真环境：`labos-kernel/scripts/sim-up.sh` 起 7 台仿真机（19500–19506）。

## 六、门禁怎么串起来

| 门禁 | 位置 | 什么时候跑 |
|---|---|---|
| `./scripts/ci-gate.sh` | 本地 + GitHub CI | 每次 push / PR（纯逻辑 547 + tsc + 建库产物一致） |
| `./scripts/ci-gate.sh --all` | 本地 | 提交前；页面轨 + 链路 + 流程矩阵 + 仿真机联调 |
| `.githooks/pre-push` | 本地 git 钩子 | 每次 `git push` 前，跑 `--all`，不过就挡下 |
| `.github/workflows/e2e-nightly.yml` | GitHub | 每天定时跑页面轨，兜住"CI 只跑纯逻辑"的盲区 |

**为什么要有 nightly**：`.github/workflows/ci.yml` 只跑不需要数据库的部分，
页面 e2e 需要整套服务在跑，所以长期以来**页面轨从未在 CI 执行过**。
nightly 把整套服务（PostgreSQL + API + 前端）拉起来补这一段。
本地 pre-push 钩子负责在推之前先挡一道。

启用本地钩子（一次性）：

```bash
git config core.hooksPath .githooks
```

## 七、提交前检查清单

- [ ] 新功能/改行为的用例已写或已改，且覆盖了两条该覆盖的轨道
- [ ] `./scripts/ci-gate.sh --all` 全绿（SKIP 的小节在提交信息里说明原因）
- [ ] `ci-gate.sh` 顶部 `MIN_*` 阈值已按用途例数同步
- [ ] 接口字段变了：`client.ts` 类型与页面展示一起改了
- [ ] 造出来的测试数据已清理（流程、实验、扣留、告警）
- [ ] 中英文档同步（如涉及），`python3 scripts/verify-en-docs.py` 硬错误 0
