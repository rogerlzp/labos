|---|---|

> **【S0-safety · 调试通路边界】**：本手册里的「走一遍（逐站下发）」「单命令探针」「shadow-run（影子运行）」「robot-points capture」等属**调试通路**——它们真实驱动设备，但**不落 run、不产生物料执行事实**。默认**关闭**（仅 admin + `LABOS_ALLOW_DEVICE_PROBE=1` / `LABOS_ALLOW_SHADOW_RUN=1` 开启）；**不得用于生产加工**，只用于装机 / 演示 / 联调。CLI / demo 入口同理，仅测试用。

## 0. 五分钟跑起来

### 启动（三个终端）

```bash
# ① Mock 驱动（可选；不启用则走内置虚拟驱动）
cd labos-kernel/sidecar-dotnet
export DOTNET_ROOT=/opt/homebrew/opt/dotnet/libexec
export PATH=/opt/homebrew/opt/dotnet/bin:$PATH
dotnet run -c Release -- --mock

# ② 内核
cd labos-kernel
./scripts/start-kernel.sh

# ③ 前端
cd webapp
npm run dev
```

### 打开

```
http://<本机IP>:5173
登录：admin / admin123
```

> 首次启动自动创建管理员，密码可用 `LABOS_ADMIN_PASS` 覆盖。
> **上线前必须改密码。**

## 1. 建一个岛

**运维 → 岛屿视图 → [ + 新建岛屿 ]**

| 字段 | 说明 | 示例 |
|---|---|---|
| 岛屿编号 | 资源树路径用，英文数字 | `LAB-A` |
| 岛屿名称 | 显示用 | `A 实验室` |

创建后下拉自动切到新岛。

---

## 2. 往池子里加设备

**左侧「设备池」→ [ + 新增设备 ]**

| 字段 | 说明 | 示例 |
|---|---|---|
| 设备编号 | 唯一 | `X900` |
| 设备名称 | 显示用 | `Incubator_37C-1` |
| 能力 | 决定它能接哪些流程节点 | `INCUBATE` |
| 设备类型 | 分类 | `Incubators` |
| 设备 IP | 标识归属与运维定位 | `192.0.2.10` |

> **一次建三样**：资源树节点（在哪）+ 型号（是什么）+ 实例（连哪）。
> 单事务，失败全回滚，不会留半条数据。

---

## 3. 拖设备进岛

**从左侧池子拖到右侧画布**（虚线框内松手）。

拖进去后立刻计数 +1。

**换岛**：把岛里的设备拖回池子，再拖到另一个岛。

---

## 4. 摆位置

岛内设备**可以直接拖动**到任意位置，松手自动保存。

```
坐标存在 resource_node.attr.pos_x / pos_y
换驱动、换 IP 都不影响位置
```

摆成实际的物理布局（机械臂在中间、孵箱在左、读板机在右）。

## 5. 编排一条搬运序列

### 5.1 加入序列

点设备卡片下的「**+ 加入搬运序列**」。

顶部出现：

```
搬运序列： [1. ID1731 ×] [Transfer ▾]  [2. ID1183 ×] [Deposit ▾]  [3. ID1775 ×] [Deposit1Ex ▾]
                                                    [走一遍] [存为流程] [清空]
```

**每站的方法可以改**——系统按能力推荐（`TRANSFER` → `Transfer`，`INCUBATE` → `Deposit`）。

### 5.2 走一遍（验证物流）

点「**走一遍（逐站下发）**」：

```
① 板子滑到 ID1731 → 下发 Transfer → OK 62ms
② 板子滑到 ID1183 → 下发 Deposit  → OK 71ms
③ 板子滑到 ID1775 → 下发 Deposit1Ex → OK 62ms
```

**每一站都是真实调用驱动**，返回设备原文。

> 这一步不落库、不产生 run——它是**现场调试工具**，
> 装完设备先串一遍看物流通不通。

## 6. 存为正式流程

点「**存为流程并打开设计器**」→ 生成 workflow 后自动跳进设计器：

```
已生成流程 #1249（3 站），正在打开设计器…
→ 400ms 后跳转 /designer/1249
```

不用回流程库找——存完就能微调节点、改连线、设参数。

落库结构：

```
节点                                          能力        方法           绑定设备
N1  Inheco_Shaking_Incubation / ActionDrawer  INCUBATE    ActionDrawer   200171
N2  XRobot A10LR / BarcodeScan                TRANSFER    BarcodeScan    200214
N3  Incubator_4C Storage / Deposit1Ex         INCUBATE    Deposit1Ex     200210

边：S→N1→N2→N3→E
```

**关键**：节点带 `bound_resource_id`——执行时必须用这台设备，
不像普通流程那样按能力随机挑。

## 8. 影子检查（验证驱动契约）

**流程库 → 选中流程 → [影子检查]**

```
影子检查 · ID1183 到 ID1775 搬运

节点 3    通过 3    失败 0    契约缺字段 0

节点                    能力        方法          设备      结果        契约
Inheco_Shaking...       INCUBATE    ActionDrawer  ID1183   OK 86ms     完整
XRobot A10LR...         TRANSFER    BarcodeScan   ID1731   OK 62ms     完整
Incubator_4C...         INCUBATE    Deposit1Ex    ID1775   OK 62ms     完整
```

**区别**：

| | 正常执行 | 影子检查 |
|---|---|---|
| 触发恢复策略 | ✅ | ❌ |
| 落 run / run_node | ✅ | ❌ |
| 某节点失败 | 停/重试/换机 | **继续跑下一个** |
| 目的 | 完成生产 | **覆盖所有节点验契约** |

## 附录：常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面空白、无报错 | token 过期 | 会自动跳登录；若没跳，刷新页面 |
| `EC-06-0001 设备未注册` | 设备 id 口径不符 | 检查 `device_instance.resource_id` |
| 影子检查设备不对 | 节点没绑设备 | 用搬运序列生成的流程才有 `bound_resource_id` |
| 拖动没保存 | 未松手或网络断 | 松手后看后端 `attr.pos_x` 是否变 |
| 搬运动画不动 | 两个节点同设备 | 正常——板子没换地方 |
