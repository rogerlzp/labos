## 一、测试策略：四层，各管一段

| 层 | 覆盖什么 | 怎么做 | 跑多久 | 依赖 |
|---|---|---|---|---|
| **L1 纯逻辑单测** | 状态机、表达式、恢复策略、型号库、模拟器行为 | `scripts/test-all.sh --pure-only` | ~40s | **无**（不连库、不连网） |
| **L2 连库测试** | 位置锁、暂停恢复、配方编译、分批落库、权限落库 | `scripts/test-all.sh`（自动探测库） | ~1min | PostgreSQL |
| **L3 链路脚本** | 中控 → sidecar → 模拟器 → 库，端到端 | `verify-device-chain.sh`（41 断言）等 | ~3min | 模拟器 + sidecar |
| **L4 页面 e2e** | 交互、展示、状态一致性 | Playwright 真点（`scripts/e2e-*.py`）；关键结论截图核对 | 场景相关 | 全套服务（+ 仿真机） |

**为什么 L1 要"不连库"**：曾经 106 个测试全部连真实数据库，CI 上等于没有测试。现在纯逻辑占绝大多数；`test-all.sh` 在 `out/` 为空时会**先编译 `src/main`**，所以任何机器 `git clone` 后能直接验证。

> 另：7 个自检类放在 `src/main/java`（会打进产物），已迁到 `src/test/java`（包名不变、跑法不变）。

## 二、怎么跑

```bash
# L1：不需要任何环境（推荐评审第一步）
cd /path/to/labos
./scripts/test-all.sh --pure-only
# 期望：通过 624 / 失败 0（跳过 9 个连库测试）
# 说明：--pure-only 会清掉 LABOS_DB_*，带库分支的断言一律不跑，所以这个数字是确定的

# L1+L2：需要库
export LABOS_DB_HOST=... LABOS_DB_NAME=... LABOS_DB_USER=... LABOS_DB_PASS=...
./scripts/test-all.sh
# 期望：通过 1005 / 失败 0（在可达的库上实测）

# L3：设备全链路（需要模拟器 + sidecar，脚本会自己起）
export LABOS_DB_HOST=... （同上）
./scripts/verify-device-chain.sh
# 期望：41 条断言全过，末尾打印失败项

# 单个用例类
cd labos-kernel
javac -encoding UTF-8 -d out -cp "out:lib/postgresql-42.7.3.jar" $(find src/test -name '*.java')
java -cp "out:lib/postgresql-42.7.3.jar" com.labos.kernel.engine.ConditionEvaluatorSelfTest
```

> `test-all.sh` 会**先编译 `src/test`** 再跑。以前不编译，新加的测试类只报"找不到主类"，看起来像失败其实是没编译。

| 6 | 真机（非模拟器） | 时序、并发、异常行为差异 | 无真机环境 |
| 7 | 长稳（跑几天） | 内存/连接泄漏 | 无长稳环境 |
| 8 | 并发压测下的正确性（不只是吞吐） | 锁竞争下的状态错乱 | 压测只看了吞吐 |
| 9 | 滚动排程（规格 §14.8：承诺窗口 / 15 分钟冻结区 / 贪心） | 承诺窗口或冻结区失效会打乱已承诺实验 | 发布之外，尚未实现到可测 |
