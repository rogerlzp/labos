# 测试文档 · LabOS 实验室中控

> 面向：评审（判断可信度）、维护者（改完怎么验）
> 配套：[功能文档](01-功能文档.md) · [技术文档](02-技术文档.md) · [设计文档](03-设计文档.md)
>
> 一句话结论：**379 条纯逻辑测试全绿（`--pure-only`，确定性）；带库全跑 397 条；端到端靠 6 个 shell 脚本 + 真点页面**。
> 页面级没有自动化（这是最大的缺口，见 §7）。

## 一、测试策略：四层，各管一段

| 层 | 覆盖什么 | 怎么做 | 跑多久 | 依赖 |
|---|---|---|---|---|
| **L1 纯逻辑单测** | 状态机、表达式、恢复策略、型号库、模拟器行为 | `scripts/test-all.sh --pure-only` | ~40s | **无**（不连库、不连网） |
| **L2 连库测试** | 位置锁、暂停恢复、配方编译 | `scripts/test-all.sh`（自动探测库） | ~1min | PostgreSQL |
| **L3 链路脚本** | 中控 → sidecar → 模拟器 → 库，端到端 | `verify-device-chain.sh`（41 断言）等 | ~3min | 模拟器 + sidecar |
| **L4 手工页面验证** | 交互、展示、状态一致性 | 浏览器真点，截图核对 | 场景相关 | 全套服务 |

**为什么 L1 要"不连库"**：曾经 106 个测试全部连真实数据库，CI 上等于没有测试。现在纯逻辑占绝大多数；`test-all.sh` 在 `out/` 为空时会**先编译 `src/main`**，所以任何机器 `git clone` 后能直接验证。

> 另：7 个自检类放在 `src/main/java`（会打进产物），已迁到 `src/test/java`（包名不变、跑法不变）。

## 二、怎么跑

```bash
# L1：不需要任何环境（推荐评审第一步）
cd /path/to/labos
./scripts/test-all.sh --pure-only
# 期望：通过 379 / 失败 0（跳过 2 个连库测试）
# 说明：--pure-only 会清掉 LABOS_DB_*，带库分支的断言一律不跑，所以这个数字是确定的

# L1+L2：需要库
export LABOS_DB_HOST=... LABOS_DB_NAME=... LABOS_DB_USER=... LABOS_DB_PASS=...
./scripts/test-all.sh

# L3：设备全链路（需要模拟器 + sidecar，脚本会自己起）
export LABOS_DB_HOST=... （同上）
./scripts/verify-device-chain.sh
# 期望：41 条断言全过，末尾打印失败项

# 单个用例类
cd labos-kernel
javac -encoding UTF-8 -d out -cp "out:lib/postgresql-42.7.3.jar" $(find src/test -name '*.java')
java -cp "out:lib/postgresql-42.7.3.jar" com.labos.kernel.engine.ConditionEvaluatorSelfTest
```

> `test-all.sh` 会**先编译 `src/test`** 再跑。以前不编译，新加的测试类只报"找不到主类"，看起来像失败其实是没编译。

## 三、L1/L2 用例清单（`--pure-only` 共 **379** 条）

| 测试类 | 条数 | 覆盖什么 | 关键断言举例 |
|---|---|---|---|
| `device.DeviceModelSelfTest` | 196 | 型号库：方法名、别名、手册证据、错误码映射 | 手册没写的指令必须标 `undocumented`；每个错误码都能翻译 |
| `sim.SimulatorBehaviorSelfTest` | 41 | 模拟器行为（真协议）：Seal/Home/RunProgram、故障注入 | 注入 `0x8000000C` 必须回无纸；正常调用必须回 ok |
| `expr.ExpressionSelfTest` | 30 | 现有表达式组件（历史） | — |
| `engine.ConditionEvaluatorSelfTest` | **32** | **条件求值器**：比较/逻辑/变量/**算术**/拒绝注入 | `(a+b)/2>=5` 成立；`${s}+1` 字符串算术抛错；`1/0` 抛错；`Runtime.exec` 被拒绝 |
| `driver.DeviceErrorChainSelfTest` | **14**（+5 条真库断言，仅带库时跑） | 错误码链路：设备码 → 中控码 → 策略 | `0x8000000C → EC-08-400C → manual` |
| `recovery.RecoverySelfTest` | 17 | 策略匹配、退避计算、作用域 | 精确 > 码级 > 通配；指数退避不超上限 |
| `engine.EngineSelfTest` | 14 | 状态机：重试/转人工/终止/跳过 | 重试次数用尽必须 `MANUAL` |
| `driver.WaitForGraphSelfTest` | 13 | 死锁检测 | 环形等待必须被拒 |
| `alert.AlertSelfTest` | 13 | 告警聚合与处置 | 同指纹合并、ack 后不再升级 |
| `workflow.GraphRunnerTest` | **8** | 图执行：分叉/汇合/去重/循环每圈上报/**内置节点** | 并行两条都执行；循环 3 圈回调 `[1,2,3]`；`__setVar`/`__expr` 走完且**不产生设备命令** |
| `driver.SidecarChainTest` | 7 | 中控 ↔ sidecar 协议 | 帧格式、错误码透传（无 dotnet 时跳过） |
| **L2** `driver.TransferPlanSelfTest` | (连库) | 搬运计划与位置锁 | 目标位被占必须拒绝 |
| **L2** `workflow.PauseManagerSelfTest` | (连库) | 暂停/恢复的库状态 | 非暂停态不能恢复 |

> 纯逻辑合计 **379**（含 SidecarChainTest 的 7 条计 1 项）。
> 带库全跑（`./scripts/test-all.sh`）= 379 + 5（DeviceErrorChainSelfTest 的真库段）+ 3（TransferPlanSelfTest）+ 10（PauseManagerSelfTest）= **397**。
> 只有 DeviceErrorChainSelfTest 会因环境跑出两个数，所以 `--pure-only` 里**强制清空 LABOS_DB_***，让它恒为 14。
> L2 两项在 `--pure-only` 下显示"跳过 2 个连库测试"。

## 四、L3 链路脚本

| 脚本 | 断言 | 覆盖 |
|---|---|---|
| `verify-device-chain.sh` | **41** | ①登录 ②型号入池（幂等）③部署实例 ④绑驱动 ⑤起模拟器+sidecar ⑥影子探针 ⑦**多节点续跑**（3 步流程，第 2 步注入无纸 → 暂停 → 换纸 → 继续 → 断言只发 2 条命令）⑧恢复策略回查 ⑨节点绑定表与图一致 ⑩**保存编排的防护**（缺参数/非法 id/不存在的 id 一律 400，且编排不被清空） |
| `verify-m4.sh` | — | 暂停恢复与故障处理：三种暂停态、板位 UNKNOWN 封锁、回程承诺、列表可见性 |
| `verify-m3.sh` | — | 启动准入 / 主链粗筛 |
| `verify-m1.sh` / `verify-m5.sh` | — | 里程碑验收 |
| `test-sidecar.sh` | 7 | sidecar 独立协议测试 |
| `load-test.sh` | — | 压测（多实验并行） |
| **`check-schema-sync.sh`** | 4 | 建库产物 vs 分片一致性：重跑 merge 比对 + 断言 `loop_index`/4 列 uk/parent 外键（BUG-20261103-01 回归） |
| **`ci-gate.sh`** | 6 道门 | 统一门禁：纯逻辑 ≥379 / tsc / **建库产物一致** / **并行能力** / 设备链 ≥41 / e2e ≥14，任一不过退出码非 0 |
| **`verify-parallel-flow.py`** | **4** | 流程内并行：自动建 fork/join 图 → 执行 → 断言两分支都完成 + 同设备命令不重叠（设备锁串行）→ 清理 |
| **`verify-parallel-experiments.py`** | **3** | 同岛并发：建 N 个实验同时异步提交 → 采样 `running` 数 → 断言**峰值并行 = 1**、有排队、全部完成 → 清理 |
| **`e2e-smoke.py`** | **14** | 前端 5 条主链路：登录+流程库、点行进画布、运行详情图例、实验执行历史展开、错误码页 |
| **`soak-test.sh`** | — | 长稳：连续 N 次执行，断言失败率 0、数据不丢、内存不涨（热身 3 次后取基线） |

**注意**：L3 脚本用随机端口起 sidecar，**收尾会把驱动端点还原**到 18501/18502（否则界面上设备永远"连不上"，下次排查会先怀疑代码）。

## 七、明确没覆盖的（评审重点）

| # | 缺口 | 风险 | 为什么还没做 |
|---|---|---|---|
| 1 | **前端零 e2e** | 页面状态错（图显示未执行、按钮不刷新）只能靠人点发现 —— 历史上正是这样抓到 5 个真 bug | 无 Playwright/Cypress 基础设施 |
| 2 | 循环**跨并行分叉** | 组合场景可能死锁 | 组合爆炸，优先保证单场景 |
| 3 | 循环重入的**圈次留痕** | 看不到第 N 圈中间态 | 需要 `run_node` 表结构改动 |
| 4 | 条件里的算术 | 现场写 `${a}+1 > 3` 会失败 | 求值器不支持 |
| 5 | 多租户隔离 | 只跑过单租户 | 无第二套数据 |
| 6 | 真机（非模拟器） | 时序、并发、异常行为差异 | 无真机环境 |
| 7 | 长稳（跑几天） | 内存/连接泄漏 | 无长稳环境 |
| 8 | 并发压测下的**正确性**（不只是吞吐） | 锁竞争下的状态错乱 | 压测只看了吞吐 |
| 9 | 节点改名后续跑 | skipKeys 按 `node_key` 匹配，改名会失配 | 未构造用例 |

## 八、回归基线（改完怎么判断"没坏"）

```bash
# 1. 纯逻辑必须全绿，条数不应减少
./scripts/test-all.sh --pure-only        # 379 / 0

# 2. 前端类型必须干净
cd webapp && npx tsc -b --force          # 0 错误

# 3. 设备链路必须全过
./scripts/verify-device-chain.sh         # 37 / 0

# 4. 前端 e2e（需要 5173 + 18080）
python3 scripts/e2e-smoke.py             # 14 / 0

# 4.5 并行能力（需要设备可达）
python3 scripts/verify-parallel-flow.py            # 4 / 0
python3 scripts/verify-parallel-experiments.py --count 4   # 3 / 0

# 5. 真跑一单（最快的烟雾测试）
curl -X POST "$API/api/workflows/1254/run?async=1" -H "Authorization: Bearer $T"
# 期望：run completed，run_node N1 completed，run_command 有 1 条且 error_code 为空
```

**判断标准**：以上 5 条全过 = 主干没坏（或直接 `./scripts/ci-gate.sh --all` 一次跑完）。若第 4 条"跑绿了但设备没收到命令"，**以 `run_command` 表为准**，不要信页面（历史上就吃过这个亏）。

## 九、手工验证的记录方式（建议）

本项目历史上靠"真点一遍"发现了大量问题，建议保持这个习惯并留痕：

| 记什么 | 例子 |
|---|---|
| 操作路径 | 流程库 → T-X3 → 详情 → 执行（vars=v=2） |
| 预期 vs 实际 | 预期 B 绿 A/C 未选中；实际一致 |
| 库里的证据 | `run_node` A:bypassed B:completed C:bypassed |
| 截图 | 存 `/tmp/xxx.png`，重要结论贴进开发日志 |

> 开发日志（`docs/开发日志.md`，2 万+ 行）里每条修复都记了"现象 → 根因 → 修法 → 实测"，可以直接当复现手册用。
