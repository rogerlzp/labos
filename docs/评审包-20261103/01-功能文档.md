## 一、这套系统是做什么的

一句话：**把实验室的仪器用"流程图"编排起来，自动按图驱动设备执行，出错能按策略自愈、治不好就停下来叫人。**

拆成三件事：

| 层 | 干什么 | 用户接触到的 |
|---|---|---|
| **设备层** | 把 S100 封膜机、ASpin 2K 离心机、孵箱、机械臂等接进来，统一成"能力 + 方法" | 岛屿视图里的设备卡片、点「详情」看到的方法列表 |
| **流程层** | 用 BPMN 图编排工艺（节点=一步操作，连线=先后），支持并行、条件分支、循环 | 流程库 → 画布 |
| **执行层** | 按图下发命令、收结果、判错、重试/换机/转人工，全程留痕 | 运行详情（流程图 + 节点表 + 事件流） |

## 四、核心功能清单

### 4.1 设备接入（设备池 → 岛屿）

**能做什么**

1. 设备池里选型号（**76 个型号**，可按名称/编号/能力搜索），拖到岛上 → 生成一台**设备实例**（248 个）
2. 填 IP / 驱动端点 → 点「测试连接」→ 心跳上线
3. 每台实例有「详情」：**支持的方法 + 参数说明 + 估算时长**（来自型号库，随设备落库）
4. 设备可挂/移出岛、可复制实例、可删除

**关键约束**

| 约束 | 原因 |
|---|---|
| 方法列表来自 `device_method` 表（不是型号库直读） | 设备可以按现场实际增删方法；历史流程引用的是这里的记录 |
| 手册里**没有**的方法会标「（手册未提供，需现场确认）」 | 型号库有 `GetStatus` 这类未记录指令，接真机时可能不存在 |
| 删除设备前要确认没有引用它的流程 | 否则流程点开会报"方法不存在" |

**入口**：运维 → 岛屿视图（部署/详情）、运维 → 设备与岛屿（台账）

---

### 4.2 流程编排（BPMN 画布）

**能做什么**

| 构造 | 支持情况 | 说明 |
|---|---|---|
| 顺序任务 | ✅ | 节点绑设备 + 方法 |
| 并行网关（AND） | ✅ | 分叉全走、汇合等齐 |
| 条件分支（XOR + 表达式） | ✅ | `${temp} > 37`、`${mode} == 'fast'`、`&& \|\| !` |
| 循环（回边） | ✅ | 最多 10 圈（可按流程配 `attr.maxIterations`） |
| 运行期变量 | ✅ | 启动传入 + **节点输出自动进变量表**（如设备返回 `plateType`） |
| 编写 → 保存 → 预检 | ✅ | 预检会检查：可达性、缺能力、条件语法（`PF-09`）、并行汇合死锁 |

**分支的三种结局**（很容易混，单独强调）：

| 图上颜色 | 状态 | 什么情况 |
|---|---|---|
| 绿色 | `completed` | 这步做完了 |
| **淡灰点线** | `bypassed` | **分支没选中**，这步不用做（正常收尾） |
| 灰虚线 | `pending` | 还没轮到（前面失败/暂停了） |
| 黄色 | `skipped` | 策略跳过 —— **板位不可信，系统会停下等人** |
| 橙色 | `manual` | 转人工（如无纸 `EC-08-400C`） |

**入口**：编排 → 流程库 → 点行（直接进画布）/ 「执行记录」

### 4.2.1 内置节点：变量 / 表达式（不用设备也能算）

画布上选中任意 task，右侧「节点设置」里能把节点设成三类之一：

| 类型 | 要填什么 | 说明 |
|---|---|---|
| **设备任务** | 设备（下拉，来自设备池）+ 方法（下拉，来自该设备的 `device_method`）+ **参数（按方法定义渲染输入框）** | 这是让流程"真的动设备"的唯一方式；不绑设备跑起来会报「无可执行资源」 |
| 变量节点 | 变量名 + 值 | 见下 |
| 表达式节点 | 变量名 + 表达式 | 见下 |

> **选了方法，画布上的节点名会跟着变**（`Seal` → `GetStatus`），这样图上一眼能看懂；
> 但如果你自己改过节点名（例如"我的封膜"），就**不会再被覆盖**。
> 内置节点显示中文（变量 / 表达式），不会在图上出现 `__setVar` 这种字符串。

> **参数输入框来自方法定义**（`device_method.param_schema`）：有什么参数就渲染什么，
> 值支持 `${变量}`；方法没有定义参数时退回一个 JSON 文本框（额外字段也能传）。
> 设备与方法的下拉依赖"入池时同步方法"（`DeviceRegistrar` → `device_method`）。
> 参数是 JSON，例如 `{"plateID":"PL001","cycles":3}`；留空表示不传参。

流程图里除了设备任务，还能放两种**不驱动设备**的节点：

| 节点 | 作用 | 参数 |
|---|---|---|
| **变量节点** `__setVar` | 把值写进运行时变量 | 变量名 + 值（值里可用 `${其它变量}`） |
| **表达式节点** `__expr` | 算一个表达式存进变量 | 变量名 + 表达式（支持 `+ - * /`） |

用途：循环计数（`counter = counter + 1`）、把上游结果整理成条件分支要用的值。

**没有"任意代码"节点**：`eval` 在工控机上等于把执行权限交出去，需要计算能力就走内置函数白名单（按需增补）。

### 4.2.2 并行的真实边界（别高估）

"能不能并行跑"要分三件事说，**结论不同**：

| 场景 | 现在会怎样 | 依据 |
|---|---|---|
| 一条流程里画了并行分支 | **两条分支都会跑**；抢同一台设备时自动排队（设备锁） | 实测 `scripts/verify-parallel-flow.py` 4/0 |
| 同一个岛上提交多个实验 | **一个跑、其余排队**（岛级互斥，不并行） | 实测峰值并行 = 1，`scripts/verify-parallel-experiments.py` 3/0 |
| 不同岛各提交实验 | 代码支持同时跑（最多 4 个），**本环境未实测** | 仅读码，见 `docs/并行能力验证-20261103.md` §4 |

**排程甘特不建模并行**：它按"同一时间只跑一个实验"串行累加，所以是**下界**——
真实完成只会更早。这是有意取舍，不是没做完（见验证文档 §5）。

### 4.3 实验编排（把流程拼成一次实验）

**能做什么**

- 一条实验 = N 条流程按 `seq` 顺序跑，每条可设**循环次数**
- 「添加流程」→「保存编排」→「执行实验」
- **执行历史可展开**：逐步显示"已执行 / 失败 / 未执行"，每步可点进运行详情

**两条入口，同一份数据**

| 形态 | 适合 | 说明 |
|---|---|---|
| 实验编排（列表） | 顺序执行 | 列表更直观、不容易连错（库内流程 99.7% 为顺序执行，见代码注释） |
| 实验画布（图） | 需要分叉/并行/变量 | 从实验编排点「画布编排」带着选中的实验跳过去 |

**关键约束**

- 实验没挂流程时「执行实验」是**禁用**的（点它后端只会回"实验没有编排任何流程"）；页面上给了「立即添加一条流程」按钮
- 改了编排不点「保存编排」不会生效
- 新建实验时可选岛（决定设备范围），编号不填自动生成 `EXP-<时间戳>-<4位>`

**入口**：编排 → 实验编排

### 4.4 运行与排障（这是系统最有价值的部分）

**看什么**

| 想知道 | 看哪里 |
|---|---|
| 正在跑到哪一步 | 运行 → 实时看板（当前节点 + 卡住原因） |
| 这次执行每一步做了什么 | 运行详情 → 事件流（`NODE_STARTED` / `COMMAND_SENT` / `COMMAND_ACKED`…） |
| 哪一步失败、什么错误码 | 运行详情 → 节点表「错误码」列 |
| **图上哪步卡住、哪步没跑** | 运行详情 → **流程图（按状态着色）** |
| 为什么停下来等人 | 暂停队列 → 「原因」列（错误码单独标红）+ 停在哪个节点 |
| 这条流程历史跑过几次 | 流程库 →「执行记录」→ 点某一次进详情 |

**能做什么**

| 动作 | 效果 | 注意 |
|---|---|---|
| 继续 | **从断点续跑**：已完成节点跳过，只补后面 | 不跳会重复执行 → 板会被再搬一次 |
| 忽略 / 批量忽略 | 标 `aborted` + `EC-HUMAN-DISMISS`，**不发任何设备命令** | 记录全保留，可反悔 |
| 中止 | 也是 `aborted`，但错误码不同 | 报表上能区分"人不理它"和"人主动终止" |
| 崩溃恢复 | 进程崩溃后，整单标 `failed` + `recoverable`，看板出现「上次被中断」卡片 | 只列**近 7 天**；更久的点继续会拿过期状态重跑，是事故 |

### 4.5 错误码与恢复策略（"出错之后怎么办"）

**模型**：一个错误码 × 一个作用域 = 一条策略。

| 作用域 | 含义 | 典型配置 |
|---|---|---|
| `command` | 单条命令重发 | `EC-05-1006` 通讯失败 → retry ×5，指数退避 |
| `node` | 整个节点重做 | `EC-08-4001` 信号量溢出 → retry ×3 |
| `run` | 整单停下 | `EC-06-0001` 驱动没加载（重试没意义） |
| `device` | 设备维度 | 离线、驱动崩溃 |

**匹配规则**：先比精确度（`码+作用域` > `只有码` > 通配 `*`），再比 `priority`，取**第一条**（`findFirst`，不是回退链）。

**为什么作用域重要**：一条 `scope=command` 的策略，对从 `node` 层抛出的错误**不生效**，会落到通配 → 转人工。历史上就是因为代码一律抛 `node`，库里配的 command 级重试全是死配置。

**能做什么**

| 动作 | 说明 |
|---|---|
| 改 | 码属性（作用域/严重度/标题）+ 按作用域管理策略 |
| **新增** | 「新建错误码」；码要和手册/驱动对得上，否则永远触发不了 |
| **删除** | 软删：列表不再显示，历史发生记录保留 |
| **标红提示** | 码自己的作用域上没有启用策略时，策略列显示「未覆盖本作用域」—— 真出错时只能落到通配策略 |

**入口**：运维 → 错误码（增删改）/ 运维 → 策略（总览）

**心跳参数**（运维 → 告警 顶部卡片）：探测间隔 / 判离线阈值可改，**改完下一个周期生效**，
不用重启 API；阈值强制 ≥ 2 倍间隔。

---

### 4.6 告警

- 设备离线：心跳超时 → 开一条 `DEVICE-OFFLINE|<id>`；恢复在线 → 自动 `closed`（已验证 42s 离线开、25s 恢复关）
- 流程节点：`manual`/`skipped` 会留痕到告警但**不升级**（现场不需要被"跳过"吵醒）
- 可确认（ack）/ 关闭（close）/ 静默（silence）/ 重开（reopen）

**入口**：运维 → 告警

## 五、技术架构与运行模型

> 本章集中回答三个评审最常追问的问题：**系统怎么搭起来的**、**一次执行有哪些状态**、
> **并行到什么程度、资源怎么锁**。权威口径见
> [功能规格说明书](../../LabOS功能规格说明书.md) 第 5 / 13 / 14 章。

### 5.1 分层架构与部署

```
浏览器  React 18 + TypeScript + Ant Design + React Flow（webapp/）
        └─ Nginx（:8080）反代 /api → 后端
ApiServer（:18080，Java；手写 HTTP 分发：路由 + 鉴权 + 审计 + 业务胶水）
        ├─ PostgreSQL（:5432/labdb）  流程 / 运行 / 事件 / 资源状态
        ├─ Redis（:6379）             会话 / 缓存
        └─ 设备适配层
             ├─ Sidecar（:18501）      本机驱动进程
             └─ 设备模拟器集群（:19500–19506）
```

| 层 | 职责 | 关键件 |
|---|---|---|
| 前端 | 画布 / 列表 / 看板 / 运行详情 | `webapp/`（`App.tsx` 定义全部路由） |
| 接口 | 鉴权 + 审计 + 组装 DTO | `ApiServer`（已知技术债：单文件偏大） |
| 内核 | 编译流程、按图推进、资源调度、恢复决策 | `kernel`：`QueryService`（编译 / 预检）、`ExperimentExecutor`（执行）、`GraphRunner`、`Scheduler` |
| 存储 | 流程 / 运行 / 事件 / 资源状态 | PostgreSQL；DAG 边存 `experiment_process_edge` |
| 设备 | 能力契约 + 驱动 | Sidecar / 模拟器；**驱动声明能力，接新设备不改业务代码** |

**端口约定**：前端 5173（dev）/ 8080（Nginx）、ApiServer 18080、Sidecar 18501、
模拟器 19500–19506、PostgreSQL 5432、Redis 6379。

**一条硬规则**：逻辑关系的校验**在代码层收口**（`QueryService` 编译器），数据库只做持久化，
不靠数据库约束 / 存储过程承担业务逻辑。

### 5.3 暂停三态与现场扣留

**「暂停」不是一个状态，而是「一个状态 + 一个原因」**：`run.status = paused` 加 `run.pause_kind`。

| pause kind | 文案 | 触发 | 恢复方式 |
|---|---|---|---|
| `paused_fault` | 设备故障 | 设备心跳超时 / 故障 | **自动**：心跳恢复后自动续跑，不需人 |
| `waiting_human` | 等待人工 | 重试 / 改派策略耗尽，或需人判断 | **人工**：点「继续」 |
| `paused_unknown` | 板位未知 | 搬运中异常，板位 `UNKNOWN` | **人工**：先盘点校正板位再继续 |

**现场扣留（hold）**：一个事件把一片范围冻结住（例如某岛设备故障，同岛其它实验也不该再往这台设备送活）。
由「为什么扣」（kind）与「扣多大范围」（scope）两个维度描述，**越内层越优先：
`experiment > island > site`**。

| hold kind | 文案 | | hold scope | 范围 |
|---|---|---|---|---|
| `fault` | 设备故障 | | `site` | 全场 |
| `plate_unknown` | 板位未知 | | `island` | 岛 |
| `human` | 等人工确认 | | `experiment` | 本实验 |
| `manual` | 人工暂停 | | | |

- 扣留期间**不释放资源**（否则并行体会把被扣留的位置抢走）；
- 但「回程预留位」（`position-return`）是承诺，**必须一直保留**，即使扣留也不释放；
- 作用域的岛 ID 必须为**正数**：负数会被逻辑视为「未分配」而导致扣留失效。

### 5.4 崩溃恢复、分批执行与断点续跑

| 机制 | 要点 |
|---|---|
| **崩溃恢复** | 进程崩溃（不是图执行停在节点边界）走另一条路径：启动时 `StartupRecovery.settleOrphanExperimentRuns` 把遗留 `running` 孤儿单**标 `failed`**；崩溃时打 `recoverable=true`，`/api/runs/recoverable` 列出可恢复单；**不自动续跑**，必须人点「继续」；**只列近 7 天**（更久的点继续会拿过期状态重跑，属事故） |
| **分批执行（S3.2）** | 样品数超阈值时按批切分、逐批提交，降低单次提交的资源峰值。`batchSplit` 为 NULL 或 ≤ 0 不切批；单批重跑 `attempt_no` 递增、历史保留；**已完成批拒绝重跑**（`COMPLETED_BATCH_NOT_RERUNNABLE`） |
| **断点续跑** | 续跑键是 **`seq:loop_index`**：同一 `seq` 的循环每一圈独立可续。恢复时读已 `completed` 节点的 `node_key` 作 `skipKeys`，跳过它们、只补后面 |

> 「暂停」与「崩溃」的区别：暂停是**图执行在节点边界等人，进程还活着**；崩溃是**进程没了**，恢复靠持久化进度。
> 已知边界：`skipKeys` 按 `node_key` 匹配，节点**改名后**旧 `node_key` 失配会重跑（已由 `workflow.GraphRunnerTest` 的「续跑：改名失配则重跑」用例钉住）。

### 5.5 并发、资源与调度

**三个并发层级（别混为一谈）**

| 层级 | 现状 | 证据 |
|---|---|---|
| ① 单实验内多流程 / 分支并行 | ✅ 支持并已实测 | `verify-parallel-flow.py` 4/0 |
| ② 同一岛多实验并发 | ✅ 但**排队串行**，峰值并行 = 1（岛级互斥） | `verify-parallel-experiments.py` 3/0 |
| ③ 不同岛并发 | ⚠️ 代码支持（线程池最多 4），本环境仅一个岛，**未实测** | 仅读码 |

排程甘特不建模并行：按「同一时间只跑一个实验」串行累加，给出的是**下界**（真实完成只会更早），是有意取舍。

**四级资源模型**：一次搬运占用的资源分四级，粒度与互斥含义不同。

| 级 | 资源 | 表 | 粒度 | 互斥语义 | 占用时长 |
|---|---|---|---|---|---|
| L1 | 位置 | `position_state` | 一个层位 | 占用级互斥 | 任务全程 |
| L2 | 通道 | `device_port` | 一个进 / 出口 | `capacity=1` 互斥；`>1` 为信号量 | **动作级** |
| L3 | 门 | `device_access` | 一个可开合部件 | 动作级独占 | **动作级** |
| L4 | 机械臂 | `device_state` | 一台机器人 | 动作级独占 | **动作级** |

L2 的 `capacity` 表示「同时能过几块板」：1 = 串行，>1 = 可并行（用 `device_port_usage` 计数）。

**固定获取顺序**：一次 Transfer 的资源申请是**固定全序**，不许乱序，从源头排除循环等待：

```
① 源门(L3) → ② 源通道(L2) → ③ 源位置(L1)
→ ④ 目标门(L3) → ⑤ 目标通道(L2) → ⑥ 目标位置(L1)
→ ⑦ 回程位置(L1) → ⑧ 机械臂(L4)
──────────────────────────────────────────  全部就绪；板仍在源位，可零代价放弃
⑨ 抓板  ← 不可逆点
```

门排在最前：门是「总闸」，没开门进不去；门开了但机械臂没抢到 → 可关门放弃，代价小。

**等待图死锁检测**：即便有固定顺序仍保留一层安全网——等待图 + DFS 判环。

| 属性 | 值 |
|---|---|
| 算法 | DFS 判环 |
| 规模 | 资源数 n ≤ 10，边数 E ≤ 20 |
| 单次耗时 | < 10 微秒 |
| 开关 | **常开，无开关** |

常开理由：一次 Transfer 约 6 次资源申请 ≈ 60 微秒，相比一次设备动作（150 ms 到 30 分钟）可忽略；
为省这点开销引入开关反而带来竞态与漏检。

**为什么不用银行家算法**：① 流程有分支，执行到判定节点前无法声明「最大需求」；
② 硬声明就得按最坏情况（分支并集）≈「我要整个岛」，并发度归零；③ 分支确定后再重算代价大且越往后越没意义；
④ 银行家假设「声明不变」，人工改参数会推翻声明，假设不成立；⑤ 工程实践几乎不用（PostgreSQL / MySQL / Linux 都用等待图或锁顺序）。

**调度器**

| 属性 | 值 |
|---|---|
| 就绪判定 | 三态：`pending` → `running` → `completed`（另有 `paused` / `cancelled`） |
| 轮询间隔 | 2 秒 |
| 岛锁获取 | `putIfAbsent`（CAS 原子，保证同岛不并发） |
| 排序 | **EDD → priority → FIFO**（先到期先跑，同到期比优先级，再同则先提交先跑） |
| 重启恢复 | rehydrate：重启后恢复队列 |

### 5.6 时长模型与滚动排程

- **口径**：p50（展示总时长）/ p90（判断是否超最长间隔，保守）。
- **样本**：只用**清洗后**、时长为正的 `completed` 记录，按「能力 + 方法」聚合。
- **波动**：同一动作耗时波动很大——`Run` 的 p50 = 18.5 s、p90 = 250 s，**波动比 13.5×**。
  这是排程必须保守、且不能对单点估计过度乐观的根本原因。
- **滚动排程**：不一次排完，每次只排未来一个窗口。**承诺窗口**（已开始的实验绝不改动）+ **未来 15 分钟冻结区**；
  算法是**贪心**（不是完整 DP）——完整 DP 状态空间是天文数字（`2^50 × 480^26`），
  而输入本身（时长）就是估计值，用不准的数据算「最优解」没有意义。

## 八、术语表（评审时对齐用）

| 术语 | 含义 |
|---|---|
| **流程 / workflow** | 一张 BPMN 图，节点是动作，连线是先后 |
| **节点 / node** | 图中一步活：设备 + 方法 + 参数（或网关） |
| **实验 / experiment** | 若干流程按 seq 排成的一次任务（可循环） |
| **步骤 / step** | 实验中一条流程的一次执行（`experiment_run_step`） |
| **执行 / run** | 一次真实的设备驱动过程；实验的每一步都会生成一条 run |
| **节点执行 / run_node** | run 里的一个节点（level=0 是业务节点，level=1 是步骤） |
| **命令 / run_command** | 一次下发/应答，带原始回包 |
| **能力 / capability** | 如 SEAL、CENTRIFUGE；流程节点按能力找设备 |
| **实例 / device_instance** | 池子里某型号部署在某个岛上的一台具体设备（有 IP、驱动） |
| **暂停 / paused** | 图执行停在节点边界等人（不是进程崩溃） |
| **可恢复 / recoverable** | 进程崩溃时的中断单，已完成部分可跳过续跑 |
