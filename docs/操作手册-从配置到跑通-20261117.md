# 点位视角 · 从配置到跑通（管理员 / 应用者 / 操作员）

> 面向三件事：**管理员怎么配**、**配完应用者怎么用**、**怎么测/怎么在仿真里真跑一遍**。
> 配套阅读：`docs/仿真环境跑法与录片手册-20261117.md`（起环境/造布局/录片）、
> `docs/architecture/点位视角设计器-设计_20261116.md`（为什么这么设计、改过哪些坑）。
>
> 本文所有命令与 ID 都来自当前这台机器的真实环境（2026-11-17 实测）。

## 0. 先对齐三层与两个"视角"

| 层 | 谁 | 入口 | 产出 |
|---|---|---|---|
| **资产层** | 管理员 / 工程师 | `/positions`、`/arm-console`、`/designer` | 点位×方法授权、示教坐标、**工艺图**（图里只有点位，没有机械臂） |
| **组合层** | 应用者（工艺） | `/templates` | 模板：选流程 + 物料清单 + 点位白名单 + 循环圈数 + 发布 |
| **执行层** | 操作员 | `/material-config` → `/runs/:id` | 实例化 → 配位置 → 核验 → 齐套 → 启动 |

两个视角（同一张图、两种拖法）：

| 视角 | 拖什么 | 图上会不会出现机械臂 | 绑定 |
|---|---|---|---|
| **设备·方法**（老） | 设备 → 方法 | **会**（连续拖两台设备会自动插 `ARM_TRANSFER`） | 手动/不绑 |
| **点位视角**（新） | 点位 → 该方法 | **不会**（点位之间的搬运由执行期 Planner 插） | **拖完自动写一条 `node_binding`** |

> 关键：点位的搬运是**执行期**的事。应用者只需要说"这一步在 `DISP1-PLATE` 跑 `Run`"，
> 板怎么过去由 `PositionFlowPlanner` 在执行前补一段机械臂 `Transfer`，
> 而 `workflow.graph` **一个字都不会改**（图永远是纯点位图）。

### 角色与权限（**现状**，别按理想假设分工）

| 角色 | 可写（前端按钮/后端拦截） | 设计器 | 物料/启动 | 账号 |
|---|---|---|---|---|
| `admin` | ✅ | ✅ | ✅ | ✅ |
| `designer` | ✅ | ✅（推荐） | ⚠ 后端未限制 | ❌ |
| `operator` | ✅ | ⚠ **也能进、也能改** | ✅（推荐） | ❌ |
| `viewer` | ❌ 全只读 | 只读 | 只读 | ❌ |

> ✅ **已强制（2026-11-17）**：`canDesign` / `canOperate` 已接到后端 `ApiAuthInterceptor`，
> 越权直接 403；前端同步按角色禁用按钮。分工规则：
>
> | 类别 | 端点（举例） | 需要 |
> |---|---|---|
> | 编排类 | `PUT /workflows/{id}/graph`、`PUT /workflows/{id}/nodes/{k}/bindings`、`POST/PUT/DELETE /positions/{id}/methods`、`POST/PUT/DELETE /material-roles`、`*/robot-points*`、`/devices/{id}/points/*`、模板增删改 | admin / designer |
> | 运行类 | `POST /workflows/{id}/run`、`/runs/**` 写、`/experiment-runs/**` 写、`/transfers/{id}/confirm`、`/plates/*/locate`、`/manual-windows/**` 写、模板 `instantiate` | admin / operator |

期望看到（当前机器实测）：


1. **不要手动 `kill` 内核再裸启** —— 仿真态要带

3. 改了内核代码要 `./scripts/compile-kernel.sh` 再 `--restart`；只改前端不用重启内核（Vite 热更新）。

## 2. 管理员配置（7 步，做一次可以复用很久）

> 目标：让"点位 × 方法 × 角色 × 示教"这套**能力边界**成立。
> 应用者只能在这个集合里拖，拖不出边界外的东西。

### 第 1 步 · 设备上线、挂到岛

- 页面：`/topology`（设备与岛屿）、`/models`（型号库）
- 关键：设备必须**在线**（心跳），否则能力池里没有它，流程会"无可用设备"。

验收：

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:18080/api/devices/pool?islandId=1000505" | head -c 300
# 期望 items 里有 ARM1 / DISP1..6 / STACK1 / P_AUTO-1..4 / D9608-1 共 13 台
```

### 第 2 步 · 造点位（`/positions`）

当前岛 `LAB-EXT-01`（id `1000505`）已有 **82 个点位**。造点位有三种方式：

| 方式 | 适用 | 接口 |
|---|---|---|
| 单点 | 设备只有 1~2 个位置 | 页面「新增点位」 |
| 批量网格 | 耗材栈这一类（`STACK1-S01..S12`） | `POST /api/devices/{resourceId}/points/grid` |
| 按规格 | 96 孔板这类规整布局 | `POST /api/devices/{resourceId}/points/spec` |

每个点位要填对这几列（点位视角 palette 直接展示它们）：

| 列 | 取值 | 影响 |
|---|---|---|
| `code` | 全局唯一，如 `DISP1-PLATE` | **Planner 与驱动都用它解析**（不能用 label 代替） |
| `position_label` | 现场叫法，如 `PLATE` / `A1` | 仅显示；两个设备可能重名 |
| `point_role` | `source` / `target` / `both` | 只影响语义与筛选 |
| `slot_index` | 槽位号（可为空） | 分液器/孵箱这类多槽设备 |
| `robot_reachable` | `true` 机械臂可达 / `false` 设备内部位 | **`false` 的点位不能让机械臂搬**（预检 PF-27 会拦） |

> ⚠ 常见误配：把"台面内工位"标成 `robot_reachable=true`。
> Planner 会把"搬进台面"派给机械臂，运行期超时。

### 第 3 步 · 给点位授权方法（**最容易漏**）

页面：`/positions` → 「方法矩阵」/ 点位行的「可用方法」
接口：

```bash
# 查：这个点位允许跑哪些方法
curl -s -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:18080/api/positions/470/methods
# 实测返回：DISP1-PLATE 只授权了 methodId=417（Run），scopeKind=global

# 加：给点位授权一个方法
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"methodId":417,"scopeKind":"global","allocation":"explicit","purpose":"该工位允许执行"}' \
  http://127.0.0.1:18080/api/positions/470/methods
```

不给点位授权方法 ⇒ 应用者绑上去，**运行期只会"转人工"**，日志里没有一句说"方法没授权"。
现在预检会拦：**PF-21（ERROR）**。

### 第 4 步 · 示教坐标（`/arm-console`，admin 可见）

机械臂抓放需要的 `robot_point`（按**点位 code** 关联），仿真环境用
`python3 scripts/gen-sim-layout.py` 一次生成 78 个；真机现场用「抓点」按钮或 CSV 导入：

```bash
GET  /api/islands/{id}/robot-points          # 列表
PUT  /api/islands/{id}/robot-points/{code}   # 单点改 x/y/z
POST /api/islands/{id}/robot-points/{code}/capture   # 现场抓点
POST /api/islands/{id}/robot-points.csv      # CSV 批量导入
```

漏了示教 ⇒ **PF-30（WARN）**，运行期表现为"搬运超时"。

### 第 5 步 · 物料角色字典（本文补的缺口）

`node_binding.material_role` 与模板的 `manifest_items.role_code` 都要填角色，
但**这个字典原先没有任何页面入口**（只有 `GET/POST /api/material-roles`），新环境里是空的
⇒ 点位视角右上角「物料角色」下拉是空的 ⇒ 绑定存成 `role=null` ⇒ PF-23 一直提示、
跨点位搬运不知道搬哪块板。

一次性补齐（幂等，可反复跑）：

```bash
python3 scripts/seed-material-roles.py          # 建 mainPlate/magPlate/sample/reagent/tipBox
python3 scripts/seed-material-roles.py --dry-run
```

> 实测（2026-11-17）：执行前 `GET /api/material-roles` 返回 `items: []`；执行后 5 个。

### 第 6 步 · 事件类型与状态字典

- `/event-types`：设备主动上报的事件码（`waiting_interaction` 等）。流程里 `__awaitEvent` 只能从这个字典里选。
- `/state-dicts`：板状态 + 设备业务状态两套枚举。

不配也能跑，但流程一旦用到等待节点就会"下拉里没有、上位机等不到"。

### 第 7 步 · 建模板（`/templates`，非必填但强烈建议）

管理员/应用者都可以建，流程是：

1. 「新建模板」：填名称、岛、选流程（可多选）、循环圈数 → 创建
2. 打开编辑器：
   - **流程清单**：从流程库选，或点「克隆为新副本」得到模板专属副本
     （**必须克隆**：两个模板共用一张图时，改一个会串到另一个）
   - **物料清单**：`roleCode`（用第 5 步的角色）+ 类型 + 数量 + 是否必需
   - **点位白名单**：留空=不限制；填了则该模板引用的流程里，节点绑的点位必须都在名单内
   - **状态**：`draft` → `published`
3. **模板自检卡片**（会随保存自动刷新）：直接告诉你"还差什么才能实例化"。

自检码速查：

| 码 | 级别 | 含义 |
|---|---|---|
| `TEMPLATE-NO-PROCESS` / `-NO-MANIFEST` | ERROR | 没选流程 / 没填物料 |
| `TEMPLATE-WORKFLOW-MISSING` / `-DELETED` / `-EMPTY-GRAPH` | ERROR | 流程没了 / 已删 / 空图 |
| `TEMPLATE-ISLAND-MISMATCH` | ERROR | 流程和模板不在同一个岛 |
| `TEMPLATE-PREFLIGHT-BLOCKING` | ERROR | 流程预检阻塞（去设计器修） |
| `TEMPLATE-WHITELIST-BINDING` | ERROR | 流程里有节点绑的点位不在白名单内 |
| `TEMPLATE-WHITELIST-FOREIGN` / `-POINT-MISSING` | ERROR | 白名单点位属于别的岛 / 不存在 |
| `TEMPLATE-NO-WHITELIST` / `-DRAFT` / `-MANIFEST-ROLE` | WARN | 建议项 |

接口（脚本化时用）：

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:18080/api/experiment-templates/{模板id}/check
# {ok, errors, warnings, issues[], stats{processes,manifestItems,whitelistPoints,status}}
```

## 2.5 整岛搬运：导出 / 导入 JSON（管理员那 7 步一次搬完）

场景和"模板搬运"一样，但搬的是**现场**而不是工艺：演示机 → 交付机、测试库 → 生产库。

| 操作 | 入口 | 接口 |
|---|---|---|
| 导出整岛 | `/topology`（设备与岛屿）→ 岛行**导出整岛** | `GET /api/islands/{id}/export` |
| 导入岛屿包 | `/topology` 头部**导入岛屿包** | `POST /api/islands/import`（`?dryRun=1` 只校验） |

包里装的是：**岛 + 设备（资源/型号/能力/IP/驱动）+ 点位（含工位类型/可达性/标签/槽位）+ 点位方法授权 + 示教点**。
当前这套环境导出的量级：`devices=13, points=82, pointMethods=122, robotPoints=78`。

可移植键（**不含任何本环境 id**）：

| 对象 | 键 |
|---|---|
| 岛 | `island.code` |
| 设备 | `device.code`（全局唯一，作用域见《点位编号规范》§1.3） |
| 点位 | `point.code`（`<设备码>-<位>`，全局唯一） |
| 方法 | `methodName`（按设备型号解析） |
| 驱动 | `driverCode`（目标环境没登记 ⇒ 警告，导入后手工挂） |

行为约定：

1. **幂等**：设备按 code 已存在就跳过；点位按 code upsert；点位方法用 `ON CONFLICT DO NOTHING`
   ⇒ **同一套环境里重复导入是安全的**（适合演练/回归）。
2. **dryRun 先看会建什么**：`POST /api/islands/import?dryRun=1` 只统计不写库。
3. `problems` 非空 ⇒ 有对象没建成（HTTP 409），响应里带计数，按提示修完再导。
4. `warnings` 不阻塞：缺驱动、缺点位方法最常见（目标环境的型号方法库还没登记）。
5. ⚠ **耗时**：82 点位 + 122 授权 + 78 示教 ≈ **20~45 秒**（远程库每条语句 ~70ms）。
   HTTP 客户端超时别设 30s 以内。

命令：

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:18080/api/islands/1000505/export > island.json

# 先干跑
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  --data-binary @island.json \
  "http://127.0.0.1:18080/api/islands/import?dryRun=1"

# 真导入
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  --data-binary @island.json http://127.0.0.1:18080/api/islands/import
# {"ok":true,"islandCode":"LAB-EXT-01","devicesCreated":0,"devicesSkipped":13,
#  "pointsUpserted":82,"pointMethodsCreated":122,"robotPointsUpserted":78,...}
```

验收脚本：`python3 scripts/verify-island-io.py`（真 API + 真库，自建临时岛并**自动清理**）。

> 想真正"搬到另一套环境"时注意两点：
> ① 设备 code 全局唯一，目标环境已有同名设备会**跳过**（不会覆盖）——
>    命名口径（尾号是实例序号还是岛标记）见《点位编号规范》§1.3；
> ② 点位方法靠"目标设备的型号方法库"解析，新环境没登记就会进 `warnings` —— 先把型号/方法库对齐，再导岛。

## 3. 应用者（designer 角色）：用点位视角画流程图

入口：`/designer/{流程id}?islandId=1000505`
（`islandId` 决定左侧 palette 能看到哪些点位；不带也能用，但要先选岛）

### 操作路径

1. 左侧切到 **「点位视角」** tab
2. 顶部先选三样东西（拖之前定，拖完还能在右栏改）：
   - **物料角色**：`mainPlate` / `magPlate` / …（第 5 步的字典）
   - **装板方式**：装一块 / 装选中 / 全装 / 不装
   - **扫码策略**：不扫码 / 读码 / 校验进 / 校验进出 …
3. 展开某个点位（如 `DISP1-PLATE`）→ 把它的 `Run` **拖到画布**
   - 节点自动创建，**同时写入一条 `node_binding`**（不用再去右栏绑）
   - 图上**不会**出现机械臂节点
4. 依次拖下一个点位 → 两个节点自动连线
5. 选中节点，在右栏「节点设置」里设 **所属阶段**（S1..S8 / S0 / S9）
   - 阶段只用于分组与甘特聚合，**不改变执行顺序**

### 保存后必须看预检

页面右侧会给 `blocking / errors / warnings` 和每条 issue 的节点位置：

| 码 | 级别 | 含义 | 怎么修 |
|---|---|---|---|
| PF-21 | ERROR | 点位没授权这个方法 | 回 `/positions` 授权（第 3 步） |
| PF-22 | ERROR | 声明点位模式但没绑定 | 重新拖，或右栏补绑定 |
| PF-23 | WARN | 点位绑定没有物料角色 | palette 顶部选角色后重拖 |
| PF-27 | ERROR | 跨设备但目标位机械臂不可达 | 换可达点位，或确认那步该由设备自己做 |
| PF-30 | WARN | 标了可达但没有示教坐标 | 去 `/arm-console` 抓点 |

### 只跑部分阶段（客户场景："这次只做 W1/W2"）

```bash
# 只跑 S1、S2；其余有阶段归属的节点记 BYPASSED，图不改
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:18080/api/workflows/{流程id}/run?async=1&stages=S1,S2"
```

规则（实测）：

- 未分阶段的节点（变量/网关/公共步骤）**照常执行**（它们是阶段间传参的胶水）
- 被裁剪的节点状态是 **`bypassed`**（不是 `skipped`，后者会被当成"板位不可信"转人工）
- 所选阶段会记进 `run.input.stages`，事后能解释"为什么有些节点没跑"
- **只支持异步**（`async=1`）；同步路径显式 400，不静默忽略

页面上等价入口：`/workflows` → 选中流程 → 执行面板里的**阶段多选**（选项来自 compile 的 `stageCode`）。

## 4. 应用者/操作员：模板 → 实例化 → 配位置 → 启动

```bash
# ① 模板页：/templates
#    选中模板 → 「实例化并配位置」→ 自动跳到 /material-config?templateId=..&runId=..
# ② 物料配置：/material-config
#    每行选目标点位 → 「核验」；顶部显示「齐套，可以启动」才可点启动
# ③ 启动后在 /runs/{runId} 看逐节点进度
```

页面字段含义：

| 字段 | 说明 |
|---|---|
| 物料角色 / 类型 / 必填 | 来自模板的物料清单 |
| 目标点位 | 该行的下拉就是**模板岛**的全部点位（岛从模板取，不用再选） |
| 核验 | 记录"现场确实放在这了"；必填项未核验 ⇒ 不能启动 |
| 生命周期 | 本次专属 / 永久库存 |
| 齐套提示 | 直接显示后端原因（缺哪个物料、哪个未核验、设备是否在线） |

> 深链支持刷新/转发：`/material-config?templateId={模板id}&runId={runId}` 不会丢上下文。

## 4.5 模板搬运：导出 / 导入 JSON

场景：演示机配好一套模板 → 搬到交付机；测试库验证过 → 搬到生产库。

| 操作 | 入口 | 说明 |
|---|---|---|
| 导出 | `/templates` → 编辑器 → **导出 JSON** | 下载 `template-<编号>.json` |
| 导入 | `/templates` → **导入模板** → 选文件 | 成功后会直接打开新模板的编辑器 |

接口：

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:18080/api/experiment-templates/{模板id}/export > tpl.json

curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  --data-binary @tpl.json \
  http://127.0.0.1:18080/api/experiment-templates/import
# {"templateId":45,"templateNo":"TPL-…","workflowIds":[…],"warnings":["流程编码已存在，导入为 …-IMP-…"]}
```

文件里装的是**一整套**：模板（名称/状态/岛/圈数/白名单）+ 它引用的**流程**（图 XML + 阶段 + 节点绑定）+ 物料清单。
所以目标环境**不需要**先有那条流程。

关键设计：**导出里没有任何本环境的数据库 id**——全部用业务码，导入时在目标环境重新解析：

| 对象 | 导出/导入用的键 |
|---|---|
| 岛 | `islandCode`（如 `LAB-EXT-01`） |
| 设备 | `deviceCode`（如 `DISP1`） |
| 点位 | `pointCode`（如 `DISP1-PLATE`） |
| 方法 | `methodName`（如 `Run`，按设备型号解析） |
| 物料角色 | `roleCode`（如 `mainPlate`） |
| 流程 | `code`（重名时自动加 `-IMP-xxxxx`，并在 `warnings` 里说明） |

行为约定（都有断言守）：

1. **先全量校验再落库**：目标环境缺岛 / 缺点位 / 缺方法 ⇒ **400 + `problems[]`**，一条数据都不写；
2. 物料角色在目标环境不存在 ⇒ 不阻塞，但该绑定角色置空并给 `warnings`（随后 PF-23 会提示）；
3. 导入后模板状态沿用导出时的状态（`draft` 还是 `draft`）；
4. 验收脚本：`python3 scripts/verify-template-io.py`（真 API + 真库，跑完自清理）。

常见失败：

| 报错 | 原因 |
|---|---|
| `目标环境没有岛「X」` | 目标环境岛编码不同，改 JSON 里的 `islandCode` 或先建岛 |
| `绑定点位「X」(DEV) 在目标环境不存在` | 目标环境没这个点位码（或设备码不同） |
| `设备「DISP1」没有方法「Run」` | 目标设备型号没登记该方法 |
| `导入失败（可能留下部分流程…）` | 落库阶段异常（如约束冲突）。响应里带 `workflowIds`，按提示清理 |

## 6. 常见问题速查

| 现象 | 原因 | 处置 |
|---|---|---|
| 点位视角 palette 是空的 | 没选岛 / 该岛没点位 | 地址带 `?islandId=`，或先在 `/positions` 造点位 |
| 点位展开后没有方法 | 没做「点位×方法」授权 | `/positions` 方法矩阵加一条（第 3 步） |
| 拖完绑定是 0 条 | 图保存失败或绑定接口报错 | 看 toast「节点已入图，但绑定写入失败」；重拖或右栏补 |
| 预检 PF-21 | 同"没有方法" | 授权方法 |
| 预检 PF-23 一直提示 | 物料角色为空 | 跑 `scripts/seed-material-roles.py`，palette 顶部选角色后重拖 |
| 图上两点位相邻，跑完没搬运 | 机械臂不在能力池 / 点位同设备 / 被 stage 裁剪 | 查 `/api/devices/pool` 有 ARM1；查 `run.input.stages` |
| 搬运节点跑到一半转人工 `EC-POSITION-OCCUPIED` | 源位没板 / 板不是本 run 放的 | 配物料并核验（`/material-config`） |
| 搬运失败 `EC-SCAN-EVIDENCE-MISSING` | 抓板闸门要求扫码证据 | 流程里要有扫码节点，或仿真态开自动确认 |
| 启动按钮点不动 | 未齐套 | 看上方原因：必填未核验 / 设备离线 |
| 阶段裁剪 400 | 用了同步执行 | 加 `async=1` |
| 文档说删了，库里还在 | 清理脚本连错库 | 用后端同一套 `LABOS_DB_*` 重跑 |
| 403「不能修改工艺配置」 | 当前是 operator | 换 admin/designer，或只做运行操作 |
| 403「不能执行/启动实验」 | 当前是 designer | 换 admin/operator，或让操作员起跑 |

## 8. 已知边界（别踩空）

1. **点位视角的图目前只支持异步执行**（同步路径对 stages 显式 400）。
2. **搬运的"成功路径"依赖物料齐套**：源位没板时设备会回 `EC-POSITION-OCCUPIED`，
   这是设计行为（停下等人），不是 bug。
3. **多块板/一个节点多绑定位**：Planner 只取 `seq` 最小的一条。
4. **多臂**：取岛内第一台 TRANSFER 设备，还没有按区域/示教覆盖选臂。
5. **物料角色字典没有页面**：只能走 `scripts/seed-material-roles.py` 或 API（缺口已记录）。
6. `shadow-run` 需要 `LABOS_ALLOW_SHADOW_RUN=1`；`LABOS_TRANSFER_AUTO_CONFIRM` 只对
   `1000830` 生效（提取线故意不自动确认，必须物理证据确认）。
7. **角色隔离已接线**（2026-11-17）：`operator` 改图/绑点位/物料角色 ⇒ 403；
   `designer` 起跑/配位置/确认搬运 ⇒ 403。前端按钮同步禁用。
   仍保留 `canWrite` 作为兜底（viewer 全只读）。
