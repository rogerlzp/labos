# 表达式引擎 — 设计

> 流程里的变量需要**算术、条件、取整**，不能只做纯替换。
> 但**不能引入脚本引擎**——安全风险和依赖都太大。

---

## 一、要支持什么

### 1.1 必支持（M1）

| 类别 | 语法 | 例子 |
|---|---|---|
| **算术** | `+ - * / %` | `${usedSlots + 1}` |
| **取整** | `floor()` | `${floor(count / 8) + 1}` |
| **最值** | `max()` `min()` | `${max(a, b)}` |
| **比较** | `> >= < <= == !=` | `${a > b}` |
| **逻辑** | `&& \|\| !` | `${a > 0 && b < 10}` |
| **三元** | `? :` | `${a > b ? 1 : 2}` |
| **括号** | `( )` | `${(a + b) * 2}` |
| **变量** | `{name}` | `${i}` |
| **数字** | 整数/小数 | `${3}`、`${0.5}` |

### 1.2 不支持（**故意**）

| 不支持 | 为什么 |
|---|---|
| **字符串函数**（`substring`/`split`/`replace`） | 点位编号是拼接，不需要处理字符串 |
| **函数定义** | 会变成编程语言 |
| **循环**（`for`/`while`） | 循环是**节点类型**，不是表达式 |
| **对象/数组** | 变量都是标量 |
| **正则** | 同上 |
| **任意代码执行** | 安全底线 |

**原则**：**表达式只做"算一个值"，不做"写逻辑"。**

## 二、语法

### 2.1 EBNF

```ebnf
expr    := ternary
ternary := logic_or ('?' expr ':' expr)?
logic_or := logic_and ('||' logic_and)*
logic_and := equality ('&&' equality)*
equality := comparison (('==' | '!=') comparison)*
comparison := additive (('>' | '>=' | '<' | '<=') additive)*
additive := multiplicative (('+' | '-') multiplicative)*
multiplicative := unary (('*' | '/' | '%') unary)*
unary   := ('!' | '-')? primary
primary := number
         | string
         | variable
         | func '(' expr (',' expr)* ')'
         | '(' expr ')'
variable := '{' ident '}'
func    := 'floor' | 'ceil' | 'round' | 'max' | 'min' | 'abs'
```

### 2.2 两个作用域

**表达式出现在两个地方，作用域不同**：

| 位置 | 例子 | 变量来源 |
|---|---|---|
| **参数值里**（`${}` 内） | `"target": "ID1183-L${i}"` | 流程变量 |
| **条件里**（整个字符串） | `"condition": "${plateCount} > 0"` | 流程变量 |

**区别**：
- 参数值里的 `${}` 是**插入**（替换成结果）
- 条件里的 `${}` 通常**整体是一个表达式**

**统一处理**：都按"找到 `${...}` → 求值 → 替换"。

### 2.3 类型

**只有两种：数字、字符串**

```
${1 + 2}          → 3        （数字）
${"a" + "b"}      → ab       （字符串拼接）
${1 + "a"}        → 1a       （数字转字符串再拼）
${1 < 2}          → true     （布尔，输出 "true"/"false"）
```

**除法**：

```
${7 / 2}          → 3.5      （浮点）
${floor(7 / 2)}   → 3        （取整）
${7 % 2}          → 1        （取余）
```

**除零**：

```
${1 / 0}          → 执行时抛异常
                   "表达式求值失败：除数为 0（表达式 1 / 0）"
```

**不静默返回 0** —— 静默会让错误藏起来。

## 三、实现

### 3.1 为什么自己写解析器

| 方案 | 依赖 | 安全 | 代码量 |
|---|---|---|---|
| **Nashorn**（JDK 自带） | 无（JDK 15+ 已移除） | **可执行任意 JS** | 0 |
| **GraalJS** | 大（几十 MB） | 可执行任意 JS | 0 |
| **AviatorScript** | 一个 jar | 可执行脚本 | 0 |
| **自己写** | **无** | **只能算数** | **~300 行** |

**选自己写**：

- **零依赖**（和项目"裸 JDK"的取向一致）
- **安全**（不可能执行任意代码）
- **可控**（不支持的东西明确报错，而不是"意外支持了"）

### 3.2 结构

```java
/** 表达式：解析一次，多次求值。 */
public final class Expression {
    private final Node root;
    private final String source;

    public static Expression parse(String src);   // 解析，语法错就抛
    public Object eval(Map<String, Object> vars); // 求值
}

// AST 节点（内部类，不对外）
sealed interface Node {
    record Num(double v) implements Node {}
    record Str(String s) implements Node {}
    record Var(String name) implements Node {}
    record BinOp(Node l, String op, Node r) implements Node {}
    record UnaryOp(String op, Node operand) implements Node {}
    record Ternary(Node cond, Node t, Node f) implements Node {}
    record Func(String name, List<Node> args) implements Node {}
}
```

### 3.3 解析（递归下降）

```java
private Node parseTernary() {
    Node cond = parseOr();
    if (peek() == '?') {
        next();
        Node t = parseExpr();
        expect(':');
        Node f = parseExpr();
        return new Node.Ternary(cond, t, f);
    }
    return cond;
}
// 其余层级同理
```

**约 300 行**，包括 tokenizer（~80）、parser（~150）、evaluator（~70）。

### 3.4 求值

```java
Object eval(Node n, Map<String, Object> vars) {
    return switch (n) {
        case Node.Num v -> v.v();
        case Node.Str s -> s.s();
        case Node.Var v -> {
            Object val = vars.get(v.name());
            if (val == null) {
                throw new EvalException(
                    "变量未定义：" + v.name() + "（表达式 " + source + "）");
            }
            yield val;
        }
        case Node.BinOp b -> applyOp(b.op(), eval(b.l(), vars), eval(b.r(), vars));
        case Node.Ternary t -> toBool(eval(t.cond(), vars))
                ? eval(t.t(), vars) : eval(t.f(), vars);
        case Node.Func f -> applyFunc(f.name(), f.args(), vars);
        case Node.UnaryOp u -> applyUnary(u.op(), eval(u.operand(), vars));
    };
}
```

### 3.5 错误处理

**四类错误，消息都要具体**：

| 错误 | 消息 |
|---|---|
| **语法错** | `表达式语法错误："${1 + }"（位置 6：缺少操作数）` |
| **变量未定义** | `变量未定义：usedSlots（表达式 usedSlots + 1）` |
| **除零** | `表达式求值失败：除数为 0（表达式 1 / 0）` |
| **类型错** | `不能对字符串做减法："abc" - 1` |

**都带表达式原文** —— 排查时不用猜是哪个。

## 四、和现有代码的关系

### 4.1 现在的 `substVars`

```java
// 现在：纯替换
private String substVars(String s) {
    return s.replaceAll("\\$\\{([A-Za-z_]\\w*)}", (m) -> vars.getOrDefault(m.group(1), m.group(0)));
}
```

**只支持纯变量名，不支持表达式。**

### 4.2 改成

```java
private String substVars(String s) {
    Matcher m = PATTERN.matcher(s);      // \$\{([^}]+)\}
    StringBuilder sb = new StringBuilder();
    while (m.find()) {
        String exprSrc = m.group(1);     // usedSlots + 1
        Object v = Expression.parse(exprSrc).eval(vars);
        m.appendReplacement(sb, Matcher.quoteReplacement(String.valueOf(v)));
    }
    m.appendTail(sb);
    return sb.toString();
}
```

**兼容性**：`${i}` 这种纯变量名，表达式引擎也能算（就是一个 `Var` 节点），
**不用特判**。

### 4.3 缓存解析结果

**同一个表达式在循环里会被求值多次**：

```json
"target": "ID1183-L${i}"    // 循环 8 次，解析 8 次？
```

**缓存**：

```java
private static final Map<String, Expression> CACHE = new ConcurrentHashMap<>();

Expression expr(String src) {
    return CACHE.computeIfAbsent(src, Expression::parse);
}
```

**注意缓存上限**（表达式种类不会太多，但防内存泄漏加个 size 限制）。

## 五、示例

### 5.1 循环 + 拼接

```json
{ "nodeType": "loop", "varName": "i", "from": 1, "to": 8,
  "body": [{ "method": "Transfer",
             "params": { "target": "ID1183-L${i}" } }] }
```

```
i=1 → ID1183-L1
i=2 → ID1183-L2
...
```

### 5.2 计算下一个空位

```json
{ "nodeType": "compute",
  "set": { "nextSlot": "ID1183-L${floor(usedSlots / 1) + 1}" } }
```

**简化**：`ID1183-L${usedSlots + 1}`

### 5.3 三层循环（8 行 × 12 列）

```json
{
  "nodeType": "loop", "varName": "r", "from": 1, "to": 8,
  "body": [{
    "nodeType": "loop", "varName": "c", "from": 1, "to": 12,
    "body": [{
      "method": "Transfer",
      "params": { "target": "PLATE-${r}-${c}" }
    }]
  }]
}
```

**注意**：这是**嵌套循环节点**，不是表达式里的循环。

### 5.4 条件选择设备

```json
{ "condition": "${plateCount} > 4",
  "then": [{ "method": "Transfer", "params": { "target": "BIG-STACKER-S${plateCount}" } }],
  "else": [{ "method": "Transfer", "params": { "target": "SMALL-STACKER-S1" } }] }
```

## 六、边界与取舍

### 6.1 浮点精度

```
${0.1 + 0.2}   → 0.30000000000000004
```

**处理**：

```java
// 输出时格式化：如果是整数就输出整数，否则保留 6 位
String fmt(Object v) {
    if (v instanceof Double d) {
        if (d == Math.floor(d) && !Double.isInfinite(d)) {
            return String.valueOf(d.longValue());
        }
        return String.format("%.6f", d).replaceAll("0+$", "");
    }
    return String.valueOf(v);
}
```

**点位编号里不会出现小数**，所以这条主要是防意外。

### 6.2 变量名规则

**只允许**：`[A-Za-z_][A-Za-z0-9_]*`

**不允许**：中文、空格、点号。

**理由**：和 `${}` 的解析绑死，越简单越不会歧义。

### 6.3 表达式长度限制

**单条 ≤ 500 字符** —— 防止有人写一整段逻辑进去。

### 6.4 求值超时

**单次 ≤ 100ms** —— 递归下降 + 短路求值，正常不会超。
超了说明写了很深的嵌套，属于设计错误。
