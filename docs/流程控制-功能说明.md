## 一、这一版新增了什么

在这之前，流程图上虽然能画网关，但**只有"并行"是真能用的**：

| 能力 | 之前 | 现在 |
|---|---|---|
| 并行分叉 / 汇合（AND） | ✅ 能用 | ✅ 不变 |
| 条件分支（XOR + 条件表达式） | ⚠️ 能分叉，但**条件从不求值**，永远走 default | ✅ **按表达式真实判断** |
| 分支没走的那条 | ❌ 一直挂 `running`，和"没轮到"分不清 | ✅ 标 `bypassed`（未选中） |
| 循环（回边） | ❌ 回边被去重忽略，第二圈不执行 | ✅ 支持，最多 10 圈（可配） |
| 运行期变量 `${x}` | ❌ 只有实验层做参数替换 | ✅ 流程条件里可以用 |
| 节点输出 → 变量 | ❌ 无 | ✅ 自动进变量表 |

## 二、怎么用

### 2.1 画一个条件分支

在流程设计器里：

```
开始 → ◇分支（异或网关，default 指向"走B"）
         ├─ 条件边：${ok} == true   → [走A分支]
         └─ default 边              → [走B分支]
                                     两者都汇到 结束
```

**配置要点**

| 项 | 说明 |
|---|---|
| 网关类型 | 必须是**异或网关**（`exclusiveGateway`）。并行网关不看条件，默认全走 |
| 出边数量 | 支持 **>2 条**：按声明顺序求值，第一条成立的胜出，都不成立走 default |
| 条件写在哪 | 写在**出边**（sequenceFlow）的 `conditionExpression` 上，不是节点上 |
| default 边 | 所有条件都不成立时走它。不设的话走"排序第一条"并在日志留痕 |
| 条件为空 | 这条边不参与判断（当它是普通顺序边） |

### 2.2 条件表达式能写什么

```
${temp} > 37
${mode} == 'fast'
(${a} > 1) && (${b} < 5)
${count} >= 3 || ${force} == true
!(${ok} == true)
```

**只支持这些**，多一个字符都会报错（这是故意的，见技术设计"为什么不用 eval"）：

| 支持 | 例子 |
|---|---|
| 比较 | `> >= < <= == !=` |
| 逻辑 | `&& \|\| !` 和括号 |
| 变量 | `${名称}` |
| 字面量 | 数字、`'字符串'`、`true`/`false` |

⚠️ **不支持**：算术（`${a}+1`）、函数调用、正则、节点输出之外的字段路径（`${a.b}` 目前会把 `a.b` 当变量名，取不到就是空串）。

### 2.3 画一个循环

用**回边**表达循环：从后面的网关连回前面的任务节点。

```
开始 → [封膜一轮] → ◇还要再来吗（default 指向"结束"）
                      └─ 条件边：${go} == 'yes' → 回到 [封膜一轮]
```

**保护**（必须有，否则表达式写错就是死循环）：

| 保护 | 值 | 说明 |
|---|---|---|
| 单节点最多圈数 | **默认 10**，可按流程配置 | 写 `workflow.attr.maxIterations = 3` 即改成 3 圈（`UPDATE workflow SET attr = attr \|\| '{"maxIterations":3}'`） |
| 总步数上限 | **500** | 超过整单强制停下，日志 `[循环] 总步数超过 500，强制停下` |

> 圈数上限目前是引擎默认值，还没有暴露到界面（见"已知限制"）。

### 2.4 变量从哪来

| 来源 | 怎么用 | 例子 |
|---|---|---|
| **启动时传入** | 执行接口带 `vars`，或实验的"实验变量" | `POST /api/workflows/1259/run?async=1&vars=go=yes` |
| **节点输出**（自动） | 每个任务节点成功后，把**设备回包 `data` 里的字段**写进变量表 | `GetPlateType` 回 `{"plateType":1}` → 变量 `plateType=1` |

页面上：实验编排 →「实验变量」表格里定义的变量，执行时会注入。

### 2.5 页面上怎么看结果

运行详情 → 「流程图（按执行状态着色）」：

| 图上样式 | 状态 | 含义 |
|---|---|---|
| 浅蓝圆 | 开始 | 流程入口 |
| 浅灰圆（深边） | 结束 | 流程出口 |
| 绿色方框 | 已完成 | 这步做完了 |
| 橙色方框 | 待人工 | 转人工（如无纸 `EC-08-400C`） |
| 灰虚线方框 | 未执行 | 还没轮到（前面失败/暂停） |
| **淡灰点线方框** | **未选中** | 异或网关选了另一条路，这步不用做 |
| 黄色方框 | 已跳过 | 策略跳过（板位不可信，会停下等人） |
| 蓝色方框 | 执行中 | 正在跑 |
| 红色方框 | 失败 / 已终止 | |

节点表里「未选中」的行会写明原因：`分支未选中（异或网关走了另一条）`。

## 三、已知限制（重要，别踩）

| # | 限制 | 影响 | 计划 |
|---|---|---|---|
| 1 | 圈数上限是**流程级**配置（`workflow.attr.maxIterations`） | 同一流程里多条回边共用一个上限 | 后续支持按网关分别配 |
| 2 | 循环重入时**同一个 run_node 行被重复更新** | 图上只看到"最终完成"，看不到第 3 圈的中间态；`attempt` 会累加 | 需要按圈次分行的 run_node（表结构改动） |
| 3 | 变量只有**顶层字段** | 设备返回嵌套对象时取不到内层 | 需要 JSON path |
| 4 | 条件表达式不支持算术 | `(${a}+1) > 3` 不成立 | 可加，但优先级低于"求值器稳定性" |
| 5 | 变量名区分大小写 | `${Var}` ≠ `${var}` | 保持现状（和 BPMN 习惯一致） |
| 6 | 表达式写错 → 走 default 并记日志 | **不会**让整单失败 | 故意的：宁可走默认边也不卡死生产 |

## 四、一次真实运行（可直接复现）

```bash
# 条件分支：ok=true 走 A，ok=false 走 default(B)
curl -X POST "http://127.0.0.1:18080/api/workflows/1258/run?async=1&vars=ok=true"  -H "Authorization: Bearer $TOKEN"
# → A completed / B bypassed（分支未选中）

curl -X POST "http://127.0.0.1:18080/api/workflows/1258/run?async=1&vars=ok=false" -H "Authorization: Bearer $TOKEN"
# → A bypassed / B completed

# 循环：go=yes 回到自身，走满 10 圈后停
curl -X POST "http://127.0.0.1:18080/api/workflows/1259/run?async=1&vars=go=yes" -H "Authorization: Bearer $TOKEN"
# → 模拟器收到 10 条 Seal，整单 completed

# 不传变量 → 条件为假 → 只跑 1 次
curl -X POST "http://127.0.0.1:18080/api/workflows/1259/run?async=1" -H "Authorization: Bearer $TOKEN"
# → 1 条 Seal
```

## 六、网关、分支与变量：成对、嵌套与条件（2026-11-08 补充）

- **一个流程一个入口/出口**：画布上恰好 1 个开始、1 个结束；除 start/end 外每个节点都要有入边和出边，所有节点从开始可达、都能到达结束。
- **网关必须成对**：有分叉（出边 > 1）就要有同类型汇合（入边 > 1）；并行网关不汇合就没有“等齐”语义，异或网关可以用同一个结束事件收口。**禁止 1 进 1 出的网关**（无意义直通，容易看错）。
- **允许嵌套，但要有边界**：并行分支里可以再放异或/并行分叉，但内层分叉必须在**它所在的外层分支内**收口；每层分叉各自一对 join，不要用同一个 join 收两层不同语义。建议嵌套深度 ≤ 2 层、单图网关对 ≤ 4 对；超过时预检应给告警（当前产品预检只提示走不到/汇合卡住，强制校验在测试侧 `validate_flow()`）。
- **条件写在哪**：选中连线 →「连线 · 条件」面板写表达式（如 `${ok} == true`、`${counter} > 3`）；网关可设 default，未命中且无 default 时按声明顺序取第一条。
- **变量从哪来**：① 图内变量节点 `__setVar` / `__expr`（页面节点设置面板填参数）；② 执行时入参：`POST /api/workflows/{id}/run` 的 `vars` 参数（如 `?vars=ok=true`，`MTRX-异或-1` 即此口径）。
- **页面能力现状**：节点设置、连线条件、自动对齐都有页面入口；但「执行参数」还没有表单（页面执行按钮只发 `mode/async`），run input 变量目前只能 API 传——执行弹窗参数列入待补。
- **自动对齐规则**：先把网关分叉/汇合对放在同一水平线，分支节点上下对称排开，再递归排分支内部的嵌套网关对；最后把孤立节点收到最下面一排，避免叠在一起。
- **保存校验（2026-11-08 落地）**：服务端保存图时校验「恰好 1 开始/1 结束、没有孤立节点、所有节点从开始可达且能到结束」；不满足直接 HTTP 400 并在错误里指出具体节点。自动化/编辑器中间态可用 `?draft=1` 保存草稿（设计器页面可通过 `localStorage.labos.designer.draft=1` 打开该开关，测试 helper 会自动设置）；草稿图不允许执行。
