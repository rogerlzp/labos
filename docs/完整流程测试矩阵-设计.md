## 一、目的与范围

把"流程 / 实验"这一层的能力——从节点到端口拓扑、从单流程到多实验并发、从正常运行到暂停恢复——收口成一张**可复跑的测试矩阵**，并明确标出哪些已覆盖、哪些是缺口、哪些是能力边界。

覆盖：执行侧节点与网关、变量与条件、循环、并行、设备进出口拓扑、实验编排、并发、暂停与恢复。
不覆盖：设备驱动与协议实现（见 `scripts/verify-device-chain.sh`）。前端交互由**页面侧矩阵**与主链路 e2e 覆盖（见 §十、`scripts/e2e-smoke.py`）。

## 二、被测能力盘点

| 维度 | 能力 | 权威实现 |
|---|---|---|
| 节点类型 | `TASK` / `START` / `END` / `SPLIT_PARALLEL` / `JOIN_PARALLEL` / `SPLIT_XOR` / `JOIN_XOR` / `BUILTIN` | 编排编译器 |
| 内置节点 | `__setVar`（`var`+`value`）/ `__expr`（`var`+`expr`） | 执行器 |
| 网关语义 | 异或：按声明顺序求值，第一条成立即选，都不成立走 `default` | 编译器 / 执行器 |
| 变量 | `run?vars=k=v` 初始化；内置节点写入；设备回包字段写入；条件用 `${var}` | 运行时上下文 |
| 条件求值 | 比较 / 逻辑 / 括号 / 加减算术（`${a} + 1 > 3`） | `ConditionEvaluator` |
| 循环 | 回边 + `maxIterations`（**流程级**）+ `loop_index` 分圈 | 图执行器 |
| 并行 | 分叉 / 汇合；同设备自动串行（`DeviceLock`）；跨设备并行 | 执行器 |
| 端口拓扑 | `both` / `in`+`out` 分开 / 多进口；通道容量 | `TransferPlan` |
| 实验编排 | 实验 = 多个流程按 `seq` + 边拓扑展开 | `ExperimentExecutor` |
| 并发 | 同岛互斥（峰值并行 = 1） | 调度器 |
| 暂停 | `paused_fault` / `waiting_human` / `paused_unknown` + 恢复动作 | `PauseManager` |
| 心跳 | 5s 周期 / 20s 离线阈值 / 自动续跑 | `HeartbeatService` |

## 五、脚本分节明细

| 小节 | 断言 | 关键断言 |
|---|---|---|
| serial | 4 | 整单 `completed`；两任务都完成；设备命令 2 条 |
| builtin | 4 | 变量真的被改（走 A）；未选中分支 `bypassed` |
| outvar | 2 | 设备回包字段进变量表并驱动条件 |
| xor | 6 | 真走 A；假走 default；两条路径都标 `bypassed` |
| xor3 | 3 | 按声明顺序求值，三档输入各走一支 |
| loop | 3 | 跑满上限；每圈独立 `loop_index`；条件假不走回边 |
| loopback | 2 | 循环体含并行区不死锁；每圈并行两分支成对完成 |
| parallel | 3 | 同设备命令时间段不重叠；跨设备并行 |
| pause | 10 | 三态暂停 + 恢复语义 + 校正 + 心跳自动续 |
| ports | 4 | 三种拓扑结束后通道占用归零；`in` 被消费 |
| experiment | 3 | 实验内两个流程都登记、整单完成、都产生执行单 |
| concurrent | 1 | 两个流程并发提交、各自完成 |

## 六、缺口与归因

| # | 缺口 | 归因 | 计划 |
|---|---|---|---|
| 1 | 回边直接指向并行分叉网关 | 不支持（并行体被整体 bypass） | C 类：能力边界，见 §七 |
| 2 | 圈数上限按网关配置 | 不支持（流程级） | C 类：能力边界，见 §七 |
| 3 | OR / 包容网关 | 不支持 | C 类：能力边界，见 §七 |

## 七、C 类能力边界声明

| # | 边界 | 事实 | 影响 |
|---|---|---|---|
| 1 | 无 OR / 包容网关 | 执行侧只有异或（`SPLIT_XOR`）与并行（`SPLIT_PARALLEL`） | 需要"多路都满足都走"的编排要用并行网关替代 |
| 2 | 圈数上限是流程级 | `maxIterations` 取自 `workflow.attr`，不按网关 | 一个流程内多个循环共享同一上限 |
| 3 | `TransferPlan` 固定取 `in` | 源 / 目标通道固定取 `in`，`out` 方向在当前执行链未被消费 | `out` 只做容量声明，不产生独立占用 |
| 4 | 心跳自动续要求租户内无离线设备 | `autoResumeFaulted` 判定 `NOT EXISTS(... online=false)` | 只要有一台设备离线，故障暂停就不会自动续 |
| 5 | 回边不能直接指向并行分叉网关 | 回边指向并行网关时，并行体被整体 bypass（整单仍报 completed，命令 0 条） | 循环体含并行区时，回边必须指向并行区**之前**的任务（`loopback` 小节验证的是这一形态） |

## 九、更正说明

| 旧结论 | 现状 | 依据 |
|---|---|---|
| 条件里的算术不支持（`${a} + 1 > 3`） | **支持**（`+` / `-`，左结合） | `ConditionEvaluator` 的 `arith()`；`builtin` 小节实测 `${counter} + 10 == 10` |
| 循环重入时 `run_node` 只有一行 | **已解决**：按 `loop_index` 分圈 | `loop` 小节实测 `T:loop=0..3` |

## 十、页面侧矩阵（`e2e-flow-matrix.py`）

后端矩阵（§三）从**接口 / XML** 一侧把能力锁住，但它绕过了界面：palette 建不出某类节点、保存没落库、运行详情画不出图、页面上的暂停按钮点不动 —— 这些它都发现不了。`scripts/e2e-flow-matrix.py` 补上**页面侧**这一段。

| 小节 | 断言 | 覆盖 | 关键断言 |
|---|---|---|---|
| 登录 | 1 | 前置 | 登录后进入控制台 |
| A 设计器装配 | 6 | 开始 / 任务 / 异或网关 / 结束 | palette 落点生效；保存有提示；预检结论已渲染；落库 XML 含四类节点；刷新后仍在 |
| B 变量节点 | 4 | `__setVar` | 选中 task 出现「节点设置」；切到「变量节点」；填 `var`/`value`；接口回读 `method=__setVar`、`params.var=go` |
| C 运行详情 | 5 | 流程图 / 图例 / 节点表 / 圈次 | 进入运行详情；有流程图卡片；图例已渲染；节点表已渲染；有循环时出「圈次」 |
| D 页面暂停恢复 | 5 | 运行控制 | 出现「暂停」按钮；点击后库 `status=paused` 且页面显示已暂停；出现「继续」按钮；点击后离开 `paused` |

```bash
python3 scripts/e2e-flow-matrix.py --base http://127.0.0.1:8080
# 期望：通过 21 / 失败 0
```

**边界（C 类）**：设计器 palette **没有并行网关入口**（只有 `create.exclusive-gateway`，脚本以「观察」打印、不判失败），并行结构只能在 XML / 接口侧建立，页面上只负责"看" —— 与 §七 的并行能力边界一致。
