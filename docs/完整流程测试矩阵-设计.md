## 一、目的与范围

把"流程 / 实验"这一层的能力——从节点到端口拓扑、从单流程到多实验并发、从正常运行到暂停恢复——收口成一张**可复跑的测试矩阵**，并明确标出哪些已覆盖、哪些是缺口、哪些是能力边界。

覆盖：执行侧节点与网关、变量与条件、循环、并行、设备进出口拓扑、实验编排、并发、暂停与恢复。
不覆盖：设备驱动与协议实现（见 `scripts/verify-device-chain.sh`）。前端交互由**页面侧矩阵**与主链路 e2e 覆盖（见 §十、`scripts/e2e-smoke.py`）。

## 五、脚本分节明细

| 小节 | 断言 | 关键断言 |
|---|---|---|
| serial | 4 | 整单 `completed`；两任务都完成；设备命令 2 条 |
| builtin | 4 | 变量真的被改（走 A）；未选中分支 `bypassed` |
| outvar | 2 | 设备回包字段进变量表并驱动条件 |
| xor | 6 | 真走 A；假走 default；两条路径都标 `bypassed` |
| xor3 | 3 | 按声明顺序求值，三档输入各走一支 |
| loop | 3 | 跑满上限；每圈独立 `loop_index`；条件假不走回边 |
| loopback | 2 | 循环体含并行区不死锁；每圈并行两分支成对完成 |
| parallel | 3 | 同设备命令时间段不重叠；跨设备并行 |
| pause | 10 | 三态暂停 + 恢复语义 + 校正 + 心跳自动续 |
| ports | 4 | 三种拓扑结束后通道占用归零；`in` 被消费 |
| experiment | 3 | 实验内两个流程都登记、整单完成、都产生执行单 |
| concurrent | 1 | 两个流程并发提交、各自完成 |

## 六、缺口与归因

| # | 缺口 | 归因 | 计划 |
|---|---|---|---|
| 1 | 回边直接指向并行分叉网关 | 不支持（并行体被整体 bypass） | C 类：能力边界，见 §七 |
| 2 | 圈数上限按网关配置 | 不支持（流程级） | C 类：能力边界，见 §七 |
| 3 | OR / 包容网关 | 不支持 | C 类：能力边界，见 §七 |

## 七、C 类能力边界声明

| # | 边界 | 事实 | 影响 |
|---|---|---|---|
| 1 | 无 OR / 包容网关 | 执行侧只有异或（`SPLIT_XOR`）与并行（`SPLIT_PARALLEL`） | 需要"多路都满足都走"的编排要用并行网关替代 |
| 2 | 圈数上限是流程级 | `maxIterations` 取自 `workflow.attr`，不按网关 | 一个流程内多个循环共享同一上限 |
| 3 | `TransferPlan` 固定取 `in` | 源 / 目标通道固定取 `in`，`out` 方向在当前执行链未被消费 | `out` 只做容量声明，不产生独立占用 |
| 4 | 心跳自动续要求租户内无离线设备 | `autoResumeFaulted` 判定 `NOT EXISTS(... online=false)` | 只要有一台设备离线，故障暂停就不会自动续 |
| 5 | 回边不能直接指向并行分叉网关 | 回边指向并行网关时，并行体被整体 bypass（整单仍报 completed，命令 0 条） | 循环体含并行区时，回边必须指向并行区**之前**的任务（`loopback` 小节验证的是这一形态） |

## 十一、仿真机联调（`e2e-sim-flow.py`）

§十 的页面侧矩阵用的是**占位设备**，只到"页面能建、能点"这一层；`verify-device-chain.sh` 又从驱动侧发起，绕过了页面。两者之间留了一段空跑缺口：**真设备那一段在页面上到底跑不跑得通**。`scripts/e2e-sim-flow.py` 补上这一节 —— 它**只复用**已经跑起来的 `DeviceSimulator`（端口 19500..19506），不负责拉起；一台都没在听就整节 SKIP 并提示去 `labos-kernel/scripts/sim-up.sh`。

| 小节 | 断言 | 覆盖 | 关键断言 |
|---|---|---|---|
| 0 仿真机在位 | 2 | 前置 | 19500..19506 有监听；`device_state.online=true` 的演示岛设备数 > 0 |
| 0b 前置复位 | 1 | 测试卫生 | 解掉演示岛上遗留的 island 级现场扣留（`runtime_hold`） |
| A 页面建流程 → 绑真机 | 8 | 设计器 + 节点设置 | 界面新建流程进设计器；palette 落点；连线；保存落库 3 条 `sequenceFlow`；绑 `ID1731`/`Home`；再保存后编译计划带上设备方法；`workflow_node.params.protocol_name='Home'` |
| B 页面建实验 | 4 | 实验编排 | 选岛 `LAB-DEMO-02`；挂流程；新建实验；编排 1 条流程 |
| C 页面执行 → 断言 | 6 | 端到端真交互 | 落 1 条 `run`；`run.status=completed`；`experiment.status=finished`；`run_command` 有设备回包原文；落库指令方法 = `Home`；页面执行历史可见 |

```bash
python3 scripts/e2e-sim-flow.py --base http://127.0.0.1:8080
# 期望：通过 24 / 失败 0
```

**测试陷阱（现场扣留残留）**：只要上一轮有一条流程跑成"转人工/跳过"，执行器会按"现场暂停是安全事件"把**整座岛**扣住（`ExperimentExecutor` 里 `raise ISLAND`），这条 `runtime_hold` 不会自己消失。之后同岛上的**任何**新实验都会在动作边界直接落 `paused`，流程级 `run` 一个都不创建 —— 表现成"执行实验后没有新 run 落库"，看着像执行链路坏了，其实是上一轮留下的现场状态。所以脚本 **开跑前先复位、收尾再复位一次**（`reset_island_holds()`），别把残留留给下一次。这是测试残留，不是被测行为。

**产品侧一致性修复（本矩阵暴露）**：`WorkflowService.saveGraph` 对**新增节点**（INSERT 分支）会写 `workflow_node.params.protocol_name`，对**已存在节点**（UPDATE 分支）原本只写 `method_params`。页面场景里节点先保存一次、绑完设备再保存 → 走 UPDATE 分支 → `protocol_name` 写不进去（图 XML 里有、库里没有）。已在 UPDATE 分支同步回写 `protocol_name`，A 小节即以断言锁死。
