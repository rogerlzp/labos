# 点位编号规范

> **这是中控与机械臂的接口约定。**
> 中控用变量/公式算出点位 code → 传给机械臂 → 机械臂按 code 查坐标执行。
> **code 必须有序、可计算、唯一。**

---

## 一、编号格式

### 1.1 五种形态

| 形态 | 格式 | 例子 | 用于 |
|---|---|---|---|
| **多板位** | `{设备}-L{序号}` | `ID1183-L3` | 孵箱、离心机、读板机 |
| **多入口** | `{设备}-IN{序号}` | `ID1775-IN2` | 多通道进料设备 |
| **多出口** | `{设备}-OUT{序号}` | `STACKER-OUT1` | 堆板机、出料塔 |
| **单口** | `{设备}-BOTH` | `ID1731-BOTH` | 单口设备 |
| **堆叠位** | `{设备}-S{序号}` | `STACKER-S5` | 可叠放的塔/仓 |
| **停靠点** | `{设备}-DOCK` | `ID1731-DOCK` | 机械臂待机位 |
| **安全高度** | `{设备}-SAFEZ` | `ID1183-SAFEZ` | 到该设备的抬升点 |

### 1.2 组成规则

```
{设备编号}-{类型}{序号}
    ↑           ↑     ↑
  resource_node.code   L/IN/OUT/BOTH/S   1..N
```

**三段都必须是**：
- **设备编号**：`resource_node.code`（如 `ID1183`），全局唯一
- **类型**：单个大写字母或短词（`L`/`IN`/`OUT`/`S`/`BOTH`/`DOCK`/`SAFEZ`）
- **序号**：**从 1 开始的正整数**（不是 0，避免"第 0 个"的歧义）

**不允许**：
- 空格、下划线、小写（除设备编号本身）
- 序号从 0 开始
- 跳号（`L1, L3` 但没 `L2`）—— 除设备物理上真的缺层

## 二、编号 vs 访问顺序：**两个概念，别混**

### 2.1 先分清这两件事

| 概念 | 字段 | 含义 | 谁定 |
|---|---|---|---|
| **点位编号** | `robot_point.code` | **标识一个物理位置**（`ID1183-L3`） | 编排/同步时生成 |
| **访问顺序** | `robot_point.order_in_device` | **机械臂先取哪个**（1=先取） | **现场示教确定** |

**用户明确**：

> "L1 现在定不了，不同的位置，需要到现场去定，
> 我们写这个系统，需要对现场很多情况都支持的。"

**所以**：**系统不假设 `L1` 是底层还是外层**。
每台设备的实际顺序，**现场示教时配 `order_in_device`**。

### 2.2 两者不一致会怎样

**不会撞机，但取板效率不同**：

```
编号：L1 L2 L3 L4（从下往上编）
机械臂实际：先取最上面（L4）

如果 order_in_device 配成 L1=1, L2=2, L3=3, L4=4
  → 机械臂会尝试"先取最下面"
  → 但最下面被上面挡住，取不出来，或者行程很长

如果 order_in_device 配成 L4=1, L3=2, L2=3, L1=4
  → 机械臂先取最上面，正确
```

**关键**：
- **编号只要唯一 + 有坐标，就不会"撞"**
- **顺序只影响"取得到取不到"和"效率"**

### 2.3 什么时候顺序影响正确性

| 场景 | 顺序影响 |
|---|---|
| **流程指定具体编号**（`ID1183-L3`） | ❌ 不影响（直接去 L3） |
| **系统自动选空位**（`autoPickSlot`） | ✅ **必须按顺序**（否则选了被挡住的层） |
| **批量取板**（循环遍历） | ✅ **必须按顺序**（否则取不出来） |

**所以**：
- **`order_in_device` 在"流程指定编号"时是可选的**
- **在"自动选位/批量取"时是必填的**

**但为了统一**：**建议所有点位都填**，缺了标 `fill_status='pending'`。

### 2.4 为什么不能靠"格式"推断顺序

**曾经想过的方案**：规定 `L1` 必须是最底层。

**为什么放弃**：

| 问题 | 说明 |
|---|---|
| **设备差异大** | 孵箱可能是垂直层架（从下），读板机是水平托盘（从外） |
| **同一型号也可能不同** | 有的厂装反了，有的改过结构 |
| **现场才知道** | 只有示教时才知道机械臂实际怎么取 |

**用户的态度**："需要对现场很多情况都支持的" —— **不做假设，全部可配**。

### 2.5 配置示例

```sql
-- 离心机：4 层，从下往上
UPDATE robot_point SET order_in_device = 1 WHERE code = 'CENT-01-L1';
UPDATE robot_point SET order_in_device = 2 WHERE code = 'CENT-01-L2';
UPDATE robot_point SET order_in_device = 3 WHERE code = 'CENT-01-L3';
UPDATE robot_point SET order_in_device = 4 WHERE code = 'CENT-01-L4';

-- 某个装反的设备：从下往上编，但机械臂从上往下取
UPDATE robot_point SET order_in_device = 4 WHERE code = 'ODD-01-L1';
-- ... L2=3, L3=2, L4=1
```

**顺序和编号无关，只和"机械臂实际怎么动"有关。**

## 三、流程里怎么算点位## 三、流程里怎么算点位

### 3.1 循环：批量填 8 个层位

```json
{
  "nodeType": "loop",
  "varName": "i",
  "from": 1, "to": 8,
  "body": [{
    "method": "Transfer",
    "params": {
      "source": "STACKER-OUT1",
      "target": "ID1183-L${i}"
    }
  }]
}
```

**展开**：

```
Transfer(source=STACKER-OUT1, target=ID1183-L1)
Transfer(source=STACKER-OUT1, target=ID1183-L2)
...
Transfer(source=STACKER-OUT1, target=ID1183-L8)
```

### 3.2 计算：算出下一个空位

```json
{
  "nodeType": "compute",
  "set": {
    "nextSlot": "ID1183-L${usedSlots + 1}"
  }
}
```

**注意**：`${usedSlots + 1}` 是**表达式**，结果拼进 code。

### 3.3 条件：按情况选不同设备

```json
{
  "nodeType": "exclusiveGateway",
  "condition": "${plateCount} > 4",
  "then": [{ "method": "Transfer", "params": { "target": "STACKER-S${plateCount}" } }],
  "else": [{ "method": "Transfer", "params": { "target": "STACKER-S1" } }]
}
```

### 3.4 表达式能力要求

**流程里能算的**：

| 运算 | 例子 |
|---|---|
| 算术 | `${a} + 1`、`${b} * 2` |
| 取整 | `floor(${x} / 8) + 1` |
| 条件 | `${a} > ${b} ? 1 : 2` |
| 字符串拼 | `ID1183-L${i}` |
| 取余 | `${i} % 8`（循环用） |

**不支持的**（故意）：
- 复杂函数调用（`substring`、`split`）
- 循环内的变量修改（只读）

**理由**：表达式越强，越容易写错，越难排查。**够用就好**。

## 四、校验：编号错了要早报

### 4.1 编排时（保存流程）

```
检查每个 Transfer 的 target/source：
  - 如果写的是字面 code（不含 ${}）→ 查 robot_point 是否存在
  - 如果含 ${} → 只检查格式（能否拼出合法 code）
```

**不含变量的写法能查出来，含变量的查不出**（要执行时才知道值）。

### 4.2 执行时（查点位前）

```java
String code = substVars(target);          // ID1183-L3
RobotPoint p = robotPointByCode(code);
if (p == null) {
    throw new IllegalStateException(
        "点位不存在：" + code
        + "（可能：变量算错、编号没同步、或设备编号拼错）");
}
if (!"ok".equals(p.fillStatus())) {
    throw new IllegalStateException(
        "点位 " + code + " 的属性不完整（" + p.fillStatus() + "），需人工补填");
}
```

### 4.3 定期核验

**每周/每次同步后**跑一次检查：

```sql
-- 有设备但没点位的
SELECT d.code FROM resource_node d
WHERE d.parent_id = <islandId> AND d.kind = 'device'
  AND NOT EXISTS (
    SELECT 1 FROM robot_point p
    WHERE p.island_id = <islandId> AND p.device_resource_id = d.id);
```

```sql
-- 点位序号跳号（比如有 L1、L3 没 L2）
SELECT device_resource_id, string_agg(code, ',' ORDER BY code)
FROM robot_point
WHERE code ~ '-L[0-9]+$'
GROUP BY device_resource_id
HAVING count(*) <> max(
    regexp_replace(code, '.*-L', '')::int
);
```

## 五、编号规则的"为什么"

### 为什么要"设备编号 + 类型 + 序号"，而不是独立流水号

| 方案 | 优点 | 缺点 |
|---|---|---|
| **独立流水号**（P001, P002） | 简单 | **看不出属于哪个设备**，人工排查困难 |
| **设备编号 + 类型 + 序号** | 一眼看出是哪个设备的第几层 | code 长一点 |

**选后者**：**可读性 > 简洁性**，因为排查问题时要靠人眼看。

### 为什么序号从 1 开始

```
L0 还是 L1 是第一个？
  → 有些人从 0 数，有些人从 1 数
  → **从 1 开始，和"第几层"的自然语言一致**
```

### 为什么不支持"跳号"

**物理上可能真跳**（比如某层坏了）。

**但跳号会让"公式算序号"变复杂**：

```java
// 有跳号时，i=3 可能对应 L4
// 得维护一张映射表
```

**建议**：跳号的层位**仍保留编号**，只是 `fill_status='disabled'`，
公式不用改，调度时跳过。

## 六、完整例子：离心机（4 层位 + 1 门）

### 6.1 配置

```sql
-- 设备：CENT-01，4 个层位，1 个门
-- 门
INSERT INTO device_access (resource_id, code, access_type, open_method, close_method)
VALUES (<CENT-01>, 'DOOR', 'door', 'OpenDoor', 'CloseDoor');

-- 4 个层位
INSERT INTO position_state (resource_id, code, ...) VALUES
  (<CENT-01>, 'L1', ...), (<CENT-01>, 'L2', ...),
  (<CENT-01>, 'L3', ...), (<CENT-01>, 'L4', ...);

-- 4 个点位（L1 在最外侧，靠门）
INSERT INTO robot_point
  (island_id, robot_resource_id, code, x, y, z,
   device_resource_id, point_type, access_id, position_id,
   approach_axis, safe_z_offset, order_in_device, fill_status)
VALUES
  (<岛>, <机械臂>, 'CENT-01-L1', 320, 140, 45, <CENT-01>, 'place', <门>, <L1>, 'front', 80, 1, 'ok'),
  (<岛>, <机械臂>, 'CENT-01-L2', 320, 180, 45, <CENT-01>, 'place', <门>, <L2>, 'front', 80, 2, 'ok'),
  (<岛>, <机械臂>, 'CENT-01-L3', 320, 220, 45, <CENT-01>, 'place', <门>, <L3>, 'front', 80, 3, 'ok'),
  (<岛>, <机械臂>, 'CENT-01-L4', 320, 260, 45, <CENT-01>, 'place', <门>, <L4>, 'front', 80, 4, 'ok');
```

### 6.2 流程

```json
{
  "nodeType": "loop",
  "varName": "i", "from": 1, "to": 4,
  "body": [
    { "method": "Transfer", "params": {
        "source": "ID1775-L${i}",
        "target": "CENT-01-L${i}" } }
  ]
}
```

### 6.3 执行时（i=2）

```
① substVars → source='ID1775-L2', target='CENT-01-L2'
② 查点位：
   ID1775-L2：access=ID1775门, safe_z=80, order=2
   CENT-01-L2：access=CENT-01门, safe_z=80, order=2
③ 申请资源（固定全序）：
   门(ID1775) → 通道(ID1775) → 位置(ID1775-L2)
   → 门(CENT-01) → 通道(CENT-01) → 位置(CENT-01-L2)
   → 回程位 → 机械臂
④ 开两边的门
⑤ 抓板 → 抬到 safe_z → 横移 → 下降 → 放下
⑥ 关两边的门
⑦ 释放通道、机械臂（回程位保持）
```

**全程由 code 驱动，没有一处硬编码坐标。**

## 七、待确认

| # | 问题 | 影响 | 结论 |
|---|---|---|---|
| 1 | `L1` 是最底层还是最外层 | 取板顺序 | **现场定 `order_in_device`，系统不假设**（已定） |
| 2 | 堆叠设备 `S1` 是最下还是最上 | 同上 | 同上 |
| 3 | 设备编号里有特殊字符（`ID1731-2` 有横杠） | 解析歧义 | 从右往左找 `-L`/`-IN`/`-OUT`/`-S` |
| 4 | 序号上限（8 层？32 层？） | 表达式 `%` 基准 | 由现场决定，系统不限 |

**第 3 点要注意**：`ID1731-2-L1` 按 `-L` 切分能正确解析，
但如果设备编号里出现 `-L`（如 `DEV-L1`），就会歧义。

**建议**：解析时**从右往左**找第一个 `-L`/`-IN`/`-OUT`/`-S`，不从头找。
