## 本轮评审目标

确认 Workflow Runtime 是否以独立 Maven 模块、普通 JAR 的方式正确嵌入 LabOS Kernel Spring Boot 进程；重点核查构建依赖、Spring Bean 装配、DataSource/事务管理器共享、MyBatis BPMN DefinitionSource 读取、tenant 隔离和 GraphPlan snapshot 创建路径。

本项目 V1 明确是单实例：
- 一个 Kernel Spring Boot 进程；
- 一个 Runtime Host；
- 一个 PostgreSQL 17；
- 不设计多实例协调、分布式 Worker Lease、Leader Election、跨节点 fencing。

## 特别关注

1. Kernel 的 Maven / javac 混合构建链是否能在干净环境可靠安装并加载 Runtime JAR。
2. 是否确实只使用 Kernel 的同一个 DataSource 和 PlatformTransactionManager。
3. MyBatis Runtime Header/XML/NodeMetadata 查询是否都按租户和 workflow 限定，Header 是否排除软删除流程。
4. Header/XML/NodeMetadata 是否由同一个 REQUIRES_NEW + REPEATABLE_READ 事务读取，是否避免并发保存时跨版本拼接。
5. BPMN XML 与 workflow_node 元数据映射是否与真实存量 BPMN 格式一致。
6. Spring Bean 是否能被 LabosApplication 扫描，Mapper statement 和参数是否可绑定。
7. Run 创建是否正确保存不可变 GraphPlan snapshot，tenant definitionKey / version / hash 是否正确。
8. 任何缺少证据的项目请标 UNKNOWN，不要推断通过。

## 重要范围边界

当前阶段不包括 GraphCoordinator 完整状态推进、网关表达式求值、EventIngress/OutboxDispatcher/DeviceAdapter/EventDispatcher 真实闭环、Mock E2E、故障注入、真机 readback 和生产流量迁移。请把这些列为未完成项，不要因为本轮 Kernel Bean 已注册就判定 Runtime 已投产。
