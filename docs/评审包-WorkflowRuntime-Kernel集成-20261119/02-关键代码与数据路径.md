# 02 — 关键代码与数据路径

## 1. Spring Bean 装配

文件：labos-kernel/src/boot/java/com/labos/boot/WorkflowRuntimeKernelConfiguration.java

预期 Bean：
- WorkflowRuntimeRepository
- BpmnGraphCompiler
- WorkflowDefinitionSource
- WorkflowRunFactory
- WorkflowRuntimeTenantResolver

注意：本配置不注册 RuntimeHost。当前 EventIngress / Dispatcher / Coordinator 未形成闭环，不能启动一个空壳 Host 并开放 SchedulingGate。

## 2. DataSource / TransactionManager

文件：
- labos-kernel/src/boot/java/com/labos/boot/DataSourceConfiguration.java
- workflow-runtime/src/main/java/com/labos/kernel/workflow/runtime/persistence/WorkflowRuntimeRepository.java

检查点：
- Kernel 只创建一个 HikariDataSource。
- Kernel 只创建一个 DataSourceTransactionManager。
- Repository 构造函数显式接收 DataSource 与 PlatformTransactionManager。
- tx 和 snapshotTx 两个 TransactionTemplate 使用同一个 manager。
- Runtime 集成测试外层事务回滚应能回滚 Repository 内部 resolveTenantId 写入。

## 3. BPMN DefinitionSource 数据路径

Kernel Mapper：
- GraphMapper.selectWorkflowHeader(tenantId, workflowId)
- GraphMapper.selectGraphXml(tenantId, workflowId)
- GraphMapper.selectRuntimeWorkflowNodeMetadata(tenantId, workflowId)（本 PR 新增）

SQL 文件：labos-kernel/src/boot/resources/mapper/GraphMapper.xml

预期：
- Header 查询有 workflow.tenant_id = tenantId AND workflow.id = workflowId。
- XML 查询有 workflow.tenant_id = tenantId AND workflow.id = workflowId。
- 新节点元数据查询有 workflow_node.tenant_id = tenantId AND workflow_node.workflow_id = workflowId。
- 不调用旧的 selectEdges / selectWorkflowNodes 来重建 GraphPlan。

Adapter：
- workflow-runtime/.../LegacyKernelWorkflowDefinitionSource.java
- runtime tenant UUID → tenant_key → legacy bigint。
- 仅接受 kernel-tenant:<positive bigint>。
- 通过注入的 LegacyWorkflowReader 读取 XML 与 metadata。

Kernel Composition Root：
- WorkflowRuntimeKernelConfiguration 将 GraphMapper 查询结果映射为 NodeMetadata。
- definitionVersion 使用 workflow.version@workflow.updated_at，因为 graph 保存 SQL 更新 updated_at，不保证业务 version 每次递增。
- BPMN SHA-256 仍是定义内容校验依据。

## 4. Run 创建路径

WorkflowRunFactory：
1. 接收 Runtime tenant UUID 与 legacy workflow id。
2. 读取当前 BPMN + node metadata。
3. 编译 GraphPlan。
4. GraphPlan definitionKey = Runtime tenant UUID + workflow id。
5. 使用 BPMN XML SHA-256。
6. Repository.createRun 持久化 definition_snapshot + workflow_run + 初始 token + RUN_CREATED event。

检查点：
- 同 requestId 重放行为；
- definition snapshot 唯一键和 hash；
- tenant scoping；
- 首个 Token 的 nodeKey 是否正确；
- 不支持 BPMN 元素是否在创建 Run 前拒绝。

## 5. 构建链

- workflow-runtime 是独立 Maven 模块。
- labos-kernel/pom.xml 声明普通 Maven dependency。
- scripts/ensure-deps.sh 确保 Maven 可用并处理首次依赖安装。
- scripts/compile-kernel.sh 安装 workflow-runtime JAR，复制到 labos-kernel/lib/spring/，再按现有 javac/out 方式编译 Kernel。
- 评审需检查旧版本 jar 是否可能残留、重复加载或与 Maven 本地仓库版本不一致。


## 追加：定义读取一致性（最新实现）

- Runtime 使用独立 Mapper `selectRuntimeWorkflowHeader(tenantId, workflowId)`，只读 `id/version/updated_at/status`，并要求 `deleted_at IS NULL`。
- 原始 BPMN 仍由 `selectGraphXml(tenantId, workflowId)` 读取；节点元数据由 `selectRuntimeWorkflowNodeMetadata(tenantId, workflowId)` 读取。
- Kernel `WorkflowDefinitionSource` 将 Header、XML、node metadata 三次 Mapper 调用包在 `REQUIRES_NEW + REPEATABLE_READ + readOnly` 的同一个事务中，防止并发保存导致跨版本拼接。
- 评审时请核对 Spring MyBatis 使用的 SqlSessionFactory 是否通过 SpringManagedTransactionFactory / DataSourceUtils 共享 Kernel 事务连接；不能仅凭 TransactionTemplate 配置推断。
