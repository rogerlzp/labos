# 04 — 独立 AI / 人工评审任务书

你是独立的 Staff/Principal Engineer 和数据库事务审查者。请对 PR #5 的最新 HEAD 做源码级、反证式评审。不要因为实施说明写了“已完成”就接受结论。

PR：https://github.com/rogerlzp/labos/pull/5

## 评审规则

1. 先读取 PR 最新 HEAD SHA，并确认它与本评审包所记录的基线一致。
2. 对照 base branch 的实际 diff；必要时读取上下文文件，不局限于新增文件。
3. 每条结论必须给出文件路径、行号/方法名、具体证据。
4. 区分代码事实、推断和缺失证据。
5. 不要把编译通过当成 Spring 容器启动成功；不要把 SQL XML well-formed 当成 MyBatis statement 已绑定；不要把 Repository 测试当成真实 Kernel 事务集成测试。
6. 不要扩展成分布式架构建议；V1 明确单实例。
7. 不要把未实现的 GraphCoordinator / Adapter / E2E 标成已完成。
8. 不要直接修改代码。先提交独立评审意见，等维护者决定。

## 必审项（逐项 PASS / FAIL / UNKNOWN）

### A. 构建与依赖
- 新增 workflow-runtime Maven dependency 能否在全新机器上被 resolve？
- ensure-deps.sh 缓存命中/未命中两条路径是否都正确？
- compile-kernel.sh 是否总能使用刚构建的 JAR，而不是旧 JAR？
- lib/spring/* classpath 是否存在重复 Spring/Jackson/PG 版本或 class shadowing？
- 构建脚本是否有 Maven 不可用、路径含空格、失败退出码丢失等问题？

### B. Spring Boot 装配
- WorkflowRuntimeKernelConfiguration 是否被 LabosApplication 扫描？
- GraphMapper 是否由 MapperScan 注册，statement id/参数名/Map key 是否一致？
- Bean 是否存在循环依赖、重复 Bean 或类型冲突？
- 该配置是否意外启动未就绪 RuntimeHost 或开放调度？
- 是否应该有 ApplicationContext 启动测试，而目前只有 javac 编译？

### C. 事务和连接
- DataSourceConfiguration 是否是唯一 DataSource / PlatformTransactionManager 创建点？
- WorkflowRuntimeRepository 是否所有 TransactionTemplate 都使用注入的同一 manager？
- MyBatis 与 JdbcTemplate 是否能加入同一个 Spring 事务和同一个线程绑定 Connection？
- 外层事务回滚测试是否真的证明参与同一个事务，而非只证明 repository 自身能 rollback？
- snapshotTx 设置 REPEATABLE_READ / readOnly 在已存在事务中是否有预期行为？

### D. 租户隔离与数据读取
- workflow header、BPMN XML、node metadata 三个查询是否均 tenant-scoped？
- workflow_node 查询是否可能返回属于其他 tenant 的行？
- workflow_node / workflow / capability 表之间是否需要额外 tenant join 条件？
- stable tenant_key 的唯一性、解析、错误处理是否完整？
- legacy tenant id 为 0、负数、溢出或 malformed 时是否 fail closed？

### E. BPMN 与 GraphPlan
- 真实存量 BPMN XML 的 protocolName/resource/methodParams/stageCode 是否能被当前 Compiler 解析？
- metadata key 是否与 XML node id 一致？
- workflow.version@updated_at 是否可靠表示图定义修订？
- definitionKey 是否跨 tenant 唯一？
- startEvent 出边约束是否符合当前支持子集？
- 是否存在 compiler 对存量 BPMN 元素静默忽略的情况？

### F. Snapshot / Run 创建
- GraphPlan hash 与 BPMN 原文 hash 是否一致、稳定？
- Run 创建是否在同一事务内原子写入 snapshot/run/token/event/dedup？
- requestId 重放与定义变化组合是否正确？
- 恢复路径是否只读 snapshot，而不重新读取当前 BPMN？（如果尚未实现，请明确 UNKNOWN/未完成）

### G. 测试与门禁
- 最新 HEAD 对应 Runtime PG17 workflow 是否成功？
- 最新 HEAD 对应 Kernel CI 是否成功？
- 新增 mapper 是否有 MyBatis binding 测试？
- 是否有 Spring ApplicationContext test？
- 测试是否依赖缓存、历史 class 文件或环境变量默认值？

## 交付格式

1. Executive Summary：最多 10 行。
2. Blocking Findings：按严重性排序；每项有证据、影响、复现/修复建议。
3. Non-blocking Findings：同上。
4. PASS / FAIL / UNKNOWN 矩阵。
5. 测试覆盖与缺口。
6. 明确说明是否建议合并：Approve / Request Changes / Not Ready。

请优先寻找会造成租户越权、事务分裂、旧 JAR 被加载、错误 GraphPlan snapshot 或 Kernel 启动失败的问题。
