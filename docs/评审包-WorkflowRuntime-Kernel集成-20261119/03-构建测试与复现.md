# 03 — 构建、测试与复现

## 1. 本地标准构建

在仓库根目录：

    ./scripts/compile-kernel.sh

预期步骤：
1. ensure-deps.sh 准备 Maven 和 Kernel 依赖；
2. workflow-runtime Maven install；
3. Runtime JAR 复制到 labos-kernel/lib/spring/；
4. javac 编译 Kernel src/main + src/boot；
5. XML 资源合法性检查；
6. Mapper / 配置资源同步到 labos-kernel/out。

本仓库历史构建并非 Maven Reactor；不要擅自把 Kernel 的既有构建改成 Maven package，除非能覆盖全部旧测试/启动脚本并给出证据。

## 2. Runtime Maven 测试

Kernel 纯逻辑测试中新增 Runtime smoke test，单个自测输出遵循 `test-all.sh` 的 `通过 N, 失败 M` 解析契约；`test-all.sh` 汇总后输出 `通过 N / 失败 M` 供 CI gate 解析。

只运行纯单元测试：

    mvn -B -f workflow-runtime/pom.xml test

PostgreSQL 17 集成测试（需要数据库环境变量）：

    RUN_RUNTIME_PG_IT=1 PGHOST=localhost PGPORT=5432 PGUSER=runtime PGPASSWORD=runtime PGDATABASE=runtime_test mvn -B -f workflow-runtime/pom.xml test

CI 工作流 .github/workflows/workflow-runtime-db.yml 会：
- 启动 PostgreSQL 17；
- 初始化 db/workflow_runtime/001_init.sql；
- 执行 schema contract；
- 执行双会话并发与 CON-01..14；
- 执行事务原子性 / Inbox 冲突；
- 执行 Java Repository 集成测试。

- WorkflowRuntimeRepositoryTest：使用显式 PlatformTransactionManager；新增外层事务 rollback 验证，证明 Repository 参与共享事务。

- BpmnGraphCompilerTest：GraphPlan 编译、条件/default、metadata、unsupported element、dangling edge、snapshot JSON round-trip。
- Kernel 新 Mapper SQL：纯逻辑 smoke test 解析 XML，使用 ParamNameResolver 从真实 Mapper 方法生成参数对象，再通过 MappedStatement.getBoundSql 验证三个 Runtime statement 的参数映射、tenant predicates、soft-delete filter 和 capability tenant join；仍需独立评审确认 MyBatis-Spring 真实 Mapper 代理和生产 DataSource 事务绑定。

## 7. Kernel 装配与 Mapper 参数测试

`WorkflowRuntimeKernelConfigurationSelfTest` 已纳入 `scripts/test-all.sh` 的 PURE 测试集合。它会：

1. 建立 AnnotationConfigApplicationContext，注入一个 DataSource 和一个 PlatformTransactionManager；
2. 检查 Runtime Repository、Compiler、DefinitionSource、RunFactory、TenantResolver、KernelFacade Bean；
3. 确认该阶段没有注册 RuntimeHost；
4. 解析 `mapper/GraphMapper.xml`；
5. 通过 `ParamNameResolver` 从真实 Mapper 方法生成参数对象；
6. 对 `selectRuntimeWorkflowHeader`、`selectGraphXml`、`selectRuntimeWorkflowNodeMetadata` 执行 `MappedStatement.getBoundSql`，检查参数映射、租户条件、软删除过滤及 capability tenant join。

此测试不连接 PostgreSQL，也不等于完整 `LabosApplication` 启动；真实 MyBatis-Spring + PostgreSQL 的同连接事务仍属于待补强集成验证。

## 8. 数据库迁移前置条件

当前 PR 不会在 Kernel 启动时自动创建 Runtime schema。首次开放 Run 创建前，部署流程必须显式应用 `db/workflow_runtime/001_init.sql`。`002_schema_contract.sql` 是 CI 验收脚本，不是生产迁移入口。若生产迁移流程尚未纳入该 DDL，必须先补迁移步骤。
