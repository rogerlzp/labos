# 逻辑节点分层与两套编辑器的分工（2026-11-05）

> 回答一个问题：**实验画布里的分叉/并行/循环/汇合/变量，流程设计器要不要也有？**
> 结论：要，而且**主战场在流程内**。实验画布只保留「跨流程编排」的最小能力。
> 本文是给接手者的实施依据；每条结论都附代码/SQL 行号，不采信文档自述。

## 0. 一句话结论

- 逻辑节点（异或、并行、条件、循环、变量）**属于流程内**，归 bpmn-js 设计器；实验画布只做「跨流程编排」。
- 当前的真实状态是**能力错位**：设计器**仍有入口缺口**（palette 仍无并行网关入口；条件表达式与循环上限入口已于批 3/批 4 补齐），实验画布**有入口但不能保存也不能执行**（`fork/parallel/loop/variable/device/join` 保存一律 400，`parallel` 执行时被跳过）。
- 所以不是「把画布那套搬到设计器」，而是：**设计器补齐编辑入口；画布收敛到只做它真正能跑的事**。

## 1. 用户口径（本文的约束）

1. 绝大多数逻辑发生在**一条流程内部** → 必须在流程设计器里画得出来、存得下去、跑得起来。
2. 只有极少情况需要**跨流程**（实验级）编排 → 实验画布保留，但不承载流程内语义。
3. 不允许「画了但不执行」或「画了但存不了」——这比缺功能更糟。

## 4. 目标分工（本文主张）

| 层 | 载体 | 承载 | 不承载 |
|---|---|---|---|
| 流程内 | bpmn-js 设计器 | 设备/方法节点、异或、并行、条件表达式、循环回边、变量 | 跨流程依赖、板子物流 |
| 实验级 | 实验画布 | 流程节点（workflow）、开始/结束、（可选）跨流程并行 | 流程内网关、设备方法、变量赋值 |
| 岛屿物流 | 岛屿动线 `/island-flow` | 设备间搬运箭头 | 逻辑控制 |

同时明确三条边界：

1. 实验画布**不再提供**「存不下/跑不了」的节点类型；要么实现到能存能跑，要么从 palette 移除。
2. 流程设计器补齐并行网关、条件表达式、循环上限三个编辑入口（并行网关、条件表达式、循环上限三项均已于 2026-11-05 完成）；不引 `bpmn-js-properties-panel`，沿用 `NodeSettings` 同款轻量面板。
3. 两套条件语法统一到后端 `ConditionEvaluator`；画布自研 `evalCondition` 下线，避免「看着通过、实际走错」。

## 5. 实施路线（接手指南）

### 批 1 · 止血：画布不再「画了骗人」（0.5 天）

- 改 `ExperimentCanvas.tsx` 的 `PALETTE`：只留流程节点（开始/结束自动铺）；把分叉/并行/循环/汇合/变量从 palette 移除，页面加一句「流程内逻辑请到流程设计器」。
- 设备节点要么保留并明确标注「仅本画布执行、不会保存」，要么一并移除（见待拍板 Q1）。
- 同步 `scripts/e2e-canvas.py`：断言从「六类」改为「流程 + 开始/结束」，`MIN_CANVAS` 相应下调并在提交信息写明原因（测试规范要求）。
- 文档：`docs/实验编排-功能设计.md` 第十一节与 `docs/技术架构与模块地图.md:231-237` 的「画布支持分叉/并行」表述改为「画布仅跨流程编排」。

### 批 2 · 设计器补并行网关（1 天）✅ 已完成（2026-11-05）

- 新增 `webapp/src/bpmn/WorkflowPalette.ts`（自定义 PaletteProvider 扩展，priority=900，`getPaletteEntries()` 返回 updater，在默认 entries 上增删），注册进 `BpmnModeler` 的 `additionalModules`。文件名不叫 `Parallel*` 是因为它同时承担「补并行网关」与「移除解析器不认的入口」两件事。
- 同时收敛 palette：移除解析器不认的入口（中间/边界事件、数据对象、数据存储、泳道/参与者、分组）。这类节点拖到链路上会被 `GraphRunner` 静默跳过（`node == null → continue`，且不把后继入队），后面整段不执行且不报错。
- 验收：能拖出、能连两条出边/两条入边、保存落库、`PreflightChecker` 的 PF-05（汇合缺边）能报；`verify-flow-matrix.py` 的 parallel 3 条不受影响。
- 页面用例：`e2e-flow-matrix.py` A 节增加 3 条——「并行网关能拖出」「保存后 XML 含 bpmn:parallelGateway」「palette 已移除解析器不认的入口」（入口缺失时单列一条直接失败）。
- **已知风险（2026-11-05 裁定：仅登记、暂不动代码）**：`subProcess` 元素不在解析器白名单（`WorkflowGraphParser.java:189-197`），palette 保留 `create.subprocess-expanded` 是为了不丢「子流程分组」能力。实测（设备 200171 / 方法 Home）：`S → 空子流程 → T1 → E` 整单报 `completed`，但 `T1=bypassed`（静默跳过后继）；`S → 子流程(内含 S1→T1→E1) → E` 的 `T1=completed` 只是「内部 `startEvent` 被 `addEvents` 当成顶层 start 各种一个种子」的偶然结果，**不是真子图语义**（盒子自身的入出边通往虚无）。同一根因的登记见 `docs/测试用例总表.md` 诚实清单第 12 条。

### 批 3 · 条件表达式 UI（1–1.5 天）✅ 已完成（2026-11-05）

- 选中 `bpmn:SequenceFlow` 时显示「条件表达式」输入与「默认边」勾选；写 `bpmn:conditionExpression` 与 `default` 属性。
- 实现落点：面板放在**右栏独立的「连线 · 条件」Card**（连线不是 task，不进 `NodeSettings` 的 kind 三态）；保存走 `modeling.updateProperties` + `moddle.create('bpmn:FormalExpression')`，源为网关时写网关 `default`。
- 语法提示复用后端 `ConditionEvaluator` 支持的集合；前端只做括号与 `${}` 的轻校验，不做第二套求值器。
- 验收：页面断言已加（`e2e-flow-matrix.py` E 节）——写条件 → 保存 → 图里含 `bpmn:conditionExpression`。

### 批 4 · 循环上限 UI（0.5 天）✅ 已完成（2026-11-05）

- 提供 `maxIterations`（写 `workflow.attr.maxIterations`，**驼峰**；后端 `loadMaxIterations` / `setMaxIterations` 同键，1..100 校验）；页面提示「流程级上限，非网关级」。
- 实现落点：右栏「流程选项」Card（流程级，不依赖回边/节点选中态）+ `GET/PUT /api/workflows/{id}/options`。
- 验收：`e2e-flow-matrix.py` E 节断言「填 5 → `GET /options` 返回 `maxIterations=5`」。

### 批 5 · 跨流程并行（可选，需先拍板 Q2）

- 若要保留画布并行/汇合：先在 `QueryService.compileExperimentGraph` 放开这两类，并让实验执行器真正并行执行子流程；否则继续隐藏。
- 风险：逻辑并行不等于墙钟并行；岛锁会把同岛设备串行化。

### 待排期 · subProcess 静默跳过（2026-11-05 裁定：先放放，后面再做）

- 问题：`subProcess` 不在解析器白名单（`WorkflowGraphParser.java:189-197`），空子流程连进链路会让后继**静默 bypass**（整单仍报 `completed`）。实测证据见本文 §5 批 2「已知风险」与《测试用例总表.md》诚实清单第 12 条。
- 三条候选修法（届时再选一条）：
  1. **预检拦截**：在 `PreflightChecker` 加一条通用规则——链路上出现解析器不认的节点即 `Level.ERROR`（保留子流程分组能力，把静默跳过变成显式阻塞）；
  2. **palette 移除**：从 `WorkflowPalette.ts` 的收敛清单里补上 `create.subprocess-expanded`（最彻底，代价是不能再用子流程做分组）；
  3. **解析器透明化**：把 `subProcess` 当透明容器（入边接内部 start、出边接内部 end），真正支持子图语义（成本最高，改动运行时行为）。
- 前置依赖：若选 ③，需同步 `GraphRunner` 与 `verify-flow-matrix.py`（45 条）的用例，并新增「空子流程 / 有内容子流程」两条对照断言。
- 未排期原因：不影响当前主链路（设计器常规用法是 start/task/网关直连），且三条修法各有权衡，需先定口径再动手。
