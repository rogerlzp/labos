# 页面自动化操作（bpmn-js 画布）踩坑记录

日期：2026-11-11
结论：**不要用 CDP/Playwright 合成鼠标事件操作设计器画布。这个方法不可用，已放弃。**

## 我在用什么方式操作

Kimi Work 内置浏览器 + CDP `Input.dispatchMouseEvent`（press / release / move），
与 Playwright 底层是同一套合成事件机制。目标是代替人工，在设计器页面
（`/designer/<workflowId>`）上拖节点、连线、删除，搭建人工验收用的测试流程。

## 为什么这个方法不行（实测记录）

bpmn-js 画布对指针事件非常敏感，合成事件与真实鼠标事件在时序、目标元素判定上
有系统性差异，导致操作结果不可控：

1. **press + move + release 语义不稳定**
   - 手型工具下，一次"拖拽平移画布"的操作（press (900,400) → move (900,600)）
     被画布判定为**点击**，结果在默认位置 (516,547) 凭空新建了一个并行网关。
     原因：之前激活的"网关工具"并未退出，canvas press 被解释为"放置元素"。
   - 也就是说：**任何一次 canvas press/release 都可能是"放置工具元素"**，而
     工具是否处于激活状态无法从 DOM 稳定判断（`.highlighted-entry` 经常缺失）。

2. **点击选不中元素**
   - 对网关中心点连续多次 press/release + hover 前置 move，元素始终不进入
     `.selected` 状态；bpmn-js 的选中依赖其自身的 pointerdown 时序逻辑，
     合成事件经常只触发 hover。

3. **工具不自动退出，产生级联污染**
   - 点击 palette 上的工具图标后，工具保持激活。此后每一次画布点击都会
     新建同类元素（拖 midpoint 也会新建网关）。必须显式点击手型工具退出，
     但点击手型工具本身也经常不生效。

4. **错误会静默落库**
   - 画布改动触发 draft 保存，错误创建的网关直接持久化到 `workflow_node` 表，
     页面上看不出来，只能靠 SQL 核对才能发现"画布上多了个东西"。

5. **会话频繁过期放大损失**
   - 页面会话约 15–30 分钟过期，过期后 draft 保存静默失败并跳登录页，
     前面辛苦做对的操作可能整段丢失，从头再来时重复踩坑。

## 判定

该方式操作正确率过低、且错误不可见（静默落库），**不可用于搭建/修改流程**。
已记录为禁止方法。搭建测试流程请改用：

- 人工在页面上操作（最可靠）；
- 或直接调用内核 API/数据库造数（此前流程 A 的 API 造数方式稳定可用，
  仅在最终需要"页面上可见"时人工微调）。

## 附录：唯一验证过相对可靠的子操作（也不建议再用）

- 拖入节点：evaluate 里构造 `DataTransfer` 对 palette 方法项 dispatch
  `dragstart`（React 自动填 payload），再对 `.djs-container svg` dispatch `drop`。
  成功率较高，但 drop 落点不可控，连续拖入虽会自动串行连线，仍受工具状态污染影响。
- 其余（选中、拖拽移动、连线、删除）在合成事件下均不可靠。
